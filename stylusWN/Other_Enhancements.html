Release 26.10 Enhancements

The following enhancements have been made:

flow Attribute Category Enhancement - New Attribute for Identifying Active Plugin Step

In this release, a new attribute, flow_plugin_canonical_current, has been added to the flow attribute category. Use this attribute to identify the canonical plugin step currently being run, enabling accurate detection of the plugin within the Flowtool‑based flows. When a plugin is not run, this attribute returns an empty value.

New Command for Reporting Connections Between Two Hinsts

In this release, a new text command, db_hinst_connection, has been introduced. You can use this command for reporting connections between two hinsts. The following are the parameters of this command:

[-help]
hInst hInst

Enhancement to Restrict Saving the Database in the ECO Batch Mode

A new attribute, write_db_restrict_under_eco_batch_mode, has been introduced. You can use this attribute to prevent the database from being saved in the ECO batch mode.

flowtool Attribute Category Enhanced

In this release, a new attribute, flowtool_schedule_flow_immediate, has been added to the flowtool attribute category. When set to true, flowtool will start the scheduled flows immediately. When set to false, it waits for the software to exit before starting the scheduled flows. 

check_ac_limit Attribute Category Enhanced

In this release, the following new attributes have been added to the check_ac_limit attribute category:

  • check_ac_limit_additional_individual_violation_report: Specifies to generate separate violation reports for each current waveform calculation method (rms, peak, or avg). If this attribute is not specified, a single violation report file is generated using the check_ac_limit_method {RMS AVG peak} attribute.
  • check_ac_limit_check_thermal_aware_em: Specifies to use the thermal map for EM checks. The thermal map file is specified using the set_rail_analysis_config -read_thermal_map parameter. The Rail Analysis engine uses the temperature specified in the thermal map file for EM analysis. EM limit has a strong temperature dependency. For a chip that has substantial temperature variation across the chip, the Rail Analysis engine can use the temperature specified in the thermal map file to perform accurate EM analysis.
  • check_ac_limit_em_cdf_percentage: Calculates the Cumulative Distribution Factor (CDF) derating factor based on the EM rules specified in the ICT EM file, given by the check_ac_limit_ict_em_models attribute. This attribute is used to calculate the failure rate and reliability of a design. The value of the CDF percentage should be between 0 and 100.
  • check_ac_limit_ircx_models: Specifies an encrypted or unencrypted RC/EM technology (.ircx) file. The foundry-specific IRCX file, which contains the process information for extraction and EM modeling, can be used when the ICT-EM file is not available for electromigration analysis.
  • check_ac_limit_lifetime_rating_factor_file: Specifies a lifetime rating factor file that contains jmax_life values for each layer. These values are defined based on temperature and lifetime pairs. When you provide this file, EM analysis will automatically select the appropriate jmax_life factor for each layer based on the specific temperature-lifetime combinations defined in the file.
  • check_ac_limit_report_unannotated_shapes: Provides visibility into partial net coverage within SPEF files.  When this attribute is set to true, the <report_name>.rpt.unannotated_shapes is generated. This report identifies and lists nets that contain shapes without resistance annotations or unanalyzed/partially analyzed segments. The feature helps to detect incomplete parasitic extraction coverage and improve accuracy during validation and signoff workflows. The reporting of partial net coverage works only when check_ac_limit_effort_level is set to high. 
  • check_ac_limit_simulation_net: Forces the specified nets to use the simulation mode.
  • check_ac_limit_simulation_net_file: Forces the nets in the specified file to use the simulation mode.
  • check_ac_limit_top_scope_ignore_block_internal_nets_on_boundary_path: Ignores the internal nets from the first instance to the first flop on the boundary path for the signal EM checking.

Added New Attribute

The following new attribute has been added:

  • timing_library_ignore_combinational_arc_mismatch_tables: When set to true, the software will give preference to timing_type over arc tables. This will change the inferred arcs based on the timing_type (liberty format) or timing tables settings. A warning message will be displayed when the preference (timing_type or arc tables) is changed.

By default, this attribute is set to false.

route_special Attribute Category Enhanced

In this release, a new attribute, route_special_pad_pin_split_from_center, has been added to the route_special attribute category. Use this attribute to split the width and spacing specified by the route_special_pad_pin_split attribute to enable connections to the center of wide pad pins. This parameter must be used with the route_special_pad_pin_split attribute.

New Commands to Abstract Cloned Instances of Large Design Modules

In this release, the following new commands have been introduced:

  • set_selectively_expanded_modules: Abstracts cloned instances of modules with a high number of instantiations, and flatten is one or more of them. This reduces memory usage and runtime significantly during the STA and ECO processes. It helps handle large designs on smaller machines and facilitates ECO implementation without the need to manually partition the design into smaller segments.
  • get_selectively_expanded_modules: Displays the values set by the set_selectively_expanded_modules command.

New Command to Zoom into Highlighted Timing Paths

In this release, a new command, zoom_highlighted_timing_path, has been introduced. Use this command to zoom into highlighted timing paths in the Timing Debug form in the Layout view, and to enable sequential traversal when multiple paths are highlighted. This command reduces the number of steps required to view and navigate timing paths in the Layout view. The command is very useful for zooming into highlighted timing paths in large designs. The following are the parameters of this command:

[-help]
[-previous | -next]

Clock Tree Debugger Enhancements

Support for Coloring Based on Maximum Fanout Constraint

The CTD is enhanced to support coloring selected nodes based on the maximum fanout constraint. For this feature, a new option, Fanout violation, is added to the Color by menu and the Control panel. The tooltip shows the violation amount and target value.

For details, see the Clock Menu chapter in Tempus Menu Reference.

Support for Displaying Partition Hierarchy

A new option called Partition Hierarchy has been provided in the Visibility menu, Color by menu, and Control panel. This option provides a color category for each partition in the design. Each marker is drawn with the color associated with that partition.

This option is only shown in these menus for designs with partitions configured and is available in unit delay and timing-based modes.

Signal Edge Coloring Enhanced

The Signal edge option in the Visibility menu, the Color by menu, and the Control panel provide options to view and color signal edges for cells and nets. In this release, the signal edge feature is enhanced in the following ways:

  • The cell coloring was previously only based on the edges found on the input and output nets. New cell coloring is based on the more accurate timing arcs.
  • The Cell and Net items of the Signal edge option now have no color associated with them in the tree view. Only the options available within each subgroup have color options.
  • The default coloring is changed to make them more colorblind friendly.
  • The Root option is removed from the Cell subgroup. This option was used for both non-generated and generated clock roots. It is replaced by a new Unknown option that includes non-generated root cells. The generated root cells are now colored according to the Simple/Inverting/Non-unate options. 
  • The Unknown option is also added in the Net subgroup. It is used for nets with no skew groups.
  • The Net subgroup coloring is enhanced to include nets connected to generator path nodes.

Support for Displaying Skew Group Source Pin

When displaying a single skew group, the source pin is typically not shown because CTD markers represent input pins, while skew groups usually start at output pins. Starting from this release, CTD is enhanced so that when coloring or displaying by skew group, a marker is treated as part of the skew group if either its input pin or the output pin of the corresponding clock node belongs to that skew group. This ensures that it remains visible when other skew groups are hidden.

Support for Zooming into a Selected Item in the Clock Tree Viewer

In this release, a new toolbar widget, Zoom Selected, is added to the row of widgets below the CTD menu bar. This widget allows you to zoom into a selected item in the Clock Tree Viewer without opening the Set Preference form. The equivalent bindkey is Ctrl+Z.

As part of this enhancement, the Enable Zoom selected option in the Set Preference form is renamed to Enable Zoom layout selected. The equivalent bindkey provided is Ctrl+E.

Support for Displaying Skew Group Source Pin

When displaying a single skew group, the source pin is typically not shown because CTD markers represent input pins, while skew groups usually start at output pins. Starting from this release, CTD is enhanced so that when coloring or displaying by skew group, a marker is treated as part of the skew group if either its input pin or the output pin of the corresponding clock node belongs to that skew group. This ensures that it remains visible when other skew groups are hidden.

Quick Access to Object Attributes

You can now view object attributes directly from the Clock Tree Viewer using the v bindkey. Select any object and press v to open the Object Attributes form, providing faster access to detailed object information without navigating menus.

Color Map Changes for Setup and Hold Slack

The color map represents the slack range from negative to positive values. In this release, it is enhanced so that white indicates the most negative slack, transitioning to red at zero slack. Positive slack is shown starting in green and progressing to purple, which represents the highest positive slack.
