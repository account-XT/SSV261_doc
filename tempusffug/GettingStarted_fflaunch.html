Launching the Foundation Flow

You can launch the Foundation flow from WORK/dir:

% mkdir WORK

The Foundation flow requires a setup.tcl as input. To create this file, copy TEMPLATES/TEMPUS/setup_*.tcl to WORK/setup.tcl and edit the file:

  1. For MMMC flow, copy TEMPLATES/TEMPUS/setup_mmmc.tcl
  2. For CPF flow, copy TEMPLATES/TEMPUS/setup_cpf.tcl
  3. For single view non-MMMC flow, copy TEMPLATES/TEMPUS/setup_default.tcl
If setup.tcl is not copied in WORK/dir, use "setenv FF_SETUP_PATH <path>" to specify the directory, which contains the setup.tcl file before launching TEMPUS.

There are two ways to run the Foundation flow in Tempus:

  • Using Code Generator
  • Using Predefined Scripts

Using Code Generator

The foundation flow scripts are difficult to read and debug. This hinders those users who would like to use the scripts as a reference flow as well as for auditing purposes where readability is important. Tempus provides a code generator to enable users to quickly generate scripts to load their design data, setup their timing environment, and execute the recommended timing and SI flow.

The foundation flow is in the SCRIPTS directory and the code generator is SCRIPTS/gen_tempus_flow.tcl.

Advantages

The following are the advantages of the Code Generator:

  • Through the Code Generator, the scripts will be "generated" instead of being "executed".
  • All flow will have the command sequence based on the user settings. A clean, flat script will be generated for conditional code that is based on static user settings (for example, setup.tcl).
  • All conditional code branches that require run time specific data will be generated as conditionals (that is, they cannot be `flattened').

For example, since analysis view can be altered via user plug-ins, checks must be made to determine which corners are active:


set vars(active_rc_corners) [list]
foreach view [concat [all_setup_analysis_views] [all_hold_analysis_views]] {
set corner [get_delay_corner [get_analysis_view $view -delay_corner] -rc_corner]
if {[lsearch $vars(active_rc_corners) $corner] == -1 } {
lappend vars(active_rc_corners) $corner
}

The following procedures will be covered in procs.tcl.

Procedure Type Description

system_info

TCL Command


Usage: tclsh ../SCRIPTS/gen_tempus_flow.tcl [ -d output_dir ]

Command-Line Options

The following are the command line options:

Command Description

-1

Prints each Tempus command out on a single line. By default, the Tempus commands may be printed across lines with an approximate line size of 80-90 characters.

-h | -help

Print this message

-f | -flat

Flatten/unroll levels

-d | -dir

The code generator creates a design specific set of run scripts in a FF directory in the local user directory. You can optionally change the name of the output directory using this option.

-p | -pseudo

Provides pseudo run script of Tempus instead of whole design specific FF environment. This option can be used as follows:

  • -p: An existing setup.tcl file is defined. File checking step is skipped to generate the pseudo code.
  • -p default: Generates a reference setup.tcl and pseudo code for the default flow.
  • -p mmmc: Generates a reference setup.tcl and pseudo code for the MMMC flow.
  • -p cpf: Generates a reference setup.tcl and pseudo code for the CPF MMMC flow.

To improve usability, the Tempus foundation flow allows the use of pseudo mode. In this mode, the foundation flow does not require any input data; the software directly dumps the Tempus run script. You can edit the script manually after checking the Tempus flow, and then replace the pseudo file name with the real data file name before running Tempus.

-s | -setup

Provide the directory containing the setup.tcl setup file required to run the Foundation Flow.

Default is ".".

Usage

Below are the steps to use the Code Generator:

  1. Dump the foundation flow code generator from the Tempus interface or download from the download manager.
    • GUI: Tools > Foundation Flow Template > Save
    • TUI: write_flow_template -directory directory
  2. Create a setup.tcl using either the foundation flow wizard or using gen_tempus_setup.tcl.
    • To create using gen_tempus_setup.tcl,
      • load an existing database
      • and "source <directory>/SCRIPTS/gen_tempus_setup.tcl " (the existing data base should be the starting point for the foundation flow)
      • Rename the files to setup.tcl.
  3. Run the code generator: tclsh directory /SCRIPTS/gen_tempus_flow.tcl -doutput_dir_name
  4. Execute the flow: make
If you are using Innovus, source ../SCRIPTS/gen_tempus_setup.tcl to generate the setup.tcl file.

Results

The code generator default to creating an "instance" of the foundation flow in a "FF" directory in the local user directory. You can optionally override this using the option
-d directory.

Here is a list of the directories created by the code generator:

  • dbs: Contains the design saved during foundation flow run.
  • log: Contains the log files
  • rpt: Contains all the timing reports
  • FF: Tcl file generated by the code generator script. It contains separate files for globals and variables.

The following files are generated as a result of running the setup generator:

  • For MMMC design, setup.mmmc.tcl is generated.
  • For CPF design, setup.cpf.tcl is generated.
  • For single corner non-MMMC design, setup.auto.tcl is generated.

Using Predefined Scripts

% cd WORK
% tempus -nowin -64 -init ../SCRIPTS/TEMPUS/run_aae.tcl # for timing analysis 
% tempus -nowin -64 -init ../SCRIPTS/TEMPUS/run_eco.tcl # for tempus signoff optimization  fixing as necessary

You can also use the SCRIPTS/Makefile.tempus to call: 

% cd WORK 
% cp ../SCRIPTS/Makefile.tempus Makefile ( modify as needed ) 
% make

Using Plug-in Variables for Settings and Reports

To allow customized timing analysis flow, plug-in variables are included to allow you to apply your own settings and generate specific reports. The entire timing analysis flow is divided into the following steps:

  • Design import
  • Parasitic load
  • STA
  • Report Generation

For each step in the flow, there are plug-ins before and after the main command. For example, in the reporting step, there is a plug-in before and after the sample timing reports generating command. The plug-ins are called tempus_pre_ <step> and tempus_post_ <step>.

So, in the case of the report generation step, the plug-in will be called vars(tempus_pre_rpt_gen) and vars(tempus_post_rpt_gen).

These variables point to a user-generated TCL file containing Tempus system commands that are run in addition to the basic flow commands.

You can also have your own flow steps to replace the standard flow steps by setting the plug-in tempus_replace_ <step>, for example, 


set vars(tempus_pre_rpt_gen) “./my_rpt_gen.rpt”.
