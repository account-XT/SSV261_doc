Global Variables

This chapter describes the global variables that can be set to change the default behavior in the make_cdB utility. You can set all global variables as follows: 

set_parm variable_name value

For example:

set_parm case_sensitive 1

To get the default value of a global variable, use the following command:

puts $parm_variable_name

For example:

puts $parm_port_gnd_r

bind_supply_to_port

Determines whether to bind the supply net in an instance to the supply port or the global nets. When set to 1, the software ties the power supply to supply ports instead of global supply nets.

When this variable is set to 0, any reference to a net in an instance is first looked up in the list of global nets and then in the local list of nets, which includes ports.

Datatype: boolean

Default: 0

cabstol


cabstol value

Specifies the capacitance threshold below which a coupling capacitor is removed. Specified as an absolute tolerance in farads.

Datatype: double

Default: 1e-18

calculate_switching_history

Specifies whether to calculate the switching history data of the cell channel connected components (CCCs) for Silicon On Insulator (SOI) device models during characterization.

When set to 1, the software calculates the switching history (pre-switching effect) for SOI models.

To set this variable, use the set_parm command.

Default: 0

Datatype: boolean

The set_simwrap_mode command triggers the search for SOI models. Therefore, you must use this command before calculating the switching history of SOI device models.

caplimit


caplimit value

Specifies the upper limit of pin capacitance. Specified as an absolute value, in farads.

Datatype: double

Default: 1e-09

case_sensitive

When set to 1, turns on case sensitivity. By default, make_cdB is case preserving, but case insensitive.

Datatype: integer

Default: 0

ccc_max_fets


ccc_max_fets value

Specifies the maximum number of FETs a CCC can have and still be analyzed in the default mode.

If the number of FETs in the CCC does not exceed large_ccc_max_fets, it is analyzed in the large CCC mode.

Datatype: integer

Default: 500

ccc_max_fets_for_vivochar


ccc_max_fets_for_vivochar value

Determines whether to perform VIVO characterization for a CCC based on the size (number of transistors) specified. If the number of transistors in a CCC exceed the number specified with this variable, the software does not perform VIVO characterization for that CCC.

Datatype: integer

Default: 100

ccc_max_nets


ccc_max_nets value

Specifies the maximum number of nets a CCC can have and still be analyzed in the default exhaustive mode.

If the number of nets in the CCC does not exceed large_ccc_max_fets, it is analyzed in the large CCC mode.

Datatype: integer

Default: 100

ccc_max_ports


ccc_max_ports value

Specifies the maximum number of combined inputs and outputs a CCC can have and still be analyzed in the default exhaustive mode.

If the number of ports in the CCC does not exceed large_ccc_max_fets, it is analyzed in the large CCC mode.

Datatype: boolean

Default: 300

do_prop_trans

When set to 0 and before issuing the generate_cell_lib command, the cells are not characterized for slew propagation and no slew propagation data is added to the BB section of the cell.

When set to 1, slew propagation is added to the BB section of the cells.

Datatype: boolean

Default: 1

large_ccc_max_fets

Specifies the maximum number of FETs a CCC can have and still be analyzed in the large CCC analysis mode.

Any CCC that satisfies the ccc_max_fets, ccc_max_nets, or ccc_max_ports global variable is analyzed using normal analysis. If the CCC does not satisfy any of these global variables, it is not analyzed.

Datatype: integer

Default: 1000

max_patterns


max_patterns number

Specifies the upper bound on the number of patterns that can be used to sensitize each noise source. When this number is exceeded, heuristics are deployed to select the appropriate vectors. This global should only be used with the make_cdB utility. The maximum value that can be set for the max_patterns global variable is 1000000.

Datatype: integer

Default: 64

max_ports


max_ports ports

Specifies the maximum number of ports that a net can have and still use dynamic simulation to measure the incremental delay. The number of ports is computed as the product of the number of input pins (drivers) and the number of output pins (receivers).

If the number of ports on a victim net exceeds this limit or if the net has no driving cell (for example, primary inputs), the signal integrity analyzer uses a superposition mode to compute the incremental delay for this net. In this superposition mode, the signal integrity analyzer uses the slew waveform on the victim net as the nominal delay waveform, then sums the glitch computed for the net with the slew to determine the max/min waveform for the net. The difference between these two waveforms is the reported incremental delay. The alignment of the glitch peak to the slew is determined by the alignment algorithm.

Datatype: integer

Default: 20

parse_vsrc_as_resvalue


parse_vsrc_as_resvalue value

Specifies the value of the resistors that will be used to replace all voltage sources present in the input SPICE netlist. This ensures that the voltage sources present in the SPICE netlist are not ignored, and the netlist data used for characterization is complete.

Datatype: integer

Default: 0.1 ohm

port_gnd_r


port_gnd_r value

The default port pull-down resistance RL in ohms.

Datatype: double

Default: 1000 ohms

port_vdd_r


port_vdd_r value

The default port pull-up resistance RH in ohms.

Datatype: double

Default: 1000 ohms

port_vh_noise_tolerance


port_vh_noise_tolerance value
This global variable should only be used with the make_cdB utility.

Specifies the default output HIGH (vH) DC noise tolerance in volts.

To set local tolerances, generate a text version of the cdB and modify the set_input and bb_set_input commands in the text cdB.

Datatype: double

Default: 0.6V

port_vl_noise_tolerance


port_vl_noise_tolerance value
This global variable should only be used with the make_cdB utility.

Specifies the default output LOW (vL) DC noise tolerance in volts.

To set local tolerances, generate a text version of the cdB and modify the set_input and bb_set_input commands in the text cdB.

Datatype: double

Default: 0.6V

print_rt_memu

Controls run time and memory usage reporting to help track potential problems that are caused by unforeseen crashes or errors. When set to 1, make_cdB prints the run time and memory usage information for the generate_cell_lib command before it exits due to an unforeseen error.

Datatype: boolean

Default: 1

prop_input_slew_cell


prop_input_slew_cell value

Specifies a characterizing effect on a cell for slew propagation in a make_cdB run if this global variable is not set. It also uses the propagated slew data wherever possible.

Datatype: integer

Default: 1

rabstol


rabstol value

Specifies the resistance absolute tolerance threshold in ohms, below which a resistor is no longer considered as a parasitic element for the purpose of grouping RC networks into logical nets. Such a small resistor is ignored and its terminals are shorted.

Datatype: double

Default: 1 (in ohms. See the set_run_mode command)

scale_cdb

Specifies the scale to use in the cdB noise library output by using the make_cdb command. Set this global to 1 to output the cdB noise library using the same units as found in the original netlist.

Datatype: boolean

Default: 0 (saves the cdB noise library in units of meters)

simwrap_spectre_cmd_line_options

Specifies spectre command line options for make_cdb run. To set this variable, use the set_parm command.

For example:

To specify '+lqt' option with spice format models :


set_parm simwrap_spectre_cmd_line_options "+spice +lqt"
All the command line options need to be in one line quoted with double quotes.

slew_fall_high


slew_fall_high value

Specifies the voltage for the first time measurement used to determine the slew of a falling signal. The value specified is a factor of VDD. The slew is measured from slew_fall_high to slew_fall_low and normalized to 100 percent of VDD.

Datatype: float

Default: 0.8

slew_fall_low


slew_fall_low value

Specifies the voltage for the second time measurement used to determine the slew of a falling signal. The value specified is a factor of VDD. The slew is measured from slew_fall_high to slew_fall_low and normalized to 100 percent of VDD.

Datatype: float

Default: 0.2

slew_rise_high


slew_rise_high value

Specifies the voltage for the second time measurement used to determine the slew of a rising signal. The value specified is a factor of VDD. The slew is measured from slew_rise_low to slew_rise_high and normalized to 100 percent of VDD.

Datatype: float

Default: 0.8

slew_rise_low


slew_rise_low value

Specifies the voltage for the first time measurement used to determine the slew of a rising signal. The value specified is a factor of VDD. The slew is measured from slew_rise_low to slew_rise_high and normalized to 100 percent of VDD.

Datatype: float

Default: 0.2

spice_hdif


spice_hdif value

Specifies the drain source diffusion extension length. Corresponds to the HDIF parameter in ACM=3 mode in HSPICE. This global is automatically set when the SPICE models are parsed.

The spice_hdif global value should be the same one specified in the HDIF value of the SPICE transistor model card.

If this value is not the same, then you should change the spice_hdif value so it matches. The signal integrity analyzer uses this global variable to calculate the AD/AS/PD/PS for any transistors that do not have those parameters.

Datatype: double

Default: 1e-6 (in meters)

spice_scale


spice_scale value

The dimension scale of the netlist in meters. Corresponds to the SCALE parameter in SPICE.

This global variable should only be used with the make_cdB utility. If the netlist your loading is already in units of meters, do not use this global.

Datatype: double

Default: 1

Do not use the SPICE SCALE parameter in conjunction with the spice_scale global variable.

spice_scalm


spice_scalm value

The dimension scale of models. Corresponds to the SCALM parameter in HSPICE and is overridden if the netlist itself specifies SCALM.

Datatype: double

Default: 1

tmpdir


tmpdir directory_path

Sets the directory path of where the signal integrity analyzer creates needed temporary data files. Use the TMPDIR environment variable to control this setting. The default directories include (in order of precedence):

  • The global variable tmpdir.
  • If tmpdir is not specified or is NULL, the environment variable TMPDIR is used.
  • If neither tmpdir or the environment variable TMPDIR are specified, /tmp is used.

The directories specified with the set_parm tmpdir global and TMPDIR environment variable are now the only directories being used for temporary data processing during signal integrity analysis.

If the set_parm tmpdir global or TMPDIR environment variable directories are not specified, the /tmp directory is used as the default for temporary data.
  • To specify a directory for temporary data, you can use the following two methods:
    • TMPDIR environment variable
      Before performing signal integrity analysis, set the TMPDIR environment variable from the UNIX prompt.
      Syntax:
      setenv TMPDIR directory_path
      Example:
      setenv TMPDIR /project/tmp
    • set_parm tmpdir global
      Set the set_parm tmpdir global in the signal integrity analyzer.
      Syntax:
      set_parm tmpdir {directory | list_of_directories)
      where:
      directory is a string
      list_of_directories is a Tcl list of directories separated by spaces.
      Example:
      set_parm tmpdir {/dir1 /dir2 /dir3}

      Directories specified with the set_parm tmpdir global take precedence over the directory specified by the TMPDIR environment variable.

Follow these guidelines when using the set_parm tmpdir global or TMPDIR environment variable to specify temporary data directories:

  • The directories that are specified in the set_parm tmpdir global will be honored in the order in which they are specified. If the directories are close to being full, the TMPDIR environment variable directory is used. If this directory is close to being full, the program will try to use system memory for temporary data, which can usually hit the 32bit process and be killed by the OS. If this happens, use the 64bit program.
  • If the directories specified in the set_parm tmpdir global and TMPDIR environment variable are on the same physical disk drive, only the first specified directory on the disk drive will be honored.
  • Directories with less than 100MB on the disk drive or directories that are not writable will not be considered.

Datatype: string

Default: NULL
