bb_set_bidi


bb_set_bidi 
[-vhtolerance float]
[-vltolerance float]
[-cap float]
[-cannotfloat] 
[-vddres float]
[-gndres float]
[-vhnoise {time_value_pairs}]
[-vlnoise {time_value_pairs}] {ports}

Marks the specified ports as a bidirectional input/output port. This command has most of the features of the set_input and set_output commands. The defaults for inputs and outputs are used for bidirectionals.

Parameters

-vhtolerance float

Sets the VH DC input noise margin in Volts on the port. See the output_tolerance global variable.

Default: 40 percent of the default VDD/GND swing below nominal VDD.

-vltolerance float

Sets the VL DC input noise margin in Volts on the port. See the output_tolerance global variable.

Default: 40 percent of the default VDD/GND swing above nominal ground

-cap float

Sets the capacitance-to-ground value at the port. Units in farads. For example 5e-15.

Default: 0 farads

-cannotfloat

Specifies that this port cannot float.

Default: Bidirectional ports are allowed to float.

-vddres float

Specifies the RH resistance of the static port model in Ohms.

Default: 1000.0

-gndres float

Specifies the RL resistance of the static port model in Ohms.

Default: 1000.0

-vhnoise {time_value_pairs}

Specifies a list of time-value pairs representing the VH waveform to be applied at the ports. Values are specified in absolute voltages.

-vlnoise {time_value_pairs}

Specifies a list of time-value pairs representing the VL waveform to be applied at the ports.

{ports}

Specifies a required list of ports to be set as bidirectional.

Example


bb_set_bidi adr

where net adr is set as bidirectional.

bb_set_input 


bb_set_input
[-vhtolerance float]
[-vltolerance float]
[-cap float] 
{ports}

Marks the specified ports as UDN inputs.

Parameters

-vhtolerance float

Sets the VH DC input noise margin, in Volts, that this port can tolerate. See the output_tolerance global variable.

Default: 40 percent of the default VDD/GND swing below nominal VDD swing.

-vltolerance float

Sets the VL dc input noise margin, in Volts, that this port can tolerate. See the output_tolerance global variable.

Default: 40 percent of the default VDD/GND swing above nominal ground voltage

-cap float

Sets the capacitance-to-ground loading to be applied at the port. Units in farads. For example 5e-15.

Default: 0 farads

{ports}

Specifies a required list of port names to be set as UDN inputs.

Example


bb_set_input {porta portb}

where nets, porta and portb, are set as primary inputs.

create_ecsm_si_lib


create_ecsm_si_lib 
-cdb cdb_name 
-synlib lib_name

Generates a .lib file containing ECSM-SI extensions by using an existing cdB and a .lib file as input.

Parameters

-cdb cdb_name

Specifies the name of the input cdB noise library.

-synlib lib_name

Specifies the name of the input .lib file.

Example

  • The following command creates an ECSM-SI .lib named my_ecsm_si_typical.lib by using the base.cdB and typical.lib files as input:
    set_parm filename_prefix my_ecsm_si_
    create_ecsm_si_lib -cdb base.cdB -synlib typical.lib

generate_cell_lib


generate_cell_lib 
[-all] 
[-bit_cell_list bit_cell_list] 
[-ccc_print_large value] 
-cell_list {list} 
[-ecsm_si]
-file_list {list} 
[-filler_list {list_of_cells}] 
-gnd {netnames} 
[-maxsize {integer}] 
[-skip {list}] 
[-skip_failed_cells] 
[-spectre_file_list {list_of_spectre_files}] 
[-strip_supply] 
[-text] 
[-tolerance] 
[-udn_list {list}] 
-vdd {netnames}

Generates the noise library that can be used to represent the cells while performing signal integrity analysis. The set_supply, set_net, and set_port commands (for unbuffered cells) must be run before the generate_cell_lib command for correct noise characterization.

It is mandatory to specify the set_supply command before the generate_cell_lib command.

This command is supported by the make_cdB utility, a noise characterization tool that encapsulates the essential information inside a cell for noise analysis purposes. Resistances, capacitances, and noise tolerance characteristics for each cell are taken into account. The characterized cdB noise library usually has a .cdB extension.

Ensure that you use the read_dotlib command to specify a timing library file for port direction settings before using this command. In addition, specify all the required make_cdB global variables and other Tcl commands before issuing this command.

This command should be issued only once in each call to the make_cdB utility.

Parameters

-all

Characterizes all unique subcircuits in the SPICE files specified in -file_list. This option can lead to longer run times because library cells are often built from smaller component cells that are characterized. It also can cause errors when make_cdB attempts to calibrate subcircuits that are not placeable and do not have valid default parameters, such as L and W. Do not use this option with the -cell_list option.
Important: Option -all is obsolete and has been replaced by the -cell_list option. Although the -all option will continue to work, the software will issue a warning message indicating that this option is obsolete. To avoid the warning message, update your script to replace the -all option will the
-cell_list option.

-bit_cell_list bit_cell_list

Specifies a list of bit cells present in the memory. When this option is used, make_cdB automatically creates the empty black-boxes for the subcircuits of the specified bit cells by ignoring any internal devices.

-ccc_print_large value

Reports the names of all channel-connected components (CCCs) that have more than the specified number of transistors.

-cell_list {list}

Specifies a required list of cells in the cell library that are characterized for noise.

-ecsm_si

Generates a Liberty (.lib) library that contains effective current source model (ECSM)-based noise data.
Before you use this option, you must load a Liberty (.lib) library using the read_dotlib command.
Note: The output Liberty library, which contains ECSM-noise data, can be used as input to Encounter Timing System for performing noise analysis.

-file string

Specifies the required output noise library file name.

-file_list {list}

Specifies a required list of SPICE files that contain the transistor-level netlist of the cells and SPICE model files. If the SPICE models are specified using the library (.lib) format, they cannot be directly loaded. Instead, create a main SPICE file and load this file.
Note: Use this option to load an ECHO file generated using a transistor-level signal integrity analysis tool.
Important: The cdB noise library is calibrated at the temperature specified by the .temp command in the SPICE format input files. If the temperature is not specified in the SPICE files, then the default temperature specified in the BSIM SPICE models is used during calibration. You must provide a comment line as the first line in the SPICE file (in title at the top of the file) because the signal integrity analyzer and the make_cdB SPICE netlist parser ignore the first line in the SPICE file.

-filler_list {list_of_cells}

Specifies a list of filler cells that need to be characterized.
A filler cell is a cell that the make_cdB utility characterizes only for capacitance and for which no noise reporting is done.
Note: Do not specify filler cells using the -cell_list option.

-gnd {netnames}

Specifies a list of net names to be treated as ground. Any supply name that contains a colon delimiter and a suffix will be treated as a supply if the prefix to the colon is specified in the -gnd list. For example, gnd:3.
Note: There are no default supply net names. The circuit supply nets must be specified.

-maxsize {integer}

Specifies that cells with a transistor count above this limit are characterized for gate level, but have a minimized transistor-level representation. Logical information does not propagate through this cell. This limit is not applied to cells specified in the
-udn_list.This limit also helps to prevent excessive run time and memory usage when the -all option is used.
Default: 100
Note: When the number of transistors in a cell exceeds the
-maxsize, the make_cdB utility issues a warning and then creates an ECHO for the transistor-level representation of the cell. The maximum legal value for the -maxsize option is 2000. This limitation helps to avoid excessively large noise libraries.
When an ECHO is utilized for the transistor-level view of a cell, the signal integrity analyzer is not able to propagate noise through that cell.

-skip {list}

Specifies a list of cells that are not calibrated. This command is particularly useful when used in combination with, but is not limited to, the -all option.

-skip_failed_cells

Causes all cells that have failed calibration on any pin to be excluded from the noise library.
Default: Include all cells in the noise library.

-spectre_file_list {list_of_spectre_files}

Specifies a list of valid Spectre® files. You can combine both SPICE and Spectre netlists as part of the Spectre netlist. The Spectre simulator includes support for the SPICE netlist from the Spectre netlist. For example, a top-level Spectre netlist can include both SPICE and Spectre in a single file:
Top-level Spectre Netlist File:
simulator lang=spectre
include "model_pt.spe"
simulator lang=spice .include inv_chain.spi Note: Make sure to include the simulator lang=spectre line at the beginning of each Spectre netlist.
After you set up the Spectre file netlist, you can use it as follows: generate_cell_lib -spectre_file_list {top.scs}
CMI Requirements
The signal integrity analyzer supports the standard elements of Spectre and the models that are dynamically loaded by Spectre using the compiled model interface (CMI) shared object feature.

If you are reading Spectre files that contain CMI elements, this option requires specifying the locations of the shared object files that contain the descriptions of the additional elements.

To specify the locations of these shared object files, use the cmiconfig utility described in Chapter 4, Syntax, Configuring CMI Shared Objects in the Spectre® Circuit Simulator Reference, which is shipped with the MMSIM release.
For example: setenv CMI_CONFIG /path1/user_cmiconfig
where user_cmiconfig contains instructions to load the CMI libusermodel.so file, such as:
load /path2/libusermodel.so


Note: The .so DLL files are platform specific and must be compiled for the platform that is being run.
All nets specified as -vdd and -gnd should have a matching global declaration in the Spectre files.
This option requires that you have Spectre included in your PATH. The generation of temporary files in the current directory is minimal.

-strip_supply

Drops power supply ports from the port list of each cell. During signal integrity analysis, the cell ports are stored in the noise library.

-text

Requests a text output format. The output file is named using a .txt extension. The text output is only created if all input files are text. For example, if the signal integrity analyzer reads in an encrypted cdB noise library, all cdB noise libraries and ECHO models are encrypted.
Default: Without this option, only a binary version is output.

-tolerance

Activates cell-level DC tolerance. After this option is set, the VH or VL DC tolerance of a cell can be changed by using the port_vh_noise_tolerance or port_vl_noise_tolerance global variables.
Note: By default, make_cdB automatically computes the VL or VH tolerance. Using the -tolerance option enables you to override the automatic calculation using the port_vl_noise_tolerance or port_vh_noise_tolerance global variables, which is not recommended.

-udn_list {list}

Specifies a list of cells in the cell library that are converted into a user-defined noise (UDN) model. The cells in this list are calibrated for gate-level analysis only. They do not contain transistor-level information for use in delay and sensitivity analysis. All cells in the UDN list must not be included in any other list such as -cell_list.

-vdd {netnames}

Specifies a list of net names to be treated as supply. Any supply name that contains a colon delimiter and a suffix will be treated as a supply if the prefix to the colon is specified in the -vdd list. For example, vdd:3.
Note: There are no default supply net names. The circuit supply nets must be specified.

Examples

  • The following command characterizes the XOR cells in the cell library for noise, loads the main.spi SPICE file that contains the transistor-level netlist and SPICE models, and outputs the noise library file as cells.cdB:
    read_dotlib timing.lib
    generate_cell_lib -cell_list { XOR } -file_list { main.spi } -file cells.cdB
    where main.spi contains:
    * title
    .lib model_lib.spi tt
    .include cells.spi

merge_cdb


merge_cdb 
[-cdb {list}]
[-no_unique]
[-text] 
-file filename

Concatenates multiple noise library files into a single noise library file. If duplicate .bbox or .subckt definitions are found, the first definition is kept and all others are ignored. By default, this command outputs the merged cdB in encrypted format.

Parameters

-cdb {list}

Specifies the names of the cdB noise libraries to concatenate.

-file filename

Specifies the required output file name.

-no_unique

Allows all .bbox and .subckt definitions to be kept, even if duplicated.

-text

Requests a text output format for the merged cdB. All input cdBs must be in text format to use this option.
Note: When this option is specified, make_cdB generates the merged cdB in text as well as encrypted format.

-uniq_models

Retains only unique transistor models (.model definitions) in the merged cdB. When you specify this option, the software detects duplicate models in the input cdB files and retains only one definition for such models in the resultant merged cdB. Even if the model names are different the software detects the identical models based on the parameter values, and retains only one definition.

Examples

  • The following command concatenates the stdcel.cdb and custom.cdb noise libraries into a single cdB noise library named main.cdb.
    merge_cdb -cdb {stdcel.cdb custom.cdb} -file main.cdb
  • The following command merges two cdB files and generates a cdB file without duplicate model definitions:
    merge_cdb -cdb { lab1.cdb lab2.cdb } -file test_merge -text -uniq_models

message_handler


message_handler 
[-msg_count_summary {OFF | ON}] 
[-no_format] 
[-revive]
[-set_constraints {{-id message_id_list | -level message_level |
-context ctxt_list -thislevelonly} | -constraint {0 | positive_integer | 
-1 | msg_id_limit}] 
[-set_error_limit number] 
[-set_info_limit number] 
[-set_msg_level {ERROR | DEFAULT | VERBOSE | ALL | msg_level}] 
[-set_output_policy {-file filename | -discard_file filename | -gzip |
-detail {terse | normal | high}}] 
[-set_screen_display {OFF | ON}] 
[-set_warn_limit number] 
[-show_constraints { -id | -global | -context | -level | -all}]
[-show_current_msg_level] 
[-show_msg_level message_id] 
[-show_report {-id {message_id_list | ALL} | -context {message_ctxt_list | ALL}}] 
[-suspend]

Lets you control the detail and the types of messages that make_cdB displays. A message contains the message severity level, message ID, and message content. For example:

INFO:(SI-6050) Now using /tmp/make_cdb_linws9.Cadence.COM_28215 (32361 MB available)

where:

INFO:

Specifies the message severity level. make_cdB supports three message severity levels: ERROR, WARNING, and INFO. Each message severity level is associated with a message level.

make_cdB does not print the message level with the message. To get the message level for a message, use the following command: message_handler -show_msg_level message_id

SI-6050

Specifies the message ID.

Now using...

Specifies the message content.

Parameters

-msg_count_summary
{OFF | ON}

Outputs statistics on the number and types (message levels) of messages make_cdB encounters during the run. make_cdB provides these statistics at the end of a run, when the message handler is closed by the application, or when you use the
-show_report option. Selecting the OFF argument will not provide statistics at the end of the run.
Default: OFF

-no_format

Turns off message formatting to keep messages from wrapping at the 80-column width limit. Each message will be displayed on one line. This option is useful when you grep for specific message information that is displayed on multiple lines.

-revive

Revives the message handler by updating the message settings.

-set_constraints {-id message_id_list | -level message_level |
-context ctxt_list -thislevelonly}
-constraint {0 | positive_integer | -1 |
msg_id_limit}
-id message_id_list

Controls the number of messages that make_cdB displays based on the message ID and the constraint that is set. You can only use this option if you know the message IDs of the messages you want to display. You can get the message IDs from the messages generated by make_cdB.
Note: You can also use this option to either suppress or display non-SI messages, such as TECHLIB, CTE, and FNP. For example, to suppress all the messages with the TECHLIB-342 ID, use the following command:
message_handler -set_constraints { -id TECHLIB-342 -constraint 0 }

When controlling the display of non-SI message IDs, it is not possible to set a number for the total messages the software will suppress or display. All the messages with the specified ID will either be suppressed (-constraint 0) or displayed (- constraint -1).
-level message_level
Controls the number of messages that make_cdB displays based on the message level and the constraint that is set. What message_level you use is dependent on what messages you want make_cdB to display. To find the message level for a message, use the -show_msg_level option.
-context ctxt_list [-thislevelonly]
Controls the number of messages that make_cdB generates based on the message context and the constraint that is set. The
-thislevelonly option is used exclusively with the
-context option and applies the constraint only to messages of the specified context type and its message level.
Omitting this option applies the constraint to all messages of the specified context type regardless of its message level. To find the message level for a message, use the -show_msg_level option.
-constraint {0 | positive_integer | -1}| msg_id_limit
Specifies a constraint for an individual message ID type or a global constraint for all message ID types. These constraints limit the total number of messages that make_cdB displays.
{0 | positive_integer | -1}

Sets a constraint on an individual message ID type that is specified with the -id, -level, or -context options.
0: Use this option to discard messages of a particular type.
positive_integer: Use this option to output a specified number of messages.
-1: Use this option to output all messages.
Note: If a constraint is set, and the message ID, message level, and message context all match a specific message, make_cdB applies the constraint in the following order of precedence: message ID, message level, global constraints, and context constraints.
msg_id_limit
Sets a global constraint to limit the total number of messages that are displayed for each message ID type. make_cdB stops displaying messages of the same message ID type if the number of messages are above the specified limit. For example:
-set_constraints { -constraint 300 }
When a message of a specific message ID type reaches a count of 300, that message ID type will no longer be displayed.

Note: The msg_id_limit option provides a global constraint to all message ID types, with the following exceptions:
When using the msg_id_limit option in combination with setting a constraint for an individual message ID type, such as:
-set_constraints { -id SI-xxxx -constraint y }
The constraint for the individual message ID type will take precedence.
Note: The individual message ID takes the highest precedence followed by level, global constraints, and context constraints.
When using the msg_id_limit option to set a global constraint for all message ID types, the following message ID types will remain unconstrained unless they are specifically constrained using the
-set_constraints -id option:
SI-9513 SI-9514
SI-500
SI-100
SI-6000
SI-2000

-set_error_limit number

Sets a limit to the number of ERROR messages that make_cdB displays. You can set this number to any value. If you set this number to 0, make_cdB will not display any error messages. If you set this number to -1, make_cdB displays all error messages.
You can use this option multiple times. Each time it is used make_cdB overwrites the previous limit. For example, if you do not want error messages to appear when running the set_supply and set_net commands, but want all error messages to appear after running the set_net command, use this option as follows:
message_handler -set_error_limit 0
set_supply...
set_net...
message_handler -set_error_limit -1
...

Sets a limit to the number of INFO messages that make_cdB displays. You can set this number to any value. If you set this number to 0, make_cdB will not display any info messages. If you set this number to -1, make_cdB displays all info messages.
You can use this option multiple times. Each time it is used make_cdB overwrites the previous limit. For example, if you do not want info messages to appear when running the set_supply and set_net commands, but want all info messages to appear after running the set_net command, use this option as follows:
message_handler -set_info_limit 0
set_supply...

message_handler -set_info_limit -1

-show_constraints { -id|-global|-context|-level|-all }

Displays the constraints of the specified type or all constraints. This option accepts the following arguments:
-id: Displays the message IDs and the constraints set for them.
-global: Displays the global constraint.
-context: Displays the message contexts and the constraints set for them.
-level: Displays the message levels and the constraints set for them.
-all: Displays all constraints regardless of the type.

-show_current_msg_level

Displays the current message level that is set.

-show_msg_level message_id

Provides the message level of the message specified by message_id. For example:
message_handler -show_msg_level CADSI_WARN
where make_cdB provides the message level of the message that contains the CADSI_WARN message ID.
Note: You can only use this option if you know the message ID of the message. You can get the message ID from the messages generated by make_cdB.

-show_report {-id {message_id_list | ALL} | -context {message_ctxt_list | ALL}}

Shows a report on all messages generated by the software that match the message_id_list or the message_ctxt_list. If the ALL keyword is specified, all message IDs or contexts are generated.
-id {message_id_list | ALL}
Calculates and shows the number of messages with the specified message IDs. When the ALL keyword is specified, the software reports the total number of messages generated for all message IDs.
-context {message_ctxt_list | ALL}
Calculates and shows the number of messages with the specified message context. When the ALL keyword is specified, the software reports the total number of messages generated for all message contexts.
Note: The outputs generated by -id and -context are independent of each other even though it is possible to use them together with a single -show_report option.

-suspend

Suspends all messages, but make_cdB updates the number of messages, message levels, and message contexts for each message.

regenerate_cell_lib


regenerate_cell_lib 
[-infile string] 
[-outfile string] 
[-temperature] 
[-text] 
[-version_string cdB_version]

Converts an old cdB noise library file to the latest cdB noise library file version.

It is mandatory to specify the set_supply command before the regenerate_cell_lib command.

The regenerate_cell_lib command supports multi-voltage cdB regeneration. This means that you can regenerate an existing cdB to create a new cdB with cells characterized at different voltage values specified during regeneration.

See Regenerating the cdB Noise Library in the make_cdB Noise Characterizer User Guide for more information.

Use the read_dotlib command to specify a timing library file for port direction settings before using this command. By default, make_cdB uses the port direction settings from the old cdB noise library file.
This command should be issued only once in each call to the make_cdB utility.
The regenerate_cell_lib command does not work with SIMI.

Parameters

-infile string

Specifies the required file name or location of the old cdB noise library file.

-outfile string

Specifies the output file name or location of the new cdB noise library file.
Default: Adds file name ${input_cdb}.new to the directory of the old cdB noise library file. If this file name exists, file name ${input_cdb}.new.1 is used or the suffix is incremented until a valid file name is found.

-temperature

Specifies the temperature for the regenerated cdB noise library file. If not specified, the temperature value of the old cdB noise library file is used.

-text

Generates a text version of the new cdB noise library file using the output file name with a .txt extension.
Note: If the original cdB noise library file that your converting is encoded or not in text format, no text output is generated.

-version_string string

Provides a tag to identify the cdB noise library file versions you are using. This is useful in situations where you generate several versions of the cdB noise library file for the same cells, such as for different voltages, process corners, and so on. You can view the version strings using the -version option of the pcdb command.

Examples

  • The following commands convert a cdB noise library file from version 4.0 to the latest version, which is identified as rechar-to-4.3.2:
    #Use set_parm as shown, when tiehi and tielo cells are present.
    set_parm port_vdd_r 1
    set_parm port_gnd_r 1
    set_supply -vdd 1.8 -gnd 0
    set_net -vdd 1.5 { vdda }
    regenerate_cell_lib -infile old.cdB \
                        -outfile new.cdB \
                        -version_string rechar-to-4.3.2
  • The following commands recharacterize an existing text-based cdB file at multiple voltages:
    set_run_mode 12
    set_parm bind_supply_to_port 1
    set_supply -vdd 3.3 -gnd 0.0
    set_supply -vdd 1.7 -gnd 0.0
    set_net -vdd 2.0 { VDD2 }
    set_net -nomvdd 3.3 -vdd 3.3 VDD
    set_net -nomvdd 1.7 -vdd 1.7 VDD
    set_port -dir in TOP {IN1}
    set_port -dir out TOP {OUT1}
    set_port -dir out TOP {OUT2}
    set_port -dir out TOP {OUT3}
    regenerate_cell_lib -infile test.cdB.txt -text
