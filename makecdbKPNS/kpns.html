make_cdB Known Problems and Solutions

This document describes important Cadence Change Requests (CCRs) for make_cdB and tells you how to solve or work around these problems. To find out what CCRs were fixed in this release, see the README.txt file in your software installation directory.

Identified in Previous Releases

  • CCR 183029: make_cdB fails to detect the SPICE model generated by Spec2Spice
  • CCR 94669: Use model inconsistencies between Spectre and SPICE
  • CCR 29539: The slash (/) symbol in a CDL netlist is not understood by make_cdB

CCR 183029: make_cdB fails to detect the SPICE model generated by Spec2Spice

Description: When you specify a Spectre model file using the -spectre_file_list option, make_cdB uses Spec2Spice to translate the Spectre model file to SPICE before characterization. However, make_cdB fails to detect the SPICE model(s) generated by Spec2Spice if the input Spectre file is instantiating a device at the top level and not within the subcircuit (subckt). This causes make_cdB to abort with the following message:


ERROR: (SI-0501) make_cdb.tmp.in.spice:10: subckt <subckt_name> device

<device_name>:  cannot find model

where:

<subckt_name> specifies the name of the subcircuit.

<device_name> specifies the name of the device at the top level.

Solution: In the input Spectre file, remove the device from the top level and specify the updated Spectre file using the -spectre_file_list option of the generate_cell_lib command to characterize the cell.

CCR 94669: Use model inconsistencies between Spectre and SPICE

Description: When using make_cdB to create the cdB noise library, the following use model inconsistencies exist between Spectre® and SPICE:

  • When using the generate_cell_lib -spectre_file_list option, you must specify the Spectre models before specifying the subcircuit in the list. When using the generate_cell_lib -file_list option for SPICE files, the order in which you specify these files does not matter.
  • When redefining cells in the cell netlist, the Spectre netlist parser stops at the next definition of a cell and issues an error message. The SPICE netlist parser ignores the next definition of a cell and issues a warning message.

Solution: This is a limitation enforced by Spectre. However, the Spectre files are processed by the parser in a specific order, so you must define the models and subcircuit before they are used and list the files using this same order.

CCR 29539: The slash (/) symbol in a CDL netlist is not understood by make_cdB

Description: Some CDL netlists use a slash (/) symbol to separate the inputs from the outputs in the port list of a .subckt definition. The make_cdB parser does not understand this syntax.

Solution: Remove the slash (/) symbol from the CDL netlist.
