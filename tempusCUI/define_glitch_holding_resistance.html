define_glitch_holding_resistance

define_glitch_holding_resistance 
[-help]
[-glitch_type {both | vl | vh | vlu | vho | vl_vh | vlu_vho}]
[-instance_pin string]
[-lib_pin string]
-value double
[-views string]

Allows you to specify the holding resistance.

You can use this command to define a net-specific holding resistance instead of using the default holding resistance of 1000 ohms.

This command can be specified more than once per net. If there is a duplicate specification, then the last setting is used.

Parameters

-help

Prints out the command usage.

-glitch_type {both | vl | vh | vlu
| vho | vl_vh | vlu_vho}

Specifies the glitch type for resistance Hold application. The option both applies the value to VL and VH.

-instance_pin string

Specifies a list of instance pin names.

-lib_pin string

Specifies the instance/pin name of the driver that the holding resistance should be applied to.

-value double

Specifies the value in ohms of the holding resistance to be used by glitch analysis.

-views string

Specifies a list of view names.

If this parameter is not specified, then by default all the views are applied.

Examples

  • The following command sets the holding resistance on the Y pin of inst1 to 233ohms for VL:
    tempus > define_glitch_holding_resistance -glitch_type vl -lib_pin {inst1/Y} 233
  • The following command sets the holding resistance on the Y pin of inst2 to 380ohms for both VL & VH:
    tempus > define_glitch_holding_resistance -glitch_type both -lib_pin {inst1/Y} 233
