write_timing_model

write_timing_model 
[-help]
model_file
[-absolute_tolerance_validation float]
[-absolute_tolerance_optimistic_validation float]
[-absolute_tolerance_pessimistic_validation float]
[-assertions constraint filename] 
[-cell_name cell_name]
[-clock_transitions {clk_slew1 clk_slew2...}]
[-gain integer]
[-include_aocv_weights]
[-include_power_ground]
[-include_power]
[-input_transitions {input_slew1 input_slew2...}]
[-lib_name lib_name]
[-max_num_loads value]
[-max_num_transitions value]
[-output_loads {output_load1 output_load2...}]
[-percent_tolerance_validation float]
[-percent_tolerance_optimistic_validation float]
[-percent_tolerance_pessimistic_validation float]
[-post_check]
[-precision integer]
[-resolution float] 
[-tolerance float]
[-validation_dir string]
[-verilog_shell_file filename]
[-verilog_shell_module top_module_name]
[-view string]

Writes the interface timing characteristics of the design in the specified timing model output file. 

Parameters

-help

Prints out the command usage.

model_file

Specifies the name of the output file.

-absolute_tolerance_validation float

Specifies the absolute tolerance value to be used during the validation of extracted ETM. The integer value specified with this parameter is read as ns/ps depending upon the time unit.

You can use this parameter when the -validation_dir is used with model extraction.

For more details refer to check_timing_model -absolute_tolerance command.

Default: 3ps
-absolute_tolerance_optimistic_validation float

Specifies the absolute tolerance limit for flagging an optimistic failure. An optimistic path violating the absolute as well as percentage tolerance limit will be flagged as FAIL in the check_timing_model command output report.

You can use this parameter when the -validation_dir is used with model extraction.

Default: 15ps
-absolute_tolerance_pessimistic_validation float

Specifies the absolute tolerance limit for flagging a pessimistic failure. A pessimistic path violating the absolute as well as percentage tolerance limit will be flagged as FAIL in the check_timing_model command output report.

You can use this parameter when the -validation_dir is used with model extraction.

Default: 15ps

-assertions constraint filename

Writes out the constraints for model, which are used in the validation flow.

-cell_name <cell_name>

Specifies the cell name used in the timing model

-clock_transitions {<clk_slew1 clk_slew2>...}

Specifies a range of slew values used at all clock pins.

-gain <integer>

Represents an increase in the number of delay arcs if a pin is removed.

-include_aocv_weights

Writes out the stage weights on individual arcs.
-include_power

Writes information about power consumed by a block.

-include_power_ground

Writes out the power ground information for pins.

-input_transitions {<input_slew1 input_slew2>...}

Specifies a range of slew values used at all the data input ports.

-lib_name <lib_name>

Specifies the library name used in the timing model.

-max_num_loads <value>

Specifies the maximum number of output load values.

-max_num_transitions <value>

Specifies the maximum number of input slews or clock slews.

-output_loads {<output_load1 output_load2>...}

Specifies a range of load values used at all output ports.

-percent_tolerance_validation float

Specifies the percentage tolerance value to be used during the validation of extracted ETM.

For more details refer to the check_timing_model -percent_tolerance command details.

You can use this parameter when the -validation_dir is used with model extraction.

Default: 3%
-percent_tolerance_optimistic_validation float

Specifies the percentage tolerance limit for flagging an optimistic failure. An optimistic path violating percentage as well as absolute tolerance limit will be flagged as FAIL in the check_timing_model command output report.

 You can use this parameter when the -validation_dir is used with model extraction.

Default: 3%
-percent_tolerance_pessimistic_validation float

Specifies the percentage tolerance limit for flagging a pessimistic failure. A pessimistic path violating percentage as well as absolute tolerance limit will be flagged as FAIL in the check_timing_model command output report.

You can use this parameter when the -validation_dir is used with model extraction.

Default: 3%

-post_check

Checks the generated ETM library using Valus.

-precision integer

Specifies the floating point precision used for the timing model

-resolution float

Specifies the magnitude of delay difference that can be ignored in extraction

-tolerance float

Specifies the accuracy level of extractor in percent

-validation_dir <string>

Enables the validation of generated ETM for corresponding view and displays number of failures at  the end of validation. It is mandatory to specify the  name of validation directory with this option (-validation_dir valDir), this contains the write_model_timing, check_timing_model and summary reports.

-verilog_shell_file filename

 Generates a Verilog shell file that instantiates the timing model

-verilog_shell_module top_module_name

Specifies the top module name of the Verilog shell file.

-view string

Specifies the view for which model needs to extracted.

Examples

  • The following command builds a .lib model (block.lib) for the block:
    tempus > write_timing_model block.lib
  • The following command creates the timing model for the tst_model cell belonging to the tst_lib library, and writes the model into the tst.lib liberty file:
    tempus > write_timing_model -cell_name tst_model -lib_name tst_lib tst.lib
  • The following command validates the generated ETM, where the pessimistic and optimistic path violation tolerance is set to 1%:
    write_timing_model tst.lib -cell_name block_1  -validation_dir -percent_tolerance_validation 1 -percent_tolerance_optimistic_validation 1
        \ -percent_tolerance_pessimistic_validation 1
  • The following command includes details related to the power ground (of the pins) and power consumed by a block:
    write_timing_model tst.lib -cell_name block_1 -include_power -include_power_ground
