report_noise

Generates text-based noise reports. 

Note: You need to ensure that the si_glitch_enable_report (to generate glitch report) or si_delay_enable_report (to generate detailed delay report) attributes are set to true, before the report_timing, update_timing, or update_glitch commands are run.

For more information on attributes, see si Category Attributes.

Parameters

-help Prints out the command usage.
-clock

Prints out the signal integrity report for the clock network.
-cell_type string

Generates a glitch report for the user-specified cell-type. You can specify one of the following options:

  • bbox: Generates a report for only the black-box receivers
  • clock: Generates a report for only the clock pin receivers
  • data: Generates a report for only the data pin receivers
  • latch: Generates a report for only the latch pin receivers

-delay {max | min}

Reports delay uncertainty instead of noise values. The valid options are min, max - for minimum or maximum path delay analysis.

The report_noise -clock -delay min | max command outputs minimum/maximum delay report for clock nets.

The attacker constituents are reported for nets which are critical and thereby reselected in the second SI iteration. For non-critical nets, the constituent section will be ignored. To report attacker constituents for such nets, the report_delay_calculation -si parameter can be used.
-double_clocking Enables double clocking reporting.
-double_switching Reports double switching analysis data in noise reports.
-exclude_failures

Excludes all failing nets from the glitch report.
-expand_virtual_attacker_bus

Reports virtual attacker components and expands bus bits in the noise reports.

This parameter works only when the bus virtual attacker feature is enabled using the si_enable_virtual_attacker_constituent_report true setting.

-failure

Reports receiver peak failures and DC tolerance failure nets. Use this option only for glitch noise failure reports.

Option: Directory Name:
-sort_by noise glitch 
-sort_by rcvr_peak glitch 
-format string

Specifies the output report format fields. The valid fields are:

arc, attacker_edge, attacker_logical_correlation_phase, attacker_net, attacker_offset, attacker_peak, attacker_slew, attacker_source, attacker_status, attacker_vdd, attacker_wire_length, attacker_xcap, cell_type, delay, glitch_slack, incr_delay, level, peak, receiver_cell, receiver_input_failure_threshold, receiver_input_pin, receiver_output_failure_threshold, receiver_output_peak, slack, slack_status, stage_info, thresh_source, verbose_logical_correlation_report, victim_edge, victim_library, victim_logical_correlation_phase, victim_net, victim_slew, victim_total_area, victim_total_cap, victim_total_cross_cap, victim_vdd, victim_width, victim_wire_length

Note: The victim_total_cross_cap option is supported only for SI delay reporting. 

Each field corresponds to the following columns of the glitch report:

  • arc: Arc
  • attacker_edge: Edge
  • attacker_net: Net
  • attacker_offset: Offset (ps)
  • attacker_peak: Peak (mV)
  • attacker_slew: Slew (ps)
  • attacker_source: Constituents: Source
  • attacker_status: Statue
  • attacker_vdd Vdd (V)
  • attacker_wire_length
  • attacker_xcap: Xcap (fF)
  • glitch_slack: Slack
  • level: Level
  • peak: Peak (mV)
  • receiver_cell: Receiver cell
  • receiver_input_failure_threshold: Receiver Input Threshold
  • receiver_input_pin: ReceiverNet
  • receiver_output_failure_threshold: Failure threshold
  • receiver_output_peak: Receiver output peak Value
  • stage_info
  • thresh_source: ReceiverThresholdType (Global | User | Library) 
  • victim_library: Library
  • victim_net: VictimNet
  • victim_total_area: TotalArea
  • victim_total_cap: TotalCap (fF)
  • victim_vdd: Vdd (V)
  • victim_width: Width (ps)
  • victim_wire_length

The following options are not available with the single line format:

  • delay
  • incr_delay
  • slack
  • thresh_source
  • victim_edge
  • victim_slew
  • victim_total_cross_cap

To choose whether the report format should be on a single line or multiple lines, you can use the -output_format parameter.
-gui_victim_nets_file Generates the GUI format glitch reports (aae or aae_<viewname> files under the reporting directory) and incremental delay reports (aae_<max/min>_incDelay or aae_<viewname>_<max/min>_incDelay  files under the reporting directory) to be used in the Display Noise Net form.
-histogram Generates the noise histogram.
-level {vl | vh | vlu | vho} Specifies the level for which a report needs to be generated when single-level report is desired. You can specify one of these options -  vl, vh, vlu, and vho.
-max_threshold float

Specifies the maximum peak noise or receiver peak thresholds to report on.
-merge

Generates a merged report that shows only the worst glitch slack for each pin level combination across views.
-merge_dir string

Specifies the name of the merge database.
-nets string

Reports the specified nets in the noise report.
-noisy_waveform

Flags nets with bumpy waveforms at the receiver output.
-out_file string 

Specifies the name of the output file name prefix. The name of the output file is generated by combining the prefix and the specified view name.

If you do not specify this option:

  • The software automatically names the text report as ‘glitch’ for noise glitch reports and ‘delay’ for noise delay reports.
  • The software dumps the generated report to the console window for better usability.

Note: If the text report file with the .gz extension is used, the output file is gzipped to generate a compressed report.
-output_format string

Specifies if the output format should be on a single line or on multiple lines. You can specify one of the following options:

  • single_line
  • multiple_line

If the single_line option is specified and the attacker info is chosen as a field, then all the attacker related format options will be printed together.

The -output_format parameter only works with the -format option and does not affect the default reporting output format.

Default: multiple_line
-overshoot_undershoot

Reports the overshoot (VHO) and undershoot (VLU) glitches.

Default: If this option is not used during glitch reporting, then VL and VH type of glitches will be reported.
-pins string Specifies the name of pins to be reported.
-precision integer

Specifies the precision value up to which the glitch data is to be printed. The allowed values are 0, 1, 2 and 3.

Default: 2
-quiet_nets  Generates the quiet attackers report.
-remove_status_row <string> Shows only the active attackers and filters out Sb, UF, and LC from the glitch report.
-report_virtual_attacker_constituents Generates reports for virtual attacker constituents.
-reverse_voltage_change_threshold <float>

Reports the clock nets with reverse swing greater than the user-specified threshold value (ratio of VDD). By default, the threshold value is set to 0.1.
-slack float

Generates a report for bumpy nets based on slack.

Units: Seconds
-skip_nets_or_pins_in_header Generates the glitch report without a list of nets or pins in the report header.
-sort_by string

Requests the sorting of entries. You can sort by:

  • noise
  • receiver_peak
  • slack
  • cell_type

Tempus determines the default HTML output directories based on the options you choose.

Depending on the sorting option you select, Tempus sorts the report fields in the following order:

-sort_by Option Level 1 Level 2 Level 3 Level 4
rcvr_peak receiver peak noise netname level 
noise noise - netname level

  

For example, if you use the -sort_by noise option, the first level of sorting will be based on noise, followed by receiver peak, netname, and level.

Note: The report displays the vl noise level before the vh noise level.

Default: receiver_peak
-style {default | detailed}

Generates reports in one of the two styles - extended and default.

  • detailed: Generates detailed reports with victim and aggressor timing windows, dropped aggressor slews, and reasons for dropped aggressors. Additionally, the report also shows driver pins and driver library pins.
  • default: Generates the default report, which is similar to the text report generated using the -text parameter.

-threshold string

Specifies the minimum peak noise, sensitivity, absolute delay uncertainty, relative delay uncertainty, and receiver peak thresholds to report on.

Default:

  • 0.10 of vdd for nets - when the glitch report is generated using the report_noise -sort_by noise option.
  • 10 (ps) for nets - when a detailed delay report is generated using the report_noise -delay parameter).

Note:

  • The -threshold parameter accepts percentage values.
  • All -sort_by values that represent voltages will be in mV.
-type string Specifies the type of noise to be reported - glitch, delay or slew.
-view string Specifies the view name.

File and Directory Naming Convention for Reports

The software uses a set of naming conventions for the report files and directories  that are generated by the report_noise command. Each type of report file or directory is identified by a combination of strings that are attached to its name. The software adds the appropriate string to the report file or directory name.

Noise Reports

For noise reports, the report_noise command uses the following naming convention for report files or directories:

glitch 

Delay Reports

For delay reports, the report_noise command uses the following naming convention for report files or directories:

delay

  • To generate a glitch report, you can use the following command:
    tempus > report_noise –txtfile glitch.txt
  • To generate a glitch report sorted by input noise, you can use the following command:
    tempus > report_noise –txtfile sort_by_glitch_input.txt –sort_by noise
  • To generate a glitch failure report, you can use the following command:
    tempus > report_noise –txtfile glitch_failure.txt –failure

  • To generate a glitch report for VL noises sorted by input noise, you can use the following command: 
    tempus > report_noise –sort_by noise -level vl

  • To generate a glitch report for only latch receiver pin cell types, you can use the following command: 
    tempus > report_noise -txtfile latch_glitch.txt –cell_type latch
