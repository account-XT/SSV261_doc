create_inst

create_inst 
[-help]
[-dont_snap_to_placement_grid]
[-location {x y}]
[-orient {r0 r90 r180 r270 mx mx90 my my90}] 
[-physical] { -base_cell <base_cell> } { -name <inst_name> } [ -parent <module|hinst|design> ] [ -place_status <place_status> ]

Adds an instance and places it in the design. The syntax is not order dependent.

After any ECO command, the tool performs either an incremental or full timing update when you run the next command that reports timing, for example, report_timing.

Note: The software supports this command for flattened designs only.

Parameters 

-help

Outputs a brief description that includes type and default information for each create_inst parameter.

For a detailed description of the command and all of its parameters, use the man command:
man create_inst.
-base_cell <base_cell> Specifies the base_cell to be used for the new instance.
-dont_snap_to_placement_grid

Places the instance at the location specified using the -location parameter even if the specified location is on or off the placement grid. By default, create_inst snaps the placement location to the placement grid.

Default: false
-location {x y}

Specifies the location of the placed instance.

Default: If you do not specify a location, the software places the instance at the design origin.

-name <inst_name>

Specifies the name of the new instance. If this is the full hierarchical path, then the parent will be derived from the name (that is the parent name is the string before the last "/".  In this case, the base_name of the new instance (that is the string after the last "/" should not have any special characters that require escaping.

When the -parent parameter is used, then the name is the base_name of the new instance. If the name has any unknown characters, it will be automatically escaped. Thus -name "i1/i2" will result in "i1\/i2" for the .escaped_name, since it uses DEF escaping semantics. This is equivalent to checking if <inst_name> is a legal Verilog identifier, and if not, prepend \ and add a trailing space to the internal Verilog name.

-orient {r0 r90 r180 r270 mx mx90 my my90}

Specifies orientation of the placed instance.

Default: r0
-parent <module|hinst|design>

Specifies the parent for the new instance. This supports both the object or the name for the specified object types.

Note: Only honored for logical instances and will be ignored when used with -physical.
-physical

Creates a physical instance without updating the netlist. This can only be used with a base_cell that does not have any lib_cells. Also, this results in the instance .is -physical attribute being set to true.
-place_status <unplaced|place|soft_fixed|fixed|cover>

Specifies the placement status of the added instance during placement and optimization.

You can specify the following as the placement status:

  • fixed: The status of the added instance is fixed. It has a location and cannot be moved by automatic tools, but can be moved using interactive commands. 
  • placed: The status of the added instance is placed. It has a location, and can be moved using automatic tools and interactive commands. 
  • soft_fixed: The status of the added instance is soft_fixed. It cannot be moved by global placement and can only be moved by the legalization step of detail placement
  • unplaced: The status of the added instance is unplaced. It does not have a location.

Default: unplaced

Note: This parameter is used with the -location option. It should not be used along with the -parent parameter.

Examples

The following example creates two instances, inst1 and inst2, of library cell LIB/BUFX2:

tempus> create_inst -insts "inst1 inst2" -cell [get_lib_cells LIB/BUFX2]
