read_hierarchical_def

read_hierarchical_def
[-help]
def_files <...>
[-add_blockage] 
[-delete_blockages_over_partition_macro] 
[-ignore_drcfill] 
[-incremental_ilm_def]
[-preserve_shape]
[-rdl_def string] 
[-rdl_orient orientation]
[-rdl_placement {x y}]
[-secondary {{suffix def_file_list}...}]
[-skip_pg] 
[-skip_fillers] 
[-skip_nets]
[-top_cell_orient orientation]
[-top_cell_placement {x y}]
[-top_scope]
[-transform_file string] 
[-skip_routing {[pg|signal] [regular|special] [high_layer_routing]}... [-to_layer routing_layer_name]]
[-use_top_def_die_area]
[-modules <vCell>+ | -hInsts <hInst>+]

Merges DEF data from various blocks to a single chip database. The read_hierarchical_def command provides the following features:

  • Takes the TOP DEF file and a set of block DEF files and merges them into a single chip database.
  • The block and TOP Verilog files (or their DEF files) can be specified in any order. However, if there are empty Verilog module stubs of blocks in some of the parent Verilog files, ensure that the parent Verilog files are specified prior to the child Verilog files.
  • There is no need to specify the LEF files for the blocks.
  • During the course of this command, TOP rows will be cut around the block boundary, and all block rows will be brought back as is.
  • Partition definitions are created for each of the assembled block as per the DIE AREA statement in the block DEF.
  • The wire at the block boundaries will be stitched with the electrically connected net’s wires at the TOP.
  • All orientations of blocks are supported for assembly. Repeated blocks are also supported. Non-R0 master is also supported.

Parameters

-help

Outputs a brief description that includes the type and default information for each read_hierarchical_def parameter. For a detailed description of the command and its parameters, use the man command:

man read_hierarchical_def
-add_blockage Specifies that the missing instances from the netlist should be converted into placement blockages.
def_files <...> Specifies DEF files to be merged.
-delete_blockages_over_partition_macro Deletes the top design placement and routing (both rectangular and rectilinear) blockages overlapping partitions modules. 
-hInsts <hInst>+

Specifies the list of hierarchical instances for which physical data needs to be loaded. The tool then reads data from def file(s) associated to the specified hInstance(s).
-ignore_drcfill Ignores the special routing with DRCFILL shape attribute.
-incremental_ilm_def Incrementally flatten the ILM def.

-modules <vCell>+

Specifies the list of modules for which physical data needs to be loaded. The tool then reads data only from def file(s) associated to the specified module(s). 
-preserve_shape Preserves the shapes and geometries when the DEF data from various blocks is merged to a single chip database.

-rdl_def string

Specifies RDL def file.
-rdl_orient orientation Specifies orientation for RDL def.
-rdl_placement {x y} Specifies offset of RDL def.
-secondary {{suffix def_file_list}...} Specifies the secondary DEF file(s) to load.
-skip_fillers Skip merging filler and decap cells.
-skip_nets Skips merging signal nets section.
-skip_pg Skips merging routing on pg nets.

-skip_routing {[pg|signal] [regular|special] [high_layer_routing]}...


Skips merging routing based on the settings specified. This setting can be any combination of the three optional keywords from the following set:

  • [pg|signal]: Specifies the type of the net on which the routing to be skipped. pg – pg net, signal – signal net, both if not specified.
  • [regular|special]: Specifies the type of routing to be skipped. regular – regular routing, special – special routing, both if not specified.
  • [high_layer_routing]: Specifies that only the routing on high layers to be skipped, where the layers are calculated automatically. If not specified, the routing on all layers are skipped. The layers can be specified with -to_layer parameter. In that case, the routing on the layers from top to the specified layer are skipped.
    Note: You need to specify the -to_layer parameter explicitly if high_layer_routing is specified in -skip_routing; otherwise, high_layer_routing is not applicable.

For example, you can specify multiple sets of arguments to this parameter, as shown below:

-skip_routing {{pg regular} {signal special high_layer_routing}}
-to_layer routing_layer_name Skips the routing of layers from top to the specified layer (inclusive) when the high_layer_routing option is specified for the -skip_routing parameter.
-top_cell_orient orientation Specifies orientation for topcell.
-top_cell_placement {x y} Specifies placement for topcell.
-top_scope Merges routing on top scope nets only.
-transform_file string Reports the final x and y offsets and orientation in the top-level of each LEF block that got replaced by DEF.
-use_top_def_die_area Enables the use of TOP DEF DIE AREA.

Examples

Below is a sample template script that describes how to run Tempus ECO for DRV/Setup/Hold optimization on a hierarchical design in Stylus mode :

set_multi_cpu_usage -local_cpu 16

read_physical -lef {tech.lef stdCell.lef }

read_mmmc viewDefinition_stylus.tcl

read_netlist “top.v.gz blockA.v.gz"

init_design


set_db add_fillers_cells "list_of_filler"

read_hierarchical_def top.def.gz blockA.def.gz


read_spef -rc_corner corner_worst_CMAX “top_CMAX.spef.gz blockA_CMAX.spef.gz"

read_spef -rc_corner corner_worst_RMIN “top_RMIN.spef.gz blockA_RMIN.spef.gz"


set_db delaycal_enable_si true

set_db opt_signoff_partition_list_file partition.txt

set_db opt_signoff_allow_multiple_incremental true

set_db opt_signoff_optimize_replicated_modules true

set_db opt_signoff_read_eco_opt_db ecoTimingDB


set_db opt_signoff_eco_file_prefix DRV

opt_signoff  -drv

set_db opt_signoff_eco_file_prefix SETUP

opt_signoff  -setup

set_db opt_signoff_eco_file_prefix HOLD

opt_signoff  -hold
