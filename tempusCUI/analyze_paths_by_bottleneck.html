analyze_paths_by_bottleneck

 analyze_paths_by_bottleneck
[-help]
{-category n | -delta_delay {worst|total}}
[-path_num m]
[-max_slack float]
[-min_slack float]
[-master master_category_name]

Creates categories according to the bottleneck analysis of the critical paths and fixes the violation according to the bottleneck information. Bottleneck Analysis detects the instances that are often involved in the critical paths in the design. Any change in timing for these instances impacts multiple critical paths in the design. Therefore you can use this information to change your design (floorplan, placement, constraints etc.) around these instances. The bottleneck analysis computes the number of occurrences that an instance appears in the paths that you display in the Timing Debug window, and provides the following output:

  • Colors most used instance based on number of occurrences.
  • Creates n number of path categories for the instances with the highest number of occurrences. n is the number you specify using the -category parameter.

Users can also perform bottleneck analysis of the critical paths based on incremental delay. Categories will be created based on the worst m paths with:

  • The biggest worst incr_delay contribution
  • The biggest total incr_delay contribution

The command can be applied wherever the user loads the machine readable timing report.

Parameters

-help

Outputs a brief description that includes type and default information for each analyze_paths_by_bottleneck parameter.

For a detailed description of the command and all of its parameters, use the man command:
man analyze_paths_by_bottleneck

-category n

Specifies the number of categories to be created for most occurring instances.

-delta_delay {worst|total}

Specifies that the categories are created based on worst incr_delay contribution or total incr_delay contribution.

-master master_category_name

Specifies that the analysis should be performed only for the specified master category.

-max_slack float

Specifies the max slack value of the critical paths for bottleneck analysis based on incr_delay.
-min_slack float Specifies the min slack value of the critical paths for bottleneck analysis based on incr_delay.

-path_num m

Specifies the number of critical paths to be analyzed when performing bottleneck analysis based on incr_delay.

Examples

  • The following command creates path categories based on bottleneck analysis of the critical paths on the instances:
    analyze_paths_by_bottleneck -category 2
    The following categories are created: BOT_instance1 and BOT_instance2. You can change the number of categories.
  • The following command creates path categories based on bottleneck analysis of the critical 20 paths on the worst incr_delay:
    analyze_paths_by_bottleneck -path_num 20 -delta_delay worst
    The following category is created: BOT_SI_WORST.
