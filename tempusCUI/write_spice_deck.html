Generates the SPICE trace for a path.

While generating a Spice Deck, the write_spice_deck command looks for library cells required to run Spice and adds all cells as ".include" in the generated Spice netlist.

The output SPICE deck includes:

  • Active and passive devices such as field-effect transistors (FETs), capacitors, and resistors.
  • Initial conditions and voltage sources
  • Actual names of the gates, nets, and cell instances, which helps the simulator interpret this information effectively. For example, consider the following excerpt, which shows an entry for a gate named U0 in the SPICE deck: 
    *Gate U0
    *--------------------
    *Cell ports in order : x a VSS VDD
    *--------------------
    XU0 U0/x U0/a 0 U0/VDD inv_ahvt_64
    *--------------------

Note: By default, the software uses the default list of power node names (VDD and VCC) and ground node names (GND and VSS).

Note: In order to output a Spice deck that generates the same report output as the report_timing command, you must run the write_spice_deck command with the -report_timing, -segment_start, and -segment_end parameters.

Parameters

-help                                    

Prints out the command usage.
-add_driver_for_constraint_check {true | false}

Enables constraint check deck generation with pre-driver.
-add_side_load_measurement {true | false}

Adds the side load measurement in clock mesh Spice deck.

By default, Tempus only measures the latencies, delays, and slews of arcs that are part of clock mesh specified using the -from parameter.

When set to true, the software additionally measures the latencies and slews of the side recievers at each stage.

Default: false
-add_voltage_for_missing_sensitization Adds the voltage for missing sensitization.
-aging_correlation_type {full | timingonly}

Creates the aging-aware Spice deck.

  • timingonly: Writes out the Spice deck for timing-only correlation mode. The Spice deck contains device degradation parameters computed by Tempus.
  • full: Writes out the Spice decks for full correlation. This involves two Spice simulations. The first Spice simulation computes device degradation using stress simulation. The second Spice simulation uses this data for transient simulation, where delays and slew are measured for timing correlation.
-aging_stress_num_cycles <integer greater than 0>

Specifies the number of cycles in stress simulation in full Spice correlation mode.

When this parameter specified, the periodic stress waveform propagates through the entire path on which correlation is required.

It is recommended to use the value 6, which is based on the path depth.
-aging_stress_use_timing_slew {false | true} Uses the slew from STA in stress Spice deck for full Spice correlation, instead of using the default slew of 1ps.
-aging_level_only <string>

Indicates the type of aging, such as BTI, HCI, or both. This parameter is required for URI models only.

Note: The exact value of aging level is foundry specific.

-bbox_cells string                    

Specifies a list of cells to be considered as black boxes.

-clock_mesh_depth integer             

Creates clock mesh spice deck of depth.

-clock_mesh_from_fall_pin string   

Creates the spice deck with mesh net starting from falling transition of specified from pin.

-clock_mesh_from_pin string     

Createsthe spice deck with mesh net starting from pin.

-clock_mesh_from_rise_pin string

Creates the spice deck with mesh net starting from rising transition of specified from pin.

-clock_mesh_no_hard_stop_at_to_pins {true | false}

When it is true, it will traverse down all the way till it hits the clock pin of a flip-flop or or if it passes the depth specified with the -depth parameter.

-clock_mesh_to_pin string               

Creates the spice deck with mesh net ending at to pins.
-constraint_check {true | false}

Enables constraint check deck generation.
-enable_fast_simulation {true | false}

When set to true, the software enables the fast simulation mode. In this mode, additional clock cycles are not required to initialize sequential cells in the Spice deck - this speeds up Spice simulations. All the sequential cells are initialized using the initial conditions and only a single clock edge is applied as input.

By default, this parameter is set to false. In this mode, two clock cycles are applied as input to the clock network, where the first triggering edge is used for initialization of sequential cells, and the second edge is used for delay measurement. 

Note:  For better performance with sequential cell simulations, you can set the -enable_fast_simulation parameter to true during constraint check generation.
-enable_spectre_x {true | false} Enables the spectreX license checkout when launching Spectre.
-enable_mis {tied_input |independent_input | none}

Enables advanced multi-input switching (AMIS) during Spice deck creation. You can specify one of the following options:

  • tied_input: Multiple inputs of an instance will be tied together in a netlist. You can set the timing_analysis_multi_input_switching_mode attribute to 1 to enable this behavior.  
  • independent_input: Allows the Spice deck to write out input stimulus for side inputs for multi-input gates. The switching times of each input depends on the timing windows. This option can be used when the timing_analysis_multi_input_switching_mode attribute is set to 2.
  • none: Disables AMIS during the Spice deck creation.

Default: none 
-exclude_side_load_cells string

Specifies a list of cells for which the pin capacitance will be used for side loads instead of instantiating them.
-exclude_side_load_cells_for_missing_subckt {true | false} When set to true, the software will add side load pin capacitance for missing Spice subckt cell instead of instantiating it.
-force_delete_output_dir Completely removes the directory specified by the user using the -out_dir parameter.
-generate_output_only {true | false}

Generates the report output only, without triggering any simulations.

Default: false
-glitch_simulation_mode {input_output | output}

Specifies the glitch simulation mode.

When set to input_output, the software uses both the RIP and ROP for Spice calculations. When output is specified, the Spice ROP will be computed using the RIP.

-glitch_receiver_pin string           

Specifies receiver pin for glitch spice deck.

-ground_nets string                    

Specifies a list of ground nodes.
-include_cell_variation {true | false}

Writes out the Spice deck required to run simulations.

When set to true, the software runs Monte-Carlo simulations from within the Tempus software.

Default: false
-lsf_job_string string

Specifies a handle to the farm job for launching the simulation.

-monte_carlo_sim_init_args string

 

Passes necessary Monte Carlo parameters that are required to run MC simulations. The Monte Carlo analysis refers to “statistics blocks”, where statistical distributions and correlations of netlist parameters are specified. This parameter initializes these parameters under the statistics block.

Note: This parameter can be used when -include_cell_variation is set to true. 

-monte_carlo_sim_transient_args string

 Initializes full transient time of simulation and transient time step. 
-measure_point {all | path | stage}

Specifies whether to add all, path, or stage measurements.

Default: all
-merge_spice_deck {true | false} Allows you to enable merged Spice deck. 
-omipath <string> Specifies the OMI (Open Model Interface) directory - required only for OMI.

-out_dir string                    

Specifies the name of the output directory that will contain the generated delay and/or glitch spice decks.

If simulation is also performed using the -run_simulation parameter, the Spice simulations output will also be saved in this directory.

Default: tempus_pathsim

-out_file_prefix string             

Adds the specified prefix to the generated Spice deck files.

If this parameter is not used, one of the following default names of the generated Spice decks will be used:

  • path_<index>_setup.sp: for setup paths
  • path_<index>_hold.sp: for hold paths
  • path_<index>_vl_glitch.sp: for VL glitch
  • path_<index>_vh_glitch.sp: for VH glitch

The <index> in the above file names is controlled based on the number of decks that are generated using the write_spice_deck command.

A user-specified string (specified using this parameter) is used as a prefix to the above mentioned file names.

-power_nets string                    

Specifies list of power nodes.
-reliability_commands string

Allows you to specify the analysis type.

The following three Spice parameters need to be defined as per the required analysis type:

Analysis                             bti_on             hci_on          btirec
BTI-Only                                1                     0                     0
BTI-Only with Recovery         1                     0                     1
HCI-Only                               0                     1                     0
BTI+HCI without Recovery    1                     1                     0
BTI+HCI with Recovery          1                     1                     1

A few examples are given below:

BTI-only without recovery:

-reliability_commands ".param hci_on=0 bti_on=1 she_on=0 btirec_on=0"

HCI-only:

-reliability_commands ".param hci_on=1 bti_on=0 she_on=0 btirec_on=0"

BTI+HCI without recovery:

-reliability_commands ".param hci_on=1 bti_on=1 she_on=0 btirec_on=0"

BTI-only with recovery:

-reliability_commands ".param hci_on=0 bti_on=1 she_on=0 btirec_on=1"

BTI+HCI with recovery:

-reliability_commands ".param hci_on=1 bti_on=1 she_on=0 btirec_on=1"

Note: HCI support for OMI is not available.
-reliability_model_type {URI | OMI | TMI} Specifies the aging-aware deck type - URI, OMI, or TMI.

-report_fields string                 

Changes run path simulation internal reporting format. The format columns should be compatible with those in the report_timing_format attribute. These settings will be used for the subsequent write_spice_deck command statement.
-report_noise_cmd string

Specifies the report_noise command parameters as a list of arguments within brackets.

When specified, the Spice deck will be generated for all the receiver pins that are reported by the report_noise command for the specified options.

When specified with the -run_simulation parameter, the software writes out a comparison report comparing various glitch parameters between Tempus and Spice, such as, RIP, input glitch area, and ROP (only if ROP node name is available in the noise models).

-report_timing_cmd string            

Specifies arguments to report_timing command.

-run_simulation

Enables path simulation in addition to generating Spice Deck.

-scale_mode string

Allows you to specify the UMC_URI scale mode option.

Default: effective 
-segment {data_path | launch_path launch_clock_path | capture_path all}

Creates the Spice deck of a segment out of the path spice deck.

The following command/global variable settings have the following impact on the -segment parameter options:

  • -path_type full_clock is defined under the write_spice_deck-report_timing parameter, then the -segment default value is launch_path.
  • -path_type full_clock is not specified, then default value is data_path.
  • timing_disable_retime_clock_path_slew_propagation attribute is set to false, the default value is launch_path (irrespective of -path_type settings).
  • timing_disable_retime_clock_path_slew_propagation attribute is set to true (default), then launch_clock_path and capture_path options are supported only when the -path_type full_clock option of the write_spice_deck -report_timing parameter is used.

-segment_end string

Specifies the name of the segment end term.
-segment_start string Specifies the name of the segment start term.

-si_sweep_range float               

Range to sweep the victim.

-si_sweep_steps integer         

Number of steps by which the victim is swept.

-si_sweep_victim {true | false}            

Enables victim sweep.

-side_path_levels integer          

Specifies side path level.
-spectre_analysis_options <string> Adds Spectre analysis options to the run. When specified, the software provides instructions to Spectre, e.g.,  run a session with extra accuracy.

-spectre_cmd_options string            

Specifies command line options for Spectre.

Specifies the name of the model files to be included in the generated spice.

-spice_stimuli_file string         

Allows you to specify the file path containing stimuli to be used for the specified library cells. The cells' sensitization coming from the user-specified stimuli file takes precedence over Tempus inferred sensitization.

Syntax for delay Spice decks is given below:
lib_cell string <from | from_rise | from_fall> string <to | to_rise | to_fall> string input_vector string num_clk_pulse integer

Syntax for glitch Spice decks is given below:
lib_cell string glitch_type <VL | VH> output_pin string input_vector string num_clk_pulse integer # For victim driver sensitization
lib_cell cell_name glitch_type <VL | VH> input_pin string input_vector string num_clk_pulse integer # For victim receiver sensitization

The num_clock_pulse integer holds significance in case of sequential arcs, and specifies where to align the data pin transition with respect to the clock transition.

For example, a value of ‘1’ (default setting) specifies that the data pin transition needs to be aligned before the last clock transition where delay measurement is intended. This value can be used in case of regular flip-flops.
The value ‘2’ specifies that data pin transition needs to be aligned with respect to the second-last triggering clock edge. This value can be used for cascaded 2-bit flip flops.

Additionally for sequential arcs, the first pin in the user-specified input vector needs to be the data pin, the signal of which will be latched in the sequential cell.

Here are some examples of stimuli file:

  • The following example shows the stimuli file containing sensitization for CP(rise)->Q(fall) and CP(rise)->Q(rise) timing arcs of library cell FF1:
    lib_cell FF1 from_rise CP to_fall Q input_vector !D&CDN&!SE&!SI num_clk_pulse 2
    lib_cell FF1 from_rise CP to_rise Q input_vector D&CDN&!SE&!SI num_clk_pulse 2
  • The following example shows the stimuli file containing sensitization for the victim driver cell AOI for both VL and VH glitches:
    lib_cell AOI glitch_type VL output_pin Z input_vector !A&!B&!C
    lib_cell AOI glitch_type VH output_pin Z input_vector A&!B&C

-spice_subckt_files string           

Specifies the subckt file, to be included in generated spice.
-supply_voltage_file string

Specifies the file containing user-specified power/ground voltages to be used for SPICE simulations. By default, the design operating voltages will be used.

The format of the supply voltage file is as follows:

GLOBAL POWER #Specifies the global supply for all power pins

GLOBAL GROUND #Specifies the global supply for all ground pins

GLOBAL #Specifies the voltage to be used for given pg pin for all instances

POWER #Specifies the VDD to be used for specified I/O port PWLs

GROUND #Specifies the VSS to be used for specified I/O port PWLs

POWER / #Specifies the VDD used for specified instanceAC/AEURAtms signal pin PWL or sensitization

GROUND / #Specifies the VSS used for specified instanceAC/AEURAtms signal pin PWL or sensitization

/ #Specifies the voltage used for specified instanceAC/AEURAtms pg pin
-supply_voltage_file_stress <file> Specifies an optional extra file containing the stress voltages for supply or ground pins that are in cell sub-circuit definition. 
-through string

Creates the Spice deck with mesh net going by -through points.
-temperature float

Specifies a user-defined temperature to be used in SPICE simulations.

Unit: Celsius
-uri_lib_file string

Specifies the URI model file (required only for URI).

Default: none
-uri_mode string

Specifies the URI appendage option.

Default: appendage
-use_control_param {true | false}

Allows you to control the power/ground voltage levels in the created Spice deck through user-specified parameters.

When set to true, an additional file with the same name as the deck, and extension .control is created that contains the parameterized design voltage levels of the PG pins of all the cells instantiated in the deck. Your can modify the *.control file as per the requirement without modifying the original deck.

-use_distributed_load_for_side_receivers {true | false}

Allows you to control whether to use the receiver output load as distributed or lumped load.

Default: false

-user_defined_measure_statements {append | overwrite}

Specifies whether to overwrite the default measurement statements in the Spice deck by user-defined measurements specified using the -user_defined_measure_statements_file parameter, or append it with default measure statements.

Default: append
-user_defined_measure_statements_file string

Allows you to add the delay/slew measurement statements for any given segment of the path for which Spice deck is generated.

The format of the file is given below:
<MEASURE_TAG_NAME TRIGGER_PIN_NAME TARGET_PIN_NAME>

Multiple such lines with unique tags can be specified in the file.

The measure statement is written in the Spice deck for delay measurement between TRIGGER_PIN and TARGET_PIN, and slew measurement at TARGET_PIN.
-use_ndw_for_constraint_check  {true | false}

Enables constraint check deck generation with NDW waveforms.
-use_noise_model_when_cond {true | false}

Allows to use the when condition from a pin noise model.

-view string                         

Specifies the view name, if glitch spice deck is create for other than default view.
-waveform_aware_pulse_width_checks {true | false} Generates the Spice deck for waveform-aware pulse width checks.

-xtalk {delay | voltage_low_glitch | voltage_high_glitch}

Generates the SI SPICE Deck for the stage. A stage can start with a victim driver input to victim receiver input or receiver output.

You can specify one of the following options:

  • delay: Used to dump the SI delay SPICE deck.
  • voltage_low_glitch and voltage_high_glitch: Specifies the type of glitch (VL or VH) the SPICE deck will be used for. This option must be used for glitch SPICE deck generation.

> filename                         

Redirects the output to a file.

>> filename                          

Appends to an output file.
