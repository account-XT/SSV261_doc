To set the value of any root attribute, use the set_db  command:

set_db attribute_name value

To get the current value of any root attribute, use the get_db  command:

get_db attribute_name

To get the current value of all attributes in the system category, use the following command:e

get_db -category system  

auto_file_dir

auto_file_dir directoryName   

Default:  ./

Specifies the directory to store files/sub-directories 'auto-generated' by the tool. This includes report files or other output files with default names that are automatically created by some commands in the current run directory. Default names that have been overridden with a name chosen by the user, are not affected. This allows multiple simultaneous runs from the same run directory to direct output files to different result directories to avoid collisions.

auto_file_prefix

auto_file_dir fileName   

Default:  ""

Specifies a prefix to be applied to all files 'auto-generated' by the tool. This includes report files or other output files with default names that are automatically created by some commands in the current run directory. So a default name like "cmd.report" will become "<prefix>cmd.report". Default names that have been overridden with a name chosen by the user, are not affected. This allows multiple simultaneous runs from the same run directory to direct default output files to different locations to avoid collisions.

distributed_mmmc_disable_reports_auto_redirection

distributed_mmmc_disable_reports_auto_redirection {true| false}   

Default: false

Allows reports to be generated in the specified location. 

When set to true, the software does not allow the reports for different views to get overwritten. When set to false, the reports are generated automatically in the DMMMC view directory structure. 

gui_verbose

gui_verbose {all db none}   

Default: db

Controls which GUI actions are logged. You can select:

  • all: Logs all GUI actions.
  • db: Logs the GUI actions that affect the DB, such as gui_select, but does not capture display-only actions such as gui_dim_foreground.
  • none: Does not log any GUI actions. So, the .log and .cmd files are incomplete.

jedai_catalog_token

jedai_catalog_token token

Default: ""

Data_type: string

Authenticates and provides access to the OpenAI services.

jedai_catalog_url

jedai_catalog_url <jedai_server_url>

Default: ""

Data_type: string

Enables the AI chat box in the Tempus GUI. You need to set the following setting in tempus_startup.tcl.
#set server url
set_db jedai_catalog_url <jedai_server_url>

log_verbose_type

log_verbose_type {pre post both}

Default: pre

When verbose logging is enabled, the default logging of each commands is pre-Tcl expansion. In some cases it is helpful to see post-Tcl expansion, or even both pre-Tcl and post-Tcl expansion when doing detailed debugging. You can switch between settings in the middle of a script.

read_db_directory

read_db_directory directory_name

Default: ""

Specifies the absolute path of the database, that is used to restore the session. In case of a non-restored session, this variable returns a blank value. 

The value of this global variable is set internally by the software. 

read_db_file_check

read_db_file_check {true | false}

Default: true

By default, read_db will check all the files inside the saved DB directory. If any file is edited, renamed, or deleted, the tool will give an error. However, read_db will not perform this check if read_db_file_check is set to false.  

read_db_stop_at_design_in_memory

read_db_stop_at_design_in_memory {true | false}

Default: true

By default, tool gives an error and stops if you call read_db more than once in the same session unless read_db_stop_at_design_in_memory is set to false. Using read_db twice in one session is not recommended as settings from the first database may not be cleaned up properly and can cause problems in the second database. 

read_db_tool_name

read_db_tool_name   

Default: ""

Indicates the tool name of the tool that created the restored db on the disk database.

read_db_version

read_db_version   

Default: ""

Indicates the version of the tool that generates an on disk database.

resolve_show_tcl_command_with_value

resolve_show_tcl_command_with_value {true | false}  

Default: false

Data_type: Boolean, read/write

When set to true, it prints the Tcl variable value in the resolve log.

script_search_path

script_search_path search_directory_path   

Default: "."

Provides a set of directories for the software to search for files that are sourced using the Tcl source command. The software will search in each search path directory for the specified file.

soft_stack_size_limit

soft_stack_size_limit size_limit

Default: 8

Specifies the soft stack size limit in mbytes. When the tool is launched, the soft stack size limit is auto-enlarged to 0.2% RAM. If 0.2%RAM is larger than the hard limit, the tool sets it to the hard limit.

source_echo_filename

source_echo_filename {true| false}

Default: false

Displays the file name being sourced before the actual sourcing.

If this is true, and verbose 'source' command logging is off (e.g. source_verbose is false), any 'source' command will be logged with 'Sourcing <filename>'. This can be useful to find which source files are calling other source files, or to log all the startup Tcl files that are loaded even though verbose logging is off. 

source_continue_on_error

source_continue_on_error  {true| false}  

Default: false

Enables or disables source to continue the script on TCL_ERROR. If true, the source command will ignore Tcl errors, and continue processing the script files. If false, a Tcl error will halt the script.

set_db_verbose

set_db_verbose {true| false}

Default: false

Specifies additional messages are issued describing what attribute is being set on what object.

source_verbose

source_verbose {true| false}

Default: true

Data_type: bool

Controls whether scripts are sourced in quiet or verbose mode:

  • By default (true), files are sourced in verbose mode. This is equivalent to source filename -verbose.
  • If you set this variable to false, files are sourced in quiet mode. 

source_verbose_line_length_limit

source_verbose_line_length_limit value

Default: -1

Data_type: int

Limits the command printed to stdout and the .log file to the specified number of characters for verbose script source. This is normally only needed if you log commands "post Tcl expansion" when long Tcl lists may occur in the command arguments. 

tcl_error_info

tcl_error_info {true| false}

Default: false

Data_type: bool, read/write

When set to true, the tcl_error_info prints the error information if there is an issue in the Tcl script.

tcl_report_header_with_value

tcl_report_header_with_value {true| false}    

Default: false

Data_type: boolean, read/write

When set to true, prints the Tcl variable value in the report header. 

Example

In the following example, tcl_report_header_with_value is set to true, the report shows the value, myct, set for the variable in the report header.

[DEV]tempus 8> report_analysis_coverage -check_type   \    
+      $myct

#  Generated by:      Cadence Innovus 24.10-dev.jinchuan
#  OS:                Linux x86_64(Host ID sjfib902)
#  Generated on:      Wed Jan 17 23:22:11 2024
#  Design:            DTMF_CHIP
#  Command:           report_analysis_coverage -check_type   \
#    $myct
###############################################################
    +----------------------------------------------------+
    |           TIMING CHECK COVERAGE SUMMARY            |
    |----------------------------------------------------|
    | Check | No. of |    Met    | Violated |  Untested  |

If the tcl_report_header_with_value is set to false, the report will show the name of the variable in the report and not its value.

ui_precision

ui_precision  number

Default: 3

Specifies the number of significant digits to be displayed in the absence of an explicit precision for that type.

ui_precision_capacitance

ui_precision_capacitance number

Default: 3

Specifies the number of significant digits to be displayed for quantities of type capacitance.

ui_precision_derating

ui_precision_derating number

Default: 3

Specifies the number of significant digits to be displayed for derating factors such as those specified via set_timing_derate constraints or AOCV derating libraries. 

ui_precision_power

ui_precision_power  number

Default: 3

Specifies the number of significant digits to be displayed for quantities of type power. 

ui_precision_sensitivities

ui_precision_sensitivities  number

Default: 3

Specifies the number of significant digits to be displayed for statistical sensitivity values and SOCV sigma values.

ui_precision_timing

ui_precision_timing  number

Default: 3

Specifies the number of significant digits to be displayed for delay type values including cell and net delays, transitions, arrival and required times, and slacks.

write_db_auto_save_user_globals

write_db_auto_save_user_globals {true| false}

Default: true

If true, write_db automatically saves the Tcl global variables created by the user. User globals are defined as any “info globals” names that do not exist at startup ( such as created by the user executed code).

You can use the define_variables command to add or delete specific Tcl variables from the automatic save list.

write_db_restrict_under_batch_mode

write_db_restrict_under_batch_mode {0| 1}

Default: 0

Data_type: bool, read/write

Controls whether to save a database under the batch mode. By default, a new database is saved under the batch mode. However, if write_db_restrict_under_batch_mode is set to true, the tool gives an error.

write_db_restrict_under_eco_batch_mode

write_db_restrict_under_eco_batch_mode {true | false}

Default: false

Data_type: bool, read/write

Controls whether to restrict saving the database in the ECO batch mode.
