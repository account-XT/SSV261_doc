create_rc_corner

create_rc_corner
[-help]
[-cap_table capTableFile]
-name rcCornerName
[-post_route_cap {capFactor1 capFactor2 capFactor3}]
[-post_route_clock_cap {capFactor1 capFactor2 capFactor3}] 
[-post_route_clock_res {resFactor1 resFactor2 resFactor3}]
[-post_route_res {resFactor1 resFactor2 resFactor3}]
[-post_route_cross_cap {xcapFactor1 xcapFactor2 xcapFactor3}]
[-pre_route_cap capFactor]
[-pre_route_clock_cap capFactor]
[-pre_route_clock_res resFactor]
[-pre_route_res resFactor]
[-qrc_tech fileName]
[-temperature temperatureValue]
[-via_variation_file string]

Creates a named RC corner object that can be referenced later when creating a delay calculation corner object. An RC corner object provides the software with all of the information necessary to properly extract, annotate, and use the RCs for delay calculation.

Note: You must use the RC corner scaling attributes when running the software in multi-mode multi-corner analysis mode. Use the extract_rc Category Attributes to set the extraction mode for all RC corner objects in the design.

Note: In multi-mode multi-corner mode, only the default RC corners created by the software inherit the derating factor values defined in the configuration file. You can set different postroute scale factors for the postroute engine variants by specifying them as duplets and triplets. For example,

resFactor1 resFactor2 resFactor3

Where:

  • Single value: If you specify one value, the scale factor applies to effort level low. Scale factor value of 1 is used for medium and high by default.
  • Duplet: If you specify two values, the first value is used for effort level low and the second value is used for medium. Scale factor value of 1 is used for high by default.
  • Triplet: If you specify three values, the first value is used for effort level low, the second value is used for medium, and the third value is used for high.

Note: If the read_spef command is specified without the -rc_scale parameter, for example, "read_spef -rc_corner early_spef_${rc_corner}", then the software does not apply capacitance scale factor specified in -post_route_cap and -post_route_cross_cap parameters. If the read_spef command is specified with the -rc_scale parameter, for example, "read_spef -rc_corner early_spef_${rc_corner} -rc_scale ", then the software applies the capacitance scale factor. Here, no factor is specified in the -rc_scale option.

Parameters


-help Outputs a brief description that includes type and default information for each create_rc_corner parameter. For a detailed description of the command and all of its parameters, use the man command: man create_rc_corner.

-cap_table capTableFile

Specifies the capacitance table to use for extraction when using this RC corner.

Default: The Tempus extraction system uses internal rules for extracting resistances and capacitances.

-pre_route_cap capFactor

Specifies the capacitance scale factor for RC Extraction in pre-route mode.

Default: 1.0

-pre_route_clock_cap capFactor

Specifies the scale factor for capacitance of clock nets in preroute mode.

Default: 0

When this parameter is not specified, the value specified with the -pre_route_cap parameter is used for preroute extraction.

When specified, this parameter overrides the value specified with the -pre_route_cap parameter for clock nets.

-pre_route_clock_res resFactor

Specifies the scale factor for resistance of clock nets in preroute mode.

Default: 0

When this parameter is not specified, the value specified with the -pre_route_res parameter is used for preroute extraction.

When specified, this parameter overrides the value specified with the -pre_route_cap parameter for clock nets.

-pre_route_res resFactor

Specifies the resistance scale factor for RC extraction in pre-route mode.

-post_route_cap {capFactor1 capFactor2 capFactor3}

Specifies the capacitance scale factor for RC extraction in post-route mode.

Default: 1.0

-post_route_clock_cap {capFactor1 capFactor2 capFactor3}

Specifies the scale factor for capacitance of clock nets in the postroute extraction mode.

Default: 0

When this parameter is not specified, the value specified with the -post_route_cap parameter is used for postroute extraction. When specified, this parameter overrides the value specified with the -post_route_cap parameter.

-post_route_clock_res {resFactor1 resFactor2 resFactor3}

Specifies the scale factor for resistance of clock nets in the postroute extraction mode.

Default: 0

When this parameter is not specified, the value specified with the -post_route_res parameter is used for postroute extraction. When specified, this parameter overrides the value specified with the -post_route_res parameter for clock nets.

-post_route_res {resFactor1 resFactor2 resFactor3}

Specifies the resistance scale factor for RC extraction in post-route mode.

-post_route_cross_cap {xcapFactor1 xcapFactor2 xcapFactor3}

Specifies the coupling capacitance scale factor for RC extraction in postroute mode.

Default: 1.0

-name rcCornerName

Specifies the name for the RC corner object being created. You can choose any name for an RC corner object, but it is recommended that you use a name that can be easily recognized as referring to a specific RC corner (for example, rc-min, rc-max, c-min, c-max, and so on).

-qrc_tech fileName

Specifies the name of the Quantus technology (.tch) file used by Quantus sign-off RC extraction.

The technology file is generated by TechGen, a built-in functionality of Quantus. For most technologies you can get this file from technology vendors. For technologies that are not available through the technology vendors, you can enter the fabrication process information into an ASCII-format interconnect technology (ICT) input file. The ICT file is then used as input to IceCaps, which in turn generates the technology file.

-temperature temperatureValue

Specifies the temperature, in units of Celsius, to use to derate resistance values.

Use this parameter when you want to override the default temperature specified in the capacitance table or the Quantus technology file.

Note: The software does not require that the temperature specified by the PVT operating condition at the delay calculation corner level be the same as the RC nominal or user-specified temperature value.

Default: The Tempus extraction system uses the default temperature of 25 degrees Celsius, unless it is overridden by the capacitance table or the Quantus technology file.
-via_variation_file string


Specifies a file for modeling via variation. The VIA variation file lists up all the VIA layer names with the corresponding multiplier. Each RC corner can have its own VIA variation file.

For example:

create_rc_corner

-name rcCornerName1 \

-via_variation_file viaVariationFileName1

create_rc_corner

-name rcCornerName2 \

-via_variation_file viaVariationFileName2

Examples

  • The following command creates an RC corner called rc-cbest that uses the capacitance table myTech_4_bc.CapTbl, and derates the resistance values based on the temperature of 50 Celsius:
    create_rc_corner -name rc-cbest -cap_table myTech_4_bc.CapTbl -temperature 50
