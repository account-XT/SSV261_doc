update_delay_corner

update_delay_corner 
[-help]
-name delayCornerName
[-early_estimated_worst_irDrop_factor percent]
[-early_irdrop_data files_or_directories] 
[-early_irdrop_files list_of_files] 
[-early_rc_corner rcCornerObj]
[-early_temperature_files list_of_files]
[-early_timing_condition conditional_pairs]
[-late_irdrop_data files_or_directories]
[-late_irdrop_files list_of_files]
[-late_rc_corner rcCornerObj]
[-late_temperature_files list_of_files]
[-late_timing_condition conditional_pairs]
[-late_estimated_worst_irDrop_factor percent]
[-irdrop_data files_or_directories]
[-irdrop_files list_of_files]
[-pg_net_voltages voltage_pairs]
[-rc_corner rcCornerObj] 
[-si_enabled {true | false}]
[-temperature_files list_of_files]
[-timing_condition conditional_pairs]

Modifies the parameters of an existing delay calculation corner object. You can use the update_delay_corner command to add or change attribute values for an existing delay calculation corner object, or for an existing power domain definition.

You can update a delay calculation corner object before the multi-mode multi-corner definition file is loaded into the design, or after. However, after the software processes the file, any change to an existing object when the software is in multi-mode multi-corner mode results in the timing, delay calculation, and RC data being reset.

You also can use the update_delay_corner command to add a power domain definition to the specified delay calculation corner. Instances contained within an MSMV power domain often require a different library or operating condition that used for the default power domain. Power domain definitions within a delay calculation corner object can be used to assign specific libraries and PVT settings per power domain.

Note: Use separate delay calculation corners to define major PVT corner differences. Use the -early_* and -late_* parameters within a single delay calculation corner to control on-chip-variation.

The -early_* and -late_* parameters can be specified separately, to update a delay corner object with early or late information. If you only specify one of the -early_* or -late_* parameters, the software uses the original information pointer in place of the missing early/late parameter.

For example, if you initially created a delay corner object using:

create_delay_corner 
-library_set libsNominal
...

Use this command after creating at least one delay calculation corner (create_delay_corner).

Parameters

-help Prints out the command usage.
-early_estimated_worst_irDrop_factor percent

Specifies the early voltage derating factor. 

When this parameter is specified, the software performs delay calculations using the voltage = nomVolt * (1 – value).

Default: 0.0
-early_irdrop_data files_or_directories

Specifies the IR drop files or directories to apply when calculating the early arrival times at a single delay corner.

-early_irdrop_files list_of_files

Specifies the list of IR drop files to apply when calculating early arrival times at a single power domain.

This parameter is used primarily when configuring the multi-mode multi-corner environment for on-chip-variation (OCV) analysis.

Note: This parameter is obsolete and will be removed in a future release. To ensure compatibility with future releases, you should update your scripts.

-early_rc_corner rcCornerObj

Specifies the RC corner object to associate with the early corner object.

-early_temperature_files list_of_files

Specifies the name of the temperature file for temperature aware delay calculation for early corner.
-early_timing_condition conditional_pairs

Specifies pair list of domains/supply sets and timing conditions to associate with this delay corner object.
-irdrop_data files_or_directories

Specifies the IR drop files or directories to apply to both the early and late delay calculation for the specified delay corner object.

-irdrop_files list_of_files

Specifies the list of IR drop files to apply to both early and late delay calculation for this power domain object.

This parameter is used primarily to configure single-corner or Best-Case Worst-Case (BC-WC) analysis modes.

Note: This parameter is obsolete and will be removed in a future release. To ensure compatibility with future releases, you should update your scripts.
-late_estimated_worst_irDrop_factor percent

Specifies the late voltage derating factor. 

When this parameter is specified, the software performs delay calculations using the voltage = nomVolt * (1 – value).

Default: 0.0
-late_irdrop_data files_or_directories

Specifies the IR drop files or directories to apply when calculating the late arrival times at a single delay corner.

-late_irdrop_files list_of_files

Specifies the list of IR drop files to apply when calculating late arrival times at a single power domain.

This parameter is used primarily when configuring the multi-mode multi-corner environment for on-chip-variation (OCV) analysis.

Note: This parameter is obsolete and will be removed in a future release. To ensure compatibility with future releases, you should update your scripts.

-late_temperature_files list_of_files

Specifies the name of the temperature file for temperature aware delay calculation for late corner.

-late_rc_corner rcCornerObj

Specifies the RC corner object to associate with the late corner object.
-late_timing_condition conditional_pairs

Specifies pair list of domains/supply sets and timing conditions to associate with this delay corner object.

Note: The -early_timing_condition and -late_timing_condition parameters should be specified together.

-name delayCornerName

Specifies the delay calculation corner to which to add the power domain definition, or to which to update the delay corner or power domain attribute values.
-pg_net_voltages voltage_pairs Specifies the power/ground net voltages to be used for both early/late timing analysis.

-rc_corner rcCornerObj

Specifies the new RC corner object to associate with this delay corner.
-si_enabled {true | false}

Controls signal integrity (SI) analysis.

When set to true, the analysis of all MMMC views will include SI analysis by default. You can use this parameter to further determine which analysis views receive SI analysis and which do not.

When this parameter is set to false on a delay corner, the software will disable SI analysis for all the views that reference that corner. By default (or when this parameter is set to true), SI analysis is computed for all the views related to that corner - whenever SI is globally enabled. (The global control of SI analysis is determined by the delaycal_enable_si true attribute setting.)

-temperature_files list_of_files

Specifies the name of the temperature file for temperature aware delay calculation for single corner.
-timing_condition conditional_pairs

Specifies pair list of domains/supply sets and timing conditions to associate with the defined delay corner object.

Some of the conditional pairs are explained below:

  • timing_condition: Specifies the default timing condition which applies to all cells not covered by any other timing condition.                              
  • power_domain_list@timing_condition: The named timing condition applies to the list of all power domains (defined in a power intent file).                                      
  • supply_set_list@timing_condition: The named timing condition applies to all blocks tied to the specified supply set.
  • hinst@timing_condition: The named timing condition applies to the specified hierarchical instance.                   

The timing conditions must be defined with the create_timing_condition command.         

Examples

  • The following example specifies a list of conditional pairs that are domains/supply sets and the timing conditions associated with the specified delay corner object:
    update_delay_corner -name ccworst_setup\
    -timing_condition {tc_1 PD1@tc_2 PD2@tc_2 PD3@tc_2 PD4@tc_2}
