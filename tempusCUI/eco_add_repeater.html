eco_add_repeater

eco_add_repeater
[-help]
[-name <string>]
[-new_net_name <string>]
[-relative_distance_to_sink <float>] 
[-spread_count <integer>]
[-spread_distance <float>]
[-spread_prefix <string>]
{-net <string> | -pins <string>} [-location {{x1 y1} {x2 y2}...} [-buffer_orient <string>]] [-sort_by {slack trans area} [-max_cells <integer>]] [-cells <string> [-evaluate_only ]] [-evaluate_only | -evaluate_all ] [{[-evaluate_all ] [-evaluate_only ]} [{[-view <string>] [-early ] [-late ] [-output_as_tcl ] [-sort_by {slack trans area}]}]] [ -early | -late ][ -fall | -rise ] [-first_spread_distance <double>]

Adds either a single buffer or two inverters to a net. In multi-mode multi-corner (MMMC) mode, this command adds a repeater and updates timing in all views. Optionally, you can specify the location of the buffer or inverters relative to the sink pin.

Note:

Evaluation is not yet supported for the eco_add_repeater command.

You do not need to provide physical information (LEF/DEF) in order to perform ECO with this command.

Parameters 

-buffer_orient string

Specifies the legalized orientation for the repeater instance.

Note: You can specify this parameter with the -location parameter only.

-cells string

Specifies the library cell to be used as repeater. If the cell is an inverter, two inverters in series will be added.
-early

Specifies that timing will be evaluated for early analysis. In such a case, only the active hold analysis views will be considered. If this parameter is not specified, timing will be evaluated for late analysis.

Note: This parameter must be specified with -evaluate_only or -evaluate_all only.
-evaluate_all

Specifies to only evaluate timing for all buffer/inverter/delay cells with matching footprint (or all footprints) without any changes in the netlist.
-evaluate_only

Specifies to only evaluate timing for the given buffer/inverter/delay cells without any changes in the netlist.
-fall

Specifies that the timing will be evaluated for fall transition. If this parameter is not specified, timing will be evaluated for both rise and fall transitions and the worst result is reported.

Note: This parameter must be specified with -evaluate_only or -evaluate_all only.
-first_spread_distance double

Specifies the distance from driver after which the first repeater is to be added.

Note: This parameter must be specified with -spread_distance. 
-late

Specifies that timing will be evaluated for late analysis. In such a case, only the active setup analysis views will be considered. If this parameter is not specified, timing will still be evaluated for late analysis.

Note: This parameter must be specified with -evaluate_only or -evaluate_all only.

-location {x y | x1 y1 x2 y2}

Specifies the x and y coordinates for the location of the buffer or inverter pair. If you do not specify this parameter, the tool determines the location.

If the cell is a buffer and the location is specified, the newly created buffer is placed at the specified location. If the cell is an inverter and only one location is specified, both inverters will be placed at the same location.
-max_cells <integer>

Specifies the maximum number of improving and degrading cells (each) to be reported for evaluation.
-name inst_name Specifies the base names of the new instances to be added.

-net net_name

Specifies the name of net on which the buffer will be added. All sinks of the net are buffered when this parameter is specified.
-new_net_name netname Specifies the base name(s) for the new net(s) to be added.
-output_as_tcl  Displays the output as a TCL list instead of displaying as a text.
-pins pin_or_ports Specifies a list of terminals with one common net.

-relative_distance_to_sink value

Specifies the location of the buffer instance based on its (relative) distance from the sink pin. The value is a number between 0 and 1 (both inclusive). A low value (such as 0.1) places the buffer near the sink. A high value (such as 0.9) places the buffer near the driver. You can use the value 0 to do sink term buffering and value 1 to do driver term buffering. The fraction is based on the length of the wire. Fractional values can only be specified for two-pin nets.

-rise

Specifies that the timing will be evaluated for rise transition. If this parameter is not specified, timing will be evaluated for both rise and fall transitions and the worst result is reported.

Note: This parameter must be specified with -evaluate_only or -evaluate_all only.
-spread_count integer 

Specifies the number of repeaters to be added for buffering.

Minimum: 1

Maximum: INT_MAX
-spread_distance float

Specifies the distance (starting from driver) after which repeaters are to be added.

Minimum: 2.2250738585072e-308

Maximum: 1073741.823
-spread_prefix string Specifies the prefix used for new instances and nets added during spread buffering.
-sort_by {slack trans area}

Specifies the sorting order for evaluation.
-view <string>

Specifies the active analysis views for which timing must be evaluated. If this parameter is not specified, timing will be evaluated for all active analysis views and results reported for the worst view.

Note: This parameter must be specified with -evaluate_only or -evaluate_all only.

Examples

  • The following examples are the two methods to add two back-to-back inverters:

    1. The following example adds two instances of INV0 inverter cell:
      set eco_check_logical_equivalence true ; # default.
      eco_add_repeater -cells {INV0} -name {{inst_0 inst_1}} ...

    2. The following example adds two instances, one each of INV0 and INV1 inverter cells: -
      set eco_check_logical_equivalence false ; # default: true.
      eco_add_repeater -cells {INV0 INV1} -name {inst_0 inst_1} ...

      After the first (1) method, you can run the following command to change one of the two inverter instances to a different inverter cell: -

      eco_update_cell -cells {INV1} -insts {<full hierarchical name of inst_1>}
  • The following command inserts a repeater with cell BUFX4 on the net connected to terminal DTMF_INST/RESULT_CONV_INST/RE_PHC369_r1336_0_/Y: 
    tempus> eco_add_repeater -term DTMF_INST/RESULT_CONV_INST/RE_PHC369_r1336_0_/Y -cell BUFX4
  • The following command inserts a repeater with cell BUFX4 and attaches it to (driver) terminal DTMF_INST/RESULT_CONV_INST/RE_PHC369_r1336_0_/Y: 
    tempus> eco_add_repeater -term DTMF_INST/RESULT_CONV_INST/RE_PHC369_r1336_0_/Y -cell BUFX4 -relativeDistToSink 1
  • The following command inserts a repeater with cell BUFX4 and attaches it to (sink) terminal DTMF_INST/RESULT_CONV_INST/RE_PHC369_r1336_0_/A: 
    tempus> eco_add_repeater -term DTMF_INST/RESULT_CONV_INST/RE_PHC369_r1336_0_/A -cell BUFX4 -relativeDistToSink 0
  • The following command inserts a repeater with cell BUFX4 on net n123, places it at the given location, and names the new repeater instance ECO_inst: 
    tempus> eco_add_repeater -net n123 -cell BUFX4 -loc {23.45 98.12} -name {ECO_inst}
  • The following command inserts a repeater with cell BUFX4 at a relative distance of 0.3 from the sink terminal of the two-pin net n123:
    tempus> eco_add_repeater -net n123 -cell BUFX4 -relativeDistToSink 0.3

  • The following commands add one instance of inverter INVX1 after every 50 um distance, starting from the net’s driver (polarity of some or all sinks may get reversed when odd number of instances are added):
    set_db eco_check_logical_equivalence false
    eco_add_repeater -net n123 -cells INVX1 -spread_distance 50

  • The following commands add one instance of inverter INVX1 after every 50 um distance, starting from the net’s driver, and if required, one instance of this inverter at a sink to preserve its polarity:
    set_db eco_check_logical_equivalence true
    eco_add_repeater -net n123 -cells INVX1 -spread_distance 50

  • The following command adds 10 instances of buffer BUFX1, equi-distant from each other, such that only the specified sinks are buffered:
    eco_add_repeater -pins {sink1 sink3} -cells BUFX1 -spread_count 10

  • The following command adds one instance each of buffers BUFX1, BUFX2, BUFX3, and BUFX4, equi-distant from each other, such that all the sinks of this net are buffered [total 4 instances added]:
    eco_add_repeater -net n123 -cells {BUFX1 BUFX2 BUFX3 BUFX4} -spread_count 4

  • The following commands add two instances each of inverters INVX1 and INVX3, and one instance each of buffers BUFX2 and BUFX4, each buffer or inverter equi-distant from each other, such that only the specified sinks are buffered [total 6 instances added]:
    set_db eco_check_logical_equivalence true
    eco_add_repeater -pins {sink1 sink3} -cells {INVX1 BUFX2 INVX3 BUFX4} -spread_count 4

  • The following command adds one instance of buffer BUFX1 after every 50 um distance starting from the net’s driver:
    eco_add_repeater -net n123 -cells BUFX1 -spread_distance 50 -spread_prefix {ab}
    The added instances are named as ab_inst_0, ab_inst_1, …  and the added nets are named as ab_net_0, ab_net_1, …
  • The following command adds four instances of buffer BUFX1, equidistant from each other so that all sinks of the net are buffered:
    eco_add_repeater -net n123 -cells BUFX1 -spread_count 4 -spread_prefix {mn}
    The added instances are named: mn_inst_0, mn_inst_1, …  and the added nets are named as mn_net_0, mn_net_1, …

    Note: The suffix number automatically starts after the last buffer or inverter added earlier.

  • The following command adds the first buffer (BUFFD4BWP)after 20 micron distance from the driver term, and subsequent buffers after 50 micron distance from the previous buffer.
    eco_add_repeater -net iso -cell BUFFD4BWP -spread_distance 50 -first_spread_distance 20
