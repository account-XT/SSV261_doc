check_noise

check_noise 
[-help]
[-all]
[-check_only {receiver_no_propagation_model | receiver_no_dc_tolerence | 
driver_no_current_source_model | driver_no_model}]
[-instance_list string]
[-instance_only {true | false}]
[-model_type {receiver | driver}]
[-pins string]
[-unique {true | false}]
[-verbose]
[-view string]
[ [ > | >> ] filename ] 

Performs several consistency and completeness checks on noise models specified for a design. These checks help to ensure that the right set of models are available for the SI analysis engine to perform cross-talk noise analysis.

The settings from both the set_glitch_threshold and set_annotated_glitch commands are taken into account when the check_noise command is issued. 

Parameters

-help Prints out the command usage.
-all Displays all the debug information.
-check_only {receiver_no_propagation_model | receiver_no_dc_tolerence |
driver_no_current_source_model | driver_no_model}

Checks the warning name. The following warnings are checked:

  • receiver_no_propagation_model: Shows how many design pins are missing the receiver model for propagation.
  • receiver_no_dc_tolerence: Shows how many pins have no DC VH/VL tolerance specified. 
  • driver_no_current_source_model: Shows how many design pins are missing the current source model.
  • driver_no_model: Specifies how many design pins are missing the driver model.
-instance_list string Specifies the names of the instances.
-instance_only {true | false} Prints each instance only once.
-model_type {receiver | driver}

Checks the presence of a valid model type - receiver or driver model. If the specified model is missing, a warning will be issued.

The valid receiver models are the models having vivo tables, such as, CDB, CCSN, ECSMN. The valid driver models are CDB, CCS, ECSM, NLDM, and UDN.
-pins string Specifies the instance pin names.
-unique {true | false} Reports unique cells or pins for each power domain.
-verbose Generates verbose details.
-view string Specifies the view name.
 filename Redirects output to a file.
>>filename Appends to an output file.

Examples

Here are some examples.

  • The following command generates the output as shown below:
    tempus> check_noise -type receiver_model 

    **WARN: (IMPESI-3125): AAE_WARN: The analysis view specified to check_noise is not found or specified. Checking view default_emulate_view_setup. 
    --------------------------------------------------------------------
    CHECK NOISE SUMMARY
    --------------------------------------------------------------------
    Warning Number of Warning
    --------------------------------------------------------------------
    receiver_no_propagation_model 17931
    receiver_no_dc_tolerence 17931

    --------------------------------------------------------------------
    # CHECK NOISE WARNING DESCRIPTIONS:

    # receiver_no_propagation_model: The receiver model for glitch  
    # propagation or ROP is not available, only RIP analysis will be performed.

    # receiver_no_dc_tolerence: The input pin do not have vh/vl dc 
    # tolerence specified in the noise file. Default tolerences will be used.

    -------------------------------------------------------------------
