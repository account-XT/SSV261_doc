distribute_start_clients

distribute_start_clients
[-help]
[-client_nowait]
[-count integer]
[-defer_launch | -minHost integer]
[-no_log]
[-no_logv]
[-outdir string]
[-overwrite]
[-startup_script <string>]

Starts Tempus on distributed clients. This command starts the client processes. It requests LSF or SGE for a machine and starts to create a copy of Tempus on it. These client machines will be given tasks to do by the master machine.

Parameters

-help

Outputs a brief description that includes type and default information for each distribute_start_clients parameter.

For a detailed description of the command and all of its parameters, use the man command: man distribute_start_clients.
-client_nowait

Specifies whether the master machine must wait for all the clients to be launched.

When this parameter is specified, the master machine will continue to process, and will not wait for all the clients to be launched. However, the master will wait until partitioning occurs.

Note: You cannot specify this parameter with the -minHost or -defer_launch parameter.

-count integer

Specifies the number of clients. This parameter is used to set the number of clients when this value is not specified by the set_multi_cpu_usage command.
-defer_launch

Defers the launch of any clients unless the distribute_launch_deferred_clients command is issued explicitly.

Note: This parameter cannot be used with the -minHost parameter.
-minHost integer

Specifies the minimum number of available remote hosts (servers) that can be accepted.
-no_log

Does not allow the software to create a client log file.
-no_logv Does not allow the software to create a verbose client log file.
-outdir string
 Specifies the base name of the client output directory.
-overwrite Overwrites an existing .log file (and associated .cmd and .logv files), and does not add an integer to make the files unique.
-startup_script <string> When specified, the software will source the flowtool file on clients for attribute and object initialization.


Examples

  • The following command starts client processes on 4 distributed clients:
    dsta> distribute_start_clients –count 4 –outdir run1_output_dir
