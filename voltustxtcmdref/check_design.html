check_design

check_design
[-help]
-format {table detail}
-id <string>
[-out_file fileName]
-type {power_intent timing hierarchical pin_assign budget assign_statements place opt cts route signoff all} 
-no_check
-type_3d {db tech_lib netlist power_intent timing place floorplan route all}

Checks that all prerequisites to run all or part of the hierarchical or block implementation flow are met. 

The check_design command checks the preconditions for major flow steps before they are run. You can run these checks standalone using the check_design command. If there are error in the check_design run, the current script will stop.


Some examples of problems that will cause design checks to fail include:

  • Cells used in the design that cannot be legally placed
  • Tracks misaligned with some or all cell pins
  • In advanced processes, power nets that cannot be colored in the expected pattern once cells are placed
  • Cell rows that are unblocked for placement but where pin layers are obstructed
  • Cell rows that are unusable due to orientation and power rail misalignment
  • Cells instantiated in the netlist that have no timing model defined
  • Tracks blocked by power grid spacing constraints
  • Instances not covered by a true timing path in any view
  • ILM model with no clock tree defined
  • No hold fixing cells are specified and delay cells are not usable by default
  • No clock inverters, buffers, clock gates or logic cells are specified and the library cells are not usable by default
  • CTS cannot balance all skew groups without increasing insertion delay
  • There are preserved nets and cells in the clock tree that will violate other constraints because they cannot be resized or buffered.

Parameters 

-help

Prints a brief description that includes the type and default information for each check_design parameter.

For a detailed description of the command and all of its parameters, use the man command:
man check_design.

-format {table detail}

Specifies the table format.

  • table: to print the results in table format.
  • detail: to print the results from check_design using the old style of log file. Basically, this is just a way to let user (if necessary) go back to the old style of log file for

-id <string>

Check violation list (e.g. 'CHKPLC-100').
-type

Specifies the category of the flow to be checked:

  • assign_statements: Performs checks for the netlist for assign statements.
  • power_intent: Performs checks related to MSV setup including power domain/fence checks.
  • timing: Performs checks related to timing setup integrity.            
  • feedthru: Performs checks related to feedthru insertion for partitioning flows.
  • pin_assign: Performs checks related to pin assignment for partitioning flows.
  • budget: Performs checks related to time budgeting for partitioning flows.
  • place: Performs checks related to placement such as PG rail alignment and pin access issues.
  • opt: Performs checks related to optimization such as checks for available cells.
  • cts: Performs checks related to clock tree definition such as constraint targets and route types.
  • route: Performs checks related to routing such as congestion, placement, and pin access issues.
  • signoff: Checks related to the signoff activities including extraction and ECOs.
  • all: Runs all categories.
-no_check

Just echo out all the messages that would be checked, don't do any checks

Do not run the checks but echo the checks that would run per the categories provided by the user

-out_file fileName

Specifies the output report file. Contents dumped to this file are in the Tcl format.

-type_3d

List of 3DIC design categories to check, accepts single & multiple values (one or more categories).
