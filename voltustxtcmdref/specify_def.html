specify_def


specify_def
-help
fileNameList
[-die_instance_name dieinstname]

Specify the name of the DEF file(s). This command can be used in lieu of read_def command for analysis purpose. When you use the specify_def command, the software passes specified DEF files to the power and rail analysis programs for internal processing without loading their physical data in memory. As a result, you will not be able to display and query layout of the design. These programs will only process the necessary data from DEF file(s). The usage of this command is recommended in dynamic power analysis, and static and dynamic rail analysis for large (>5M components) designs with hierarchical DEFs or in general to obtain better performance during analysis. You will be able to save memory and runtime that takes to load design during analysis. Once the analysis is complete, you can subsequently load DEFs in the same or new session using the read_def -specialnets_components <DEFs> command to view design layout and analysis results.

Note that for MSMV design, in order to use specify_def, static power analysis mode will require CPF (Common Power Fomat) that defines logical connectivity of the instances to power nets. If CPF is not available, you can optionally run dynamic power analysis which calculates dynamic as well as static power.

The DEF files must be specified in the top-down order of the design hierarchy, that is, top-level DEF, followed by block-level DEF, and then sub-block DEF. This is illustrated in the following example script:

Example flow script with specify_def:

read_lib -lef <LEFs>
read_lib <timing libs>
read_verilog <verilog file(s)>
set_top_module <design name>
read_sdc <timing constraints>
read_spef -decoupled <signal parasitics file(s)>
specify_def <top.def> <block.def> <sub_block.def>

#----- power calculation -----------------------------#

read_spef -decoupled ../DATA/spef/dma_mac.spef.gz

# Option (-dynamic_only true) available to turn off static power calculation during dynamic power calculation
set_power_analysis_mode -reset
set_power_analysis_mode -method dynamic_vectorless -create_binary_db true -write_static_currents true
set_dynamic_power_simulation -period 14ns -resolution 50ps
set_default_switching_activity -input_activity 0.2 -seq_activity 0.15 -clock_gates_output 2.0 -period 10.0
report_power

#----- rail analysis ----------------------------#

set_rail_analysis_mode -method dynamic -accuracy fast_accurate -power_grid_library { stdcells.cl memories.cl }
set_power_data -reset
set_power_data -format current {dynamic_VDD.ptiavg dynamic_VSS.ptiavg}
set_pg_nets -net VDD -voltage 1.08 -threshold 0.972 -tolerance 0.3
set_pg_nets -net VSS -voltage 0.0 -threshold 0.108 -tolerance 0.3
set_rail_analysis_domain -name allDomains -pwrnets {VDD VDDm} -gndnets VSS
set_power_pads -net VDD -format xy -file ../DATA/vstorm/dma_mac-VDD.ppl
set_power_pads -net VSS -format xy -file ../DATA/vstorm/dma_mac-VSS.ppl
analyze_rail -type domain allDomains

#----- load DEF and view results ----------------------------#

read_def -specialnets_components <top.def> <block.def> <sub_block.def>
start_gui
view_analysis_results


-help

Prints out the command usage. 

-die_instance_name dieinstname


Specifies the die instance name for multi-die analysis. This option is only available in multi-die analysis (set_rail_analysis_mode -die_mode multi-die).

fileNameList

Specifies the DEF filenames but not to load in (string, required).
