analyze_jitter


analyze_jitter
[-help]
[-cycle_interval <integer>]
[-eiv_end_time time]
[-eiv_file file_path]
[-eiv_start_time time]
[-eiv_vdd_vss net_names]
[-enable_spectre_x {true | false}]
[-force_delete_output_dir]
[-from pin_name]
[-from_fall pin_name]
[-from_rise pin_name]
[-levels_combine value]
[-lsf_job_string job]
[-max_spectre_lic value]
[-mode {period cycle_to_cycle time_interval_error backward_compatible}]
[-model_file filename]
[-no_hard_stop_at_to_pins {true | false}]
[-outdir directory_name]
[-run_simulation]
[-skip_stage_fanout value1 value2]
[-spectre spectre_path]
[-spectre_cmd_options options]
[-subckt_file file_path]
[-through through_points]
[-to pin_name]
[ [ > | >> ] ]

Analyzes jitter for the user-defined clocks and calculates clock jitter for all the clock end points or user-defined end points. The analyze_jitter command profiles the cycle-to-cycle EIV values from rail analysis, applies the two worst-case cycle-to-cycle EIV values for two simulations, measures the delta delays for each of the clock tree cells, and computes the effective jitter at the end point.

Parameters


-help

Outputs a brief description that includes type and default information for each analyze_jitter parameter.

For a detailed description of the command and all of its parameters, use the man analyze_jitter command.

-cycle_interval <integer>


Specifies the cycle interval to be considered while selecting the EIV values of each instance for jitter computation. The default value is 1, where all the EIV values are considered for jitter computation.

When ‘N’ is specified, the analyze_jitter command considers only the EIV entries in step size of ‘N’, starting from the value specified by the -start_cycle parameter.

-eiv_end_time time


Specifies the end time of the EIV timing window.

-eiv_file file_path


Specifies the path to the effective instance voltage files for accounting IR Drop in jitter computation.
-eiv_start_time time

Specifies the start time of the EIV timing window.
-eiv_vdd_vss net_names

Specifies the power and ground net name for each EIV file provided in the -eiv_file parameter.
-enable_spectre_x {true | false}

Enable spectreX license checkout when launching spectre.
-force_delete_output_dir

Completely remove the directory given by the user in the Outdir option.
-from pin_name

Creates the spice deck with mesh net starting from the specified from pin.
-from_fall pin_name

Creates the spice deck with mesh net starting from the falling transition of the specified from pin.
-from_rise pin_name

Creates the spice deck with mesh net starting from the rising transition of the specified from pin.
-levels_combine value

Specifies the number of levels above the leaf node from which sub trees are to be created. This parameter specifies the level at which the sub  trees are to be combined. The default value is 0, which indicates that a separate tree will be created for each leaf node. After determining the nodes to be combined together, the tree is broken into smaller trees, and jitter analysis on these smaller trees can be done in parallel.

-lsf_job_string job

Specifies a handle to the farm job for launching the simulation.
-max_spectre_lic value

Specifies the number of Spectre license available to run multiple Spectre instances simultaneously.
-mode {period cycle_to_cycle time_interval_error backward_compatible}

Runs the analyze_jitter command natively - with the specified mode.

Default: period
-model_file filename

Specifies the model file to be included in generated Spice.
-no_hard_stop_at_to_pins {true | false}

When set to false (default mode), the spice deck is generated only for traced paths starting from the -from pin and ending at the -to pin. It does not traverse through the fanout branches that do not lead to the -to specified pin.

When set to true, traversal occurs through the whole fanout cone of the -from pin till it hits a clock pin of a flop, or any stop point specified with the -to parameter.
-outdir directory_name

Specifies the name of the output directory that will contain the generated jitter analysis reports:

  • summary.jitter
  • clock_branch1.jitter
  • clock_branch2.jitter
-run_simulation

Enables path simulation in addition to generating the spice deck.
-skip_stage_fanout value1 value2

Takes two positive integers in the format "N1 N2". When specified, scans up to the N1 stage in the fanin cone of each end point, and skips the segments where a stage is found to have fanout greater than N2.
-spectre spectre_path

Specifies the location of the Spectre version that should be used for simulation. If the path is not specified with this option, the software will check if you have the Spectre location defined in your path.
-spectre_cmd_options options

Specifies the command line options for Spectre.
-subckt_file file_path

Specifies the path of the Spice sub-circuit file that contains the Spice information. This information is necessary to get accurate Spice information.
-through through_points

Creates the spice deck with mesh net going by the -through points.
-to pin_name

Creates the Spice deck with mesh net ending at the specified to pins.
> filename

Redirects the -run_simulation output to the specified file.
>> filename

Appends the -run_simulation output to the specified file.

Examples

  • The following command creates jitter reports for the clock path starting from the i_REC_CLK and places the results directories in the jitter_output directory:
    analyze_jitter -eiv_vdd_vss {VDD VSS} -eiv_file /IRDROP/PD_25C_dynamic_1/Reports/VDD_VSS.win_avg.rpt -model_file /../include.ss -subckt_file /../worst.spi -spectre /icd/flow/MMSIM/MMSIM161/ISR9/lnx86/tools.lnx86/bin/spectre -no_hard_stop_at_to_pins true -outdir jitter_output -from i_REC_CLK -spectre_cmd_options {+aps +spice +mt=8  +postlayout +dcopt  } -lsf_job_string {/grid/sfi/farm/bin/bsub -q rnd -P VOLTUS:16.1:PV:regTest -W 140:00 -R "OSNAME==Linux && OSBIT==64 && (OSREL==EE60||OSREL==EE50)" -Is } -run_simulation -levels_combine 2 -max_spectre_lic 100
