Power Analysis Options

This section lists the PowerMeter options (Power Objects) that do not have an equivalent option in Voltus. PowerMeter uses Power Objects, which indicate the kind of power, the type of method used to calculate the instance-based power consumption, the default for the frequency and voltage, the interconnect parasitic used, the clock specification for the design, and many others. These Power Objects can be included in Voltus using the set_power_include_file command.

  • calCellsToUseWaveEst
  • calCellsToUseWaveEstFile
  • calPinTransitionTime
  • calRailExclude
  • calSwitchingCells
  • rDefaultNetCap
  • rDefaultPinCap
  • rDynamicSwitchAllBuffers
  • rDynamicSwitchAllClockBuffers
  • rDynamicSwitchAllFlops
  • rEnhancedBlackboxMode
  • rEnhancedBlackboxAvg
  • rEnhancedBlackboxMax
  • rIgnoreBidirCap
  • rUseFastestClockDomain
  • rUseLibAdjustTransitionTime
  • rUseUserDefinedCurrent


calCellsToUseWaveEst

pwrMetObj calCellsToUseWaveEstcell_name

Allows the user to force triangular estimation on certain cells, even when the ECSM information for those cells is available.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

cell_name

The name of the cell that will use triangular waveform estimates rather than the enhanced ECSM information in the .lib file.

Example

  • The following example causes PowerMeter to ignore the ECSM extension information for the xor cells:
    chip_Pwr calCellsToUseWaveEst xor


calCellsToUseWaveEstFile

pwrMetObj calCellsToUseWaveEstFilefile_name

Allows the user to force triangular estimation on certain cells, even when the ECSM information for those cells is available.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

file_name

Specifies the file that includes the names of cells that will use triangular waveform estimates rather than the enhanced ECSM information in the .lib file.

Example

  • The following example causes PowerMeter to ignore the ECSM extension information for the cells listed in triangular_file.txt:
    chip_Pwr calCellsToUseWaveEstFile triangular_file.text


calPinTransitionTime


pwrMetObj calPinTransitionTime pin_transition_time_file

You can also specify the name of a file that contains the transition time for specific pins or instances in the design.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

pin_transition_   time_file

Specifies the name of the file containing the transition time for the pins or instances in the design. See "Example" for the format of this file and an example of it.

Note: There are three ways that PowerMeter gets transition times (slews): 1) from TWF, 2) a transition time file (pin_transition_time_file), or 3) a default transition time (rDefaultTransitionTime). Other than TWF where thresholds are given, the slew thresholds for pin transition time file and default transition time will be assumed to be 0 to 100 by default. If rUseLibAdjustTransitionTime switch is on, the slew thresholds will be assumed to be the ones defined in the first liberty (.lib) file.

Note: Any negative transition time read from command file or other input file will generate a fatal error.

Example

  • The following example specifies a pin transition-time file named mydesign.slew:
    ChipPwr calPinTransitionTime mydesign.slew
  • Here is an example of the pin transition-time file:
    VERSION "1.0"

    CREATION "12"

    CREATOR "NOIDEA"

    PROGRAM "power.tcl"

    DIVIDERCHAR "_"

    DELIMITERCHAR "/"

    DESIGN "PG22E2_audclk"

    UNITS "TIME 1ps"

    InstanceName/PinName Max-Rise Max-Fall Min-Rise Min-Fall

    ----------------------------------------------------------

     

    SLOPES ;

    - Logic0/input 0.000000 0.000000 0.000000 0.000000

    - BITCLK 0.519086 0.350941 0.519086 0.350941

    - U123/A 0.519086 0.350941 0.519086 0.350941

    - sm2288_clkdiv_110_clk_reg/Q 0.100453 0.062533 0.100453 0.062533

    - sm2288_clkdiv_111_U70/A 0.291355 0.098510 0.291355 0.098510

    - sm2288_clkdiv_111_U70/B 0.092222 0.070174 0.092222 0.070174

    - sm2288_clkdiv_111_U73/A 0.101057 0.073799 0.101057 0.073799

    END ;

     

    The format of the pin transition-time file is as follows:

    instance_name/pin_name max_rise max_fall min_rise min_fall

    This syntax contains the following parameters:
    • instance_name
      Specifies the name of the instance to which the pin is attached.
    • pin_name
      Specifies the name of the pin.
    • max_rise
      Specifies the value of the maximum rise time.
    • max_fall
      Specifies the value of the maximum fall time.
    • min_rise
      Specifies the value of the minimum rise time.
    • min_fall
      Specifies the value of the minimum fall time.

A separator character is required between the instance and the pin names. If no separator character appears in a pin name, the pin is a top pin.

You must also enter in this file a delimiter character in quotation marks--for example, "/"--and the unit for the rise and fall time. If your design is hierarchical, you must specify a divider character to indicate the levels of hierarchy. You can optionally enter the following:
    • The version number of the program that created the file
    • The date that the file was created
    • The creator of the file
    • The name of the program that created the file
    • The design name

LOADS ;

- plltsmc_audclk/OE 0.073629 NA

- sm2288_clkdiv_111_U76/C 0.010614 NA

- sm2288_clkdiv_111_U76/A 0.005532 NA

- sm2288_clkdiv_111_U76/B 0.006345 NA

END ;


PowerMeter uses only the slew-rate information from the pin transition-time file. It only takes slew information specified on input pins. Information shown above for sm228_clkdiv_110_clk_reg/Q will be ignored. It also does not take information from the LOADS section of the file.

You can generate a pin transition-time file using stand alone Tempus Timing Signoff Solution or in PrimeTime. In Tempus Timing Signoff Solution, use the -Powermeter option of the report_slew command.

See Tempus Timing Signoff Solution manuals for more detail.

In PrimeTime, follow these steps to output the transition times to a file:
  1. Perform a delay or timing calculation before outputting the transition times.
  • Set the correct search path, link the appropriate libraries, and so forth.
  • Invoke PrimeTime by typing the following:
  • pt_shell
  • Use the read_verilog command to read in the Verilog netlist file.
  • Specify the top-level design name with the current_design and link_design commands.
  • Read in the DSPF or SPEF file by using the read_parasitics command.
  • Source the Cadence-provided script called pt_dump_slopes_loads.tcl by using the following command:

source pt_dump_slopes_loads.tcl

This TCL script is available in the toolbox provided with the PowerMeter software.
  • Output the transition times for the nets in the design by issuing the following command:

pt_dump_slopes_loads top_level_design > filename.log

The name of the resulting pin transition-time file is top_level_design.slopes.
  • You can submit this file to PowerMeter by using this TCL syntax:

pwrMetObj calPinTransitionTime top_level_design.slopes

Sometimes PowerMeter may guess that a particular net is a power rail when it is not. For these cases the calRailExclude power object may be used.

Parameters

Specifies the name of the power object. It can be any TCL string.

rail_name

The name of the net that is not a rail.

Example

  • This example specifies that vdd_dummy is not a rail.
    chipPwr calRailExclude vdd_dummy


calSwitchingCells


pwrMetObj calSwitchingCells filename

When you use the vectorless timing-windows-based method of dynamic power-consumption calculation, you can switch all cell types in the design from 0 to 1 or 1 to 0 to observe the impact of simultaneously switching outputs on them. This feature is useful when you want to focus on a particular problem involving different cell types.

You can specify the name of a file that contains the names of all cell types to be switched from 0 to 1 or 1 to 0 and the minimum loading capacitance for each. The instance will be selected for power calculation only when its loading capacitance exceeds the minimum capacitance. See "rDynamicSwitchAllClockBuffers" for the format and an example of this file.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

filename

Specifies the name of the file containing the optional minimum loading capacitance value for each cell type in the design. The instance will be selected for power calculation only when its loading capacitance exceeds the minimum capacitance. See "rDynamicSwitchAllClockBuffers" for information on the format of this file and an example of it.

File Format

The switching cells file is an optional input to PowerMeter for dynamic analysis. It is an ASCII file. Each line is in the following format:

cellname <min_loading_cap_value>

Example

  • The following example specifies a switching cells file called switch_599:
    ChipPwr calSwitchingCells switch_599
  • Switching cells file example
    cakbuf1 20fF

    ff1     15fF

    drv1

The instance will be selected for power calculation only when its loading capacitance exceeds the minimum capacitance.

rDynamicSwitchAllBuffers


pwrMetObj rDynamicSwitchAllBuffers threshold_loading_capacitance

When you use the vectorless timing-windows-based method of dynamic power-consumption calculation, you can direct PowerMeter to switch all buffer cells that have a loading capacitance greater than the specified value and observe the impact.

When this debugging command is issued, only these specified cells are switched during dynamic analysis. rDynamicSwitchAllBuffers only schedules the buffer cells in the design giving user the visibility of the buffers as they switch. Scheduling is still done using the timing window of the buffer pins in TWF.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

threshold_loading_capacitance

Specifies a loading capacitance, in farads, for the buffers, above which PowerMeter switches them from 0 to 1 or 1 to 0. If the threshold value is less than 0.0, the switching feature is considered off.

Example

  • In the following example, PowerMeter switches all buffers whose loading capacitance is greater than 30 femtofarads:
    ChipPwr rDynamicSwitchAllBuffers 30fF


rDynamicSwitchAllClockBuffers


pwrMetObj rDynamicSwitchAllClockBuffers [0|1]

When you use the vectorless timing-windows-based method of dynamic power-consumption calculation, you can switch all clock buffers in the design and observe the impact.

When this debugging command is issued, only these specified cells are switched during dynamic analysis. rDynamicSwitchAllClockBuffers only schedules the clock buffers in the design giving user the visibility of the clock network switching. Scheduling is still done using the timing window of the clock buffer pins in TWF.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

[ 0 | 1 ]

If set to 1, turns off the switching of the clock buffers

If set to 0, turns on the switching of the clock buffers.

This command has no default setting.

Example

  • The following example directs PowerMeter to switch the clock buffers:
    ChipPwr rDynamicSwitchAllClockBuffers 1


rDynamicSwitchAllFlops


pwrMetObj rDynamicSwitchAllFlops threshold_loading_capacitance

When you use the vectorless timing-windows-based method of dynamic power-consumption calculation, you can direct PowerMeter to switch all flip-flops and latches that have a loading capacitance greater than the specified value and observe the impact.

When this debugging command is issued, only these specified cells are switched during dynamic analysis. rDynamicSwitchAllFlops only schedules the flip-flops and latches in the design giving user the visibility of the flip-flop and latches as they switch. Scheduling is still done using the timing window of the flip-flop and latch pins in TWF.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

threshold_loading_capacitance

Specifies a loading capacitance, in farads, for the flip-flops and latches, above which PowerMeter switches them from 0 to 1 or 1 to 0. If the threshold value is less than 0.0, the switching feature is considered off.

This command has no default setting

Example

  • In the following example, PowerMeter switches all flip-flops and latches whose loading capacitance is greater than 20 femtofarads:
    ChipPwr rDynamicSwitchAllFlops 20fF



rEnhancedBlackboxMode

pwrMetObj rEnhancedBlackboxMode [0|1]

To specify whether blackbox propagation takes clock pins and timing arcs into account.

Definitions:

The following definitions are needed for the output activity descriptions in the syntax section below.

  • Blackbox
    A blackbox is any instance that has no functional information. For PowerMeter there are two types of blackbox instances:
    • An instance with only a port view.
    • An instance with a .lib that lacks functional data.
  • Designated clock pin
    A pin on an instance that is designated as a clock because of a .lib clock tag (e.g. clock: true)
  • Propagated clock pin
    A pin on an instance (with or without a .lib) that has no clock tag, but has a clock network propagated to it.
  • Related pin
    An input pin that has a timing arc related to an output pin.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

[ 0 | 1 ]

If set to 0, blackbox propagation does not take clock pins and timing arcs into account.

If set to 1, see behavior described below.

Default is 0.

If rEhancedBlackboxMode is set to 1, the output activity will be as follows:

  • Cell with port view only
    • With a propagated clock pin the output activity will be:
      min (1/2 propagated clock pin activity, highest non-clock input activity)
    • Without a propagated clock pin the output activity will be:
      same as input with highest activity
  • Cell with .lib and timing arcs but no functional information.
    • With a designated clock pin output activity will be:
      min (1/2 designated clock pin activity, highest non-clock related-pin input activity)
    • Without a designated clock pin output activity will be:
      • With a propagated clock pin:
        min (1/2 propagated clock pin activity, highest non-clock related-pin input activity)
      • Without a propagated clock, output activity will be the same as the related pin with the highest activity.
  • Cell with .lib but with no timing arcs or functional information.
    • With a designated clock pin output activity will be:
      min (1/2 designated clock pin activity, highest non-clock input activity.
    • Without propagated clock pin, output activity will be same as the input with highest activity.

If a cell has multiple designated clock pins, the one with the highest activity will be considered to be the clock pin and any other clock pins will be treated as normal inputs. Propagated clock pins have lower priority and will be treated as normal inputs as well.

If a cell has no designated clock pins but multiple propagated clock pins, the propagated clock pin with the highest activity will take precedence. Other propagated clock pins will be treated as normal inputs.

Example

  • The following example specifies that clock pins and timing arcs are taken into account for blackbox propagation:
    chip_Pwr rEnhancedBlackboxMode 1

rUseFastestClockDomain


pwrMetObj rUseFastestClockDomain [ 0 | 1 ]

When using clock domain-based assignments (ChipPwr rNoClockDomains 0)and if a net is assigned to multiple clock domains, the rUseFastestClockDomain setting will determine if the highest or lowest frequency will be used.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

[ 0 | 1 ]

With a value of 0, PowerMeter will use the lowest frequency for clock domain-based activity assignment.

With a value of 1, PowerMeter will use the highest frequency for clock domain-based activity assignment. The default is 1.

This command will be ignored if rNoClockDomains is set to 1.

Note: When the activity of an input signal is unknown (i.e. no input activity from a file such as VCD or TCF), it will use the product of the default input activity and the frequency of the fastest (or slowest) clock associated with any pin connected to the net.

Example

  • The following example specifies that PowerMeter will use the highest frequency for domain-based activity.
    ChipPwr rUseFastestClockDomain 1


rUseLibAdjustTransitionTime

pwrMetObj rUseLibAdjustTransitionTime [0|1]

Provides a way of telling PowerMeter to use the transition threshold from the first .lib.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

[ 0 | 1 ]

When set to 0, PowerMeter will treat slew thresholds as           0-100%.

When set to 1, slews specified by rDefaultTransitionTime and pin transition time file will use thresholds specified in the first .lib.

The default is 0.

Note: For TWF flow, the voltage thresholds given in TWF will be used irrespective of the value of this switch.

Example

  • The following example specifies that the transition threshold should be 0 - 100:
    chip_Pwr rUseLibAdjustTransitionTime 0


rUseUserDefinedCurrent


pwrMetObj rUseUserDefinedCurrent [0|1]

Determines whether PowerMeter uses Enhanced Port or Quick Detailed Views or not.

Parameters


pwrMetObj

Specifies the name of the power object. It can be any TCL string.

[ 0 | 1 ]

If set to 0 enhanced port views are ignored.

If set to 1, enhanced port or quick detailed views take precedence over all other views (including .lib).

The default is 0.

Example

  • The following example tells PowerMeter not to use Enhanced Port views:
    ChipPwr rUseUserDefinedCurrent 0
