Voltus IC Power Integrity Solution Text Command Reference
Product Version 26.10, May 2026

set_voltus_insight_mode

set_voltus_insight_mode
[-help]
[-all_scenario_ranking {wiv | tiv}]
-config filename
[-db_mapping filename]
-domain  name
[-disable_layer filename]
[-groundREFF_threshold value]
[-groundRLRP_threshold value]
[-hier_block_instance  names]
[-hierarchical {true | false}]
[-initialize]
[-input_insight_db database_path]
[-instance_mapping filename]
[-ir_effort {high||medium||low}]
[-master_list {list_of_master_blocks}]
[-master_mapping filename]
[-nParallel value]
[-output_insight_db database_path]
[-path_group {all | reg2reg}]
[-powerREFF_threshold value]
[-powerRLRP_threshold value]
[-scenario_default list]
[-scenario_ranking {wiv | tiv | powerrlrp | powerreff | groundrlrp | groundreff}]
[-skip]
[-timing_effort {high||medium||low}]
[-timing_protection_config filename]
[-violation_input filename]
[-watch_box  filename]
[-watch_inst filename]


Specifies the user-defined settings related to the Voltus InsightAI flow. The command allows you to configure flows for various scenarios, such as differing EIV method, EIV evaluation window, and thresholds for each instance type. Using this command, you can tailor your configurations precisely, ensuring optimal performance for every scenario.

Parameters

-all_scenario_ranking {wiv | tiv}

Specifies that all scenarios are ranked either based on the total number of violations (TIV) or worst violations (WIV).
-help

Outputs a brief description that includes the type and default information for each set_voltus_insight_mode parameter.

For a detailed description of the command and all of its parameters, use the man command man set_voltus_insight_mode.

-config filename


       

(Mandatory) Specifies the name of the configuration file that includes details about the PG network definition, EIV method, EIV evaluation window, list of scenarios, and their setting.

-db_mapping filename


       


Specifies the name of the file that contains the mapping between a scenario and its corresponding rail directories. Each scenario can be mapped to multiple rail directories. 

Following is a snippet of the rail database mapping file (db_mapping.txt):
SCENARIO_1 {RailDB1 RailDB2}
SCENARIO_2 {RailDB1}
-domain  name

(Mandatory) Specifies the name of the power domain.
-disable_layer filename

Specifies the name of the file that contains the list of layers to be disabled or excluded during pre-route and post-route RPG.

The format of the file is:
Layer1
Layer2
Layer3
-groundREFF_threshold value

Specifies that the violation report contains only instances that have values less than the specified ground REFF threshold.    
-groundRLRP_threshold value

Specifies that the violation report contains only instances that have values less than the specified ground RLRP threshold.

-hier_block_instance  names


 

Specifies the list of instances of the master block that are to be repaired or reported.  This parameter is specified with the -hierarchical parameter. When the instances are specified using this parameter, only the specified instances are repaired or reported.

-hierarchical {true | false}


       

Specifies to run the hierarchical repair flows (reinforce_pg, IR-aware placement, and ECO). When this parameter is set to true, you must specify at least one state directory in the configuration file.

Default: false
-initialize

Saves the current power settings before running the Insight repair commands using internal power/rail values. After InsightAI-based analysis, this parameter enables restoration of the original power settings.
-input_insight_db database_path

Specifies the path of the input Voltus InsightAI database.  

After generating the output database using the -output_insight_db parameter (in the <output db>/master directory), the input database specified with -input_insight_db will be one of the master from the output database generation. You can then run reinforce_pg without loading the entire rail database, enabling you to fix issues without reloading the rail result. 

Example:

1st Step: Output Database Generation

set_voltus_insight_mode -config <insight_config> -db_mapping <db_mapping_file> -output_insight_db <output_db>

The database is generated under the directory <output_db>

2nd Step: Insight Database Fixing

set_voltus_insight_mode -config -input_insight_db <input_db>
reinforce_pg –auto_ir_fix postroute
-instance_mapping filename

Specifies the name of the file that contains the mapping between a scenario and its corresponding instance files. Each scenario has its own set of instance files.  Each line in an instance file defines either an instance name or a block instance name.

Following is a snippet of the instance mapping file (instance_mapping.txt):

SCENARIO_1 {instance1.txt instance2.txt}
SCENARIO_2 {instance1.txt}

The content of the 2 instance files is shown below:

instance1.txt
------------
Inst_A*
Inst_B*

instance2.txt
-------------
Inst*
-ir_effort {high||medium||low}

Specifies the effort level for running IR repair. The effort level for IR repair can be set to high, medium, or low. By default, the level is set to high. If there is an impact on Quality of Results (QOR), you may choose to lower the effort level.

Default: high

To achieve optimal results, a balance between IR and timing efforts is crucial. The default setting is high IR and low timing effort, which generally provides the best IR fix rate. However, if there is a degradation in timing, you should increase the timing effort to safeguard it. If the timing continues to degrade even with a high timing effort, then you should reduce the IR effort.
-master_list {list_of_master_blocks}

Specifies the list of master blocks to be reported for IR repair. 
-master_mapping filename

Specifies the name of the file that contains the mapping between a scenario and its corresponding master files. Each scenario has its own set of master files.  Each line in a master file defines one master block.

Following is a snippet of the master mapping file (master_mapping.txt):

SCENARIO_1 {master1.txt master2.txt}
SCENARIO_2 {master1.txt}

The content of the 2 master files is shown below:

master1.txt
-------------
Top

master2.txt
-------------
Super_filter
-nParallel value

Specifies the number of scenarios or databases that are to be analyzed.
-output_insight_db database_path

Specifies the path of the output Voltus InsightAI database.  

After generating the output database using this parameter (in the <output db>/master directory), the input database specified with -input_insight_db will be one of the master from the output database generation. You can then run reinforce_pg without loading the entire rail database, enabling you to fix issues without reloading the rail result. 

Example:

1st Step: Output Database Generation

set_voltus_insight_mode -config <insight_config> -db_mapping <db_mapping_file> -output_insight_db <output_db>

The database is generated under the directory <output_db>

2nd Step: Insight Database Fixing

set_voltus_insight_mode -config -input_insight_db <input_db>
reinforce_pg –auto_ir_fix postroute
-path_group {all | reg2reg}

Specifies which timing paths to protect during reinforce_pg.

  • ALL: Protects all timing paths
  • reg2reg: Protects only register-to-register paths
-powerREFF_threshold value

Specifies that the violation report contains only instances that have values less than the specified power REFF threshold. 
-powerRLRP_threshold value

Specifies that the violation report contains only instances that have values less than the specified ground RLRP threshold. 
-scenario_default list

Specifies the list of default scenarios or databases.

-scenario_ranking {wiv | tiv | powerrlrp | powerreff | groundrlrp | groundreff}

Specifies that the scenario ranking is done for a single scenario. When specified, the ranking is done based on the given parameter.
-skip

Skips user-defined instances specified with -watch_box and -watch_instances.
-timing_effort {high||medium||low}

Specifies the effort level the software uses for timing optimization.  The effort level for timing can be set to high, medium, or low. By default, the level is set to low to ensure best IR fix. If timing degrades, you may choose to increase the effort level.

To achieve optimal results, a balance between IR and timing efforts is crucial. The default setting is high IR and low timing effort, which generally provides the best IR fix rate. However, if there is a degradation in timing, you should increase the timing effort to safeguard it. If the timing continues to degrade even with a high timing effort, then you should reduce the IR effort.
-timing_protection_config filename

Defines timing degradation thresholds per timing view using a configuration file. A template of the configuration file for a design can be generated with get_voltus_insight_mode -timing_protection_config after loading the design database in Innovus.


The following is a snippet from the configuration file:

Global 0.0001
View1 0.0002

This sets a global threshold of 0.0001 ps, with a specific threshold of 0.0002 ps for View1.
-violation_input filename

Enables repair operations based on violation specifications that align with an external signoff tool. This feature allows Innovus to replicate violation magnitudes for individual instances, ensuring consistent repair behavior between the external signoff tool and Innovus while eliminating the need for global threshold adjustments.

You can specify a text file containing a per‑instance violation specification in the following format:
instance_name   threshold(mV)   violating_amount(mV)
Example:    
inst_1  100  35
inst_2  80  20

For instance 1 (inst_1), an external signoff tool detected a 35mV violation against a 100mV threshold. This violation data allows Innovus to perform repairs using the same violation magnitude values reported by the external tool, ensuring consistency between the tools.
-watch_box filename

Specifies a file containing the list of regions, wherein only the instances inside these regions will be reported. You can write multiple regions in the file.

The format of the file is:
{{x1,y1}{x2,y2}}
{{x3,y3}{x4,y4}}
-watch_inst filename

Specifies a file containing the list of instances to be reported for IR repair. You can write multiple instances in the file. 

The format of the file is:
instance_1
Instance_2
