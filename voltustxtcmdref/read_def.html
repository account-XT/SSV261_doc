read_def


read_def
[-help]
<defFile>
[-force_create_phy_inst]
[-keepPinGeometry]
[-preserve_shape]
[-rdl_def def_file]
[-rdl_orientation { N|S|W|E|FN|FS|FE|FW }]
[-rdl_placement {X Y}]
[-read_flat_data dir]
[-skip_pg]
[-skip_signal]
[-top]
[-top_scope]
[-top_scope_ignore_block_internal_nets_on_boundary_path]
[-topcell_orientation { N|S|W|E|FN|FS|FE|FW }]
[-topcell_placement {X Y}]
[-write_flat_data dir]
 
Reads the DEF files. This command can be used to supply hierarchical DEFs to generate a flattened physical database. read_def supports multi-level hierarchy flattening. The command also allows you to read and write floorplan, placement, and routing flat binary files from the specified directory.

The read_def command can read multiple DEF files for the design with multiple levels of hierarchy and display a flattened database as shown below:
read_def top.def block1.def block2.def

When multiple DEFs are passed to read_def, the software flattens all the levels of hierarchical DEFs and displays layout for the design.


All hierarchical DEFs are passed to power and rail analysis without flattening and processed by Power Analysis and Rail Analysis engines separately. The flattened DEF is only used for display of layout in the GUI. The flattened DEF should not be used for analysis.

See Innovus Text Command Reference for information on the defOut command.

The flattened DEF can then be loaded in new session as follows:
read_def top.def block1.def block2.def block3_flat.def

Note: read_lib -lef is required in order to load DEFs. This command should never include LEF definition of the block level partitions. It should only include LEF definition for primitive cells like standard cells, IOs and memories.

Parameters


-force_create_phy_inst

Specifies to force create physical cell instances. By default, the software skips physical instances (like fillers) without the “+ SOURCE DIST” attribute when reading DEF. This parameter considers instances without “+ SOURCE DIST” in DEF as physical instances, and adds them into the netlist during analysis.
-help Outputs the command usage and a brief description about the command parameters.

<defFile>

Specifies the name of the DEF files, starting with the top-level DEF. It is mutually exclusive to the -read_flat_data parameter.
-keepPinGeometry

Specifies to keep pin shapes equivalent to the block pin shapes in the form of special route. This parameter ensures that the pin shapes of all layers in the hierarchical DEF are retained in routing after merge of the hierarchical DEF files.
-preserve_shape

Specifies to prevent creation of symbolic center-line connected routing data and preserve the routing data as-is.
-rdl_def def_file

Specifies to instantiate the RDL instance/DEF at the top level and merge it with the DEF of the top level block being analyzed.
-rdl_orientation { N|S|W|E|FN|FS|FE|FW }

Specifies the orientation of the RDL DEF file.
-rdl_placement {X Y}

Specifies to place the RDL at a given X,Y location (in micron).
-read_flat_data dir

Specifies to read binary flat data files from the specified directory. The flat data directory is generated by the -write_flat_data parameter. This parameter is mutually exclusive to [list_of_DEFs].
-skip_pg Skips the power and ground nets with USE POWER/GROUND attributes when reading the input list of DEF files. This parameter can be used to reduce the memory footprint in the signal electromigration flow.
-skip_signal

Reads PG nets with USE POWER/GROUND attributes in both SPECIALNETS/NETS sections in the input list of DEF files. Skips signal nets when reading [list_of_DEFs].

This parameter is not available with -read_flat_data and -write_flat_data parameters.

-top

Specifies to merge two or more flattened DEF files with the same top cell name.

The -top parameter does not support hierarchical DEF. The hierarchical DEF is read by specifying it directly with the read_def command, as shown below:

read_def {chip_top_routed.def chip_top_floorplan.def block_hierachical_routed.def}
-topcell_placement {X Y}

Specifies to place the top DEF block at a given X,Y location (in micron) with respect to virtual top  (0,0).
-topcell_orientation { N|S|W|E|FN|FS|FE|FW }

Specifies the orientation of the top DEF block.
-top_scope

Reads the top-level nets only, and skips creation of the physical nets. By default (when -top_scope is not specified), the read_def command will create physical nets in the physical database if nets in the SPECIALNETS section do not exist in the database.

This parameter must be used in the top scope signal electromigration flow to skip reading of these physical nets. The read_def -top_scope parameter can be used only after the running the create_top_scope  command.
-top_scope_ignore_block_internal_nets_on_boundary_path

Specifies to ignore the physical layout of the internal nets from the first instance to the first flop on the boundary path for the signal EM checking. If this parameter is used with read_def, you must specify the same parameter with verify_AC_limit. The read_def -top_scope_ignore_block_internal_nets_on_boundary_path parameter can be used only after the running the create_top_scope command.

The read_def -top_scope_ignore_block_internal_nets_on_boundary_path  parameter is mutually exclusive with the -top_scope parameter.
-write_flat_data dir

Specifies the output directory in which the flat data is saved. This parameter is specified with [list_of_DEFs].

Examples

  • The following command reads the compressed DEF file dma_mac_filled.def.gz:
    read_def dma_mac_filled.def.gz
  • The following command reads the two flattened DEF files top_level_flattened_floorplan.def and top_level_flattened_routing.def at the top level:
     read_def -top top_level_flattened_floorplan.def top_level_flattened_routing.def
