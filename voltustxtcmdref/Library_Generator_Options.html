Library Generator Commands

cell_decap_area


cell_decap_area { cell_name_list } cap_value <unit>

This command specifies the amount of area based decoupling capacitance in a cell. This command is used in generating dynamic port or detailed power-grid views. Similar to "cell_decap" command, if only a port view is created for a cell, the capacitance specified by the "cell_decap_area" command is evenly distributed over the taps in the port view. For detailed views this is different than using the "cell_decap" command, in that the capacitance value assigned by using this command will not be used to scale the capacitance value calculated, since it is assumed that the value calculated by Thunder is more accurate.

The capacitance specified will be used for both the POWER and GROUND nets. If there are multiple POWER nets or GROUND nets, this value will be evenly distributed among those nets.

Note: If user wants to specify a decap value for a GENERIC supply net, one must specify it explicitly onto the net. If user specifies the decap value for the cell it will be applied on only the POWER and GROUND net. If the GENERIC supply net existed in the cell, LibGen will issue an INFO message to indicate that the value will not be used for the GENERIC supply net. If the user specifies the decap value for the cell, and only a generic supply net exists in the cell, LibGen will apply that value onto the generic supply net and issue a warning message.

Parameters


cell_name_list

Lists the cell names used to assign a capacitance value. The cell name supports wildcard characters (e.g. * ?).

cap_value

Specifies the amount of area based decoupling capacitance. Default unit is femtofarads per square micron.

unit

For specifying an optional parameter used to specify the unit of length. LibGen will use square "unit" as the area unit internally. Default unit is micron.

Example

  • The following example specifies a decoupling capacitance of 5 femtofarads per square micron for cells starting with letters NTZ:
    cell_decap_area NTZ* 5

cell_decap_area_file


cell_decap_area_file filename

This command specifies the name of a file containing a list of cells and the area based decoupling capacitance value for each.

Parameters


filename

The name of the area based decoupling capacitance file.

Note: If user wants to specify a decap value for a GENERIC supply net, one must specify it explicitly onto the net. If user specifies the decap value for the cell it will be applied on only the POWER and GROUND net. If the GENERIC supply net existed in the cell, LibGen will issue an INFO message to indicate that the value will not be used for the GENERIC supply net. If the user specifies the decap value for the cell, and only a generic supply net exists in the cell, LibGen will apply that value onto the generic supply net and issue a warning message.

File Format

Decoupling capacitance file format

The lines of the area based decoupling capacitance file are as follows:

  • CAP_UNIT unit_in_farads
    The UNIT definition is optional. If no UNIT statement is present at the beginning of the file, all capacitance values not followed by a unit specification are assumed to be in femtofarads.
  • LENGTH_UNIT unit_in_meters
    The LENGTH_UNIT is optional. Default length unit is microns
  • CELL cell_name cap_value
    cell_name specifies the name of the cell. cap_value specifies the amount of area based decoupling capacitance. The default unit is femtofarads per square micron. The cellname can contain wildcard characters(e.g. * ?).

    All capacitance values can be followed by a unit specification. The following units are recognized: millifarads (mF), microfarads (μF), nanofarads (nF), picofarads (pF), femtofarads (fF). If specified this will take priority over the CAP_UNIT specification.

Examples

  • The following example specifies a file named decap_cell_list that contains a list of cells and the area based decoupling capacitance for each.
    cell_decap_area_file decap_cell_list
  • The following examples illustrate the contents of the area based decoupling capacitance file.
    This line in the decoupling capacitance file is optional. It assumes that the default units are femtofarads.

    CAP_UNIT            1.0e-15

    In the next part of the file, the area based decoupling capacitance for Cell_A is 100 femtofarads per square micron.

    CELL            Cell_A        100.00

    The capacitance specified will be used for both the POWER and GROUND nets. If there are multiple POWER nets or GROUND nets, this value will be evenly distributed among those nets.

cell_ground_names

cell_ground_names [cell [cellname+] nets [ground_net_name+} value [supply_value] <bulk>

This command specifies the net names to be used as the ground nets for the named cells and the nominal voltage of those nets. Use this command when any of the generate_*_powerview variables are set to true, that is, when LibGen generates power-grid views.

When you specify the names of cells with cell_ground_names, you must also specify them with cell_power_names. See "cell_power_names" for information on this command.

Note: LibGen only takes nets listed by the cell_ground_names or cell_power_names command as supply nets and treats all other nets as signal nets. This is done even if those nets are listed by the generic_ground_names or generic_power_names commands. If the cell is not in the cell_ground_names or cell_power_names list, LibGen will use LEF and generic_ground_names or generic_power_names settings.

Parameters


cell {cellname+}

Identifies the cell or cells to which the ground net supplies power. No wildcards are allowed for the specification of cell names.

nets {net_name+}

Identifies the ground net or nets that supply power to the named cells. No wildcards are allowed for the specification of net names

value value

Gives the nominal voltage of the ground nets. If you specify the ground net names to use for cells, you must also specify the power net names for those same cells. Refer to "cell_power_names" for more information on the cell_power_names command.

bulk

Indicates that all nets specified by the cell_power_names command be considered bulk nets. No current will be distributed to these nets.

Examples

  • The next example specifies that the gnd ground net supplies a nominal voltage of 0.0 volts to the block_a cell:
    cell_ground_names cell {block_a} net {gnd} value 0.0
  • The next example indicates that the gnd and gnd1 nets supply a nominal voltage of 0.0 volts to the na cell:
    cell_ground_names cell {na} net {gnd gnd1} value 0.0
  • The next example indicates that the gnd_bulk net is a bulk net:
    cell_ground_names cell {na} net {gnd_bulk} value 0.0 bulk

cell_ignore_list

cell_ignore_list {cellname+}

This command lists the cells that LibGen is not to process. LibGen processes any cell specified by the cell_list or cell_list_file command, unless it is specified by the cell_ignore_list or cell_ignore_list_file command.

Parameters


Cellname

Specifies the names of the cells that LibGen is not to process.

Example

  • In the following example, LibGen will process all cells given by the cell_list or cell_list_file command, except the MUX21X05, MUX22, and MUX01FT3 cells:
    cell_ignore_list {MUX21X05 MUX22 MUX01FT3}
  • An example, if you wanted to process all cells in the design except one named mem_blk1, you would put the following lines in the LibGen command file:
    cell_list {*}

    cell_ignore_list {mem_blk1}

Identifies the power net or nets that supply power to the named cells. No wildcards are allowed for the specification of net names.

value supply_value

Gives the nominal voltage of the power net. If you specify the power net names to use for cells, you must also specify the ground net names for those same cells. Refer to "cell_ground_names" for more information on the cell_ground_names command.

cell_supply_names_file

cell_supply_names_file filename

This command specifies the name of the file containing the names of the power and ground nets and their nominal supply values for one or more cells. This file is in ASCII format. Use this command when any of the generate_*_powerview variables are set to true, that is, when LibGen generates detailed power-grid views.

Parameters


filename

The name of the file containing the names of the power and ground nets and their supply values.

File Format

The format of the cell supply names file is as follows.

CELLS {cellname+}

POWER value {net_name+}

GROUND value {net_name+}

GENERIC {net_name+}

  • Use the CELLS keyword, then specify a list of cells that the next POWER and GROUND statements refer to.
  • Use the POWER keyword, then specify a voltage value and a list of net names to be used as the power connections for the previously specified cells.
  • Use the GROUND keyword, then specify a voltage value and a list of net names to be used as the ground connections for the previously specified cells.
  • Use the GENERIC keyword, then specify a list of net names to be used as the generic supply connections which could be connected to either power or ground for the previously specified cells.

The file can contain multiple CELL, POWER, GROUND,and GENERIC statements. No wildcards are allowed for the specification of cell names and net names. LibGen ignores blank lines and lines beginning with the pound sign (#).

Note: If user wants to specify a decap value for a GENERIC supply net, one must specify it explicitly onto the net. If user specifies the decap value for the cell it will be applied on only the POWER and GROUND net. If the GENERIC supply net existed in the cell, LibGen will issue an INFO message to indicate that the value will not be used for the GENERIC supply net. If the user specifies the decap value for the cell, and only a generic supply net exists in the cell, LibGen will apply that value onto the generic supply net and issue a warning message.

Examples

  • The following example identifies the pwrnets.file as the file containing the names of the power and ground nets:
    cell_supply_names_file pwrnets.file


current_region

current_region <PROP [FLAT | HIER]> cell_name net_name layer_name x1 y1 x2 y2 current_value   <cap_value>

current_region cell_name net_name layer_name current_value <cap_value>

This command allows the user to specify an amount of current to be distributed over an area of the power grid.

The input from the current_region_file command and the current_region command will be combined together. See also current_region_file. If there are any conflicts between the commands, the first one specified will be used and a warning will be generated.

The current_region and current_region file will override any values calculated by Thunder/Makedpm. See makedpm chapter of this manual for a discussion on makedpm. The current_region_default will only be used for those cells which are not specified by current_region, current_region_file, or by Thunder/Makedpm.

Parameters


PROP         [FLAT | HIER]

If the keyword FLAT is applied, LibGen will not perform hierarchical tracing for the given net in this cell.

If the keyword HIER is presented, LibGen will perform hierarchical tracing for the given net in this cell. This provides the ability for LibGen to automatically specify a current value to all instances of a cell in the design hierarchy. The assumption is that all of these instances of the cell will consume the same power. This is used with Quick Detailed View generation.

The default is HIER.

cell_name

Specifies the name of the cell. Wildcards can be used in the cell_name.

net_name

Specifies the name of the net. Wildcards can be used in the net_name.

layer_name

Specifies the name of a via or contact layer. Libgen will create a tap current on the conducting layer below this via or contact layer. The tap will be created on the circuit node attached to the via or contact. The value of the current drawn by the tap will be 1/n of the total current assigned to the current region, where n is the number of taps within the current region. The number of taps within a current region is the same as the number of vias or contacts on the specified layer.

The layer_name must be a library layer name. If the layer could not be found, LibGen will issue an error message and exit out. The user must provide a valid layer name for LibGen to run.

If the user specified a valid layer, but LibGen does not find any via in the assigned current region, LibGen will issue a warning message, but the process will still keep going and exit successfully. In this case, user may get a 0 current value for the specified cell.

LibGen will try to attach a current tap onto the conduct layer directly underneath it (which could be regular metal layer, poly layer or diffusion layer). If the conduct layer directly underneath can not be found, LibGen will search for the first metal layer above this via layer (here, the poly layer will not be considered as metal layer), and assign the current tap onto this layer.

If no XTC command file is provided, LibGen requires to use VIA_1 or higher as current region layer since contact layer is part of device forming layers. A LibGen automatically generated XTC command file is not able to handle device forming layers very well because of lack of information. Also, use VIA_1 or higher to reduce the resistor/capacitance count, which will improve the overall performance.

x1 y1 x2 y2

Bounding box coordinates for the region to distribute the current. Values are assumed to be in GDSII coordinate units and will be interpreted according to the scale and precision settings contained in the GDSII file that contains the cell. The default unit of x1 y1 x2 y2 is in database units.

current_value

Amount of current that will get distributed.

cap_value

Optional capacitance value. Default is zero.

Second form of syntax can be used only when there is only one current region specified for a cell. In this case Libgen can automatically use the bounding box of the cell for the region.

Example

The following line specifies a cell called an4_80, a net grd ,and layer CONT. The cell will have 1.0uA of current and 2.0fF of capacitance.

current_region an4_80 gnd CONT 25500 0 28900 2000 1.0uA 2.0fF

current_region_default

current_region_default layer_name current_value <cap_value>

This command provides a default way to create current regions for cells without explicitly listing all the cell and net names by using the current_region or current_region_file commands. The settings provided by this command are only used for cells which do not have more specific information provided by a current_region or current_region_file commands. The current_region_default will also not override any values calculated by Thunder/Makedpm. See makedpm chapter of this manual for a discussion on makedpm.

This command should only be used when the device_recognition_required variable is set to false.

Parameters


layer_name

Specifies the name of a via or contact layer.

The layer_name should be the name of the lowest via or contact layer in the design data.

For each power net of any cell which does not have specific current_region data defined, LibGen will place a current tap with the given values at the bottom node of each resistor on the specified layer.

Note that this is different than the current_region command, where each current tap received 1/n of the value, based on the number of taps being created for the cell.

It is mandatory to specify this parameter when you define multiple contact layers, to avoid any errrors due to layer conflict.

current_value

Amount of current that will get applied to each tap. The current value will be inverted when applied to ground nets in order to keep the polarity correct.

This is optional. It is not needed in lvs-neutral flow because libgen uses thunder calculated current. Not needed in regular spice netlist flow because it uses thunder calculated current and distributes it evenly.

cap_value

Optional capacitance value. Default is zero. If supplied, the full capacitance value will be applied to each current tap created.

Example

  • The following line specifies a current_region_default for layer CONT. Each tap will have 1.0uA of current and 2.0fF of capacitance.
    current_region_default CONT 1.0uA 2.0fF

current_region_file

current_region_file file-name

This command allows the user to specify in a file a list of regions and the amount of current to be distributed within them for the power grid.

The input from the current_region_file command and the current_region command will be combined together. See also current_region. If there are any conflicts between the commands, the first one specified will be used and a warning will be generated.

The current_region and current_region file will override any values calculated by Thunder/Makedpm. See makedpm chapter of this manual for a discussion on makedpm. The current_region_default will only be used for those cells which are not specified by current_region, current_region_file, or by Thunder/Makedpm.

Parameters


file-name

Specifies the name of the file that includes a list of current regions.

Example

  • The following line specifies a current_region_file called adder_currents.
    current_region_file adder_currents
  • The following shows the current_region_file format
    UNIT CURRENT default_unit_in_amps

    UNIT CAPACITANCE default_unit_in_farads

    CELL cell_name

    <PROP [FLAT | HIER]>

    NET net_name

    LAYER layer_name

    [ REGION x1 y1 x2 y2 current_value <cap_value>

    | REGION current_value <cap_value> ]
    • UNIT
      Defines the default scale to be used with the current and capacitance values read from the current region file. These scales apply to any value that is not followed by an explicit unit specification. Valid current values are: A (Amps), mA (miliAmps), uA (microAmps), and nA (nanoAmps). Valid capacitance values are: F(Farads), mF (miliFarads), uF (microfarads), nF (nanofarads), pF (picoFarads), and fF (femtoFarads).
    • CELL cell_name
      This command specifies the name of the cell. All following NET, LAYER, and REGION commands will apply to this CELL until another CELL specification is encountered. Wildcards can be used in the cell_name.
    • <PROP [FLAT | HIER]>
      If the keyword FLAT is applied, LibGen will not perform hierarchical tracing for the given net in this cell.

If the keyword HIER is presented, LibGen will perform hierarchical tracing for the given net in this cell. This provides the ability for LibGen to automatically specify a current value to all instances of a cell in the design hierarchy. The assumption is that all of these instances of the cell will consume the same power.

The default is HIER.
    • NET net_name
      This command specifies that all the LAYER and REGION commands following it apply to the net_name. This stays in effect until another NET or CELL specification is encountered. Wildcards can be used in the net_name.
    • LAYER layer_name
      This command specifies that all the REGION commands following it apply to the layer_name. This stays in effect until another LAYER, NET, or CELL command is encountered.

The layer_name must be a library layer name. If the layer could not be found, LibGen will issue an error message and exit out. The user must provide a valid layer name for LibGen to run.

If the user specified a valid layer, but LibGen does not find any via in the assigned current region, LibGen will issue a warning message, but the process will still keep going and exit successfully. In this case, user may get a 0 current value for the specified cell.
    • REGION x1 y1 x2 y2 current_value <cap_value>
      This command specifies that current values and optionally the capacitance value to be associated with the rectangular region specified by the bounding box (x1 y1 x2 y2).

Current taps will be created at the locations of the vias or contacts specified by the most recent LAYER command. These current taps will be attached to the layer that is below the specified via or contact layer. Coordinate values are assumed to be in GDSII coordinate units and will be interpreted according to the scale and precision settings contained in the GDSII file that contains the cell. The value of the current drawn by each current tap will be 1/n of the value specified for the current region, where n is the number of taps within the current region.

The second variation of the REGION command without the bounding box is valid only if there is only one current region. In this case LibGen can automatically use the bounding box of the cell for the region.

See also current_region for a related command.

  • Example of current_region_file.
    UNIT CURRENT uA

    UNIT CAPACITANCE fF

     

    CELL an4_80

    NET vcc

    LAYER CONT

    REGION 0 14000 28900 17000 3.0 5.0

     

    NET gnd

    LAYER CONT

    REGION 1.5e-2mA


cell_decap


cell_decap cellname cap_value

This command specifies the amount of decoupling capacitance in a cell. This command is used in generating dynamic port or detailed power-grid views.

If only a port view is created for a cell, the capacitance specified by the cell_decap command is evenly distributed over the taps in the port view. If a detailed view is created for this cell, the capacitance values of the taps calculated during the detailed view generation are scaled up or down as necessary so that the total capacitance of all the taps in the cell matches the value specified by this command. For a related command see cell_decap_area.

Parameters


cellname

Specifies the name of the cell.

cap_value

Specifies the amount of decoupling capacitance associated with the cell, in femtofarads.

Note: If user wants to specify a decap value for a GENERIC supply net, one must specify it explicitly onto the net. If user specifies the decap value for the cell it will be applied on only the POWER and GROUND net. If the GENERIC supply net existed in the cell, LibGen will issue an INFO message to indicate that the value will not be used for the GENERIC supply net. If the user specifies the decap value for the cell, and only a generic supply net exists in the cell, LibGen will apply that value onto the generic supply net and issue a warning message.

Example

  • The following example specifies a decoupling capacitance of 5 picofarads for the NTZ3802 cell:
    cell_decap NTZ3802 5pF


derived_layer_list


derived_layer_list {layer_name+}

This command specifies to LibGen the names of any extra derived layers, which are layers generated in XTC as a result of logical operations that XTC performs on the GDS layers. It is not necessary to use this command under normal circumstances, because LibGen automatically generates this data from the layer maps and the file specified by the gds_extractor_command_file variable. Its purpose is to assist in debugging.

Parameters


layer_name

Specifies the names of the extra derived layers.

Example

  • The following line specifies that the DIFF, NIMP, and NDIFF layers are extra derived layers:
    derived_layer_list {DIFF NIMP NDIFF}


discard_detailed_powerview_cell_list

discard_detailed_powerview_cell_list {cellname+}

This command specifies a list of cells for which to delete the detailed power-grid view from the library. A detailed power-grid view is only deleted if an abstract power-grid view, reduced power-grid view, or both are generated for the same cell, whether or not the cell is included in the list. This command is useful if you are concerned about the amount of disk space required for the power-grid view libraries. However, deleting the detailed power-grid views limits your ability to perform electromigration  analysis when you use this library. database_precision


setvar database_precision number

This variable specifies the number of internal database units corresponding to one micron. All coordinates in the cell libraries are stored in 32-bit integers, and the setting of this variable affects the minimum feature size that can be resolved. The default setting of this variable is 10000, which means that 1 micron (1 LEF unit) corresponds to 10000 units in the cell library. Each cell library unit therefore represents 1e-10 meter, or one angstrom.

Some common valid values for the database precision setting, other than the default value of 10000, would be 1000 or 100. The magnitude of the maximum coordinate value in the LEF data multiplied by the factor specified by database_precision must be less than 2,147,483,647. For example, if a maximum LEF coordinate is 248304, a database_precision factor of 1000 would be appropriate, because 248304 X 1000 = 248,304,000, which is less than the maximum value of 2,147,483,647.

Under normal circumstances, you do not need to change the database_precision setting from the default setting. However, for certain applications or if you are designing in lambda units, where 1 LEF unit != 1 micron, you may want to set this variable to another value to prevent internal overflow. It is recommended that you reduce the setting from its default value by factors of 10 as necessary to get the data to fit into the appropriate range, but no further.

If you change the setting of database_precision to a non-default value, you must place the variable near the beginning of the LibGen command file, before any other commands that input coordinate or layout data, such as the source_location_file command or the port_view_current_file command.

Parameters


Number

The data base precision.

It must be a positive number greater than 0

Example

  • The following example sets the number of internal database units corresponding to one micron at 1000:
    setvar database_precision 1000

This variable specifies the name and location of the temporary directory, where LibGen places the temporary library files that it creates. Normally the name of this directory is libname_temp, where libname is the name of the library created. This variable can be useful if the disk space on your machine is running low and you want to put the temporary files at a location other than the default location.

Parameters


directory_name

The name of the temporary directory where LibGen places the temporary library files.

Example

  • In the following example, LibGen places the temporary library files that it creates in the /usr/src5/vs320 directory:
    setvar temp_directory_name /usr/src5/vs320

thunder_command_file

This variable specifies the name of a file that passes additional user commands to Thunder during detailed power-grid view generation. These commands may be needed, for example, when conflicts with the hierarchy separator occur and you need to re-define the hierarchy separator used by Thunder.

use_lef_only_itfnodes


setvar use_lef_only_itfnodes [true|false]

Interface nodes are nodes which connect the top level routing with the cell internal resistor network. This variable controls the algorithm used for interface nodes generation.

Parameters


executable_name

If this variable is true, interface nodes are generated using only the port geometry data from the LEF files. This is done before extraction has been done.

If this variable is false, interface nodes are generated after extraction has been completed. Libgen decides on interface nodes based on the resistor network combining the information from the LEF and GDS files.

Default: true

Example

  • The following example specifies that interface nodes are generated after extraction has been completed.:
    setvar use_lef_only_itfnodes false

use_lef_technology


setvar use_lef_technology [cell_library_name|LEF_file_name]

This variable takes the technology data from one of the libraries in the list of libraries to link or merge other than the first library or from a separate LEF file. Normally LibGen obtains the technology data from the first library in the list of libraries to link or merge. If you use a separate LEF file, you must set up a correct layer map in the LibGen command file corresponding to this LEF file.

This variable is optional when linking or merging libraries with the input_type link_library or input_type merge_library commands, respectively.

Parameters


cell_library_name

Specifies the name of the cell library from which to take the technology data.

LEF_file_name

Specifies the name of the LEF file from which to take the technology data.

Example

  • The following example specifies that LibGen take the technology data from the pgvu_360 cell library:
    setvar use_lef_technology pgvu_360

use_old_lef_parser


setvar use_old_lef_parser [true|false]

This variable determines whether LibGen uses the default parser or a parser that can read LEF files created before version 5.6. If the default parser issues warning messages when you try to process a LEF file created before version 5.6, you can invoke another parser to read the LEF file.

Parameters


[true|false]

If this variable is set to true, LibGen uses a parser that can read a LEF file created before version 5.6.

When this variable is set to false, it uses a parser that cannot read a LEF file created before version 5.6.

The default is false.

Example

  • In this example, LibGen uses a parser that can read a LEF file created before version 5.6:

setvar use_old_lef_parser true
