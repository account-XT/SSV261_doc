Certus Template Scripts

Use the template scripts below to run Certus in different modes:

Script 1 - Certus Distributed Hierarchical Timing Closure - Full Flat Mode

The script below performs distributed hold optimization in full-flat mode and ends with the ECO implementation step. This step performs ECO routing and parasitic extraction for each Certus client, followed by a timing update with the updated parasitics on the timing clients.

set_multi_cpu_usage -localCpu 24 -remoteHost 8 -cpuPerRemoteHost 4
set_distribute_host <your LSF args> -timeOut 10000
set eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set eco_dynamic_view {setup_3v} ; set eco_leakage_view {setup_3v}

File Pointing to all Innovus DBs Opened for ECO

set_eco_opt_mode –distributed_opt_block_restore_file blocks.txt

Loads the STA Sessions on Tempus Clients

distribute_read_design -restore_design all -restore_dir \ TIMING_SESSIONS/ -outdir reports

Sets the Distributed Options for Certus Clients

set_multi_cpu_usage -remoteHost <equal_to_partition_count> \
-cpuPerRemoteHost <value>
set_distribute_host <your LSF args> -timeOut 10000

Starts ECO Clients

start_distributed_eco_clients

Runs Hold Fixing in PBA Mode

eco_opt_design –hold

Performs ecoRoute/extraction and Parasitic Back-annotation

implement_distributed_eco

Collect Final Signoff Timing from Tempus Clients and Save the Final Innovus DB

time_design_signoff
export_distributed_eco -out_dir Final -export_only innovus_dbs

Script 2- Certus Distributed Hierarchical Timing Closure - Inter-partition High Capacity ECO Mode

The script below performs Hold timing closure by enabling existing High capacity ECO for large sub-systems and top level designs. It optimizes the logical inter-partition, meaning that each timing path crosses the boundary of one of the listed partitions. The script ends with the ECO implementation step, which performs ECO routing and parasitic extraction on each Certus client, followed by a timing update with updated parasitics on the timing clients.

set_multi_cpu_usage -localCpu 24 -remoteHost 8 -cpuPerRemoteHost 4
set_distribute_host <your LSF args> -timeOut 10000
set eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set eco_dynamic_view {setup_3v} ; set eco_leakage_view {setup_3v}

File Pointing to all Innovus DBs Opened for ECO

set_eco_opt_mode –distributed_opt_block_restore_file blocks.txt

Reduces the DB around partition-to-partition and between top-and-partition

set_distribute_mmmc_mode -enable_high_capacity_eco
set_eco_opt_mode -inter_partition {blockA blockB}

Loads the STA Sessions on Tempus Clients

distribute_read_design -restore_design all -restore_dir \ TIMING_SESSIONS/ -outdir reports

Sets the Distributed Options for Certus Clients

set_multi_cpu_usage -remoteHost <equal_to_partition_count> \
-cpuPerRemoteHost <value>
set_distribute_host <your LSF args> -timeOut 10000

Starts the Certus Clients

start_distributed_eco_clients

Runs Hold Fixing in PBA Mode

eco_opt_design –hold

Performs ecoRoute/extraction and Parasitic Back-annotations

implement_distributed_eco

Collects Final Signoff Timing from Tempus Clients and Saves the Final Innovus DB

time_design_signoff
export_distributed_eco -out_dir Final -export_only innovus_dbs

Script 3- Distributed Hierarchical Power Reduction - With ECO Implementation and Parasitic Back-annotation Loop

The script below performs Power recovery by enabling existing High capacity ECO for large subsystems and top-level designs. It optimizes the logical inter-partition, meaning that each timing path crosses the boundary of exactly one of the listed partitions. The script does the ECO implementation step, which performs ECO routing and parasitic extraction on each Certus client, followed by a timing update with updated parasitics on the timing clients. Next, the Setup timing recovery using Vth swapping only is performed to address any remaining timing violations that would have resulted from extensive ECO during power optimization.

set_multi_cpu_usage -localCpu 24 -remoteHost 8 -cpuPerRemoteHost 4
set_distribute_host <your LSF args> -timeOut 10000
set eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set eco_dynamic_view {setup_3v} ; set eco_leakage_view {setup_3v}
set_eco_opt_mode –distributed_opt_block_restore_file blocks.txt
set_distribute_mmmc_mode -enable_high_capacity_eco
set_eco_opt_mode -inter_partition {blockA blockB}
distribute_read_design -restore_design all -restore_dir TEMPUS_SESSIONS/ -outdir reports
set_multi_cpu_usage -remoteHost <equal_to_partition_count> \
-cpuPerRemoteHost <value>
set_distribute_host <your LSF args> -timeOut 10000
start_distributed_eco_clients
set_eco_opt_mode -max_slack 1000  
set_eco_opt_mode -allow_multiple_incremental true
set_eco_opt_mode -verbose false
eco_opt_design –power
implement_distributed_eco

Performs Setup Timing Recovery to Fix any Timing Gaps Post ECO Implementation

set_eco_opt_mode –setup_recovery true -max_slack 0
eco_opt_design –setup
