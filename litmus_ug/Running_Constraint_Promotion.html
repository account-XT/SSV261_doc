Running Constraint Promotion

Once the design is initialized and promotion configuration parameters are defined, the actual Constraint Promotion step is triggered using the promote_hierarchical_constraints command. This step performs the core Promotion Analysis, applying user-defined priority ordering, conflict resolution strategies, and evaluating registered block‑level SDCs. The following illustration shows where this operation takes place in the Constraint Promotion Flow:

Constraint Promotion Command

The promote_hierarchical_constraints command supports flexible invocation modes: global promotion, per-block promotion, or per‑constraint‑type promotion. This makes it easy to use for to both full‑chip hierarchical signoff and targeted incremental debugging scenarios.

Command Usage

promote_hierarchical_constraints [-help] \
[-blocks <string>] \
[-instances <string>] \
[-types <string>] \
[> <file>] [>> <file>]

Options

-help

Prints command usage.
-blocks <string> Promotes constraints for specific module(s).
-instances <string> Promotes constraints only for listed instances.
-types <string> Promotes only selected constraint classes.
> <file> Writes the promoted SDC to a specific output file.
>> <file>

Appends to an existing file.

Examples

Promote only selected instances:

promote_hierarchical_constraints -instances {U1 U2}

Promote only clock creation constraints:

promote_hierarchical_constraints -types "create_clock create_generated_clock"

Promote only case analysis settings:

promote_hierarchical_constraints -types set_case_analysis

Write output directly to a file:

promote_hierarchical_constraints > promote.sdc

Root Attributes Controlling Promotion

Root attributes can be used to refine how specific classes of constraints are interpreted during constraint propagation. These attributes are useful when block-level constraints include internal IO delays, loads, or clock structures that may require special handling.

Available Attributes

AttributeDefaultDescription
timing_promote_boundary_path_exceptionstrue Enables promotion of exceptions involving block boundary ports.
timing_promote_in_out_delay_over_combinational_conetrue Allows input/output delays to propagate through combinational logic when promoting constraints.
timing_promote_internal_set_input_delayfalse Controls promotion of set_input_delay inside blocks.
timing_promote_internal_set_output_delayfalse Controls promotion of set_output_delay inside blocks.
timing_promote_set_load_over_combinational_conefalse Enables promotion of load constraints across combinational logic.
timing_disable_promotion_clock_prefixfalse Removes instance name prefixes from promoted clock names if no conflict exists.
timing_promote_clock_to_top_portfalse Allows block‑level clocks to be promoted directly to top-level ports.
timing_disable_promotion_clock_group_prefixfalse

Disables the automatic addition of instance name prefixes to clock group names after promotion.

Example:

Input Block SDC: set_clock_groups -name blk_clk_grp -physically_exclusive -group {CLK} -group {CLK2}

Default: set_db timing_disable_promotion_clock_group_prefix false

Expected Promoted Constraint: set_clock_groups -name blk/blk_clk_grp -physically_exclusive -group [get_clocks {CLK}] -group [get_clocks {CLK2}]

With set_db timing_disable_promotion_clock_group_prefix true

Expected Promoted Constraint: set_clock_groups -name blk_clk_grp -physically_exclusive -group [get_clocks {CLK}] -group [get_clocks {CLK2}]

Typical Use Cases

  • Enabling timing_promote_boundary_path_exceptions ensures correct propagation of false paths or multicycle paths defined on block IO.
  • Disabling prefix removal (timing_disable_promotion_clock_prefix) preserves hierarchical uniqueness in multi‑IP environments.
  • Enabling timing_promote_clock_to_top_port can simplify SoC‑level clock modeling when block clocks directly drive SoC pins.

These options provide low‑level control to enable working with complex or non‑uniform block constraint topologies.
