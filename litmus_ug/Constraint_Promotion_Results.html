Constraint Promotion Results

This stage generates a comprehensive set of diagnostics that describe how each block‑level constraint was interpreted, matched, promoted, or rejected during Promotion Analysis. This enables you to quickly identify mismatches, conflicts, or structural issues. Litmus assigns every examined constraint a CP‑tag, which encodes both the category of the result and additional property‑specific differences where applicable. These tags appear in the promotion report as structured messages.

Interpretation of CP‑Tags

During promotion, Litmus evaluates block constraints against the SoC context. For each constraint, one of the following outcomes is recorded:

CP-CodeMeaning
CP‑<base#> + 0 A match exists, but with property differences (e.g., waveform/period mismatch).
CP‑<base#> + 1 An equivalent constraint already exists at the top level; block constraint is redundant.
CP‑<base#> + 2 Constraint is successfully promoted to the SoC level (missing at top).
CP‑<base#> + 3 Multiple matching candidates found at the top level; ambiguous promotion.
CP‑<base#> + 4 Promotion blocked due to a conflict with an existing top‑level constraint.
CP‑<base#> + 5 Promotion rejected because it impacts objects outside the originating block.
CP‑<base#> + 6 Constraint is skipped (various reasons depending on constraint type and strategy).

Note:

  • CP‑3, CP‑4, and CP‑5 constraints are preserved in their original hierarchical context and written into reports unless overridden by set_constraint_promotion_strategy.
  • Each constraint category (clocks, case analyses, IO delays, exceptions) receives its own CP‑base code.
  • A CP‑x0 message may accompany any category when property-level differences (For example, clock waveform or period) are detected.

Detailed CP‑Tag Scenarios

The following examples illustrate how Litmus applies CP‑tags using simple structural SDC scenarios.

CP +1: Equivalent Constraint Exists at the Top

This scenario occurs when the block defines a constraint that matches an existing top-level constraint.

Top-level SDC:

# top.sdc
create_clock –name clk_0 ..[get_ports clk0]
create_clock –name clk_1 ..[get_ports clk1]
set_case_analysis 0 [get_ports A]

Block SDC:

# B.sdc
create_clock –name foo ..[get_ports B_clk]
set_case_analysis 0 [get_ports B_A]

Final Promoted SDC:

# top.sdc + promoted sdc (final)
create_clock –name clk_0 ..[get_ports clk0]
create_clock –name clk_1 ..[get_ports clk1]
set_case_analysis 0 [get_ports A]

Explanation:

The block’s case analysis matches the top-level intent. Promotion is not necessary.

Tag:

CP-xxx +1

CP +2: Constraint Promoted (Missing at Top)

A block constraint is not present at the top and is promoted.

Top-level SDC:

# top.sdc
create_clock –name clk_0 ..[get_ports clk0]

Block SDC:

# B.sdc
create_clock –name foo ..[get_ports clk]
set_case_analysis 0 [get_ports A]

Final Promoted SDC:

# top.sdc + promoted sdc (final)
create_clock –name clk_0 ..[get_ports clk0]
set_case_analysis 0 [get_ports A]

Explanation:

The block’s set_case_analysis constraint was missing at the top and is promoted.

Tag:

CP-xxx +2

CP +3: Multiple Top-Level Candidates

Promotion is ambiguous because the block's source can map to multiple top-level ports or signals.

Top-level SDC:

# top.sdc
create_clock –name clk_0 ..[get_ports clk0]

Block SDC:

# B.sdc
create_clock –name foo ..[get_ports clk]
set_case_analysis 0 [get_ports A]

Final Promoted SDC:

# top.sdc + promoted sdc (final)
create_clock –name clk_0 ..[get_ports clk0]
set_case_analysis 0 [get_ports U1/out]

Explanation:

The block port A maps to multiple SoC‑level nodes (two or more branches), and Litmus flags the ambiguity.

Tag:

CP-xxx +3

CP +4: Conflict With Top-Level Constraint

Promotion is blocked because the block constraint contradicts an existing top-level constraint.

Top-level SDC:

# top.sdc
create_clock –name clk_0 ..[get_ports clk0]

Block SDC:

# B.sdc
create_clock –name foo ..[get_ports clk]
set_case_analysis 0 [get_ports A]

Final Promoted SDC:

# top.sdc + promoted sdc (final)
create_clock –name clk_0 ..[get_ports clk0]
set_case_analysis 0 [get_ports B1/A]
set_case_analysis 0 [get_ports B2/A]

Explanation:

Promoting the block’s case analysis creates a conflict across two block instances. The constraint remains written in the context of the respective instances.

Tag:

CP-xxx +4

CP +5: Impact on External Objects

Promotion is rejected because applying the constraint at the SoC level incorrectly affects objects or paths outside the originating block.

Top-level SDC:

# top.sdc
create_clock –name clk_0 ..[get_ports clk0]

Block SDC (A.sdc or B.sdc):

# A.sdc
create_clock –name foo ..[get_ports clk]
set_case_analysis 0 [get_ports A]
# B.sdc
create_clock –name foo ..[get_ports clk]

Final Promoted SDC:

# top.sdc + promoted sdc (final)
create_clock –name clk_0 ..[get_ports clk0]
set_case_analysis 0 [get_ports B1/A]

Explanation:

Promoting the constraint alters timing for paths of other block instances. Thus, it is restricted to the specific instance where context is valid.

Tag:

CP-xxx +5
