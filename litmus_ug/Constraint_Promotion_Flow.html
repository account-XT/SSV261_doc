Constraint Promotion Flow

Constraint Promotion in Litmus follows a structured three‑stage progression: Setup, Analysis, and Review to migrate block‑level design constraints to the SoC level. Although promotion is inherently iterative, Litmus minimizes the number of user iterations by enforcing a consistent flow, providing contextual diagnostics, and enabling targeted user inputs only when necessary. The following figure illustrates this flow:

Setup Phase

The Setup phase establishes a stable and unified design context before any constraint processing occurs. During this step, Litmus:

  • Loads the SoC‑level constraints and design data (RTL, netlist, or Innovus database).
  • Registers block/IP‑level SDCs using a consistent hierarchical mechanism.
  • Performs SDC lint checks and structural validation to ensure the design is ready for promotion.
  • Simplifies the ingestion of block and SoC constraints so downstream analysis can occur without ambiguity.

A clean Setup phase reduces downstream iteration and ensures consistent interpretation of constraint intent across all blocks.

Analysis Phase

The Analysis phase performs the actual constraint promotion. Processing occurs in an orderly, block‑by‑block sequence, driven by both tool defaults and optional user configuration. During this phase, Litmus:

  • Iterates through constraint types in a well‑defined order (constants, clocks, IO delays, exceptions).
  • Applies incremental propagation of clocks and constants to establish a stable timing foundation.
  • Categorizes every examined constraint into a promotion outcome using CP‑tags, enabling rapid diagnosis and resolution.
  • Accepts targeted user input, such as defining block priority or specifying promotion strategies, only where conflicts or ambiguities arise.

This stage is intentionally structured to minimize unnecessary iteration while ensuring full transparency into how each constraint is interpreted and promoted.

Review Phase

The Review phase consolidates the results of the Analysis and enables the engineer to quickly assess and finalize the promoted constraint set. Litmus provides:

  • Clean, low‑noise reports organized by constraint type, promotion result, and severity.
  • Both GUI and CLI environments for reviewing CP‑tag annotations, mismatches, and unresolved conflicts.
  • A configurable write_sdc output mechanism that generates a unified, signoff‑ready top‑level SDC (promote.sdc) based on user preferences.

Once reviewed and validated, the resulting SoC‑level SDC becomes the authoritative input for downstream signoff and implementation flows.
