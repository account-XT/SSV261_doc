TCL Command Example for Domain-based Through-Silicon Via Flow

The following is the TCL command example for setting up and running domain-based TSV analysis:


set_power_data -format current -scale 1 {./data/tier1_static_power/static_VDD.ptiavg} -die_instance_name mother_die
set_power_data -format current -scale 1 {./data/tier2_static_power/static_VDD.ptiavg} -die_instance_name daughter_die
set_power_data -format current -scale 1 {./data/tier1_static_power/static_VSS.ptiavg} -die_instance_name mother_die
set_power_data -format current -scale 1 {./data/tier2_static_power/static_GND.ptiavg} -die_instance_name daughter_die

set_rail_analysis_mode 
-method static \
-die_mode multi-die \
-die_instance_name mother_die \
-accuracy hd\
-power_grid_library {./data/libgen/accurate_io_tier1/accurate_ios.cl \
./data/libgen/accurate_std_tier1/accurate_stdcells.cl} \
-report_via_current_direction false 
-read_thermal_map map1.file 

set_rail_analysis_mode 
-method static \
-die_mode multi-die \
-die_instance_name daughter_die \
-accuracy hd \
-power_grid_library {./data/libgen/accurate_std_tier2/accurate_stdcells.cl \
./data/libgen/fast_block_tier2/fast_allcells.cl} \
-report_via_current_direction false
-read_thermal_map map2.file

The -die_mode parameter specifies to perform multi-die analysis and the -die_instance_name parameter specifies the die instance name. You can use the -read_thermal_map parameter to use the distribution temperature defined in the specified thermal map file of each die generated from thermal analysis to do resistance scaling. The set_rail_analysis_mode command parameters are specified for both master and slave die.


set_pg_nets -net VDD -voltage 1.08 -threshold 0.9 -tolerance 0.3 -die_instance_name mother_die -force
set_pg_nets -net VDD -voltage 1.08 -threshold 0.9 -tolerance 0.3 -die_instance_name daughter_die -force
set_pg_nets -net VSS -voltage 0 -threshold 0.12 -tolerance 0.3 -die_instance_name mother_die -force
set_pg_nets -net GND -voltage 0 -threshold 0.12 -tolerance 0.3 -die_instance_name daughter_die -force

set_power_pads -net VDD -format xy -file ./data/VDD_t1.pp -die_instance_name mother_die
set_power_pads -net VDD -format xy -file ./data/VDD_t2.pp -die_instance_name daughter_die
set_power_pads -net VSS -format xy -file ./data/VSS_t1.pp -die_instance_name mother_die
set_power_pads -net GND -format xy -file ./data/GND_t2.pp -die_instance_name daughter_die

c ./data/mother_die.def -die_instance_name mother_die
specify_def ./data/daughter_die.def -die_instance_name daughter_die

Specify these commands for each die instance by specifying the instance name using the -die_instance_name parameter. For example, you can specify the power grid nets, power data, power pad file, and DEF file for each die instance.


set_rail_analysis_domain -name pd -pwrnets "mother_die/VDD daughter_die/VDD" -gndnets "mother_die/VSS daughter_die/GND"

Use the set_rail_analysis_domain command to specify the die name/ net name pairs for power and ground nets in the specified domain.


set_multi_die_analysis_mode -name tsv -die_list {mother_die daughter_die} \
-stacked_die_mapping ./data/pwr.mapping

The pad location file and the bump mapping file support embedded bumps in the hierarchical TSV design flow.

Specify the set_multi_die_analysis_mode command to specify the multi-die analysis type (tsv), list of die instances, and the mapping file containing the connections between the two stacked die.

analyze_rail -type domain -output . pd 
exit
