IR Drop Analysis Setup in Multi-CPU Mode

Multi-CPU support is available in power-grid extraction and matrix solver to perform IR drop analysis. You can use multiple CPUs for static and dynamic analysis when performing domain-based analysis. Dynamic analysis has better run time as compared to static analysis.

Distributed processing in both local and distributed (rsh) modes is supported for extraction and matrix solver. By default, matrix solver uses multi-CPUs on the local machine, that is, it relies on local CPUs on the machine where the job is executed. The number of CPUs used on the local machine is controlled by the set_multi_cpu_usage -localCpu command. For maximum performance, it is recommended that set_multi_cpu_usage -remoteHost is set to number of associated nets in the domain for better load balancing.

To enable distributed solver, you must specify the -enable_distributed_processing_in_solver parameter of the set_rail_analysis_mode command. You can set up the solver to use multiple network hosts using the following distributed processing commands:

set_distribute_host -rsh -add {host1 host2 host2 host2 host3 host3 host3}

set_multi_cpu_usage -localCpu 4

Multiple specification of the same host using the set_distribute_host command will enable the solver to use as many CPUs on that machine. You can enable the distributed solver when peak memory of the analysis exceeds machine memory in the local multi-threaded mode. In the distributed mode, peak memory on the local machine will be reduced as child processes will be executed on network hosts. However, the master thread on the local machine will continue to consume the majority of peak memory even in the distributed mode.

In domain based analysis, extraction jobs for associated nets are distributed across network hosts. The ideal setup for domain based analysis is to use network hosts with multi-CPU for parallel power-grid extraction and matrix solver. Using local mode for domain based analysis will increase memory requirement on the local machine because extraction for all nets will be performed in parallel, for example, the domain with a power and a ground net extracted in local machine in parallel will approximately take twice as much memory on local machine.

The net based analysis should always use the local mode.

Tcl Script for Domain Based IR Drop Analysis

The following is the Tcl script for domain based IR drop analysis:

# Parallel extraction for each net using two remote hosts and 2 CPUs on each host

# Matrix solver is run in parallel using 8 CPUs on local machine

set_distribute_host -rsh -add {pe-opt11 pe-opt12}
set_multi_cpu_usage -localCpu 8 -remoteHost 2 -cpuPerRemoteHost 2s

read_lib -lef <LEF>
read_lib <timing libraries>
read_verilog <verilog netlist>
read_sdc <timing constraints>
read_def -skip_signal <DEFs>

# Use specify_def for better performance

set_power_data -reset
set_power_data \
-format current \
-scale 1 \
{./dynamic_power_allOn/dynamic_VDD.ptiavg \
./dynamic_power_allOn/dynamic_VSS.ptiavg }

set_rail_analysis_mode \
-method dynamic \
-accuracy hd \
-temperature 25 \
-report_msmv_format true \
-save_voltage_waveforms true \
-generate_movies true \
-power_grid_library { \
../lab3_libraries/stdcells_accurate/accurate_stdcells.cl \
../lab3_libraries/memories_accurate/TSDN65LPA1024X32M8F.cl \
../lab3_libraries/memories_accurate/TSDN65LPA128X16M8F.cl}

# Use -reset option to reset previously set power data

set_pg_nets -net VDD -voltage 1.08 -threshold 0.972 -tolerance 0.3
set_pg_nets -net VSS -voltage 0.0 -threshold 0.108 -tolerance 0.3
set_rail_analysis_domain -name core -pwrnets VDD -gndnets VSS

# vsrc names must be unique for all nets in the domain,e.g. vdd1 vdd2,vss1 vss2

set_power_pads -net VDD -format xy -file ../DATA/dma_mac-VDD.ppl
set_power_pads -net VSS -format xy -file ../DATA/dma_mac-VSS.ppl
analyze_rail -type domain core
