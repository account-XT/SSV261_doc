Setting up Native Power-up Analysis using GUI

To set up native power-up analysis, perform the following steps:

  1. Perform library generation of power-gate cells.
  2. Set up and run Dynamic Power Analysis.
  3. Select Power & Rail - Set Rail Analysis Mode.
    The following form appears:
  4. Set Analysis Method as Dynamic.
  5. Set Accuracy.
    XD uses LEF based views, and HD uses GDS based accurate views.
  6. Specify Power-grid library.
  7. If CPF is loaded, select Analysis View.

  8. Select Switched Off Nets to specify a list of nets to be excluded from analysis.

    Switched Off Nets and Block Power Up Net are mutually exclusive.

  9. Select Powering Up Nets. This option takes into account the IR drop effect of always-on nets. You can specify a list of powering up nets. You can select Block Power Up Net to specify a single net for block power-up analysis.

    Powering Up Nets and Block Power Up Net are mutually exclusive.

  10. Specify EM Analysis Models if analyzing Electromigration.

    If you do not specify an Electromigration model file, the software will select Electromigration models from the QRC technology file. You can use the command set_rail_analysis_mode -em_models file to override these settings.

  11. Select Generate Movies. This will provide the ability to view plots over simulation time.
  12. Select the Advanced tab of the Set Rail Analysis Mode form.
  13. Select Generate Boundary Voltage File if using Hierarchical view for the block
  14. Specify GDS for Flip-chip RDL or Full-chip GDS if needed.
  15. Fill in the decap fields as needed.
  16. Click OK or Apply.

Sample Tcl Script for Native Power-up Analysis

The following is the sample Tcl script for native power-up analysis.

Example: Native Power-up Analysis (powering-up nets)

#There is no change in the use model of power-gate library characterization and dynamic power analysis.


You must ensure that you have an accurate Liberty file for the power-gate cell.

#This section covers the example Tcl script to drive the native power-up analysis.

set_distribute_host -local -timeout 300
set_multi_cpu_usage -localCpu 2
read_lib -lef <LEF>
read_lib -max <maximum timing analysis libraries>
read_lib -min <minimum timing analysis libraries>
read_verilog <verilog netlist> 
set_top_module <design name>
read_sdc <timing constraints>
read_def <DEF>
read_spef <RC parasitic files>
set_dynamic_power_simulation -period 60ns
report_power

#Specify names of powering-up rails.

set_power_data -format current ./Dynamic_vectorlessDir/dynamic_VDD.ptiavg
set_power_data -format current ./Dynamic_vectorlessDir/dynamic_VSS.ptiavg
set_power_data -format current ./Dynamic_vectorlessDir/dynamic_VDD_SW1.ptiavg
set_power_data -format current ./Dynamic_vectorlessDir/dynamic_VDD_SW2.ptiavg
set_rail_analysis_mode -method dynamic -accuracy hd -generate_movies false -power_grid_library {Powergate/HEADBUF16MA10TR.cl Powergate/HEADBUF32MA10TR.cl Powergate/memory.cl Powergate/accurate_stdcells.cl} -powering_up_rails {VDD_SW1 VDD_SW2}

# In addition to current files for always-on nets, specify current files for powering-up rails.

set_pg_nets -net VSS -voltage 0 -threshold 0.02 -tolerance 0.3 -force
set_pg_nets -net VDD -voltage 1.1 -threshold 1.08 -tolerance 0.3 -force
set_rail_analysis_domain -name ALL -pwrnets VDD -gndnets VSS -threshold 0.3
set_power_pads -net VDD -format xy -file new_VDD_sources.ppl
set_power_pads -net VSS -format xy -file new_VSS_sources.ppl
analyze_rail -type domain -output Dynamic_rail ALL

View Rush Currents (powering-up nets)

view_dynamic_waveform -type current -instance_name total_current_VDD_SW1\ 
 -waveform_files dynamic_powerup_VDD_SW1_VDD.ptiavg


You must specify the view_dynamic_waveform -instance_name parameter to view the rush current value for a specific instance. The .pti file contains the instance level current and the total current (total_current_<powering_up_rail>) waveforms.

Upon successful completion of rail analysis for rush current analysis, Voltus generates a power-up rush current file and a power-up text based report for the net under the <net_name> directory in the state directory of the power nets.

The software generates a text report file called <powerup_net>_powering_up.report in the <net_name> directory with measurement of turn on time and peak rush current. It highlights the wake-up time of individual power-gates in the design. If any power-gate is not turned on during simulation, it is also highlighted in the report. Example: Native Power-up Analysis (block power-up net)

#There is no change in the use model of power-gate library characterization.


You must ensure that you have an accurate Liberty file for the power-gate cell.

#This section covers the example Tcl script to drive the dynamic IR drop analysis.

read_lib -lef <LEF>
read_lib -typ <typical timing analysis libraries>
read_verilog <verilog netlist> 
set_top_module <design name>
read_sdc <timing constraints>
read_def <DEF>
set_dc_sources <power_net_name> -power -voltage 1 set_dc_sources <ground_net_name> -ground read_spef <RC parasitic files>
set_power_data -format current -repeat 100n dynamic_result_native_powerup/dynamic_VCC_SWITCHED.ptiavg
set_rail_analysis_mode -method dynamic -accuracy hd -generate_movies false -power_grid_library {Powergate/HEADBUF16MA10TR.cl Powergate/HEADBUF32MA10TR.cl Powergate/memory.cl Powergate/accurate_stdcells.cl} -block_powerup_rail VCC_SWITCHED -powerup_sequence_file <file_name>

#Only one power-up rail is supported at a time.

set_dynamic_rail_simulation -start 0ns -stop 100ns
set_pg_nets -net VCC_SWITCHED -voltage 1.0 -threshold 0.95 -tolerance 0.3 -force
set_power_pads -net VCC_SWITCHED -format xy -file /dev/null
analyze_rail -type net -output BLOCKPOWERUP VCC_SWITCHED

In the native power-up analysis flow for a block power-up net, rail analysis of the power-up net is not done.
