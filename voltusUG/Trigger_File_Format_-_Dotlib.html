Trigger File Format - Dotlib

For dotlib-based current characterization, the trigger and stimulus files are automatically generated from an existing dotlib. This flow is applicable only for memory cells. Voltus generates stimuli for the worst power groups (rise_power, fall_power or power) in the specified dotlib. It reads only the internal power groups having the "when" condition and constructs stimulus vectors. Each of the generated stimulus belongs to one of the following groups:

  • pin power based (this group is associated with input pin)
  • arc-based (this group is associated with output pin)

arc-based group without related_pin will be ignored.

The following is the file format of the trigger file:

CURRENT_CHARACTERIZATION_METHOD DOTLIB
DOTLIB_LIST {a list of memory dotlibs files}
MODE_COUNT <specifies the maximum number of modes to be generated. Valid values are either a positive number or `all'. The default value is 4>
MODE_CONFIG_FILE <file_path>
SIM_STOP_TIME <time>
SIM_STEP_SIZE <step_size>

If the dotlib contains arc-based power groups, you must specify MODE_CONFIG_FILE and include the memory_write condition in the memory description file. Otherwise, arc-based power groups will be skipped. The memory description file contains the following information:

  • Signals slew: Specifies slew for signals. These slew values will be used in the case where rise or fall is to be applied on the signal. The slew value specified using this construct takes priority over the slew value saved for the group. The default slew unit in the slews construct is ns. The syntax is as follows:
    slews { <signal_1> <slew_value_1> <signal_2> <slew_value_2> .... }
  • Signals: Specifies signals' active values irrespective of memory_write. The syntax is as follows: signals { <sig_1_name> <active_value> <sig_2_name> <active_value> .... } where <active value> can be H or L
  • Memory write information: Specifies the information required to write data to memory through memory_write block. memory_write { clock <clock_name> <type>, where <type> can be R, F, H or L data_in <data_bus_name> address <address bus name> signal <sig_1 name> <active_value>, where <active value> can be H or L signal <sig_2 name> <active_value>, where <active value> can be H or L .... }

A sample memory description file is as follows:

cell memory1
{
memory_write
{
address A
data_in D
clock CLK R
signal WEN L
signal CEN L
}
slews

{
CLK 0.1
}
signals
{    D[1] H
}
}

Example 1: Dotlib

CURRENT_CHARACTERIZATION_METHOD DOTLIB
DOTLIB_LIST {}
MODE_COUNT all
SIM_STOP_TIME 10ns
SIM_STEP_SIZE 100ps
