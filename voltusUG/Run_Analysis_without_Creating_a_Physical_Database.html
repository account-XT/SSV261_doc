Run Analysis without Creating a Physical Database

Running the hierarchical flattener or restoring a physical database for very large designs (>10M components) can take a long time and significant resources.

Voltus allows you to pass the physical data of the design (DEFs) directly to the power and rail analysis engine without creating a physical database in the memory. The specify_def command allows you to pass DEF(s) directly to the power and rail analysis engines.

Once the analysis is complete, and you want to debug the result in the context of layout, a physical database can be read in the same session using the read_def command.

Tcl Command:

The following is the Tcl script for Voltus Specify Hierarchical Design:

read_lib -lef tech.lef allcells.lef
read_lib stdcells_min.lib memories_min.lib
read_verilog top.v block1.v block2.v
set_top_module top
read_sdc top.sdc
specify_def top.def block1.def block2.def
read_spef top.spef block1.spef block2.spef
read_power_domain -cpf design.cpf

# Perform analysis

set_power_analysis_mode -method static ..
report_power
set_rail_analysis_mode -method static ..
analyze_rail -type domain ALL

# Read physical data

read_def -skip_signal top.def block1.def block2.def

In the specify_def mode, static power calculation does not use the specified DEF. Instead, it only uses the Verilog netlist to calculate power. In case of a single power domain design, there is no impact on accuracy. In the case of an MSMV design with multiple voltage islands, you must provide the CPF file or logical connections of power pins to power nets using the globalNetConnect command to define logical connectivity. Optionally, you can choose to run dynamic power analysis which calculates static power as well. The dynamic power analysis uses DEFs specified by the specify_def command. The static and dynamic rail analysis engines use DEFs specified by the specify_def command as well.
