Release 26.10 Enhancements

The following enhancements have been made.

Timing Analysis Enhancements

Support for Hierarchical Timing Context Analysis

The Tempus hierarchical timing context feature provides top-down analysis techniques to model accurate block boundary constraints from the top hierarchy or top STA environment. Tempus provides a bottom-up (Boundary Models) and top-down (Context Models) hierarchical timing analysis/closure solution to address challenges encountered during timing and glitch analysis/closure of large hierarchical designs. The context models for lower-level modules are generated from top level analysis to perform accurate block level timing and glitch analysis. The context data is generated in a proprietary format and can be read with Tempus only. 

To use this feature, the following setting is required:

set_analysis_mode -analysisType onChipVariation

The context analysis feature is not supported in best-case worst-case (BcWc) timing analysis mode. 

The following features have been added:

New Commands

  • set_timing_context_clock_mapping
  • set_timing_context_view_mapping
  • report_timing_context_clock_mapping
  • compare_timing_context

New Global Variables

  • timing_hierarchical_context_continue_on_top_block_clock_mismatch: Allows loading of the timing context model with unmapped clocks. Default: false
  • timing_enable_hier_context_unmapped_clock_analysis: When set to true, for unmapped block clocks, the software enables timing analysis based on the block SDC constraints set on block ports. Default: false
  • timing_context_port_based_clock_mapping: When set to true, clock mapping is done depending solely on clock property of the top and block clock for each clock and data port separately. Default: false
  • timing_context_apply_port_sdc_exceptions: When set to true, the software will consider path exceptions on block constraints in the hierarchical context flow. Default: false

For more information, refer to "Hierarchical Timing Context Analysis" section in the Tempus User Guide.

Added New Global Variables

The following new global variables have been added:

  • timing_consider_late_arrival_for_ssi_derate: When set to true, the software uses the late arrival time for window overlapping evaluation during simultaneous switching input (SSI) analysis. Default: false
  • timing_enable_hierarchical_get_nets_support: When set to true, the software enables the hierarchical segment support for the get_nets command. Default: false
  • timing_disable_get_clocks_for_current_instance: When set to true, the software disables the existing current_instance command support on the get_clocks command. Default: false

  • timing_ipd_xdomain_path_filtering_threshold: When this global variable is used, the specified threshold (in ns) will be used in the path filtering criteria during native inter-power domain (xdomain) solution. Default: 0.003

Added New timing_spatial_derate_distance_mode Option

By default, spatial derate calculation uses the chip_size mode in GBA, which is conservative. The new arc bounding box mode has been introduced in Tempus STA, which reduces GBA spatial derate pessimism by limiting bounding box calculations to all timing paths through an instance. The reduced GBA-PBA gap and reduced GBA pessimism result in improved PBA runtime.

The following new option has been added to the timing_spatial_derate_distance_mode global variable:

  • arc_bounding_box

You can use this option when the timing_enable_pessimistic_cppr_for_reconvergent_clock_paths global variable is set to true.

Timing Constraint Enhancements

set_path_adjust_group Command Enhancements

The set_path_adjust_group command supports the following edge-specific parameters:

  • -fall: Applies set_path_adjust_group at the falling edge of the signal on the path endpoints.
  • -fall_from <from_list>: Applies set_path_adjust_group at the falling edge of the signal on the from pins.
  • -fall_through <through_list>: Applies set_path_adjust_group at the falling edge of the signal on the through pins.
  • -fall_to <to_list>: Applies set_path_adjust_group at the falling edge of the signal on the to pins.
  • -rise: Applies set_path_adjust_group at the rising edge of the signal on the path endpoints.
  • -rise_from <from_list>:  Applies set_path_adjust_group at the rising edge of the signal on the from pins.
  • -rise_through <through_list>: Applies set_path_adjust_group at the rising edge of the signal on the through pins.
  • -rise_to <to_list>: Applies set_path_adjust_group at the rising edge of the signal on the to pins.

Added New create_generated_clock Parameter

The following create_generated_clock parameter has been added:

  • -preinvert: Inverts the polarity of a master clock at the specified source pin. 

timing_generated_clocks_inherit_ideal_latency Global Variable Enhanced

Earlier, when the set_clock_latency command was used to define network latency for ideal clock mode at intermediate pins of a clock network, Tempus ignored the latency. In this release, the timing_generated_clocks_inherit_ideal_latency global variable has been enhanced to accept Enum values that also allow including the closest applied network latency for ideal inheritance. The following new options have been added:

  • actual_partial_latency_path: Uses the network latency of the master clock asserted closest to the target pin and propagated delays for the path from this point to the assertion point of the generated clock.
  • ideal_partial_latency_path: Uses the network latency of the master clock asserted closest to the target pin and ideal delays for the path from this point to the assertion point of the generated clock.

Note: When the -source parameter is used to specify the latency of a generated clock, the software completely overrides any inherited latency. 

By default, this global variable is set to false.

Added New Parameters

The following parameters have been added:

  •  set_sense -clock_leaf:  When specified, the software propagates clock phases to the specified pin.
  • reset_timing_derate -transition: Resets the transition derate values.

IPD Analysis Enhancements

Enhanced write_ipd_scope Command

Tempus allows the identification of inter-power-domain (IPD) paths with more than two power-domain crossings. The write_ipd_scope command has been enhanced to support multiple power-domain paths during early IPD checks. The following new options have been added to the -early_structural_checks parameter:

  • multiple_pd_data_paths
  • multiple_pd_clock_paths
  • multiple_pd_paths

The following write_ipd_scope command parameters have been added:

  • -include_constraints: Allows to write IPD scope with victim constraints.
  • -include_derates: Allows to write IPD scope with timing derates.

For more information, refer to the Inter Power Domain (IPD) Analysis chapter in the Tempus User Guide. 

Scope Analysis Enhancements

 create_boundary_model Command Enhancements

The following create_boundary_model command parameters have been added:

  • -skip_disabled: Skips tracing of logic through disabled arcs (user or constant disabled) in the boundary model.
  • -include_userpins: Includes the specified pins in the boundary model. No fanin/fanout tracing is performed for the specified pins.
  • -latch_effort_low: Skips tracing of logic through latch aggressors that are not part of the interface logic. The aggressors in the fanout of latch aggressors will use an infinite timing window. By default, the entire fanin cone of latch aggressors is preserved to ensure accurate latency adjustment, which may increase the size of the boundary model.

The following parameters have been removed:

  • -absolute_tolerance
  • -exclude_constraints
  • -include_full_netlist
  • -validate_localCpu
