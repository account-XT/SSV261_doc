Release 26.10 Overview

Release Highlights

Timing Analysis Enhancements

Derate-Based Advanced Multi-Input Switching (AMIS-Derate) Analysis

The new analysis feature, Derate-based AMIS (AMIS-Derate), is now available in this release.  A simulation-based advanced multiple-input switching (AMIS-Simulation) analysis, already available in Tempus previous releases, can model MIS effects on both delay and slew. As a result of modeling MIS effects on slew, enabling AMIS-simulation can be very pessimistic. Due to the detailed simulation performed for each instance, the runtime overhead can be high.

To mitigate these shortcomings, the AMIS-derate feature has been introduced. AMIS-derate pre-characterizes MIS impact on multi-input cells as delay derates for different slew/load combinations and uses these derates in timing analysis. AMIS-derate applies MIS impact only to the base delay component. AMIS-derate maintains accuracy similar to AMIS-simulation and provides better runtime, debuggability, and reporting capabilities.

For more information, refer to "Support for Derate-Based Advanced Multi-Input Switching (AMIS-Derate) Analysis".

Virtual IDX (VIDX) SPEF Support in Tempus 3DIC Analysis

Tempus STA now supports reading VIDX SPEF generated by Quantus. The VIDX SPEF models the capacitance impact between two dies.

GBA Pessimism Reduction Improvements

Arc Bounding Box Mode for Spatial Derates

Spatial derate calculation uses the chip_size mode in GBA, which is conservative. The new arc bounding box mode has been  introduced in Tempus STA, which reduces GBA spatial derate pessimism by limiting bounding box calculations to all timing paths through an instance. The results in reduced GBA-PBA gap and reduced GBA pessimism result in improved PBA runtime.

Improved GBA Waveform Compression

The enhanced GBA waveform compression reduces pessimism in graph-based analysis by refining the transition waveform representation to better reflect true signal behavior. This preserves waveform accuracy while minimizing conservatism. And also results in a reduced GBA-PBA gap.

Hierarchical Flow Enhancements

Interface Timing Context Generation in DSTA 

Tempus now supports timing context generation in DSTA, enabling interface path reporting in hierarchical context analysis. Previously in DSTA, it was limited only to register-to-register path reporting.

Pushdown SDC Support in DSTA

Tempus supports Pushdown SDC generation in DSTA and enables both register-to-register and interface path reporting in hierarchical context analysis.

Boundary Model Generation without Additional Timer Update

Tempus has been enhanced to support boundary models generation without triggering a timer update internally. Previously, boundary models generation implicitly triggered a timer update, resulting in performance overhead. This enhancement is primarily beneficial for hierarchical flows that require both timing context and boundary models generation in the same run.

Runtime and Memory Improvements

Faster update_timing with Selective in-Memory SI Reporting

This enhancement improves the update_timing command performance by optimizing single-CPU runtime and multi-CPU scalability with the set_si_mode -enable_delay_report true setting.

New Advanced SI Analysis

The new advanced SI analysis changes how attacker slews are computed by establishing a signoff accurate base delay calculation before SI analysis begins. This replaces the earlier approach that relied on a fast pre-SI analysis attacker slew computation. Beyond the accuracy benefits, it also offers runtime benefits from enhanced reuse provided by signoff-accurate base iteration.

Accuracy Improvements

Consolidated Delay Calculation Framework

This enhancement in delay calculation aligns key simulation steps within a single, consistent computation framework across timing and SI analysis. By synchronizing these steps, the analysis achieves improved accuracy, greater robustness, and better correlation with SPICE results.

Infrastructure Enhancements

Python Shell Support

In this release, Python Shell is supported in Tempus STA. This can be used for data analysis, visualization, and algorithm development. Python shell can be accessed in two ways:

  • Dedicated Python shell mode: In this mode, the Tempus console is changed into a Python interpreter where Python code can be specified directly. All the Tempus Python commands are available as Python functions.
  • Embedded Python execution (within Tcl): In this mode, blocks of Python code can be inserted within Tcl scripts using the eval_python {} command. This mode can be used to leverage Python's data processing and scripting capabilities for specific tasks in a Tcl-based flow.

Parallel report_timing (PRT) Framework

Tempus STA now supports a robust and flexible framework that allows parallel execution of multiple report_timing commands. This helps to reduce overall reporting runtime when the right set of report_timing commands is specified for PRT execution.
