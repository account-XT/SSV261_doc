Voltus Setup for Power and IR Drop

Clock jitter analysis requires minimum and maximum voltage for each instance in the design. To achieve this, IR drop analysis is run with minimum and maximum activity which translates to min and max power for the design. This power is fed to IR drop analysis to generate min and max voltage for each instance in the design, as shown in the following figure:


The min activity during power analysis is defined by turning off activity of combinational logic and toggling only clock network. This is achieved by setting negligible activity (1%) on primary inputs and output of sequential logic. If the design has gated clock, it should be enabled. Note that specifying 0% activity does not work at this time, as power analysis will revert to default activity of 20% in this case.

The max activity during power analysis is defined as expected average activity on primary inputs and output of sequential logic. In addition, gated clocks are disabled.

Alternately, if VCD is available with low and high activity cycles, it can be specified in Voltus using read_activity_file command with start and stop times. Optionally, you can find high or low activity cycles by profiling VCD file.

The instance voltage file has .iv extension. It is saved under the IR drop results directory, for example, "core_25C_dynamic_1/Reports/VDD_VSS.iv". The .iv and .iv.gif files are located in the Reports folder under the state directory. The instance voltage is determined using power and ground IR drop waveforms inside the switching window of the instance, as shown below. It is also referred to as effective instance voltage.


This file can be read in Tempus/Voltus using update_delay_corner command as discussed in the subsequent sections of clock jitter and skew analysis. The instance voltage can be displayed in the context of layout using the gui_set_power_rail_display command as well.

Example:

read_power_rail_results -rail_directory core_25C_dynamic_1/VDD
gui_set_power_rail_display -plot ivdn

In addition to instance voltage, IR drop waveforms are also stored inside the IR drop results directory, for example, core_25C_dynamic_1/VDD/VDD.ptiavg and VSS/VSS.ptiavg. These voltage waveforms can be used for critical path analysis using SPICE. If dynamic power and IR drop analysis is done using the vector-based method, you may be required to shift these waveforms during critical path analysis using the write_spice_deck command. This will be required to align IR drop waveform with the clock edges of SDC. The IR drop waveform for instance can be viewed using view_dynamic_waveform TCL command in Voltus, as shown below:

view_dynamic_waveform \
-type voltage \
-waveform_files \
{core_25C_dynamic_1/VDD/VDD.ptiavg core_25C_dynamic_1/VSS/VSS.ptiavg} \
-effective_voltage_waveform \
-instance_name inst1


You can use the set_rail_analysis_config -eiv_method {best worst} command to generate min and max instance voltage files within the timing window file in Voltus. The min/max IR drop files are fed into Static Timing Analyzer (STA) to perform clock jitter analysis in Tempus.

To ensure compatibility with Tempus to run jitter analysis, the following command should not be used:

set_rail_analysis_config –report_voltage_drop –eiv_detail_report –eiv_threshold –eiv_max_instance

Sample Tcl Script for Dynamic Analysis at Min and Max Activity in Voltus

The following is an example of Voltus script for the flow:


#######################################################
# Voltus Script 
# Purpose: Dynamic analysis at min and max activity 
# Run

>voltus -files script.tcl 
####################################################### 

# Import design
read_physical -lefs <lef files>
read_libs -min_libs <min libraries>
read_libs -max_libs <max libraries>
read_netlist <verilog netlist> -top <top_module_name>
init_design
read_sdc <timing constraints>
read_def <physical netlist>
read_spef <signal parasitics>

# Power analysis
set_db \
 power_method dynamic_vectorless \
 power_corner max \
 power_write_db true \
 power_write_static_currents true

# dynamic power @low activity
set_default_switching_activity \
 -input_activity 0.01 \
 -sequential_activity 0.01 \
 -clock_gates 1.0 \
 -period 4.0

set_power_output_dir ./dynamic_power_min

report_power

# dynamic power @high activity
set_default_switching_activity \
 -input_activity 0.25 \
 -sequential_activity 0.25 \
 -clock_gates 0.0 \
 -period 4.0

set_power_output_dir ./dynamic_power_max

report_power

# IR drop analysis
set_rail_analysis_config \
 -method dynamic \
 -accuracy hd \
 -write_movies true \
 -power_grid_libraries {stdcells.cl memories.cl}

# Power nets, domain and IR drop threshold
set_pg_nets \
 -net VSS \
 -voltage 0.0 \
 -threshold 0.05 \
 -tolerance 0.3

set_pg_nets \
 -net VDD \
 -voltage 1.0 \
 -threshold 0.95 \
 -tolerance 0.3

set_rail_analysis_domain \
 -domain_name core \
 -power_nets VDD \
 -ground_nets VSS

# Power pad location
set_power_pads \
 -net VDD \
 -format xy \
 -file ../DATA/powerpads/VDD.pp

set_power_pads \
 -net VSS \
 -format xy \
 -file ../DATA/powerpads/VSS.pp

# IR drop anlaysis @min power
set_power_data \
 -format current \
 -scale 1 \
 { dynamic_power_min/dynamic_VDD.ptiavg \
 dynamic_power_min/dynamic_VSS.ptiavg }

report_rail \
 -type domain \
 -output_dir ./dynamic_rail_min \
 core

# IR drop analysis @max power
set_power_data -reset
set_power_data \
 -format current \
 -scale 1 \
 { dynamic_power_max/dynamic_VDD.ptiavg \
 dynamic_power_max/dynamic_VSS.ptiavg }

report_rail \
 -type domain \
 -output_dir ./dynamic_rail_max core

##################### END #######################################
