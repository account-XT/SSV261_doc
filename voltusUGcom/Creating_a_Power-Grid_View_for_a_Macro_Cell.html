Creating a Power-Grid View for a Macro Cell

Macro power-grid views are generated to accurately capture current and capacitance distribution inside the memory, macro, and IO cells. For macro/memory/IO, Voltus generates all the three views: Early, EM, and IR.

The library generation requires GDS and Spice subckt with device X-Y location. The library characterizer simulates the Spice subckt and based on Spice device models it calculates the accurate capacitance and current distribution for the cell. The power net parasitics are extracted down to contact or up to the user-specified via layer, and current taps are snapped to the nearest via location.

If you have a Spice netlist without the device X-Y location, the accurate views will still capture the correct capacitance but it will distribute the total current evenly on the current taps. This could potentially mask the real IRdrop and EM problem inside the cell or result in false violations.

The following procedure describes how to generate a macro cell power-grid library, and the various inputs and outputs of this flow.

Required Input Files

  • Technology LEF
  • Cell LEF
  • Quantus technology file
  • LEFDEF layermap - optional. If you do not specify this file, Voltus will automatically generate it.
  • Spice netlist for the macro cell
  • Spectre file that points to the Spectre models, or Spice models
  • GDS file of the macro

  • GDS layermap

    For macro PGV generation, the input files should contain only one macro definition. That is, each LEF, netlist (Spice or CDL), and GDS file should contain only one macro definition.

Procedure

To create power-grid views for a macro cell, complete the following steps:

  1. Read the LEF file for the cell to be characterized.
    Tcl command:

    read_physical -lefs 
    ../data/lef/tech.lef \
    ../data/lef/pll.lef

  2. Specify the settings for macro cell library characterization through the command line or through the GUI.

    GUI: Select Power & Rail - Set PowerGrid Library Mode.
    In the Advanced tab, you can specify the following:
    • Stop@via: Specifies to stop the extraction of the power-grid network at the specified via layer. VIA_1 is the commonly used layer to create current tap. CONT diffusion contact layer is used when IP is not qualified for EM. Upper layers, such as VIA_2 and VIA_3, are used when IP is qualified for EM and its effect is to be seen at the top level. Higher layer reduces the memory, disk footprint, and run time due to reduced resistor and node count.
    • Current Distribution: Specifies the method of current distribution inside the cell.


    Tcl command:

    set_pg_library_mode \
    -stream_files ../data/gds/pll.gds \
    -ground_pins VSS \
    -cells_file ../data/voltus/macro.list \
    -power_pins {VDD 0.9} \
    -cell_type macros \
    -spice_subckts ../data/netlists/pll.sp \
    -stream_layer_map ../data/voltus/gds.layermap \
    -lef_layer_map ../data/voltus/lefdef.layermap \
    -stop_via CONT \
    -spice_models ../data/netlists/spectre_load.sp \
    -current_distribution propagation \
    -extraction_tech_file ../data/qrc/gpdk090_9l.tch


  3. Generate the output for power-grid library generation through the command line or through the GUI.
    GUI: Select Power & Rail - Generate PowerGrid Library.
    Tcl command:

    write_pg_library -out_dir macro_pgv

The log file will generate the power-grid view generation statistics, as shown in the following log file snippet:

** INFO: (VOLTUS_LGEN-3265):
Power Grid View Generation Statistics:
# Total number of cells: 1
# EARLY view created: 1 (100%)
# IR view created: 1 (100%)
# EM view created: 1 (100%)

Output

The output directory will contain the following information:

File Name

Description

macros_<cellname>.cl

The default name of the macro power-grid library is macros_<cellname>.cl.

Inside the macro Early power-grid views:

  • Power net parasitic is extracted for power-pins only
  • Accurate coupling capacitance between power and ground pins is calculated from spice simulation.
  • "Current Taps" are added to the power-pins
  • No visibility of current distribution and power-grid inside macro cell.

Inside the macro IR power-grid views:

  • Reduced distributed RC for power net and intrinsic capacitance
  • Current Taps added to merged devices in the region with relatively small current consumption (for example, bit cells region in the memory)
  • Complete visibility inside the cell for power-grid and transistor

Inside the macro EM power-grid views:

  • Distributed RC for power net and intrinsic capacitance
  • Current taps for each device’s contact in the design
  • Complete visibility inside the cell for power-grid and transistor

macros_<cellname>.report

A report for the cell's power/ground net containing:

  • Name of power and ground nets, voltage value for power pins
  • Capacitance value which is simulation based
  • Number of taps for the Early/EM/IR views

macros_<cellname>.summary

A report containing the capacitance, the current of analyzed nets, resistors, and the number of current taps and layers for the Early/EM/IR views.

tapSnapReport.txt

A report that gives the detailed information about current assigned to taps/devices. The report allows you to verify the current and capacitance values assigned to each device, and the tap current distribution for each interface node.

The format of the file is:

Cell Name:
Net Name:
Layer Name:
NODE DEVICE(X,Y) NODE(X,Y) CURRENT CAPVALUE TAP NAME SWITCH_NODE(X,Y)
....
nodeId : NODE % of taps connected


Here,

  • Cell Name is the macro cell name
  • Net Name is the power/ground net that supplies power to the macro cell
  • Layer Name is the via layer name. The current taps will be attached to the layer that is below the specified via or contact layer.
  • NODE is the unique node ID
  • DEVICE(X,Y) is the X,Y co-ordinate of the device specified in the netlist file
  • NODE(X,Y) is the X,Y location of the node in GDS. This location is relative to the LEF coordinate space.
  • CURRENT is the current value for the node
  • CAPVALUE is the capacitance value for the node
  • TAP NAME is the name of the device
  • NODE % of taps connected is the % of taps connected to a node. This can be used to determine the list of nodes that are heavily connected.
  • SWITCH_NODE(X,Y) is the X,Y co-ordinate of the switched net connected to the power/ground (PG) net. This column is displayed only if the PG net is connected to a switched net. The switched net will have a separate section for those taps where it is not connected to the PG net.
