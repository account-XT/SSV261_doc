Innovus Mapping File Format

The mapping file from Innovus is a virtual mapping that provides the connections between any 2 stacked die with communication directly between the die (master/slave configuration). Depending on the stacking die configuration, Innovus generates one or more mapping files. For example, if you are stacking 3 die, one on top of each other, Innovus generates 2 mapping files, die1-die2 and die2-die3. Alternatively, if you are stacking two smaller die on top of one large die, Innovus generates a single mapping file, die1-die2/die3.

The following diagram illustrates these two cases:


The format of the mapping file is as follows:


POWER {
<mapping_pair_1> 
<mapping_pair_2> 
… 
<mapping_pair_i>
} 
GROUND {
<mapping_pair_1> 
<mapping_pair_2> 
… 
<mapping_pair_j>
} 
SIGNAL {
<mapping_pair_1> 
<mapping_pair_2> 
… 
<mapping_pair_k>
}

where, <mapping_pair_*> for power means:

<design1> <net_in_design1> <Vsrc_in_design1>
<design2>   <net_in_design2> <Vsrc_in_design12>

The components are separated with a white space or tab. One line has one mapping pair.

<design1> = instName1(cellName1) for one of the die

<net_in_design1> is the name of the power net connected to the power bump in design1

<Vsrc_in_design1> is the name of the power bump in design1

Example

SIGNAL {
(tsv_top) A[0] A[0] mother_die(mother_die) A[0] A[0] 
(tsv_top) A[1] A[1] mother_die(mother_die) A[1] A[1] 
(tsv_top) A[2] A[2] mother_die(mother_die) A[2] A[2] 
(tsv_top) A[3] A[3] mother_die(mother_die) A[3] A[3] 
...................................................... 
daughter_die(daughter_die) test_Q[8] test_Q[8] mother_die(mother_die) test_Q[8] test_Q[8] 
daughter_die(daughter_die) test_Q[9] test_Q[9] mother_die(mother_die) test_Q[9] test_Q[9]
} 
POWER {
daughter_die(daughter_die) VDD frontBump_1 mother_die(mother_die) VDD backBump_320 
daughter_die(daughter_die) VDD frontBump_10 mother_die(mother_die) VDD backBump_311 
daughter_die(daughter_die) VDD frontBump_11 mother_die(mother_die) VDD backBump_310 
................................................... 
daughter_die(daughter_die) VDD frontBump_9 mother_die(mother_die) VDD backBump_312
} 
GROUND {
daughter_die(daughter_die) GND frontBump_26 mother_die(mother_die) VSS backBump_295 
daughter_die(daughter_die) GND frontBump_27 mother_die(mother_die) VSS backBump_294 
...................................................... 
daughter_die(daughter_die) GND frontBump_50 mother_die(mother_die) VSS backBump_271
}
