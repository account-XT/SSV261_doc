Performing Multi-Die Analysis

To perform multi-die analysis, complete the following steps:

  1. Read multi-die design. This step involves importing the design data for the logic (LDIE1 and LDIE2) and interposer dies (IDIE). The -die_instance_name is used to specify the DEF file for each die instance name.

    set_power_def_files $DIE1_DEF -die_instance_name LDIE1
    set_power_def_files $DIE1_DEF -die_instance_name LDIE2
    set_power_def_files $INTERPOSER_DEF -die_instance_name IDIE

  2. Set up rail analysis for each die instance. This step involves defining the rail analysis attributes for the logic and interposer die instances. The rail analysis attributes can be uniquely configured for each die.

    set_rail_analysis_config -method dynamic \…\…\
    -enable_xp true -die_mode 3dic \
    -die_instance_name LDIE1
    set_rail_analysis_config -method dynamic \…\…\
    -enable_xp true -die_mode 3dic \
    -die_instance_name LDIE2
    set_rail_analysis_config -method dynamic \
    -enable_xp true -die_mode 3dic \
    -die_instance_name IDIE
    The -die_instance_name and -die_mode parameters are mandatory for multi-die analysis.

  3. Specify the current files for logic dies. This step involves specifying the location of the current files generated during dynamic power analysis for the logic die instances. This is not required for the interposer die as this die does not consume current.

    set_power_data -format current [glob "./ldie1 /dynamic_*.ptiavg"] -scale 1 -die_instance_name LDIE1
    set_power_data -format current [glob "./ldie2 /dynamic_*.ptiavg"] -scale 2 -die_instance_name LDIE2

  4. Define power nets. This step involves defining the power/ground nets and their attributes for each die instance.

    set_pg_nets -net VDD_AO -force -voltage 1.1 -threshold 1.08 -die_instance_name LDIE1
    set_pg_nets -net VSS -force -voltage 0.0 -threshold 0.12 -die_instance_name LDIE1
    set_pg_nets -net VDD_AO -force -voltage 1.1 -threshold 1.08 -die_instance_name LDIE2
    set_pg_nets -net VSS -force -voltage 0.0 -threshold 0.12 -die_instance_name LDIE2
    set_pg_nets -net VDD_AO -force -voltage 1.1 -threshold 1.08 -die_instance_name IDIE
    set_pg_nets -net VSS -force -voltage 0.0 -threshold 0.12 -die_instance_name IDIE

  5. Specify voltage sources (Power Pad Location File). This step involves specifying the PG net voltage source location file for each die instance. The interposer die's both sides (top/bottom) connect to another die or package design, therefore, its related P/G ports (or bumps) need to be defined in the ploc file.

    set_power_pads -format xy -net VDD_AO -file ../LDIE/PADS/VDD_AO.ploc -die_instance_name LDIE1
    set_power_pads -format xy -net VSS -file ../LDIE/PADS/VSS.ploc -die_instance_name LDIE1
    set_power_pads -format xy -net VDD_AO -file ../LDIE/PADS/VDD_AO.ploc -die_instance_name LDIE2
    set_power_pads -format xy -net VSS -file ../LDIE/PADS/VSS.ploc -die_instance_name LDIE2
    set_power_pads -format xy -net VDD_AO -file ../Interposer/PLOC/Int_VDD_AO.ploc -die_instance_name IDIE
    set_power_pads -format xy -net VSS -file ../Interposer/PLOC/Int_VSS.ploc -die_instance_name IDIE

    The format of the .ploc file is:
    vsrc name X(um) Y(um) LEF/Tech Layer type=vsrc|nonvsrc <R> <C > <L >
    Here,

    • "vsrc": indicates a real voltage source that connects to the ideal voltage source or pin of the package netlist. This is the location where the package is stitched.
    • "nonvsrc": indicates a non-real voltage source that does not connect to an ideal voltage, but is used for connecting to another die's non-real voltage source or to a die's Spice port.

    In the context of the examples given in this document, the LDIE to IDIE connection will be of the type "nonvsrc" and the IDIE to package connection will be of the type "vsrc".

    The following table gives a snippet of the .ploc file types:

    LDIE to IDIE connection .ploc

    IDIE to LDIE (top) and IDIE to package (bottom) .ploc

    LDIE_GND_BUMP1 120.0 60.0 Metal9 type=nonvsrc LDIE_GND_BUMP2 240.0 60.0 Metal9 type=nonvsrc LDIE_GND_BUMP3 120.0 180.0 Metal9 type=nonvsrc LDIE_GND_BUMP4 240.0 180.0 Metal9 type=nonvsrc LDIE_GND_BUMP5 120.0 300.0 Metal9 type=nonvsrc

    BUMP_GND_2 255 75 AP type=nonvsrc BUMP_GND_1 135 75 AP type=nonvsrc BUMP_GND_44 605 622 MB type=vsrc BUMP_GND_43 485 622 MB type=vsrc BUMP_GND_42 245 622 MB type=vsrc

    Here,

    • LDIE-to-IDIE connection .ploc – has a single-layer Metal9 with a connection to the bottom side (interposer) and no connection/stack on the top side. The layer has the type nonvsrc, indicating ploc for connectivity.
    • IDIE to LDIE and IDIE to package .ploc – has 2 layers of ploc, AP and MB. The AP layer has the type nonvsrc indicating ploc for connectivity to the top (LDIE), and the MB layer has the type vsrc indicating ploc for ideal voltage source location to the bottom side (package).
    • The ploc file with types vsrc and nonvsrc can also be applied in the Voltus single-die mode, in which the tool treats vsrc as an ideal voltage source and ignores nonvsrc voltage sources.

    Note: It is recommended to specify the set_rail_analysis_config -enable_multi_die_connectivity_check true parameter to check if the voltage source with type=nonvsrc has a resistance path to any voltage source with type=vsrc inside each die. The purpose is to find out if the connected type vsrc is floating and to ignore this vsrc during rail analysis.

  6.  Import die model (HBM) on die interposer (Optional). This step involves importing the die model on die interposer or on package netlist. When a die A has shared P/G network with a logic die B through an interposer die and wants its effect to be considered during IR drop analysis of die B, you can use the set_die_model command to import the die model of die A.

    set_die_model -spice_model_file../DieModel/core_nportModel.sp.subckt -mapping_file ../DieModel/die_model.map -die_instance_name LDIE3

  7. Specify die instance names and die mapping file.  This step involves specifying the list of die instances with dies in the DEF format. It also specifies the mapping file to define connection between dies (between interposer and logic die). This file provides the information on bump-to-bump mapping (one bump from interposer die and the other bump from logic die) and Voltus will use the connection relationship to build die to die's P/G logical connection for multi-die rail analysis.

    set_multi_die_analysis_mode -analysis_name  multi_die -die_list {LDIE1 LDIE2 IDIE} -stacked_die_mapping_file ../StackMap/bump.map

    The format of the 6-column mapping file is:
    IDIE_INST_NAME(idie_inst_name)     Inet_name     Ibump_name\
    LDIE_INST_NAME(ldie_inst_name)    Lnet_name    Lbump_name

    Here,

    • The first 3 columns are for the interposer die instance name, net name, and bump name(vsrc name), and the last 3 columns are for the logic die instance name, net name, and bump name.
    • The die instance names are written in upper case that is followed by the die instance names specified in the rail TCL for each die instance name.
    • The file is split in two sections, POWER and GROUND.
    • Voltus will read the information about $die_instance_name/$Inet_name/$Ibump_name for die/die power/ground connection.

    The following is a snippet of the mapping file:
    POWER  {
    IDIE(idie) VDD_AO BUMP_PWR_1 LDIE1(ldie1) VDD_AO LDIE_PWR_BUMP1
    IDIE(idie) VDD_AO BUMP_PWR_2 LDIE1(ldie1) VDD_AO LDIE_PWR_BUMP2
    IDIE(idie) VDD_AO BUMP_PWR_3 LDIE1(ldie1) VDD_AO LDIE_PWR_BUMP3
    .... }
    GROUND {
    IDIE(idie) VSS BUMP_GND_1 LDIE1(ldie1) VSS LDIE_GND_BUMP1
    IDIE(idie) VSS BUMP_GND_2 LDIE1(ldie1) VSS LDIE_GND_BUMP2
    ......
    IDIE(idie) VSS BUMP_GND_13 LDIE2(ldie2) VSS LDIE_GND_BUMP1
    IDIE(idie) VSS BUMP_GND_14 LDIE2(ldie2) VSS LDIE_GND_BUMP2
    IDIE(idie) VSS BUMP_GND_15 LDIE2(ldie2) VSS LDIE_GND_BUMP3
    ...}

  8. Specify the package model and the package terminal mapping file. This step involves defining the package and specifying the package terminal mapping file (PTMF format) for die to package connection. In this example, the package netlist will be hooked only to the interposer die. Thus, the mapping should be between the package netlist and the interposer die instance. Therefore, the PTMF file should be in the multi-die mode format having die instance name combined with voltage source name. (Single die mode PTMF will not have any die instance name defined).

    set_package -spice_model_file ../Package/design_single_PinBaseSPICE.ckt -mapping_file ../Package/map.ptmf -sub_circuit_name  design_single_PinBaseSPICE

    The format of the PTMF mapping file is:
    ###PKG to die connection (when in single die mode)
    package_port pin voltage_source
    ##BGA Definition (when in single die mode)
    package_BGA_port power|ground_pin power|ground_net_name
    ###PKG to die connection (when in multi-die mode)
    package_port pin die_inst_name/voltage_source
    ##BGA Definition (when in multi-die die mode)
    package_BGA_port power|ground_pin die_inst_name/power|ground_net_name

    The following is a snippet of the mapping file:
    CD1_BUMP_PWR_19 pin IDIE/BUMP_PWR_19
    CD1_BUMP_PWR_20 pin IDIE/BUMP_PWR_20
    .............
    CD1_BUMP_GND_28 pin IDIE/BUMP_GND_28
    CD1_BUMP_GND_44 pin IDIE/BUMP_GND_44
    .............
    BGA_A2 power_pin IDIE/VDD_AO
    BGA_A4 power_pin IDIE/VDD_AO
    .............
    BGA_A1 ground_pin IDIE/VSS
    BGA_A5 ground_pin IDIE/VSS
    .............

    You can also use the MCP Editor utility to make a die/package connection mapping by importing the package netlist and ploc files before importing to pkg netlist.

    To call the MCP Editor utility through Voltus, you can use the map_die_package command.
    connect_die_package -package_model_file test_pkg.spi \
    -net_pad_file_pair_list {{VDD1 VDD.pp} {VSS VSS.pp }} ALL

  9. Specify package model with the package terminal mapping header inside. This step involves defining the package netlist, the netlist that specifies the package terminal mapping file (PTMF format) header for the die to package connection. In this example, the package netlist will be hooked to the interposer die. The mapping should be between the package netlist and the interposer die instance.

    set_package -spice_model_file ../Package/design_single_PinBaseSPICE_withPTMF.ckt

    The format of the PTMF mapping header in package model is:
    ###PKG to die connection 
    *[Mapping Begin]
    *[Device] Die  #-> Keyword “Die” connect to die voltage source
    *[Component] PKG_Component_defined_in_Sigrity
    *[DieInstance] die_inst_name

    *package_port pin voltage_source

    ##BGA Definition
    *[Device] Board   #-> Keyword “Board” connect to ideal voltage sources.
    *[Component] PKG_Component_defined_in_Sigrity
    *[DieInstance] die_inst_name

    package_BGA_port power_pin|ground_pin PG_net_name

    The following is a snippet of the mapping file:
    *[Mapping Begin]
    *[Device] Die
    *[Component] PKG_InFO
    *[DieInstance] IDIE
    * CD1_BUMP_PWR_19 pin BUMP_PWR_19
    * CD1_BUMP_PWR_20 pin BUMP_PWR_20
    .............
    * CD1_BUMP_GND_26 pin BUMP_GND_26
    * CD1_BUMP_GND_27 pin BUMP_GND_27
    *[Device] Board
    *[Component] PKG
    *[DieInstance] IDIE
    * BGA_A2 power_pin VDD_AO
    * BGA_A4 power_pin VDD_AO
    .............
    * BGA_F2 ground_pin VSS
    * BGA_A3 ground_pin VSS
    *[Mapping End]

  10. Run rail analysis. This step involves running Voltus IR drop analysis on the die side. Note that the power and ground net names specified in set_rail_analysis_domain will be in the $die_instance_name/$net_name format which is different from the single-die mode with only the net name.

    set_rail_analysis_domain -domain_name ALL \
    -power_nets {LDIE2/VDD_AO LDIE1/VDD_AO IDIE/VDD_AO} \
    -ground_nets {LDIE2/VSS LDIE1/VSS IDIE/VSS} 
    report_rail -type domain -output_dir StaticRailResults ALL
