Performing Tempus Power Integrity Analysis

The following procedure describes the various inputs and outputs of the Tempus Power Integrity (PI) analysis flow.

Required Input Files

  • Design data (LEF, timing libraries, netlist, SDC, DEF, SPEF)
  • Technology PGV

Procedure

To perform Tempus PI analysis, complete the following steps:

Step 1: Performing Tempus STA Analysis Using IR Derates

  1. Load the design data.
    Tcl command:

    read_physical -lefs $lefs
    read_mmmc ../design/viewDefinition.tcl
    read_netlist ../design/postRouteOpt.enc.dat/super_filter.v.gz -top super_filter
    init_design
    read_def ../design/super_filter.def.gz


    Tcl command - Snippet of viewDefinition.tcl:

    create_library_set -name LS_wc_1p00 -timing ./standard_cells_1p00_125C.lib
    create_library_set -name LS_wc_0p90 -timing ./standard_cells_0p90_125C.lib ;# This library set will be used to improve interpolation later in the flow
    create_library_set -name LS_wc_0p85 -timing ./standard_cells_0p85_125C.lib
    create_rc_corner -name RC_wc_125 temperature 125

    create_timing_condition –name TC1 –library_set LS_wc_1p00 
    create_timing_condition –name TC2 –library_set LS_wc_0p85
    create_delay_corner -name DC_wc_1p00 -rc_corner RC_wc_125 -timing_condition TC1 
    create_delay_corner -name DC_wc_0p85 -rc_corner RC_wc_125 -timing_condition TC2 
    create_constraint_mode -name CM_wc -sdc_files ./design.sdc

    create_analysis_view -name AV_wc_1p00 -constraint_mode CM_wc -delay_corner DC_wc_1p00 ;# This is the non-derated/non-margined view at 1.0v for IR drop analysis
    create_analysis_view -name AV_wc_0p85 -constraint_mode CM_wc -delay_corner DC_wc_0p85 ;# This is the traditional STA view at 0.85V with voltage margined/derated for IR drop analysis

  2. Specify the SPEF file for signal net parasitic information.
    Tcl command:

    read_spef -rc_corner  RC_wc_125 ../design/postRouteOpt_RC_wc_125.spef.gz

  3. Define the analysis views to be used for setup and hold analysis, and update timing for the design.
    Tcl command:

    set_analysis_view -setup {AV_wc_1p00 AV_wc_0p85} -hold {AV_wc_1p00 AV_wc_0p85}

Step 2:Performing Voltus Power and IR Drop Analysis (EIV DB Generation)

  1. Specify the directory where the power results will be stored.
    Tcl command:

    set_power_output_dir dynVecLessPowerResults

  2. Define the power analysis mode. The Tempus PI analysis flow is applicable only to the dynamic vectorless power calculation method.
    Tcl command:

    set_db \
        power_method                 dynamic_vectorless \
        power_disable_static true \
        power_enable_state_propagation    true \
        power_honor_combinational_logic_on_clock_net false \
        power_report_instance_switching_info all \
        power_grid_libraries { \
            ../data/pgv_dir/tech_pgv/techonly.cl \
            ../data/pgv_dir/stdcell_pgv/stdcells.cl \
            ../data/pgv_dir/macro_pgv/macros_pll.cl \
        } \
        power_enable_tempus_pi true \
        power_ir_derated_timing_view AV_wc_0p85 \
        power_enable_pba_for_tempus_pi true

    The following are the attributes specific to the Tempus PI analysis flow:

    • power_enable_tempus_pi true - specifies to enable the Tempus PI analysis flow.
    • power_ir_derated_timing_view view_name - specifies the name of the timing view used to calculate timing slack and to rank the flops. This attribute must be specified if there are multiple views. 
      The -power_ir_derated_timing_view attribute defines the timing view used to detect the IR-sensitive paths using a lower voltage than the actual analysis. This lower voltage simulates the IR drop for each instance in the design. The software uses this view to prioritize the end-points that need to be prioritized for switching.
    • power_enable_pba_for_tempus_pi true - specifies to enable the Path-Based Analysis (PBA) for slack calculation. By default (false), the Graph-Based Analysis (GBA) is used.

  3. Optional. Define default activities for various points in the design.
    Tcl command:

    set_default_switching_activity -input_activity 0 \

      -period 4.0 -clock_gates_output_ratio 0.5 -sequential_activity 0.2

    The default switching activity for sequential cells (-sequential_activity) in percentage (ratio 0.0 to 1.0) specifies the number of fully expanded data paths that will be scheduled to switch in the Tempus PI flow.

  4. Optional, but recommended. Define the power simulation period and resolution.
    Tcl command:

    set_dynamic_power_simulation -resolution 50ps -period 320ns

    The dynamic power simulation period defines the number of power analysis cycles to be run.

    The user-defined sequential activity per cycle (set_default_switching_activity -sequential_activity) and the total power analysis simulation period (set_dynamic_power_simulation -period) control the number of critical path end-points that will be covered per simulation cycle and the total simulation time. Allowing a larger power simulation period will allow Tempus PI to cover all the end-points.

  5. Run power analysis.
    Tcl command:

    report_power

  6. Define the rail simulation resolution, and specify the location of the binary current files generated through dynamic power analysis (step 5).
    Tcl command:

    set_dynamic_rail_simulation -resolution 50ps
    set_power_data -scale 1 -format current [glob dynVecLessPowerResults/*.ptiavg]

  7. Define the rail analysis mode.
    Tcl command:

    set_rail_analysis_config \
        -method                     dynamic \
        -accuracy                   hd \
        -analysis_view              AV_wc_1p00 \
        -power_grid_libraries { \
            ../data/pgv_dir/tech_pgv/techonly.cl \
            ../data/pgv_dir/stdcell_pgv/stdcells.cl \
            ../data/pgv_dir/macro_pgv/macros_pll.cl \
        } \
        -enable_rlrp_analysis       true \
        -verbosity true \
        -temperature 125 \
        -eiv_eval_window switching \
        -eiv_method {bestavg worstavg}


  8. Optional. If you do not load the CPF file, use the set_pg_nets command to define the power nets in the design, and assign attributes to these nets. Then, use set_rail_analysis_domain to define the power domains.
    Tcl command:

    set_pg_nets -net VDD_AO -voltage 1 -threshold 0.95 -force
    set_pg_nets -net VDD_column -voltage 1 -threshold 0.95 -force
    set_pg_nets -net VDD_ring -voltage 1 -threshold 0.95 -force
    set_pg_nets -net VDD_external -voltage 1 -threshold 0.95 -force
    set_pg_nets -net VSS -voltage 0.0 -threshold 0.05 -force
    set_rail_analysis_domain -domain_name ALL -power_nets { VDD_AO VDD_external } -ground_nets VSS

  9. Define the location of the voltage sources for each power/ground net.
    Tcl command:

    set_power_pads -net VDD_AO -format xy -file ../design/super_filter_VDD_AO.pp
    set_power_pads -net VDD_external -format xy -file ../design/super_filter_VDD_external.pp
    set_power_pads -net VSS -format xy -file ../design/super_filter_VSS.pp

  10. Run rail analysis.
    Tcl command:

    report_rail -output_dir ./dynVecLessRailResults -type domain ALL



    The Voltus console will display rail analysis statistics, as shown in the following snippet:

    Rail Analysis completed successfully.
    Finished Rail Analysis at 19:32:45 02/10/2019 (cpu=0:01:12, real=0:02:33, peak mem=1697.00MB)
    Current Voltus IC Power Integrity Solution resource usage: (total cpu=0:09:48, real=1:06:51, mem=1697.00MB)
    ***Info: Found 70 instances with IR drop violations in design based on eiv_method: Worst and eiv_eval_window: elapse.

Step 3:Performing Tempus IR-Aware STA Using EIV Database (any IR Derates Removed)

  1. Calculate IR-aware slack by specifying the IR analysis output as input to the Tempus run:
    Tcl command:

    update_delay_corner -name DC_wc_1p00 \
                 -timing_condition {TC1 TC2} \
                 -irdrop_data ./dyn_rail_phaseIII/ALL_25C_dynamic_1
    set_analysis_view -setup {AV_wc_1p00} -hold {AV_wc_1p00}
    update_timing -full
    report_timing -max_paths 200000 -retime path_slew_propagation -retime_mode exhaustive > pi_timing.pba.rpt


    The final analysis within Tempus PI is done at the non-derated voltage corner (that is, 1.0V in the viewDefinition.tcl example). Therefore, the AV_wc_1p00 view is selected for analysis, and the corresponding delay corner (DC_wc_1p00) is updated to enable voltage tri-lib interpolation by specifying multiple library sets (-library_set)at various voltages (1.00V, 0.90V and 0.85V).

    The following are the parameters specific to the Tempus PI analysis flow:

    • -irdrop_data directory_name - specifies the IR drop files or directory of files to apply to both the early and late delay calculation for the specified delay corner object.

Step 4: Tempus ECO Fixing

In the 19.11 release, the Tempus PI feature can only identify the IR-sensitive timing critical paths and report timing with IR drop voltages. The ECO fixing of timing violations will be supported in a future release.

Output

The rail output directory will contain the following information:

Directory Name

Description

<domainName>_<temperature>_dynamic_<X>

For each run, an output directory is generated with the default name <domainName>_<temperature>_dynamic_<X>. <domainName> will be replaced with ALL if all domains are to be analyzed (report_rail -output_dir dir -type domain ALL), or with <netName> if a power net is to be analyzed. The output directory contains state directories for each net, such as VDD and VSS.

Each state directory contains the following:

  • results – a file that gives a summary of the rail analysis results for various plots, such as tc (tap current), rc (resistor current), and so on.
  • Reports – a folder that contains a list of useful report files that contain all power-grid integrity data.
  • Auto-generated GIF files of the rail analysis plots



The current work directory contains the timing report:

Directory Name

Description

<timing_report>.rpt

A timing report that provides information about the various paths in the design. The report_timing > <timing_report>.rpt command is used to generate the report and write it to the specified file name. For more information on Tempus commands, refer to Tempus Text Command Reference.
