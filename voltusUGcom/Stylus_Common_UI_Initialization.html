Stylus Common UI Initialization

Initialization is the first step in Stylus Common UI. It is the process of reading timing data, physical data, an HDL/netlist, and power intent. After initialization, the design is in a consistent state, and is ready for manipulation or timing analysis.

There are two main types of initialization possible:

  • MMMC timing (Multi-Corner, Multi-Mode)
  • Physical only

MMMC Timing Initialization (Supported by Innovus, Tempus, Genus, Voltus)

This starts with read_mmmc to load a Multi-Mode Multi-corner Configuration file with all the timing setup data. Physical data is required by Innovus, and can optionally be loaded into Tempus, Voltus, and Genus to support physical flows such as Tempus ECO. Power intent is required for all multi-supply, multi-voltage (MSV) designs. This flow is common to all the tools, and supports all the optimization and analysis flows.

An example initialization script would look like this:

read_mmmc top.mmmc                          #required
read_physical -lef  {tech.lef stdcell.lef}  #optional in Genus, Tempus, Voltus, required for Innovus
read_netlist top.v                          #required 
read_hdl/elaborate                          #Genus only
read_def top.def                            #optional in all tools

#Innovus also allows read_floorplan top.fp
read_power_intent -1801 top.1801            #required for MSV designs
init_design                                 #required
  • read_mmmc will create the library_set, rc_corner, timing_condition, constraint_mode, and analysis_view objects as specified in the MMMC file. It will also load the timing libraries required by the active views from the set_analysis_view command in the MMMC file. The reading of other files like SDC constraints is deferred until init_design. During init_design, only the files required by the active views from the set_analysis_view command are loaded. Timing libraries or constraint files for non-active views are not loaded unless those views are made active with set_analysis_view later in the flow.
  • read_physical is used to load LEF or OA technology data and physical library data. It is required by Innovus and can be loaded in Tempus, Voltus, and Genus to support physical design flows.
  • read_netlist is used to load a Verilog gate-level netlist, or an OA netlist. Genus also allows the usage of read_hdl instead of read_netlist to synthesize an RTL netlist (see the Genus documentation for details).
  • read_def can optionally be used to load an initial DEF file. Innovus also allows read_floorplan to read in a previously saved floorplan file instead of read_def.
  • read_power_intent can optionally be used to load a power intent file (IEEE 1801, or CPF). The power data is incomplete until the binding done with the timing data during init_design. A power intent description in either CPF or IEEE 1801 format is generally required for MSV designs.
  • init_design loads any deferred timing data from read_mmmc, and binds the timing data to the netlist, and binds the analysis_views to any power_domains, if needed. Various consistency checks are done, and after this step the design is ready for use.

Physical Only Initialization (Supported by Innovus only)

Physical data is required. No timing or power intent data is allowed.

A typical initialization script would look like this:

read_libs all.lib                            #required
read_physical -lef {tech.lef stdcell.lef}    #required
read_netlist top.v                           #required. Use -def for DEF netlist.
read_def top.def                             #optional, read_floorplan top.fp is also allowed
init_design                                  #required
  • read_libs will save the file names, but defer reading them until the netlist is read. To configure the physical aware ECO flow of Tempus, use read_physical to add physical library data after read_libs.
  • read_physical is used to load LEF or OA technology data and physical library data. It is required.
  • read_netlist is normally used to load a Verilog gate-level netlist, or an OA netlist. With the -def option, a netlist can be loaded directly from DEF along with placement and routing info, but the netlist is completely flat, with no hierarchy. A DEF netlist is suitable for placement or routing experiments, but is not suitable for any flow that requires timing.
  • read_def can optionally be used to load an initial DEF file after reading a Verilog netlist. You can also use read_floorplan to read in a previously saved floorplan file.
  • init_design does consistency checks, and finishes initializing the design. After this step the design is ready for physical-only usage.
