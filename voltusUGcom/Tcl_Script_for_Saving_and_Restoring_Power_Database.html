Tcl Script for Saving and Restoring Power Database

You can save power databases for incremental power report generation (including TCF output), view power histograms and graphical power plots, without having to re-run power analysis during both the static and dynamic runs. This is applicable for flat or hierarchical designs.


Tcl Script for Generating Power Database

The following is the Tcl script for generating power database


read_physical -lefs
read_libs <timing libraries>
read_netlist <verilog netlist> -top <top module name>
init_design
read_sdc <timing constraints>
read_def <DEFs>

# Use set_power_def_files for better performance

read_spef <RC parasitic files>

#You can choose the method to be dynamic vector-based or static

#The power database will not be generated if power_disable_static is set to true when running either of the dynamic power analyses

set_db power_method dynamic_vectorless power_write_db true -power_db_name Dynamic.db

#Power database name is optional. The default name is power.db

set_dynamic_power_simulation -period 8ns -resolution 50ps
set_default_switching_activity -input_activity 0.2 -sequential_activity 0.1 -period 10.0
report_power

Tcl Script for Restoring Power Database

The following is the Tcl script for restoring power database:

read_db -physical_data new.dat top
read_power_db -file Dynamic.db

# You will be able to view the power histograms once the power database has been restored

# Incremental report generation can be done without re-doing power analysis. The power db can be restored in the same session also. It is important that you should not change any power mode settings because that will re-trigger power analysis.

report_power -out_file restore.rep
report_power -clock_network { all } -out_file Clock.rep
report_power -cell_type { all } -out_file Cell.rep
write_tcf TOP.tcf
