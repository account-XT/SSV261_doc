Run Dynamic Power Analysis and Rail Analysis in Parallel

You can run dynamic power analysis in parallel with rail analysis to improve the overall turnaround time. To run this flow, you must specify the following parameter:

set_rail_analysis_config -report_power_in_parallel

In this usage model, you do not need to modify the power analysis setup. Remove the report_power command and set the –report_power_in_parallel parameter of set_rail_analyis_config to true. The report_rail command will run both dynamic power and rail analysis in parallel. The usage model is given below:

#Power Analysis Setup

set_db power_*...
set_switching_activity ...
read_activity_file ...
set_power ...
set_power_output_dir <dirname>

If set_power_output_dir is not specified, it defaults to the current working directory to look for the required current files.

#Rail Analysis Setup

set_rail_analysis_config –report_power_in_parallel <true|false> ..(default: false) 
set_pg_nets ... 
set_rail_analysis_domain ... 
set_power_pads ...

In this parallel flow, set_power_data <power_file> will be set internally to the auto-generated power data file in the directory specified by the set_power_output_dir command. Therefore, set_power_data <power_file> is not required when -report_power_in_parallel is set to true. If set_power_data <power_file> is still specified, the tool will error out. To run the set_power_data parameters (scale/offset/etc.) on the dynamic power current files, specify it with the parameter -power_output_directory, as shown below: set_power_data –power_output_directory <dirname> ...

#Run Dynamic Power and Rail Analysis

report_rail
