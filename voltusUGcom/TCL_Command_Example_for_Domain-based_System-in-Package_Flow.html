TCL Command Example for Domain-based System-in-Package Flow

The following is the TCL command example for setting up and running domain-based TSV analysis:

set_multi_cpu_usage -local_cpu 4
set_rail_analysis_config -method dynamic \
-die_mode multi-die \
-die_instance_name EngineX4 \
-accuracy xd \
-power_grid_libraries { \
../data/EngineX4/libgen_bump/bump.cl \
../data/EngineX4/libgen_libs/tcb013ghp.cl \
../data/EngineX4/libgen_libs/tpz013g2.cl} \
-report_via_current_direction false
-read_thermal_map map1.file

set_rail_analysis_config -method dynamic \ 
-die_mode multi-die \ 
-die_instance_name dtmf_chip \ 
-accuracy xd\ 
-power_grid_libraries { \ 
../data/dtmf/PGV/io_wc/fast_allcells.cl \ 
../data/dtmf/PGV/lp_wc/fast_allcells.cl \ 
../data/dtmf/PGV/macro_level_wc/fast_allcells.cl \ 
../data/dtmf/PGV/std_wc/accurate_stdcells.cl \ 
../data/dtmf/PGV/tech_only/techonly_library.cl} \ 
-report_via_current_direction false 
-read_thermal_map map2.file

The -die_mode parameter specifies to perform multi-die analysis, and the -die_instance_name parameter specifies the die instance name. You can use the -read_thermal_map parameter to use the distribution temperature defined in the specified thermal map file of each die generated from thermal analysis to do resistance scaling. The set_rail_analysis_config command parameters are specified for both master and slave die.

set_pg_nets -net VDD -voltage 1.2 -threshold 1.08 -tolerance 0.3 -die_instance_name EngineX4
set_pg_nets -net VSS -voltage 0 -threshold 0.12 -tolerance 0.3 -die_instance_name EngineX4
set_pg_nets -net VDD_IO -voltage 0.81 -threshold 0.729 -tolerance 0.3 -die_instance_name dtmf_chip
set_pg_nets -net Avdd -voltage 0.81 -threshold 0.729 -tolerance 0.3 -die_instance_name dtmf_chip
set_pg_nets -net VDDL -voltage 0.72 -threshold 0.648 -tolerance 0.3 -die_instance_name dtmf_chip
set_pg_nets -net VDDL_sw -voltage 0.72 -threshold 0.648 -tolerance 0.3 -die_instance_name dtmf_chip
set_pg_nets -net VDD -voltage 1.2 -threshold 1.08 -tolerance 0.7 -die_instance_name dtmf_chip
set_pg_nets -net VDD_sw -voltage 1.2 -threshold 1.08 -tolerance 0.7 -die_instance_name dtmf_chip
set_pg_nets -net VSS -voltage 0 -threshold 0.072 -tolerance 0.3 -die_instance_name dtmf_chip
set_pg_nets -net Avss -voltage 0 -threshold 0.072 -tolerance 0.3 -die_instance_name dtmf_chip


set_power_data -format current -scale 1 {../data/EngineX4/voltus/dynamic_VDD.ptiavg ../data/EngineX4/voltus/dynamic_VSS.ptiavg} -die_instance_name EngineX4
set_power_data -format current -scale 1 {../data/dtmf/voltus/dynamic_VDD.ptiavg ../data/dtmf/voltus/dynamic_VDD_sw.ptiavg ../data/dtmf/voltus/dynamic_VDDL.ptiavg ../data/dtmf/voltus/dynamic_VDDL_sw.ptiavg ../data/dtmf/voltus/dynamic_VSS.ptiavg} -die_instance_name dtmf_chip
set_power_pads -net VDD -format padcell -file ../data/EngineX4/data/pad_cell.VDD -die_instance_name EngineX4
set_power_pads -net VSS -format padcell -file ../data/EngineX4/data/pad_cell.VSS -die_instance_name EngineX4
set_power_pads -net VDD -format padcell -file ../data/dtmf/data/pad_cell.vdd -die_instance_name dtmf_chip
set_power_pads -net VDDL -format padcell -file ../data/dtmf/data/pad_cell.vdd -die_instance_name dtmf_chip
set_power_pads -net VSS -format padcell -file ../data/dtmf/data/pad_cell.vss -die_instance_name dtmf_chip


local_cpu ../data/EngineX4/data/routed1_5.5via.def.gz -die_instance_name EngineX4
local_cpu ../data/dtmf/data/test2.def.gz -die_instance_name dtmf_chip

Specify these commands for each die instance by specifying the instance name using the -die_instance_name parameter. For example, you can specify the power grid nets, power data, power pad file, and DEF file for each die instance.

set_package -spice_model_file ../data/package/paksi_interconn.ckt -mapping_file ../data/package/paksi_interconn.ptmf

You must specify this command as the two die connect through the package. This command is optional for TSV analysis.

set_multi_die_analysis_mode -analysis_name sip -die_list {EngineX4 dtmf_chip}

Specify the set_multi_die_analysis_mode command to specify the multi-die analysis type (sip) and the list of die instances. SiP analysis does not require a mapping file as there are no connections between the two stacked die.

set_rail_analysis_domain -domain_name ALL -power_nets {dtmf_chip/VDD dtmf_chip/VDDL EngineX4/VDD} -ground_nets {dtmf_chip/VSS EngineX4/VSS};

Use the set_rail_analysis_domain command to specify the die name/ net name pairs for power and ground nets in the specified domain.

report_rail -type domain -output_dir ./ ALL
exit
