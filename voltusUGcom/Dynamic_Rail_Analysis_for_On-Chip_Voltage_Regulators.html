Dynamic Rail Analysis for On-Chip Voltage Regulators

System-on-a-chip (SoC) voltage regulators (Vreg) have been widely used in designs to improve device power efficiency as well as device stability. Voltus IC Power Integrity Solution supports analysis of on-chip Vreg in SoC to stabilize voltage supplies and to handle Dynamic Voltage and Frequency Scaling (DVFS). This analysis has been included in the IR Drop analysis flow to understand how Vreg affects the on-chip voltage drop, chip package co-design, and how it interacts with the IC/package/board system. This feature allows you to accurately model Vreg modules for rail analysis.

In the following diagram, the chip configuration has a Vreg that is connected to an input and output domain along with a common ground:

During Vreg analysis, the tool captures the noise at the output of Vreg caused due to loading current and RC effects, and uses this time varying voltage waveform for rail analysis. When you perform Vreg analysis, a reduced grid is created for both input and output, and reduced ground resulting in a much concise RC netlist to do simulations of vectors with these loadings. The noise at the output of Vreg is captured and used for rail analysis.

Designs with on-chip Vreg have a non-linear circuitry of Vreg in the midst of large linear networks of power-grid. Therefore, the tool simulates the Vreg module using Spectre and the linear networks of power-grid using Voltus solver.

Use the set_voltage_regulator_module command to enable the Voltage Regulator analysis flow. You must specify this command multiple times for multiple Vreg instances. This command is used to specify all required information for defining a Vreg module, such as Vreg module name, SPICE netlist, power pin mapping for input/output/ground domains, component list (DEF instances working as a voltage regulator), and top-level Vreg subcircuit. The Spice netlist of the Vreg cell should encapsulate the testbench required for the Vreg module to work. When Voltus loads this netlist, it traces the connectivity inside the netlist and maps the top-level pin to instance pin, if the VRM is constructed by multiple sub-instances. After identifying all physical pin locations for Vreg input and output, the physical pins for Vreg output is used as voltage source. The location and placement of voltage sources on VRM cells is done by the tool based on the LEF port definitions of the power pin of the VRM cells.

After performing rail analysis, you can view the time varying waveform created at the output domain of the voltage regulator. The current waveforms through voltage sources are saved inside the voltus_rail.tran.ptiavg file to analyze voltage variation. The dynamic IR drop waveforms can be plotted using Power Rail - Report - Dynamic Waveforms form.

The following is the Tcl script for Vreg analysis:

# Load the design# Perform Power Analysis# Rail Analysis

set_pg_nets -net VDD_out -voltage 1.35 -threshold 1.21 -tolerance 0.3 -force
set_pg_nets -net VDD_in -voltage 3.00 -threshold 2.70 -tolerance 0.3 -force
set_pg_nets -net VSS -voltage 0.00 -threshold 0.13 -tolerance 0.3 -force
set_rail_analysis_domain -domain_name PD -power_nets {VDD_out VDD_in} -ground_nets VSS

For running this flow, you must analyze the input domain, output domain, and ground domain in rail analysis.


set_rail_analysis_config \
    -method dynamic \
    -accuracy xd\
    -power_grid_libraries ../accurate_stdcells.cl

set_power_data \
    -format current { \
    dynamic_power/dynamic_VDD_out.ptiavg \
    dynamic_power/dynamic_VDD_in.ptiavg \
    dynamic_power/dynamic_VSS.ptiavg \
    }

set_power_pads -net VDD_in -format xy -file ./VDD_in.pp
set_power_pads -net VSS -format xy -file ./vs/VSS.pp
set_voltage_regulator_module \ 
    -name vrm1 \
    -netlist ./TEST.spi \
    -input_power_pin_mapping {{ VDD_in VDD_in }} \
    -output_power_pin_mapping {{ VDD_out VDD_out }} \
    -ground_pin_mapping {{ VSS VSS }} \
    -sub_circuit_name VRM_MODEL \
    -component_list { reg_1 } 

set_voltage_regulator_module \ 
    -name vrm2 \
    -netlist ./TEST.spi \
    -input_power_pin_mapping {{ VDD_in VDD_in }} \
    -output_power_pin_mapping {{ VDD_out VDD_out }} \
    -ground_pin_mapping {{ VSS VSS }} \
    -sub_circuit_name VRM_MODEL \
    -component_list { reg_2 }

report_rail \
    -type domain \
    -output_dir ./dynamic_rail \
    PD
