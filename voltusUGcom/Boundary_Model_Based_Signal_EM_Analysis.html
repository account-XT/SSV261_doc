Boundary Model Based Signal EM Analysis

The boundary model for a block provides sufficient details of its interface paths to accurately analyze these paths when loading the model into the signal EM analysis of the top-level module. These details include interface netlist, SPEF, and side inputs. Aggressors that are not on the boundary paths are not included in the model, and any coupling capacitance to such nets is grounded. To create the cell boundary model, use the create_cell_signal_em_model command. After the boundary model is generated, it is automatically loaded to the higher-level module.

The following figure shows the top scope with the block boundary model:

Here,

  • Red nets indicate signal EM analysis is performed
  • Black nets indicate skipped from signal EM analysis
  • Yellow logic is removed during boundary model generation
  • Full clock propagation such that slew and clock marking are done correctly

In the top-level signal EM run, the boundary model is loaded instead of the full block contents. Boundary models can be loaded for multiple blocks. If you specify a Verilog for a block that already has a boundary model, the specified Verilog will override the netlist in the boundary model. The boundary model should not be overridden with a Verilog definition.

You can specify the create_cell_signal_em_model command before or after running the init_design command. The details of the two use models are as follows:

  • If the create_cell_signal_em_model command is specified before init_design, the command will generate the boundary model for a sub-cell and load it. For this use model, the -cell, -dir, -spef, and -verilog parameters must be specified.
  • If the create_cell_signal_em_model command is specified after init_design, the command will generate the model for the top cell for use in a subsequent top-level run. In this case, the command is issued in a block-level run, and the SPEF should be loaded prior to the create_cell_signal_em_model command. For this use model, the -dir parameter must be specified. Since the design is already loaded, the relevant information is obtained from the current session.

Sample Tcl Script for the Boundary Model Based Top Scope Signal EM flow

The following is the command for creating a boundary model and loading it into the current session:

create_cell_signal_em_model -dir bm_dir  -cell cella  -verilog cella.v  -spef cella.spef.gz  -overwrite -tech_lef tech.lef  -tech_file 65lp_typical.tch -tech_file_map  leflayermap

The following is the command for creating a boundary model after running init_design in a block-level session:

create_cell_signal_em_model -dir bm_dir -overwrite

## Create Top Scope

create_top_scope -include_side_loads -summary -thread_count 8 -cell_list $cell_list

## Boundary model Verilog files to be read for blocks "automatically"

init_design <top>
read_def -skip_pg -keep_pin_geometry -top_scope_ignore_block_internal_nets_on_boundary_path

## Boundary model SPEF files to be read for blocks "automatically"

read_spef -extended -keep_star_node_locations $spef_list  
read_sdc $sdc_list

## Set the process node before EM analysis

set_db design_*...
check_ac_limits...
