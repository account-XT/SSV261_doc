Rail Analysis including Package Model

Rail analysis is performed with the package model included. In the SPA flow, rail analysis will automatically pick the package model generated using the extract_package command. Hence, you do not need to specify the package model file via the set_package command. You can specify whether or not to perform the auto chip-package connection by using the following command:

set_rail_analysis_config -unconnected_die_package_pins {ignore | error | edit}
  • If the -unconnected_die_package_pins parameter is set to "ignore", then Voltus will continue simulation without pausing or stopping. This means that there are some unconnected pins between package and die, and you would like to continue with whatever connections are made.
  • If the -unconnected_die_package_pins parameter is set to "error", then Voltus stops the simulation by erroring out. This means that there are some unconnected pins between package and die, and you do not want to ignore them, but want to start the MCP Editor GUI to make manual connections.
  • If the -unconnected_die_package_pins parameter is set to "edit", then the Voltus simulation will pause, and the MCP Editor GUI will appear to allow you to make manual connections between package and die pins. This means that there are unconnected pins, and you want to start the MCP Editor GUI to try manual connections.

After performing manual connections, the simulation will continue irrespective of whether there is a 100% match or not.
