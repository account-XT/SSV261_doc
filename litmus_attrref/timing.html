timing_all_registers_filter_clock_pins_by_clock

timing_all_registers_filter_clock_pins_by_clock {true | false}

Default: false

Data_type: Boolean

Reports clock pins filtered based on specified clocks.

When set to true, the software will filter and return only those clock pins where at least one clock is from the specified list of clocks.

This attribute applies only when any of the all_registers command parameters, -clock, -rise_clock, -fall_clock, is specified.

timing_all_registers_identify_macros_include_is_macro_cell

timing_all_registers_identify_macros_include_is_macro_cell {true | false}

Default: true

Data_type: Boolean

Enables to include cells as macro cells.

When set to true, the software includes cells as macro cells if the is_macro_cell property (see get_property) is set to true in the library.

When set to false, the all_registers command will not return cells for which the is_macro_cell property is true.

timing_all_registers_include_icg_cells

timing_all_registers_include_icg_cells {true | false}

Default: true

Data_type: Boolean

Includes integrated clock gating (ICG) cell information from the all_registers report output. 

When set to false, the attribute does not allow the all_registers command report output to display ICG cell details.

When set to true, this attribute allows the software to apply input delay constraints on a pin where a clock was previously asserted.

timing_analysis_aging

timing_analysis_aging {true | false}

Default: false

The aging feature must be enabled before the timing updates are done.

Note: You cannot disable this feature in the same session later.

timing_analysis_async_checks

timing_analysis_async_checks {async | no_async | async_only | auto}

Default: auto

Data_type: Enum

Reports timing violations for asynchronous timing checks, including recovery and removal, and other checks on pins defined as preset or clear in the Liberty file.

The following options are supported:

  • async: Reports timing checks on pins that are defined as preset or clear in the Liberty file.
  • no_async: Reports timing violations while ignoring the two time arc attributes.
  • async_only: Reports only recovery and removal checks.

The following setting corresponds to set timing_disable_recovery_removal_checks true in Tempus legacy.

set_db timing_analysis_async_checks no_async 

The following setting corresponds to set timing_disable_recovery_removal_checks false in Tempus legacy.

set_db timing_analysis_async_checks async

Default: setup

Checks the design for setup or hold violations in the current analysis.

Note: When simultaneous setup/hold mode analysis is on, this settiing does not have any impact. You can use the report_timing -late/-early parameter to report setup/hold timing reports.

timing_analysis_clock_gating {true | false}

Default: true

Data_type: Boolean

Enables clock gating checks.

timing_analysis_clock_propagation_mode

timing_analysis_clock_propagation_mode {sdc_control | forced_ideal}

Default: sdc_control

Data_type: Enum

Specifies how to determine whether clock end points are interpreted as having either ideal or propagated clock timing.

  • sdc_control: Reports the timing violations considering clock tree and enables propagating clocks to report clock latency. You must set the set_propagated_clock constraint to propagate the clocks.
    Note: By default, CTS will instruct the timer to make all of the clock roots propagated. In this case, you do not need to set the set_propagated_clock constraint.
  • forced_ideal: Does not report the timing violations considering the clock tree.

timing_analysis_clock_source_paths

timing_analysis_clock_source_paths {true | false}

Default: true

Data_type: Boolean

Reports combinational paths from the clock source to the timing checks on data pins.

When set to false, the clock portion of the path is considered as ideal (due to the SDC constraints or the timing_analysis_clock_propagation_mode forced_ideal attribute setting), the delay calculation software treats the clock nets as ideal nets when calculating the delays and slews along the data path.

timing_analysis_cppr

timing_analysis_cppr {both | none | setup | hold}

Default: none

Data_type: Enum

Removes pessimism from clock paths that have a portion of the clock network in common between the clock source and clock destination paths.

The pessimism is introduced when the timing analysis tools assume that the common path has different delay values for two different paths in case of on-chip variation. The pessimism can also be because of clock reconvergence in the clock network. The pessimism effects all analysis modes including single, best case-worst case (bcwc), and on-chip variation.

  • none: Disables removal of clock reconvergence pessimism.
  • both: Enables removal of clock reconvergence pessimism for both setup and hold modes. 
  • setup: Enables removal of clock reconvergence pessimism in setup mode only.
  • hold: Enables removal of clock reconvergence pessimism in hold mode only.

timing_analysis_enable_robustness_mode

timing_analysis_enable_robustness_mode {true | false}

Default: false

Data_type: Boolean

Enables PTR analysis.

The Parametric Timing Robustness (PTR) analysis calculates the probability of an entire chip meeting timing requirements, instead of relying on the probabilities on individual paths to compute the robustness of a chip.

timing_analysis_graph_pba_mode {true | false}

Default: false

Data_type: Boolean

timing_analysis_multi_input_switching_mode

timing_analysis_multi_input_switching_mode int

Default: 0

Data_type: Integer

Sets the multiple-input switching (MIS) mode.

You can specify one of the following options below:

  • 0: Simultaneous input switching is not considered.
  • 1: MIS analysis considers cells for which multiple inputs of a cell are tied together (tied-inputs).
  • 2: MIS analysis considers both the tied-inputs and inputs of cells switching independent to each other.
  • 3: Enables derate-based MIS. When MIS-derate is enabled, Tempus will automatically disable AMIS-simulation.

timing_analysis_precision_ps

timing_analysis_precision_ps {0.1 | 0.01}

Default: 0.01

Data_type: Double

Allows you to set the delay precision value (in 0.1ps or 0.01ps) for the write_sdf command. 

The write_sdf command shows a double digit value after the decimal point by default. You can use this attribute for more accuracy.

timing_analysis_self_loops_paths_no_skew

timing_analysis_self_loops_paths_no_skew {true | false}

Default: false

Data_type: Boolean

Checks for self loop paths without skew.

When set to true, the software eliminates clock skew due to clock uncertainty for a path starting and ending at the same register. If the clock skew is not eliminated, the timing for such paths is pessimistic.

timing_analysis_socv

timing_analysis_socv {true | false}

Default: false

Data_type: Boolean

Enables SOCV Analysis.

timing_analysis_type

timing_analysis_type {single | best_case_worst_case | ocv}

Default: ocv

Data_type: Enum

Sets the timing analysis type to single, best case worst case or on-chip variation.

In this mode, the software calculates the delay for one path based on maximum operating condition while calculating the delay for another path based on minimum operating condition for setup or hold checks.

  • single: Scales the delay values based on one operating condition. 
  • best_case_worst_case: Checks the design for two extreme operating conditions. The software uses the maximum delays for all paths during setup checks and minimum delays for all paths during hold checks. 
  • ocv: Calculates the delay for one path based on maximum operating condition while calculating the delay for another path based on minimum operating condition for setup or hold checks. 

If you read in one library set and do not specify any timing analysis type, the software uses single by default. If you read in two library sets and do not specify any timing analysis type, the software uses best_case_worst_case by default.

For more information, see Timing Analysis Modes in the Tempus User Guide.

timing_use_latch_early_launch_edge {true | false}

Default: true

Data_type: Boolean

Enables the latch use early launch edge feature.

During timing analysis when time borrowing and clock path pessimism removal (CPPR) is enabled, the given time is calculated using both borrow time and CPPR time. This may result in unnecessary timing violations. Since CPPR is an accurate means of pessimism removal, you are required to set the timing_use_latch_early_launch_edge attribute to false so that CPPR is applied to all the paths in the design.

When set to true, the launch clock path of timing paths starting at a latch is timed in early mode for setup analysis, and for late mode for hold analysis. No CPPR credit is given to the timing path. 

When set to false, the behavior is like for any other path. The launch clock path of timing paths starting at a latch is timed in late mode for setup analysis, and early mode for hold analysis. The CPPR credit is given to the path according to the attribute CPPR settings.
