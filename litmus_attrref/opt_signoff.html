opt_signoff_allow_multiple_incremental

opt_signoff_allow_multiple_incremental {true | false} 

Default: false

Data_type: Boolean

Allows to run multiple types of optimization in incremental mode. Note that there should not be any report_* commands between successive opt_signoff commands. The recommended order to fix violations is DRV, Hold, and Setup. Hold and Setup can be interchanged but DRV optimization must be performed first. You must specify a unique ECO file prefix before each optimization step. You can then source all the ECO files in the same order as these were generated to run the What-If analysis later.

Note:

If set, this attribute must be applied before opt_signoff.

Related Commands
  • opt_signoff

opt_signoff_allow_skewing

opt_signoff_allow_skewing {true | false}

Default: false

Data_type: Boolean

Allows clock skewing to be done during Setup timing optimization to further improve Setup slack. When set to true, opt_signoff -setup works on any level of the clock tree to modify the clock skew in order to improve Setup timing closure. Modification on the clock tree can be either resizing of the last level of the clock tree or buffering to pad endpoint clock pin.

Note:

  • If set, this parameter must be applied before opt_signoff.
  • When opt_signoff_allow_skewing is active, opt_signoff will automatically unfix all clock tree instances/nets. This is also performed when implementing the ECOs.
  • As for data path optimization, skewing is not allowed to create new Hold violated paths.
Related Commands
  • opt_signoff

opt_signoff_along_route_buffering

opt_signoff_along_route_buffering {true | false}

Default: true

Data_type: Boolean

When set to 1, the software uses node location provided through the parasitic data in order to insert buffers along the routing topology not only at the start or end of the net. This helps to better balance the slew or the load for long nets, which is typically needed for setup timing optimization or DRV fixing.

Note: If set, this attribute must be applied before opt_signoff.

opt_signoff_clock_max_level

  opt_signoff_clock_max_level integer

Default: 0

Data_type: Integer

Specifies the maximum levels in clock skewing thus limiting the amount of clock tree levels and avoiding the creation of an unbalanced clock tree. This attribute sets an upper boundary when adding a buffer or pair of inverters to the clock nets. The software counts the number of levels in the clock tree branch that is being modified to ensure that the maximum level will be equal to or less than the value set by this attribute.

opt_signoff_disable_geometry_checks

opt_signoff_disable_geometry_checks {true | false}

Default: false

Data_type: Boolean

Performs Vth swapping without checking the cell pins and geometry. Skipping the geometry checks during Vth swapping allows the software to only check the cell size while performing Vth swapping. This will lead to more Vth swaps. However, if you use this attribute, ecoRouting will need to be done once the ECOs are applied since the pin geometries between old and new cells might not match.

Note: If set, this attribute must be applied before opt_signoff.

Fixes the electromigration (EM) type during DRV optimization in standalone Tempus ECO. You can specify any one of the following options:

opt_signoff_fix_hold_allow_setup_degrade

opt_signoff_fix_hold_allow_setup_degrade {none | low | medium}

Default: none

Data_type: Enum

Guides the Hold fixing engine to determine the effort it has to put to resolve timing violations, and how much flexibility it has to impact the Setup timing.

  • When set to low, the Hold optimization engine will buffer sink pins that have large Setup positive slack even though the net Setup slack is hardly meeting timing.
  • When set to medium, the Hold optimization engine will behave the same as in the low mode but will also allow Setup TNS to degrade, if required.

Note:

  • This attribute is honored by the Hold optimization engine.
  • If set, this attribute must be applied before opt_signoff.
  • When opt_signoff_fix_hold_allow_setup_degrade is set to low or medium, the opt_signoff_fix_hold_allow_setup_tns_degrade attribute is ignored.

opt_signoff_high_effort_cell_list

opt_signoff_high_effort_cell_list list of cells

Default: " "

Data_type: String

Enables the controlled utilization of high-leakage or high-power cells during signoff optimization. These cells are typically classified as dont_use or dont_touch due to their power characteristics; however, they may be beneficial in specific scenarios. When this attribute is specified, ensure that the don’t_use constraint is set to false for cells included in opt_signoff_high_effort_cell_list. 

  • In setup timing optimization, the cells are considered only if they are essential to meet timing requirements without causing a significant increase in power consumption. 
  • In power optimization, the cells may be inserted if their usage leads to an overall decrease in power usage, such as enhancements in fanin/fanout cone.

This attribute permits considering the specified cells as high-effort resources, using them only when necessary to enhance timing or power efficiency, while maintaining the broader design objective of reducing power impact.

opt_signoff_inter_partition

opt_signoff_inter_partition

Default: " "

Data_type: String

Selects a list of partition module names to be optimized for the interface logic of the specified partition. During the High Capacity ECO flow, it will reduce the database having the interface logic of the listed partitions only. Each listed partition is treated separately, thus all from/to paths for each partition are included. This attribute must be applied before write_eco_opt_db and opt_signoff. In case of the Tempus Paradime flow or Certus, it must be applied before distribute_read_db.

Note:

It is mandatory to list the partition name inside the file specified with opt_signoff_partition_list_file.

  • For High Capacity ECO flow, opt_signoff_partition_list_file should be specified before distribute_read_db.
  • For non-High Capacity ECO flow, opt_signoff_partition_list_file should be specified before first optimization.

However, any partition name, which is a part of opt_signoff_inter_partition and missing in opt_signoff_partition_list_file will result in an error, as shown below:

**ERROR: (IMPESO-616):   Partition 'ptn_wrapper' is missing in opt_signoff_partition_list_file file. Partition specified for inter/intra partition fixing should be present in opt_signoff_partition_list_file list as well.

In case of Certus, since opt_signoff_partition_list_file is not required, the software will use opt_signoff_distributed_optimization_block_restore_file to identify the partition names.

opt_signoff_power_aware

opt_signoff_power_aware {true | false}

Default: false

Data_type: Boolean

Tempus ECO provides the ability to take power as part of the overall cost function when doing timing closure.

When this parameter is enabled before the start of an optimization session, the current optimization and any subsequent optimizations (if running in incremental mode) checks for power changes for all optimizers and transforms during any changes in the design.

In any of the above cases, the first priority remains getting best final timing but enabling this option will get there with possibly slighter ECO although resulting in lesser final power.

For example, while fixing a Setup timing path violation, by default, the tool chooses to size one instance to a high leakage cell, while with the -opt_signoff_power_aware mode, the tool tries to get to same timing by doing multiple sizing to non-high leakage cells.

Note :

  • This feature requires power activity to be annotated on the netlist with the report_power command, either through external activity file (recommended) or using propagated activity based on some default toggling rate.
  • This feature honors the -opt_signoff_power_opt_focus parameter, which means that you can decide to force the tool in reducing more the total or leakage or dynamic power increase.
