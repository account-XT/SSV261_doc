generate_special_via_accuracy_effort

generate_special_via_accuracy_effort {low | medium | high}

Default: high

Data_type: enum {low medium high}, read/write

Controls the balance between accuracy and runtime during via generation.

  • When set to high, viagen checks full DRC rules and creates DRC clean vias.
  • When set to medium, viagen runs DRC check in the moderate mode.
  • When set to low, viagen runs in the quick DRC check mode. With this value specified, some available vias may be missed, since the conservative rules are checked.

The vias generated through this parameter are DRC clean. This parameter generates vias with reduced runtime in the special scenarios where complex DRC rules are triggered. These complex rules include (but are not limited to) same metal aligned cuts spacing.

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:
    get_db attribute_name

generate_special_via_check_signal_routes

generate_special_via_check_signal_routes {0 | 1 | 2}

Default: 0

Data_type: enum {0 1 2}, read/write

Controls whether the via generation software honors pre-existing signal routes.

If set to 1, instructs the via generation software to read pre-existing signal routes and avoid creating DRC violations for the routes.

If set to 2, instructs the via generation software to read pre-existing signal routes and avoid creating DRC violations for the routes. And improve the runtime of VIA12 process.

Note: Using this setting can affect software performance significantly.

If set to 0, instructs the via generation software to ignore any pre-existing signal routes.

Note: DRC violations can occur if this setting is used.

generate_special_via_cut_class_preference

generate_special_via_cut_class_preference {default | {[square] [bar] [large]} | cutclass_name_list | file_name}

Default: default

Data_type: string, read/write

Specifies the preference for the via cut class while inserting special vias. You can specify one of the following values:

  • default: Prefers to use the first viacell in tech LEF without drc violation or the first generate viarule to generate maximum cut area. For example, cutWidth * cutHeight * cutNumber.
  • square: Prefers to use the SINGLE cut vias. In the LEF definition, the cut width and length are usually the same and the smallest in that layer. For example, 0.032 by 0.032.
  • bar: Prefers to use the DOUBLE cut vias. In the LEF definition, the cut width is the usually the smallest. For example, 0.032 by 0.08. It mostly equals to 2 SINGLE cut.
  • large: Perfers to use the LARGE cut vias. In the LEF definition, the neither the cut width not the length is the smallest. For example, 0.08 by 0.08, equals to 4 SINGLE cut.

The following figure shows the difference between the square, bar, and large values:

Note:

  1. The attribute setting does not support incremental specification. The last cutClass preference setting is used.
  2. When you specify {[square] [bar] [large]}, there should be 2 or 3 cutClass defined in the LEF file. If Innovus detects that there are more than 3 or less than 2 cutClasses, the setting is ignored.
  3. In the specified file, different arguments can be separate by space or line break.

generate_special_via_enable_check_drc

generate_special_via_enable_check_drc {true | false}

Default: false

Data_type: bool, read/write

Enables or disables check_drc called by the via generation software.

  • When set to true, the via generation software calls check_drc to detect any min_step violations, then calls the fix_via -min_step command to fix them. This may impact the run-time performance.
  • When set to false, the via generation software will not call check_drc. This may leave min_step violations in the design.

Note: When both the generate_special_via_enable_check_drc and generate_special_via_opt_cross_via attributes are set to true, and the process node is above 10N, DRC violations can be reported.

  • The fixed grid does not get influenced by the shape of the design or macros.
  • distance_value2 needs to be set same as distance_value1.

generate_special_via_symmetrical_via_only

generate_special_via_symmetrical_via_only {true | false}

Default: false

Data_type: enum {auto true false}, read/write

By default the metal-width of a generated-via matches the width of the intersection of the metal above and below the via. If the width is an odd number of manufacturing grids (mgrids) wide, the resulting via cannot be represented by a parameterized via (LEF/DEF VIA with VIARULE and parameters or OpenAccess standardVia) because they require a symmetrical enclosure values on both sides of the cuts. In that case, a fixed-name via (LEF/DEF VIA with RECT statements or OpenAccess customVia) must be created to have the same width as the intersection area.

If this option is true, the via metal is enlarged one mgrid in the odd-mgrid directions order to make the via symmetrical so it can be represented as a parameterized via. This does not cause any DRC violations in general because the via metal should still be covered by the metal above/below the via and avoid any min-step violations.

Fixed-name vias can cause problems in hierarchical flows as the fixed-names from different blocks may collide. Parameterized via-names can be freely changed by applications and avoid this problem. If the design has odd-mgrid width wires or pins, this option is normally a good choice.

If this attribute is selected as auto, it is true for OpenAccess design, false for non-OpenAccess design.

This is a root attribute.
