add_target_pg

The root attributes in the add_target_pg category are:

  • add_target_pg_allow_weak_connect
  • add_target_pg_max_extension_distance
  • add_target_pg_pins
  • add_target_pg_pins_group_distance
  • add_target_pg_respect_routes
  • add_target_pg_share_resource

To set the value of any root attribute, use the set_db command:

set_db attribute_name value

To get the current value of any root attribute, use the get_db command:

get_db attribute_name

To get the current value of all attributes in the add_target_pg category, use the following command:

get_db -category add_target_pg

add_target_pg_allow_weak_connect

add_target_pg_respect_clock_routes {true | false}

Default: false

Data_type: bool, read/write

When set to false, the number of wires created on every stack layer need to satisfy the defined count with DRC clean. Else, the PG pin is left open. When set to true, the count lesser than defined can also be accepted while creating the total count causing DRC.

add_target_pg_max_extension_distance

add_target_pg_max_extension_distance value

Default: 2.14748e+09

Data_type: double, read/write

Specifies the maximum distance that the target PG pin can extend to the target layer. If the distance between the target PG pin and the candidate target layer is lesser than or equal to the specified distance, the candidate target is treated as the real target.

If the target PG wire cannot be found within add_target_pg_max_extension_distance, the instance is left open. If this attribute is not used, the software connects the stripe layer to the closest target PG wire with DRC clean, by default. See the figure below for understanding:

add_target_pg_pins_group_distance

add_target_pg_pins_group_distance value

Default: auto

Data_type: string, read/write

Specifies the side-to-side distance of the pins to be treated as a group while connecting the target PG pins. The pins belonging to the same group share the same target PG stripes connection.

When this attribute is set to its default value, auto, the add_target_pg command uses the default behavior of target PG generation to group the pins. If this attribute is not specified, the software uses the pitch of metal layer above the pins layer with same direction (layer_pin+2) as the group distance.

If the pitch of metal layer above the pins layer with the same direction (layer_pin+2) is not defined, the pins will be connected separately.

add_target_pg_respect_routes

add_target_pg_respect_routes {none | fixed | fixed_and_clock | all}

Default: fixed_and_clock

Data_type: enum {none | fixed fixed_and_clock all}, read/write

Specifies the route types to respect for DRC check during target PG generation. This attribute always honor all covers and PGs, but does not honor the trail routes, Following are the attribute values:

  • none: Specifies that no route types are respected.
  • fixed: Respects fixed regular wires.
  • fixed_and_clock: Respects fixed and routed clocks.
  • all: Respects fixed and routed clocks along with the routed signals.

add_target_pg_share_resource

add_target_pg_share_resource {true | false}

Default: true

Data_type: bool, read/write

When set to true, the newly added PGs of the intermediate stacked layer can connect to the existing PG wire of the same layers and are preferred to be shifted to the track of the existing PG to save the track resource. If there are DRCs between the added PG and the existing PG after shifting, the added PG will follow the behavior explained below:

  • If the added wire is on different net from the existing PG, it will be shifted again to avoid DRC.
  • If the added wire is on the same net of the existing PG, it will be merged with the existing wire.

When set to false, the stacked layer cannot connect to the existing intermediate layers between the cell PG pin and target PG layer. Additionally, the newly added PG will be shifted if its original location causes DRC.

This is a root attribute.

    set_db attribute_name value

    get_db attribute_name
