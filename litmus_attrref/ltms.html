ltms_hier_compare_propagated_clock_latency

ltms_hier_compare_propagated_clock_latency {true|false}

Default: false

Data_type: boolean

Controls the behavior of the CONST_HIER_LAT1 partitioning check, specifically in scenarios involving propagated clocks and clock latency settings.
When set to false, the check ignores cases where:

  • A block clock (bclk) is mapped to a top-level propagated clock (tclk),
  • set_clock_latency is defined for bclk in the block SDC,
  • But not defined for tclk at the top level.

This allows flexibility in hierarchical clock latency validation when block-level constraints are applied independently of top-level mappings.
