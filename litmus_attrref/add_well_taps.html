add_well_taps_abut_boundary_tap_distance

add_well_taps_abut_boundary_tap_distance {{cell1 cell2 distance1} {cell1 cell3 distance1} {cell2 cell3 distance3} … }

Default: ""

Data_type: string, read/write

Specifies the boundary cells and their tap distance when they are vertically abutted. If you do not set this attribute, the abut cell still uses the single cell distance. If you specify it, the abut cell tap cover distance uses the defined new value. You need to add additional tap cell at the area when the tap cell checkboard cannot cover it.

This attribute works for the N4 process.

You can control the tap distance of a single cell using the set_db add_well_taps_tap_function_cells {cellnames rule value} attribute.

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:

               get_db attribute_name

add_well_taps_insert_cells

add_well_taps_insert_cells {cellName rule dense_layer dense__rule boundary_layer boundary_rule}

Default: ""

Data_type: string, read/write

Inserts well-taps based on cell, layer, and interval.

  • cellName: Specifies the cell name.
  • rule: Cell with this rule would be added as a general tap cell for all placeable area. The center to center spacing of tap cells would be ≤ (2*$rule) without -checker_board and ≤ (4*$rule) with -checker_board.  
    Note: Center of the tap cell is used to check the spacing.
  • dense_layername: Specifies the dense layer name.
  • dense_rule: Cell with dense layer would be added to the given layer regions only. Cell with dense layer must follow the dense rule. The center to center spacing of dense tap cells would be ≤ (2*$dense_rule) without -checker_board and ≤ (4 *$dense_rule) with -checker_board.
  • boundary_layername: Specifies the boundary layer name.
  • boundary_rule: A cell would be added for boundaries inside the given layer regions. The spacing between the boundary to the center of boundary tap cells would be ≤ $ boundary rule. Boundary layer regions which cover partial sites should be extended. Boundary taps can be located in or out of boundary layer regions.

Note:

  • You can define multiple cells for -insert_cells by separating each cell by { }.
  • There should be at lest one rule, dense layer or boundary layer, defined for each cell.
  • The order of tap cell insertion is:
    1. Dense tap
    2. Boundary tap
    3. General tap

  • If the area is covered by both dense layer region and boundary layer region, both layer rules must be satisfied.

  • If -insert_cells is defined multiple times, the last setting is accepted by the tool.

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:

               get_db attribute_name

add_well_taps_rule

add_well_taps_rule RuleValue

Default: 0.0

Data_type: double, read/write

Specifies the rule to be honored when adding well taps. 

To define multiple TAP rules in a design , add_well_taps parses TAPDISTANCE defined in the cell LEF and Tech LEF. It works on the following conditions:

  • If you do not define set_db add_well_taps_rule, the tool will use the LEF rule.
  • If both set_db add_well_taps_rule and LEF rule are not specified, the tool will error out.
  • If there are multiple tap distance values defined in the Tech LEF, add_well_taps will take the smallest value.
  • For existing tap cells, you need to use add_well_taps -incremental. If you specify a tap cell with tap distance bigger than the incremental cell, the tool will add the cell and print a warning message.

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:

               get_db attribute_name

add_well_taps_tap_function_cells

add_well_taps_tap_function_cells cell_list

Default: ""

Data_type: string, read/write

Defines the endcap cells which have tap functions. Use of tap function cells reduces the number of tap cells to be inserted. The defined endcap cells are treated as tap function cells during the tap cell insertion. The tool will consider the tap distance between welltap cell and the defined endcap cell with tap function.

To insert tap cells considering the tap function not only on the checkboard but also on the termination tap cell insertion flow, addWellTap treats the endcap cell as a tap function cell when set_db add_well_taps_tap_function_cells is set. 

The check_well_taps command honors the add_well_taps_tap_function_cells settings to check the tap distance.

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:

               get_db attribute_name

add_well_taps_termination_cells

add_well_taps_termination_cells cellist

Default: ""

Data_type: string, read/write

Specifies the list of cells that can be used as termination taps. The command add_well_taps selects the best fit termination cells from this list and inserts them at the top and bottom of well tap column segment. The existing non-termination well taps are deleted as needed. If the well tap columns have already been terminated with a valid termination cell, the existing termination cell are kept in the incremental run and no changes are made.

Note: It is recommended that well tap columns are added before termination cell insertion.

Note: This attribute must be specified for termination tap cell insertion.

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:

               get_db attribute_name
