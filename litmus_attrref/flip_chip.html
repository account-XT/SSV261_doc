flip_chip_allow_layer_change

flip_chip_allow_layer_change {true | false}

Default: false

Data_type: bool, read/write

Turns on the layer change feature, when set to true. Only the PIO mode supports this feature. Both Manhattan and 45-degree routing support this constraint.

Different setting for routing layers will have the different behaviors as shown in the following examples. Assume the top RDL is TOP_RDL and the second top RDL is 2nd_RDL:

  • Use TOP_RDL as much as possible and 2nd_RDL is used only when a single layer cannot finish routing in case of cross-over:
    flip_chip_bottom_layer TOP_RDL flip_chip_top_layer TOP_RDL
  • Freely change layers so that the tool will use the layer resources by its intelligence
    flip_chip_bottom_layer 2nd_RDL flip_chip_top_layer TOP_RDL

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:
    get_db attribute_name

flip_chip_bump_use_octagon_shape

flip_chip_bump_use_octagon_shape {true | false}

Default: false

Data_type: bool, read/write

 Controls how route_flip_chip handles special bumps with multiple shapes:

  • When this attribute is set to true, the tool uses an octagonal shape to mimic the special bump. 
  • When this attribute is set to false, the tool:
    • Uses the bump’s exact LEF description if the bump is simple enough. 
    • May replace the bump shape with an octagonal shape if the bump is not simple according to the tool’s internal criterion.

Note: When the special bump is replaced with an octagonal shape, the routing quality may be improved, but there may be DRC violations.

This is a root attribute.

flip_chip_cell_connection_type

flip_chip_cell_connection_type {route_width | bump_edge | bump_center | bump_end}

Default: bump_center

Data_type: enum {route_width bump_edge bump_center bump_end}, read/write

Specifies the type of bump cell connections. Each type represents a distinct connection method:

  • route_width: Connects the cell by extending the routing path by a distance equal to one route width.
  • bump_edge: Connects the cell to the outer edge of the bump. In this configuration, the connection terminates precisely at the bump's perimeter and does not extend further into the bump structure.
  • bump_center: Connects the cell directly to the geometric center of the bump.
  • bump_end: Connects the cell to the bump edge and then continues the connection path until it reaches the far end of the bump structure.

This is a root attribute.

    set_db attribute_name value

flip_chip_check_bump_access_directions

flip_chip_check_bump_access_directions {true | false}

Default: false

Data_type: bool, read/write

Specifies whether route_flip_chip should check the access direction of bump cells. Use this attribute if you have an octagonal bump pad structure with a pre-drawing wire for outside access, where the pre-drawing wire is a pin in the bump LEF.

  • When this attribute is set to true,  route_flip_chip checks the bump LEF to detect the bump access direction and then connects the pad to the bump pre-routed wire based on the detected direction. If the pre-routed wire is a 45-degree wire, the manhattan routing style is not supported.
    Note that one bump cell can have multiple access directions. 
  • When this attribute is set to false, route_flip_chip skips checking bump access direction.

Note: This attribute is applicable only for route_flip_chip -target connect_bump_to_pad. If this option is used for route_flip_chip -target connect_bump_to_ring_stripe, route_flip_chip will ignore the setting and display a warning.

In the example below, route_flip_chip checks the bump LEF to detect the bump access directions and then connects the pads to the bump pre-routed wires based on the detected directions:

> set_db flip_chip_check_bump_access_directions true

> route_flip_chip -target connect_bump_to_pad -route_engine global_detail

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value

flip_chip_compaction

flip_chip_compaction {true | false}

Default: false

Data_type: bool, read/write

Enables compact routing, when set to true.

In the flip chip post-route stage, the compaction function pushes the routing as close as possible to bumps in order to leave more routing resource for subsequent routing steps, such as P/G bump connections or general power routing.

Note: This feature cannot be used with resistance driven and diffpair routings because the compaction action may change the wire length and routing pattern. This feature does not support two-layer RDL routing.

This is a root attribute.

flip_chip_connect_power_cell_to_bump

flip_chip_connect_power_cell_to_bump {true | false}

Default: false

Data_type: bool, read/write

Connects all power bumps to the I/O cell pin. It does not connect to a power or ground stripe or ring.

When used with the route_flip_chip -target signal parameter, you can connect power bumps to I/O power pads. To make this type of connection, you need the following information:

  • The Verilog netlist must contain the I/O power pad, for example: 
    VDDCELL VDD_INST (.PAD());
  • The LEF macro pin must contain the USE POWER statement, for example: 
    MACRO VDDCELL
    PIN PAD
    USE POWER;

To improve the quality of routing in situations where there may be many power bumps in the design, you can pair power bumps to power cells by using this attribute in conjunction with the flip_chip_constraint_file attribute. For example:

set_db flip_chip_connect_power_cell_to_bump true

set_db flip_chip_constraint_file pair.const

where pair.const specifies the following information:

### Syntax: net pad [pad2] bump [bump2] ###

PAIR

VDD IOPADS_INST/esd Bump_90_9_8

END PAIR

flip_chip_merge_nearby_pin

flip_chip_merge_nearby_pin {true | false}

Default: false

Data_type: bool, read/write

Merges pins that are close but not touching. If this attribute is set to true and there are multiple non-overlapping pin shapes sharing the same net, the tool will merge these pins and drop a via automatically on these pin shapes at the same time while connecting the bumps to pins. A single shape in the specified layer that contains an array of vias is transferred to flip chip route by VIAGEN. The array of vias is the largest via that fits on each of the multiple physical pin shapes.

  • The merged pins must have the same net on the same layer.
  • The distance between these merged pins should be small and there should be no other objects between the pins.
  • The pin shapes should be aligned with each other.

This is a root attribute.

flip_chip_multi_pad_routing_style {default serial star}

Default: default

Data_type:  enum {default serial star}, read/write

Specifies the routing style for multi-pad routing:

  • default: The flip chip router (route_flip_chip) connects a bump to multiple pads with multiple different wires as shown below:

  • serial: route_flip_chip connects a bump first to one pad and then to the other pad, as shown below, provided that the distance from the bump to either pad is more than the distance between the two pads:

    If the distance from the bump to any pad is shorter than the distance between the two pads, route_flip_chip reverts to the default behavior of multiple wire connection even if flip_chip_multi_pad_routing_style is set to serial.


    This mode supports only two-pad routing.

  • star: route_flip_chip connects a bump first to the closest pad. It then finds a minimum cost point on its routing path and connects this point to another pad as shown below:

    The minimum cost point could be anywhere on the first routing path, including its beginning and end.

Both the serial and star modes are useful for saving routing resources in complex designs as they share the routing between pads. However, the serial mode supports only two-pad routing. Use the star mode if you want to route more than two pads.

Note: The flip_chip_multi_pad_routing_style works only if the flip_chip_multiple_connection multiple_pads_to_bump is specified. For example, to use the star mode, you should specify the following commands before running route_flip_chip:

flip_chip_multiple_connection

flip_chip_multiple_connection {multiple_pads_to_bump | multiple_bumps_to_pad | multiple_bumps_to_multiple_pads | default}

Default: default

Data_type: enum {multiple_pads_to_bump multiple_bumps_to_pad multiple_bumps_to_multiple_pads default}, read/write

Specifies routing connections between multiple pads and bumps. You can specify one of the following options:

  • multiple_pads_to_bump
    Enables routing from multiple pads to one bump in parallel. This option is supported by both AIO and PIO routing styles.
  • multiple_bumps_to_pad 
    Enables routing from multiple bumps to one pad in parallel. This option is supported by both AIO and PIO routing styles.

  • multiple_bumps_to_multiple_pads

    Multiple bumps to multiple pads connections are only supported when flip_chip_multi_pad_routing_style is set to serial.

  • default
    Enables routing from one bump to one pad in parallel. This means there is no multiple connection.

flip_chip_prevent_via_under_bump_extension

flip_chip_prevent_via_under_bump_extension value

Default: default

Data_type: string, read/write

Specifies a spacing value to define an extension area around the bump in which vias should not be dropped. By default (or when value is set to default), the tool automatically chooses the appropriate spacing around bumps to avoid dropping vias. 

The following examples illustrate how the flip_chip_prevent_via_under_bump and flip_chip_prevent_via_under_bump_extension attributes can be used to control the spacing around bumps when vias are dropped:

  • In the example below, no vias are dropped directly under the bump as flip_chip_prevent_via_under_bump is set to true:
    > set_db flip_chip_prevent_via_under_bump true
    > route_flip_chip -target connect_bump_to_pad -route_engine global_detail


    If, additionally, flip_chip_prevent_via_under_bump_extension is set to 0, vias can be dropped in the space immediately around the bump. 
    By default, however, the tool will automatically choose the appropriate spacing around bumps in which to avoid dropping vias. 
  • In the example below, no vias are dropped in the extension area defined around the bump:
    > set_db flip_chip_prevent_via_under_bump_extension 1.2
    > route_flip_chip -target connect_bump_to_pad -route_engine global_detail
  • In the example below, vias are dropped directly under the power bumps as flip_chip_prevent_via_under_bump is set to false:
    > set_db flip_chip_prevent_via_under_bump false
    > route_flip_chip -target connect_bump_to_ring_stripe
  • In the example below, no vias are dropped in the extension area defined around the power bumps:
    > set_db flip_chip_prevent_via_under_bump true
    > set_db flip_chip_prevent_via_under_bump_extension 1.2
    > route_flip_chip -target connect_bump_to_ring_stripe
