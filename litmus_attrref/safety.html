safety_dcls_isolate_halo_type

safety_dcls_isolate_halo_type {soft | hard}

Default: soft

Data_type: enum {soft hard}, read-only

Specifies the type of isolation halo required for the Dual Core Lock Step (DCLS) groups. This attribute supports the following values:

  • hard: Specifies that the isolation cells on a group's input/output nets should always be placed inside the group's isolation halo boundary.
  • soft: Works the same as hard, but can also move the isolation cells inside the group boundary, if required, to improve timing.

This is a root attribute.

    get_db attribute_name

safety_dcls_isolate_type

safety_dcls_isolate_type {soft | hard}

Default: soft

Data_type: enum {soft hard}, read-only

Specifies the type of isolation required for the Dual Core Lock Step (DCLS) groups. This attribute supports the following values:

  • soft: Specifies that the isolation networks (insts and nets) need not avoid the boundary of the exclusive_groups of the groups that they isolate.
  • hard: Specifies that the isolation networks (insts and nets) must avoid the boundary of the exclusive_groups of the groups that they isolate.

This is a root attribute.

safety_dcls_route_types

safety_dcls_route_types {internal | interface | common | top}

Default: 

Data_type: enum* {internal interface common top}, read-only

Specifies the type of nets on which routing rules need to be enforced for the Dual Core Lock Step (DCLS) groups. This attribute supports the following values:

  • none: Specifies that routing rules will not be enforced on any nets for DCLS.

  • internal: Specifies the nets whose all the pins are logically inside a single DCLS group. These net cannot route outside of the group boundary.

  • interface: Specifies the net that has pins logically inside and outside a DCLS group, and outside of the exclusive_groups. This net cannot route over the boundary of its exclusive_groups.

  • common: Specifies the net that has pins logically inside two or more DCLS exclusive_groups. This net can route inside the boundary of those groups to complete the connections, but a violation should be reported.

  • top: Specifies the nets whose pins are logically outside of DCLS groups. This net can route over the boundary of any DCLS group, but cannot route over the boundary of two or more exclusive_groups.

This is a root attribute.

safety_midas_enable

safety_midas_enable {none | fmeda | physical}

Default: none

Data_type: enum {none fmeda physical}, read/write

Enables the Unified Safety Format (USF) technology. The supported values of this attribute are:

  • none: Does not enable this attribute.
  • fmeda: Enables the USF command set for the failure mode effect and diagnostic analysis.
    Note: This value is supported only in Genus.
  • physical: Enables the USF command set for physical implementation of safety mechanisms.
    Note: This value is supported in both Innovus and Genus.

To enable USF commands (such as read_usf, write_usf, and check_safety_mechanism) in Innovus/Genus, set safety_midas_enable to physical:

set_db safety_midas_enable physical

You will see a message like this:

Once USF Physical is loaded, it is not possible to disable or reload it in the current session.

safety_ser_type

safety_ser_type {hard | soft}

Default: hard

Data_type: enum {hard soft}, read-only

Specifies the type of Soft Error Resilience (SER) safety mechanism to be used for failure mode mapping between the insts to ser cells. The supported values of this attribute include:

  • hard: Always uses SER cells for instances that have an SER safety mechanism.
  • soft: Uses SER cells for instances that have an SER safety mechanism, except in cases where using a non‑SER cell can improve timing.

This is a root attribute.

safety_tmr_isolate_clock

safety_tmr_isolate_clock {none | split_net | split_network}

Default: none

Data_type: enum {none split_net split_network}, read-only

Specifies the type of clock isolation required for Triple Modular Redundancy (TMR) flops. The supported values of this attribute include:

  • none: Specifies that no isolation is required.
  • split_net: Specifies that the net directly driving a TMR flop cannot directly drive either of the other two flops from the same TMR group.
  • split_network: Specifies that the network driving the TMR flops should split at the last combinational cell (excluding buffering) on that network. Each branch can drive multiple TMR and non-TMR flops, but can only drive one of the three flops in a TMR group.

This is a root attribute.

  • To get the current value of any root attribute, use the get_db command:
    get_db attribute_name

safety_tmr_isolate_reset

safety_tmr_isolate_reset {none | split_network | split_net}

Default: none

Data_type: enum {none split_network split_net}, read-only

Specifies the type of isolation required for the reset signals driving the Triple Modular Redundancy (TMR) flops. The values by this attribute include:

  • none: Specifies that no isolation is required.
  • split_net: Specifies that the net directly driving a TMR flop cannot directly drive either of the other two flops from the same TMR group.
  • split_network: Specifies that the network driving the TMR flops will split at the last combinational cell (excluding buffering) on that network. Additionally, each branch can drive multiple TMR and non-TMR flops, but only one of the three flops in a TMR group.

This is a root attribute.
