route_antenna_diode_insertion

route_antenna_diode_insertion  {true | false} 

Default: false

Data_type: bool, read/write

Enables or disables the insertion and placement of antenna diode cells when available placement locations exist.

By default, the NanoRoute router fixes antenna violations using layer changes (also called antenna stapling or layer hopping). However, it can also repair these violations by inserting antenna diode cells as close as possible to input gates to safely discharge accumulated charge.
When enabled, the router inserts antenna diode cells even if the filler cells are already placed. It can automatically swap filler cells with diode cells and adjust spacing if the diode cell size differs from the original filler cell.

To specify which diode cells to use, set the attribute:
route_antenna_cell_name.

Note: NanoRoute router can reclaim only those diode cells that it inserted itself. It does not reclaim user-inserted antenna diode cells.

This is a root attribute.

route_concurrent_minimize_via_count_effort

route_concurrent_minimize_via_count_effort value 

Default: medium

Data_type: string, read/write

Specifies the effort level for reducing the total number of vias during routing. Use this attribute together with the route_detail_use_multi_cut_via_effort attribute to control the effort toward reducing the total number of vias and the effort toward increasing the ratio of double-cut vias to single-cut vias concurrently with routing.

If you specify route_detail_use_multi_cut_via_effort medium or high, the software sets the value of route_concurrent_minimize_via_count_effort to medium unless you specify route_concurrent_minimize_via_count_effort yourself. To realize further savings, set route_concurrent_minimize_via_count_effort  to high. This could further reduce the total via count up to 10 percent.

Note: If you specify the flow_effort attribute of the init Category Attributes  to high, the software sets the value of  route_concurrent_minimize_via_count_effort  to high.

Note:  Results might vary with your design.

Specify one of the following attributes:

  • low: Reduces the total via count using low effort.
  • medium: Reduces total via count by 15 percent, with negligible runtime overhead. This is the default setting.
  • high: Reduces the total via count by 20 percent to 25 percent, with marginal runtime overhead.

route_detail_min_length_for_spread_wire

route_detail_min_length_for_spread_wire { layer1 length1 ... layerN lengthN }

Default: 0

Data_type: string, read/write

Specifies the minimum length in microns for a wire segment of a net before the necessity for a jog to avoid OPC issues. Spreading wires further apart (creating jogs in the wires) helps avoid design rule violations, signal integrity problems, and yield loss caused by shorts in the wires.

This parameter supports the following values:

  • layer: Specifies the metal layer. The supported metal layer name is Mx, they are Metal1, Metal2, Metal3, etc.
  • length: Specifies the minimum length, in microns. The length value can be a floating number, default, or skip. 
    • The default value is 0, it means wire spreading will determine the threshold automatically.
    • The skip value means there is no wire spreading on this layer.

Note: You should specify the value for each metal layer. To get the number of metal layers used in the design, use db command (dbGet head.layers.name).

Note: Turn wire spreading on or off with route_detail_post_route_spread_wire

This is a root attribute.

  • To set the value of any root attribute, use the set_db command:
    set_db attribute_name value
  • To get the current value of any root attribute, use the get_db command:
    get_db attribute_name

For example, when you specify the following command, no wire spreading is done on layer Metal1. For layer Metal2, the wire spreading value is set to 0 signifying that wire spreading will determine the threshold automatically. Similarly, for layers Metal3, Metal4, Metal5, and Metal6 the wire spreading length is set to 2.0.

set_db route_detail_min_length_for_spread_wire {Metal1 skip Metal2 0 Metal3 2.0 Metal4 2.0 Metal5 2.0 Metal6 2.0 }

route_detail_min_slack_for_opt_wire

route_detail_min_slack_for_opt_wire value

Default: 0.0

Data_type:  double, read/write

Specifies the minimum slack on pins associated with nets that are candidates for wire spreading or wire widening. Using this parameter reduces the timing impact of wire spreading, wire widening, and via swapping, and helps reduce congestion and the yield loss due to shorts and opens.

Note: To enable this attribute, you must also specify route_with_timing_driven true.

Wire spreading and wire widening use the minimum slack value differently. While wire spreading only works for timing critical nets where the worst setup slack is less than the minimum slack value, wire widening only works for non-timing critical nets where the worst setup slack is greater than the minimum slack value.

You can use the  route_detail_min_slack_for_opt_wire attribute to reduce the timing closure effort during post-route ECO. NanoRoute will replace via to multi-cut via on non-critical nets, if a violation does not occur.

route_detail_on_grid_only

route_detail_on_grid_only none | false | true | all | {[wire [metall:metalh]] | [via [metall:metalh]]}

Default: none

Data_type:  string, read/write

Controls the routing of the objects, wires, and vias in relation to the user-defined routing tracks.  

  • On grid wire means that the center of the wire is on the preferred routing track.
  • On grid via means that the center of the via is on the intersection of preferred routing tracks.

Note: A preferred routing track is the track which has the same direction as that of the metal routing direction defined in the LAYER section in LEF.

  • When there are off-grid objects on fully-routed data, NanoRoute skips those nets and issues a warning message.
  • When there are fixed off-grid objects, NanoRoute skips those nets and issues a warning message.
  • When there are non-fixed off-grid objects, NanoRoute deletes those nets and issues a warning message.

Specify one of the following arguments:

  • all: Specifies that all routing objects (vias and wires) have to be on the preferred and non-preferred routing tracks.  It forces all routing objects to be on grid.
  • none: Specifies that the routing objects (vias and wires) can be off-grid. It does not force routing objects to be on grid . They can go off-grid depending on other restrictions.
