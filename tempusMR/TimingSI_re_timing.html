Timing

Use the Timing Analysis form to build the timing graph for the design and generate a slack report and a detailed timing violation report.

  • Choose Timing & SI - Timing.

Fields and Options

Slack Report File

Reports the end point slacks in the design.

Histogram

Generates a histogram of end-point slacks.

Default: On

Count Non-Violating Paths

Generates a histogram consisting of violating and non-violating paths in the design.

Minimum Slack

Specifies the higher bound of the histogram.

Category

Determines on what category the timid report is based.

Path Group

Reports the timing based on the default path groups, including input-to-register, register-to-register, and register-to-output.

Clock Domain

Report the timing based on clock domains.

Generate Violation Report

Generates a timing report that provides information about the various violating paths in the design.

Detailed Report File

Generates a detailed timing report with the specified file name.

Debug Report File

Generates a violation report in machine-readable format with the specified name. This report is used for debugging timing results using the timing debug feature.

Number of Violations To Report

Specifies the number of worst paths in the design on which to report, regardless of the endpoint. This is useful, but can be time consuming if a large number of paths is specified. The paths are always sorted based on slack.

Display Report in Timing Debug Window

Displays the generated .mtarpt file in the Analysis tab.

Report Timing Crit. inst.

Reports timing critical instance (bottleneck) information to the specified file.

Maximum Instance

Specifies the number of worst cost instances to report.

Default: 20

Maximum Slack

Specifies the lower bound of the slack range. Only paths with slack worse than the specified slack value are reported.

Default: 0

Sequential instance

Includes the sequential instances group in the output.

Default: Off

Estimate

Generates a critical instance report based on the fast algorithm (linear-complexity) to give a slightly pessimistic estimation that may include some false paths. Select this option in early design phase.

Default: Off

Cost Type:

Specifies the criteria for choosing the critical instance.

You can use the Maximum Slack and Cost Type options together to filter the paths to only those with slack worse than the specified slack value, then report the filtered set of paths based on the specified cost.

Worst Slack

Sets the criteria as the worst slack of all points that pass through an instance.

Default: On

Total Slack

Sets the criteria as a sum of the slack of the end points.

Default: Off

Start End Point

Sets the criteria as the sum of the total start and end points connected to the instance.

Default: Off

Path End Count

Sets the criteria as the sum of the total paths through the instance.

Default: Off

Statistical Block Based Reporting

Reports timing analysis results based on block-based statistical static timing analysis (SSTA).

Statistical Path Based Reporting

Reports timing analysis results based on path-based SSTA. By default, the software runs block-based SSTA.

Statistical Path Based Worst-RC corner Reporting

Reports timing analysis results based on path-based SSTA with worst RC corner.

Percentile Value

By default, the percentile value is 99.865.

Related Text Commands

The following text command provides equivalent or additional functionality:

  • report_slack_histogram
  • report_timing
  • report_critical_instance

For more information, see "Timing Analysis Commands" in the Tempus Text Command Reference.

Report Detail Timing

Use the Report Detail Timing form to select options for customizing the timing reports.

  • Choose Timing & SI - Report Detail Timing.

Fields and Options

Path

From

Selects the paths starting from the object(s). The supported objects are pins and ports.

To

Selects the paths leading to the pin(s).

Through

Selects the paths that traverse through pin(s) or net(s).

Not Through

Selects the paths that do not traverse through the specified nets, ports, or pins of a cell.

Path Groups

Selects the paths that are contained in path groups.

Path Type

Specifies the format of the report by path type. You can choose one of the following options:

  • end
  • summary
  • full
  • full_clock
  • end_slack_only
  • summary_slack_only

Setting

Early

Generates the timing report for early paths (hold checks).

Late

Generates the timing report for late paths (setup checks).

Views

When you select this option:

  • Select "Setup Views" if you choose Late or Check Type as Setup/ Setup & Hold
  • Select "Hold Views" if you choose Early or Check Type as Hold/ Setup & Hold

Retime

Reanalyzes the specified set of paths using path-based analysis (1 path per endpoint). You can specify the following options:

  • aocv
  • path_slew_propagation
  • aocv_path_slew_propagation

I-PBA

Enables exhaustive path-based analysis mode (IPBA)

nWorst

Specifies the maximum number of paths which can be reported for a particular endpoint.

Default: 1

Max Slack

Reports only those paths with slack less than the specified value.

Default: 0.75

Max Generated Paths

Reports the specified number of worst paths in the design.

Default: 50000

Report

Timing Report File

Specifies the name of the timing report to be generated.

Related Information
