read_power_rail_results


read_power_rail_results
[-help]
[-detail_delta_temperature_file file]
[-effective_resistance_file file]
[-force]
[-instance_delta_temperature_file file]
[-power_db file ]
[-rail_directory dir]
[-tile_delta_temperature_file file]
[-cell_library { library1.cl}]
[-reset]
[-custom_value_inst_file_1 file]
[-nets net_names]
[-instance_voltage_method { best | worst | avg | worstavg }]
[-instance_voltage_window { timing | whole }]
[-instances instancenames]
[-enable_plots plot_names]
[-signal_em_db file]
[-short_file file]
[-esd_directory dir]
[-thermal_file filename.txt]
[-esd_em dir]
[-die_instance_name dieinstname]
[-data_type {rail | all}]
[-profiling_power_file file]
[-tile_thermal_config_file filename]
[-physical_db dir_name]
[-top_cell_name topcell_name]
[-power_directory power_output_directory]

Loading power/rail analysis results into GUI.

Parameters

-help

Outputs a brief description that includes type and default information for each read_power_rail_results parameter.

For a detailed description of the command and all of its parameters, use the man command: man read_power_rail_results.
-cell_library { library1.cl}

Specifies the single cell library that is required to load the state directory. The specified cell library must contain the technology layer information that is required to load the state directory. Therefore, you do not need to load all cell libraries used during analysis.
-custom_value_inst_file_1 file

Specifies the name of the custom value instance file (CVIF). This file can be used to display a user-specified instance voltage file in GUI.

The format of the CVIF file is:

value1    instancename1
value2    instancename2
....

where, value1 and value2 are voltage values mapping to the specified instance.

You can use the cvil argument of the gui_set_power_rail_display -plot command parameter to view the EIV map in GUI.
-data_type {rail | all}

Controls the type of data to be loaded in the GUI. The possible arguments of this parameter are:
  • rail - Loads only the rail analysis results.
  • all - Loads both the power and rail analysis results. This is the default value.

-detail_delta_temperature_file file


Specifies the name of the detailed wire-based delta temperature file from self-heating analysis.
-die_instance_name dieinstname

Specifies the name of the die whose results you need to view. This parameter is only applicable to the multi-die analysis flow (set_rail_analysis_config -die_mode multi-die).

The -die_instance_name parameter must be specified with the -rail_directory parameter (multi-die rail directory).
-effective_resistance_file file

Specifies the result file from effective resistance analysis (only instance-based result is supported). When the rail analysis plot type effr is selected and a result file is specified, the layout shows effective resistance analysis result for each instance.

Note: Currently, this feature only supports loading one net at a time.
-enable_plots plot_names

Specifies the list of power or rail plots names that are to be loaded.
-esd_directory dir

Specifies the ESD analysis directory.
-esd_em dir

Specifies the name of the directory where the current density/EM results generated by a previous ESD analysis run reside. This parameter allows you to selectively load the required EM result directory if there are multiple ESD EM result directories under the ESD directory.

You must either load the rail directory (-rail_directory) before running this command, or specify the rail directory with the -esd_em parameter.
-force



Specifies to block the pop-up window that appears when the read_power_rail_results -reset parameter is specified. The pop-up window displays a confirmation message for resetting the power and rail directories.

Example:

read_power_rail_results -reset -force
-instances instancenames

Specifies a list of instances to load in the GUI. This parameter loads only those partitions that include the specified instances. The -instances parameter allows you to analyze parts of the designs, thereby reducing the loading time and memory footprint.

The -instances parameter is applicable to the Voltus-XP flow only.
-instance_delta_temperature_file file


Specifies the name of the instance-based delta temperature file from self-heating analysis. This is the device instance temperature.
-instance_voltage_method { best | worst | avg | worstavg }

Loads the instance voltage data for the specified EIV computing method. If this parameter is not specified (default), the instance voltage results for all the four methods are loaded.
-instance_voltage_window { timing | whole }

Loads the instance voltage data for the selected EIV window. If this parameter is not specified (default), the instance voltage results for both the timing and switching windows, and the entire rail simulation are loaded.
-nets net_names

Loads only the specified nets in the domain-based state directory to the GUI. If this parameter is not specified with the -rail_directory parameter, all the nets will be loaded.
-power_db file

 

Specifies the power database file. This file was created by using the power_write_db attribute.

-power_directory power_output_directory


Specifies to load the power analysis results and display the power plots directly without loading the rail analysis results.

-profiling_power_file file


Specifies to display the tile-based power density results generated from the vector profiling flow.
-physical_db dir_name Specifies the name of the hierarchical design directory to be loaded to the GUI along with the rail analysis results.
-reset

Frees the loaded analysis state directory or power database from the memory.
-rail_directory dir

 

Specifies the rail analysis directory. You can load all the domain results by selecting the automatically generated analysis directory under the output directory (<domain>_<temp>_<dynamic/avg>_#), or load individual nets by going one level further and selecting the net directory.
-short_file file

Specifies the path to the short violations report (voltus_short.report) . This file is generated using the set_rail_analysis_config -report_shorts true command parameter, and is located in the work directory.
-signal_em_db file

Specifies to read the signal electromigration data from the specified database file generated by the check_ac_limits -report_db command parameter.
-thermal_file filename.txt

Specifies to load the tile-based temperature map file generated by Sigrity PowerDC to be used for both power calculation and IR drop analysis.

The following is an example of reading the thermal map file:
read_power_rail_results -rail_directory output/static_rail/core_25C_avg_1/ -thermal_file output/power_map_by_layer.txt
gui_set_power_rail_display -plot thermal
-tile_delta_temperature_file file

 

Specifies the name of the tile-based delta temperature file of self-heating analysis. This is the worst instance temperature among all wire segments in a tile. This is also layer-based. The FEOL or cell layer is used to show the device instance temperature.
-tile_thermal_config_file filename

Specifies to load the configuration file that contains the mapping between the hierarchical levels with corresponding layer-based temperature map files generated by Celsius (system-level thermal analysis tool). When specified, you can view tile-based temperature distribution for each layer of the chip.

The following is the format and example of the hierarchical configuration file:
<hierarchy>    <block name>    <X_tile_no,Y_tile_no>  <LEF/DEF Flip/Rotation>       <temperature map>
TOP           DIE            0,0            N                 /thermal_data/DIE_TemperatureMap
TOP/IP1       IP1            25,50          N                 /thermal_data/IP1_TemperatureMap
TOP/IP1/B1    B1             50,125         N                 /thermal_data/B1_TemperatureMap
TOP/IP1/B2    B2             200,125        S                 /thermal_data/B2_TemperatureMap

This is a mandatory parameter for the tile_thermal plot when loading hierarchical temperature maps.
-top_cell_name topcell_name

Specifies the name of the top module or top cell name to be loaded. This parameter must be specified with the -physical_db parameter.


Examples

  • The following command specifies the appropriate files needed for viewing the instance voltage and power data:
      read_power_rail_results\
        -rail_directory analysis/domain_25C_avg_1 \
        -power_db powermeter.db \
  • The following command specifies to load only the rail directory:
    read_power_rail_results -rail_directory dynamic_rail/core_25C_dynamic_1 -data_type rail
  • The following command specifies to display the tile-based power density results in the GUI:
    read_power_rail_results -profiling_power_file ./vectorProfileResults/profile.rpt.density
  • The following command specifies to load the power analysis results and display the power plots directly by running the power analysis without loading the rail analysis results:
    read_power_rail_results -power_directory ./dynamic_power
