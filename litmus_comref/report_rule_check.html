report_rule_check

report_rule_check
[<rule_name* ...>]
[-category category_name] ...
[-filter filter_expression [-regexp]]
[-filtered_by filter_name*]
[-limit [natural_number]]
[-nofiltered_out | -filtered_out | -complete | -object_filtered_out]
[-occurrence_count]
[-rule_separation num]
[-sdc_design design_name]
[-sdc_lint command_name*]
[-sdc_mode mode_name]
[-severity severity_name] ...
[-status name]
[-summary | -verbose]
[-spreadsheet file_name.xlsx | -csv file_name.csv]
[-replace]
[-no_header]

Reports the rule occurrences encountered when running the specified rule instances.

Parameters

<rule_name* ...>

Specifies the name(s) of the rule set(s), group(s), or instance(s) to report. This accepts wildcards.

-category <category_name>

Reports only rule instances in the given category.

-filter <filter_expression>

Report only occurrences for which the specified filter_expression evaluates to true. The syntax for filter_expression is the same as for the Tcl find command.

-regexp

Specifies that the pattern matching operators used inside the filter_expression (such as =~) should use regular expressions as patterns, rather than glob-style patterns.

-filtered_by <filter_name*>

Reports only the occurrences filtered by the specified filter(s). Wildcards are accepted.

-limit [<number>]

Specifies the maximum number of occurrences of each rule instance that be reported if the -verbose option is specified. Zero (0) means no limit, which is the default if <number> is not specified.

-nofiltered_out

Reports only occurrences that have not been filtered. This is the default.

-filtered_out

Reports only occurrences that have been filtered.

-complete

Reports all rule occurrences.

-object_filtered_out

Reports only occurrences that are related to the filtered-out objects.

Object filter is specified by add_rule_filter -object_filter.

-occurrence_count

Reports the number of occurrences even if it is zero.

-rule_separation <num>

<num> specifies the number of blank lines to print before each rule is reported. Without this option, no blank lines are printed before each reported rule.

-sdc_design <design_name>

 Reports rule instances in hierarchical flow for design with name 'design_name'.

-sdc_lint <command_name*>

Reports only SDC lint occurrences related to the specified SDC command names. If this option is given, only SDC lint rules will be reported. This accepts wildcards.

-sdc_mode <mode_name>

Reports rule instances in multimode flow for mode with name 'mode_name'.

-severity <severity_name>

Reports only rule instances of the specified severity level.
<name> can be Error, Warning, Note, Ignore, or the name of any severity level added by the add_severity command.

-status

When used with the -sdc_lint option, -status refers to the status of the sdcstmt. Otherwise, -status refers to status of rule instances. When used with -sdc_lint, valid values are pass and fail. Otherwise, valid values are pass, fail, not-run, and inconclusive .
See the Examples section below, for more information.

-summary

Reports a summary of each rule instance that has been run and has rule occurrences. This is the default.

-verbose

Reports extended information for all rule occurrences of each specified rule instance.
-spreadsheet <file_name>.xlsx Reports rule instances in spreadsheet format. File name must end with '.xlsx'. It generates '<file_name>.xlsx' for all of specified rule instances.
-csv <file_name>.csv Reports rule instances in csv format. File name must end with '.csv'. It generates '<file_name>_<rule_name>.csv' for each of specified rule instances.
-replace Overwrites the output file.
-no_header Hides the header in the spreadsheet or CSV file.

Examples

The following command reports a summary of the check results of the rule instances of the Error severity in the CONSTRAINT_LINT category:

report_rule_check -severity error -category CONSTRAINT_LINT

CONST_LINT_* rules with a severity of Warning or Note do not cause an SDC command to fail. Therefore, when you use the "report_rule_check -sdc_lint * -status fail" command, it does not report occurrences of CONST_LINT_* rules that have a severity of Warning or Note; it only reports occurrences of severity Error.

While for all other rule types, rule occurrences of Warning or Note are considered fail and would be included when you issue the following command:

report_rule_check -status fail
