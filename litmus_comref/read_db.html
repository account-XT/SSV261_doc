Litmus Text Command Reference
Product Version 26.10, May 2026

read_db

read_db
[-help]
[-debug]
[-module_dirs list_of_dirs]
[-no_timing_graph]
[-read_globals tcl_file_name]
[-physical_data]
{[<in_dir> [-mmmc_file <string>]] | [-oa_lib_cell_view {<libname> <cellname> <viewname>} [-mmmc_file <string>][-lef_files list_of_files]]} 
[-setup_views <string> -hold_views <string>]
[-leakage_view <string> -dynamic_view <string>]

Loads the saved design files of a previous design session. The files included depend on the work completed in the design session when it was saved. The directory can include floorplan files, special route files, placement files, early global route files, and power switch state files.

To restore designs saved in Litmus format, usage is as follows:
read_db {sessionName.dat}  

Note: You must rebuild the timing graph after you restore the design. Run extraction, then timing analysis.

You must specify all pin types in the LEF file. Without these definitions, the Litmus software attempts to determine the pin type from the pin name when restoring a design, and does not always do this correctly. If this is the case, Litmus generates the following error message:

**ERROR: Current net list does not match wires file.


Modifying the contents of the sessionName.dat directory created by saveDesign can cause major unexpected results. Never modify the design.dat directory contents.


To restore OpenAccess designs, usage is as follows:

read_db
{-oa_lib_cell_view string}

You can use the read_db command after starting the Litmus software.

Note: Litmus supports only the following begin/end extension values for DEF NETS style wiring segments (0, width/2 or LEF LAYER WIREEXTENSION). If any of the wire extensions has unsupported extension value, then Litmus converts it to a special wire (DEF SPECIALNETS). While writing back OpenAccess, these special wires will again be converted back to DEF NETS style wiring.

From the 14.1 release, the read_db command accepts a tar file, when a tar ball is given. For instance, if you specify the following command:

read_db myDesign.inn.dat.tar.gz

read_db will untar the tar ball under the current working directory, restore the design, and then remove the temporary data directory. This enables a single DB file operation all the time.

Parameters 

-help

Prints a brief description that includes the type and default information for each read_db parameter.

For a detailed description of the command and all of its parameters, use the man command:
man read_db
-dynamic_view string Specifies the analysis view for the dynamic power analysis.
-debug Enables debug data.
-hold_views string Specifies the hold views for loading, rather than the hold views active during write_db.
in_dir Specifies the .dat directory from which to load the files. If the session name of the saved design includes the extension .enc, make sure that you include this extension in the in_dir name: for example, session1.enc.dat.
-leakage_view string Specifies the analysis view for leakage power analysis.
-lef_files list_of_files

Specifies the LEF files name for loading. Use this option if you want to override the existing LEF files in the design being restored and load different LEF files instead.

  • This option is intended to allow upgrading to new versions of LEF files that are compatible with the old versions. The list of all LEF files used by this design must be given.
  • If any pin locations or cell boundaries or OBS shapes are changed for used cells, new DRC violations may occur.
  • If pins are added or removed from used cells, or used cells are removed, fatal errors may occur when loading the netlist.
  • If the removed pins and cells are unused in the design, warnings or errors may still occur if any library-specific data was stored for those cells or pins during the design flow (such as dont_touch data)

Examples

Existing LEFs used by write_db: tech.lef, A.lef

You can change A.lef to A_v2.lef as given below: 
read_db place.dat -lef_files {tech.lef A_v2.lef}
-mmmc_file Specifies the path name to a Multi-Mode/Multi-Corner (MMMC) configuration file (viewDefinition.tcl). Use this option if you want to override the settings in the existing MMMC configuration file in the design being restored and instead load a different MMMC file.
-module_dirs list_of_dirs Specifies module-level sessions which should override the corresponding modules in the top-level hierarchical session.
-no_timing_graph

Restores the design data without a timing graph.

-oa_lib_cell_view string

Specifies the library name, cell name, and view name for restoring design information from the previous design session in the OpenAccess database format.
-physical_data

Enables physical data to be read.
-read_globals tcl_file_name

Specifies the UDM variables to be honored when restoring the design. You need to provide a tcl file stating the pre-defined UDM variable names to be honored.
-setup_views string Specifies the setup views for loading rather than the setup views active during write_db.

Examples

  • The following command loads the saved design files from the test.inn.dat directory:
    read_db test.inn.dat
  • The following command restores the my.enc.dat design without loading the timing libraries and MMMC configuration information:
    read_db -no_timing_graph my.inn.dat 
  • The following command restores the placed.enc.dat design but overrides the existing MMMC settings in the design with the settings in the new_mmmc.tcl file:
    read_db placed.inn.dat -mmmc_file new_mmmc.tcl
  • The following command restores the "designLib top placed" OpenAccess cellview but overrides the existing MMMC settings in the design with the settings in the new_mmmc.tcl file:
    read_db -oa_lib_cell_view "designLib top placed" -mmmc_file new_mmmc.tcl
