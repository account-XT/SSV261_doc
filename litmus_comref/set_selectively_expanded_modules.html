set_selectively_expanded_modules

set_selectively_expanded_modules
[-help]

While performing Static Timing Analysis (STA) or Engineering Change Orders (ECO), very large designs often contain modules with a high number of instantiations. Creating RTL-level configurations for smaller portions of such designs is often challenging.

The set_selectively_expanded_modules command addresses this issue by specifying modules with instantiations that are to be abstracted, or are not timed, based on the specifications set through the set_expanded_hinsts command.

This reduces memory usage and runtime significantly during the STA and ECO processes. It helps in handling large designs on smaller machines and facilitates ECO implementation without the need of manually partition the design into smaller segments.

  • This command is recommended exclusively for modules with high instantiation counts and is not recommended to use for single-instance modules.
  • All STA views must use consistent flattening specifications. For ECO, the same netlist and flattening specifications must be loaded to ensure alignment.

Parameters

-help

Prints a brief description that includes the type and default information for each set_selectively_expanded_modules parameter.

For a detailed description of the command and all its parameters, use the man command:

man set_selectively_expanded_modules

Examples

  • The following command set presents an example of instantiation of a and c modules, which are selectively expanded:
    read_lib my_lib
    read_verilog my_verilog   # instantiations of modules “a” and “c” are to be selectively expanded
    set_selectively_expanded_modules “a c”   # expand “u1” and “u1/u2”
    set_expanded_hinsts “u1 u1/u2”; # No order requirement: “u1/u2 u1”   is OK, too
    set_top_module top
    Netlist:
    module top;
      a u1; a u2;
    endmodule
    module a;
      b u1; c u2; c u3;
    endmodule
    module b;
      BUFX2 u1;
    endmodule
    module c;
      BUFX2 u1;
    endmodule

    Following is the expansion result of the above example:
    COMPONENTS 4 ;
      - u1/u1/u1 BUFX2 ;
      - u1/u2/u1 BUFX2 ;
      - u1/u3 c ;
      - u2 a ;END COMPONENTS
  • The following command set presents an example of instantiation of c module, which is selectively expanded:
    read_lib my_lib
    read_verilog my_verilog  # instantiations of modules “c” are to be selectively expanded
    set_selectively_expanded_modules “c”   # expand “u1/u2”, “u2/u2” and “u2/u3”
    set_expanded_hinsts “u1/u2 u2/u2 u2/u3”
    set_top_module top
    Netlist:
    module top;
      a u1; a u2;
    endmodule
    module a;
      b u1; c u2; c u3;
    endmodule
    module b;
      BUFX2 u1;
    endmodule
    module c;
      BUFX2 u1;
    endmodule

    Following is the expansion result of the above example:
    COMPONENTS 6 ;
      - u1/u1/u1 BUFX2 ;
      - u1/u2/u1 BUFX2 ;
      - u1/u3 c ;
      - u2/u1/u1 BUFX2 ;
      - u2/u2/u1 BUFX2 ;
      - u2/u3/u1 BUFX2 ;
    END COMPONENTS
  • The following command set presents an example of instantiation of b and c modules, which are selectively expanded:
    read_lib my_lib
    read_verilog my_verilog   # instantiations of modules “b” and “c” are to be selectively expanded
    set_selectively_expanded_modules “b c”   # expand “u2/u1”, “u2/u2” and “u2/u3”
    set_expanded_hinsts “u2/u1 u2/u2 u2/u3”
    set_top_module top
    Netlist:
    module top;
      a u1; a u2;
    endmodule
    module a;
      b u1; c u2; c u3;
    endmodule
    module b;
      BUFX2 u1;
    endmodule
    module c;
      BUFX2 u1;
    endmodule

    Following is the expansion result of the above example:
    COMPONENTS 6 ;
      - u1/u1 b ;
      - u1/u2 c ;
      - u1/u3 c ;
      - u2/u1/u1 BUFX2 ;
      - u2/u2/u1 BUFX2 ;
      - u2/u3/u1 BUFX2 ;
    END COMPONENTS
  • The following command set presents an example of instantiation the a module, which is selectively expanded:
    read_lib my_lib
    read_verilog my_verilog  # instantiations of modules “a” are to be selectively expanded
    set_selectively_expanded_modules “a”  # do not expand any instantiation of “a”
    set_expanded_hinsts “”; # Note: same result if this line is removed
    set_top_module top
    Netlist:
    module top;
      a u1; a u2;
    endmodule
    module a;
      b u1; c u2; c u3;
    endmodule
    module b;
      BUFX2 u1;
    endmodule
    module c;
      BUFX2 u1;
    endmodule

    Following is the expansion result of the above example:
    COMPONENTS 2 ;
      - u1 a ;
      - u2 a ;
    END COMPONENTS
