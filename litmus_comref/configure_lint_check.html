configure_lint_check

configure_lint_check <cmd_name> {
   command {
        usage { supported | unsupported | forbidden | unhandled}
        is_sdc_compliant { yes | no }
        warn_if_overwritten { yes | no }
        mandatory_options { <option> | <option> [ | <option> ]* }
        recommended_options { <option> | <option> [ | <option> ]* }
        mutex_options { <option> | <option> [ | <option> ]* }
        append_msg { lint_rule_name "msg" }
   }
   <option> {
        usage { mandatory | recommended | dontcare | forbidden | unsupported}
        is_sdc_compliant { yes | no }
        required_options { <option> [ | <option> ]* }
        valid_types { [<type>]+ }
        valid_values < [<pattern>]+
   }
   valid_range { <Tcl expression> }
   valid_object_types { [<object_type> [-if <expression>] ]+ }
   flag_on_object_types { [<object_type> [-if <expression>] ]* }
   append_msg { <lint_rule_name> "msg" }
}

Configures the parameters that affect SDC lint checks.

Parameters

Parameters for command

usage

supported: Command is supported in the SDC file. No checks are flagged.

unsupported: Command is not supported in the SDC file. CONST_LINT_CMD2 rule check is flagged every time the command is used.

forbidden: User-defined forbidden command in the SDC file. Specifies that the command, although valid (in Litmus CD and the target tool), cannot be used in the SDC file. CONST_LINT_CMD3 is flagged every time the command is used.

unhandled: User-defined unhandled command in the SDC file. Specifies that the command is valid in Litmus, but is not valid in the target tool. CONST_LINT_CMD8 is flagged every time the command is used.
is_sdc_compliant

yes: Specifies that this command is SDC compliant. No checks are flagged.

no: Specifies that the command is not SDC compliant. CONST_LINT_CMD4 is flagged every time the command is used.
warn_if_overwritten

yes: Issues a command each time this command is overwritten. CONST_LINT_CMD6 is flagged each time this command is overwritten.

no: Do not issue a warning if this command is overwritten.
mandatory_options

Species that at least one of the listed options must be specified for the given command. CONST_LINT_OPT6 is flagged each time the given command is used without any of the specified options.

You can specify more than one set of mandatory options.
recommended_options

Specifies that at least one of the listed options is recommended for the given command. CONST_LINT_OPT7 is flagged each time the given command is used without any of the listed options.

You can specify more than one set of recommended options.
mutex_options

Specifies that the listed options are mutually exclusive for the given command. CONST_LINT_OPT8 is flagged each time the given command is used with more than one of the listed options.

You can specify more than one set of mutually exclusive options.
append_msg Append the specified message to each occurrence of the specified lint rule check.

Parameters for option

usage

mandatory: Option is mandatory in the SDC command. CONST_LINT_OPT6 rule check is flagged each time the given option is not used.

recommended: Option is recommended in the SDC command. CONST_LINT_OPT7 is flagged each time this option is not used.

dontcare: No checks are flagged.

forbidden: Option is forbidden in the SDC command. CONST_LINT_OPT4 is flagged each time this option is used.

unsupported: Option is not supported in the SDC command. CONST_LINT_OPT2 rule check is flagged every time the option is used. When an option is specified as unsupported, you cannot modify it; if Litmus encounters an SDC command with an unsupported option, it will ignore the option.
is_sdc_compliant

yes: Specifies that this option is SDC compliant. No checks are flagged.

no: Specifies that the option is not SDC compliant. CONST_LINT_OPT4 is flagged every time the command is used.
required_options

Specifies that at least one of the listed options must be specified if the given option is used. CONST_LINT_OPT5 is flagged each time the given command is used without any of the specified options.

You can specify more than one set of required options.
valid_types

Specifies a list of valid types for the value(s) of the given option. CONST_LINT_VAL2 is flagged each time a specified value does not match one of the listed values. Accepts wildcards. The following are the valid types: enum, string, float, boolean, integer, explicit_or_implicit_obj, and explicit_obj.

See Examples section for more information.
valid_values

Specifies a list of valid values for the given option. CONST_LINT_VAL3 is flagged each time a specified value does not match one of the listed values. Accepts wildcards.

To specify an AND condition between lists of valid values, each list must be on a separate line. For example:
valid_values *b

valid_values {a* c*}

specifies that the tool allows values that start with a or c AND end with b.
valid_range Specifies a Tcl expression that determines if a specified value has a valid range or not. The expression should evaluate to 1 (true) if the value has a valid range.
CONST_LINT_VAL4 is flagged each time a specified value is out of range. Two predefined variables can be used in the expression: $value is the value being checked and $length is the number of elements if the value is a list.
valid_object_types Specifies a list of valid object types for the given option. CONST_LINT_REF4 is flagged for every object of an invalid type. In addition, you can define an expression (in the format accepted by the find command) to determine if an object of a certain type is valid. If the expression evaluates to true, the object is valid. See Supported Object Types.
flag_on_object_types

Specifies a list of object types that are not recommended for the given option. CONST_LINT_REF7 is flagged each time one of the specified object types is used.

See the Examples section for an example that uses an expression to specify the object type.
append_msg Append the specified message to each occurrence of the specified lint rule check.

Supported Object Types

The following lists the supported object types:

port Any type of port: input_port, output_port, or inout_port.
net Type of net. leaf_net specifies a net with a leaf-level driver pin.
hier_net Hierarchical net.
pin Any type of pin: leaf_cell_pin (pin must be a leaf cell pin), timing_exc_start_point (clock pin of a DFF/DLAT, a data pin of a DLAT, or a pin with input or output delay specified), or timing_exc_end_point (clock pin of a DFF/DLAT or a data pin of a DLAT, or a pin with output delay specified).
hier_cell_pin Hierarchical pin.
cell Any type of cell: hier_cell (hierarchical cell), leaf_cell (non-root, nonhierarchical; includes black boxes, library cells and RTL primitives), seq_cell (sequential element), or library_cell (library cell).
clock Any type of clock: virtual_clock, real_clock, or generated_clock.
design Any type of design.
lib_cell Library cell.
lib_pin Library pin.
lib Library.

Examples

The following command changes the valid values of the -analysis type option and makes the -max option mandatory in the set_operating_conditions command:

configure_lint_check set_operating_conditions {
-analysis_type { valid_values { single bc_wc } }
-max { usage mandatory }
}

The following command specifies that input ports are the only valid objects for the object list of the set_clock_uncertainty command:

configure_lint_check set_clock_uncertainty {
object_list {
valid_object_types {
port -if "(direction==in)"
}
}
}

The following command specifies that any clock name specified for the create_clock command must start with clk and the period specified must be between 0 and 10:

configure_lint_check create_clock {
-name { valid_values clk* }
-period { valid_range { (($value>=0) && ($value <= 10)) } }
}

The following command specifies that the -min option is required when using the -max option in the set_clock_transition command:

configure_lint_check set_clock_transition {
-max { required_options { -min } }
}

The following command specifies that only objects (not strings) can be specified for the set_clock_transition command:

configure_lint_check set_clock_transition {
clock_list { valid_types object }
}

The following command specifies that the set_level_shifter_strategy is not supported:

configure_lint_check set_level_shifter_strategy {
command { usage unsupported }
}

The following command specifies that the message "Unhandled for RC" be appended each time CONST_LINT_OPT10 is triggered for the -reset_path option of the set_false_path command:

configure_lint_check set_false_path {
-reset_path { append_msg { CONST_LINT_OPT10 "Unhandled for RC" } }
}

The following command specifies that objects for the create_clock command can be specified with or without a corresponding get* command that specifies the object type:

configure_lint_check create_clock {
source_objects { valid_types explicit_or_implicit_obj }
}

With the following command, objects for the create_clock command that are specified by name, but do not have a corresponding get* command that specifies their object type, will trigger the CONST_LINT_REF5 rule check since this option has more than one available object type (port, pin, and net):

configure_lint_check create_clock {
source_objects { valid_types explicit_obj }
}

The following example specifies a pin whose is_start_point attribute is false is not recommended:

configure_lint_check create_clock {
flag_on_object_types { pin -if {!is_start_point}}
}
