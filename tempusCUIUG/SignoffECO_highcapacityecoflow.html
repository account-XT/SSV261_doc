High Capacity ECO Flow for Timing and Power Closure

The High Capacity ECO flow is used to perform timing and power closure on large netlists. This flow allows huge reduction of the database being used during ECO phase, and therefore reduces the memory peak and runtime significantly.

Based on the user-defined settings, the database is reduced using any of the following methods:

  • Reduction based on the timing violations seen during STA (Setup/Hold/DRV).
  • Reduction based on list of partitions to be optimized for inter or intra timing paths.
  • Reduction based on the user-defined path groups and list of DRV violated nets or pins.

To use this flow, Tempus ECO follows two approaches:

  • Run STA in independent Tempus sessions (SMSC or CMMMC or DMMMC) in order to collect the ECO timing DB. And, then run an ECO session (MMMC) with Physical data to perform timing/power closure. This methodology is known as the Two Sessions flow. In this flow, the settings must be provided during the STA sessions before performing ECO DB generation in order to decide on what criteria the database should be reduced.
    This methodology also supports D-STA for ECO timing DB generation.

The following figure describes the different flow steps required for the user to complete initial STA for ECO DB generation, ECO physical-aware timing/power closure, ECO implementation at block and top only levels, and final STA with implemented ECO.

Figure -8 Steps for Completing STA

Step 1: Run full flat timing analysis and ECO DB generation for each view.

Step 2: Physical aware timing closure in MMMC mode on reduced violating zone database.

Step 3: Implement ECOs independently at top-level and block-level in Placement and Route (P&R) tool.

Step 4: Run full flat final timing analysis.

  • Run Tempus Paradime to start Tempus clients (one per view) and each client collects data so that the master session can run ECO fixing in MMMC mode with Physical data in order to perform timing/power closure. This methodology is known as the Paradime flow. In this flow, the settings must be provided before the distributed design loading on clients in order to decide on what criteria the database should be reduced.

The following figure describes the different flow steps required for the user to run Tempus Paradime for ECO physical aware timing/power closure, ECO implementation at block and top only levels, and final STA with implemented ECO.

Figure -9 Steps for Running Tempus Paradime

Step 1: Start Paradime with Physical data on saved sessions, and select the desired sub-part of the design to focus on (for example, top-only, or some partitions, or some path groups, or some endpoints..)

Step 2: Implement ECOs independently at top-level or block-level in P&R tool.

Step 3: Run full flat final timing analysis.

In order to use the flow set up, below are the templates for the Two Sessions and Paradime flows, which uses three different database reduction mode:

Template 1: The Two Sessions flow performs full chip Hold timing closure on a reduced database based on the timing violations seen during STA. You can choose to enable either GBA or PBA mode.

Session1: The STA session can be SMSC, MMMC, or DMMMC. 

<load_design_logical_mode_with_SPEF>
set_db opt_signoff_enable_high_capacity_eco true
set_db opt_signoff_retime path_slew_propagation
set_db opt_signoff_max_path 5000000 
set_db opt_signoff_nworst 50
set_db opt_signoff_max_slack 0
set_db opt_signoff_pba_effort high
set_db opt_signoff_save_eco_opt_db HC-ECO-DB
set_db power_dynamic_power_view setup_ss_1p170v
set_db opt_signoff_write_eco_opt_db HC-ECO-DB
write_eco_opt_db

Session2: The ECO DB directory must be provided in the script before the design is loaded.

set_multi_cpu_usage -local_cpu 32
set_db opt_signoff_read_eco_opt_db HC-ECO-DB
read_physical -lefs {../libs/lef/FreePDK45_lib_v1.0.lef\     ../libs/MACRO/LEF/pllclk.lef \     ../libs/MACRO/LEF/ram_256X16A.lef \     ../libs/MACRO/LEF/rom_512x16A.lef }
read_mmmc viewDefinition.tcl
read_netlist “top.v blockA.v blockB.v”
init_design
set_db add_fillers_cells_<options>
read_hierarchical_def top.def blockA.def blockB.def
<load SPEFs>
set_db opt_signoff_pba_effort high
set_db opt_signoff_partition_list_file partition.txt
set_db opt_signoff_optimize_replicated_modules true 
opt_signoff –hold

Template 2: The Two Sessions flow to perform inter-partition Hold timing closure on a reduced database based on a user-defined partition during STA.

Session 1: The STA session can be SMSC, MMMC or DMMMC. 

<load_design_logical_mode_with_SPEF>
set_db opt_signoff_enable_high_capacity_eco true
set_db opt_signoff_inter_partition {blockA blockB} 
set_db opt_signoff_intra_partition {} 
set_db opt_signoff_retime path_slew_propagation
set_db opt_signoff_max_path 5000000 
set_db opt_signoff_nworst 50
set_db opt_signoff_max_slack 0
set_db opt_signoff_pba_effort high
set_db opt_signoff_save_eco_opt_db HC-ECO-DB
set_db power_dynamic_power_view setup_ss_1p170v
set_db opt_signoff_write_eco_opt_db HC-ECO-DB
write_eco_opt_db

Session 2: The ECO DB directory must be provided in the script before the design is loaded.

set_multi_cpu_usage -local_cpu 32
set_db opt_signoff_read_eco_opt_db HC-ECO-DB
read_physical -lefs {../libs/lef/FreePDK45_lib_v1.0.lef\                ../libs/MACRO/LEF/pllclk.lef \             ../libs/MACRO/LEF/ram_256X16A.lef \                ../libs/MACRO/LEF/rom_512x16A.lef }
read_mmmc viewDefinition.tcl
read_netlist “top.v blockA.v blockB.v”
init_design
set_db add_fillers_cells_<options>
read_hierarchical_def top.def blockA.def blockB.def
<load SPEFs>
set_db opt_signoff_inter_partition {blockA blockB}  
set_db opt_signoff_intra_partition {} 
set_db opt_signoff_pba_effort high
set_db opt_signoff_partition_list_file partition.txt
set_db opt_signoff_optimize_replicated_modules true 
opt_signoff –hold

The same template can be used to perform inter-partition Power recovery.

Template 3: The Two Sessions flow performs DRV, Setup, Hold timing closure on a reduced database based on the user-defined Setup/Hold path_groups and a list of DRV pins during STA.

Session 1: The STA session can be SMSC, MMMC or DMMMC. 

<load_design_logical_mode_with_SPEF>
<TCL script which creates mySetupPG and myHoldPG path_groups>
set_db opt_signoff_enable_high_capacity_eco true
set_db opt_signoff_include_setup_path_groups {mySetupPG}
set_db opt_signoff_include_hold_path_groups {myHoldPG}
set_db opt_signoff_select_drv_pin_file {myDRVPinList.txt} 
set_db opt_signoff_retime path_slew_propagation
set_db opt_signoff_max_path 5000000 
set_db opt_signoff_nworst 50
set_db opt_signoff_max_slack 0
set_db opt_signoff_pba_effort high
set_db opt_signoff_save_eco_opt_db HC-ECO-DB
set_db power_dynamic_power_view setup_ss_1p170v
set_db opt_signoff_write_eco_opt_db HC-ECO-DB
write_eco_opt_db

Session 2: The ECO DB directory must be provided in the script before the design is loaded.

set_multi_cpu_usage -localCpu 32 
set_db opt_signoff_read_eco_opt_db HC-ECO-DB
read_physical -lefs {../libs/lef/FreePDK45_lib_v1.0.lef\     ../libs/MACRO/LEF/pllclk.lef \     ../libs/MACRO/LEF/ram_256X16A.lef \     ../libs/MACRO/LEF/rom_512x16A.lef }
read_mmmc viewDefinition.tcl
read_netlist “top.v blockA.v blockB.v”
init_design
set_db add_fillers_cells_<options>
read_hierarchical_def top.def blockA.def blockB.def
<load SPEFs>
set_db opt_signoff_include_setup_path_groups {mySetupPG}
set_db opt_signoff_include_hold_path_groups {myHoldPG}
set_db opt_signoff_select_drv_pin_file {myDRVPinList.txt} 
set_db opt_signoff_pba_effort high
set_db opt_signoff_partition_list_file partition.txt
set_db opt_signoff_optimize_replicated_modules true
opt_signoff –drv; opt_signoff –setup; opt_signoff -hold

Template 4: The Paradime flow performs a full chip Hold timing closure on a reduced database based on timing violations from the STA clients. You can choose to enable either GBA or PBA mode.

The STA saved session can be SMSC or MMMC.

set_distributed_hosts -local -time_out 10000
set_multi_cpu_usage -local_cpu 24 -remote_host 4 -cpu_per_remote_host 4 
set_distributed_mmmc_mode -eco true
set_distributed_mmmc_mode -eco_merge_mmmc
set_distributed_mmmc_mode -enable_high_capacity_eco 
set_db eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set_db eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set_db eco_dynamic_view {setup_3v} ; set_db eco_leakage_view {setup_3v}
set_db eco_lef_file_list “tech.lef std.lef ram_256X16A.lef"
set_db eco_def_file_list “top.def blockA.def blockB.def "
set_distributed_mmmc_mode -set_filler_mode {-corePrefix FILL}
distribute_read_db -restore_design all -restore_dir PARADIME_SESSIONS_211/ -out_dir reports_Paradime
set_db opt_signoff_retime path_slew_propagation
set_db opt_signoff_max_path 5000000 
set_db opt_signoff_nworst 50
set_db opt_signoff_max_slack 0
set_db opt_signoff_pba_effort high
set_db opt_signoff_partition_list_file partition.txt
set_db opt_signoff_optimize_replicated_modules true 
opt_signoff –hold
