Design Import Flow

The design import flow involves the following steps:

  • Initializing the design
  • Writing the design
  • Reading the design

Initializing the design involves reading the timing data, physical data, HDL/netlist, and power intent data. After initialization, the design is in consistent state and is ready for timing analysis.

There are two main types of initialization:

  • MMMC Timing Initialization
  • Simple Timing Initialization

MMMC Timing Initialization

The MMMC (multi-mode multi-corner) timing initialization uses the read_mmmc command to load a MMMC configuration file with the timing setup data. The physical data can optionally be loaded into Tempus to support physical flows, such as Tempus ECO. The power intent data is required for all multi-supply, multi-voltage (MSV) designs. This flow is common to all the tools and supports all the optimization and analysis flows.

The following is an example script to import MMMC data: 

read_mmmc top.mmmc                          #required
read_physical -lef {tech.lef stdcell.lef}   #optional in Genus, Tempus, 
                                            #required for Innovus
read_netlist top.v                          #required, Genus also allows
read_hdl/elaborate                          #Genus only
read_power_intent -1801 top.1801            #required for power domain designs
init_design                                 #required
read_def top.def                            #optional in all tools

The above flow is described below:

  • read_mmmc will create the library_set, rc_corner, timing_condition, constraint_mode, and analysis_view objects as specified in the MMMC file. It will also load the timing libraries required by the active views from the set_analysis_view command in the MMMC file. The reading of other files like SDC constraints is deferred until init_design. During init_design, only the files required by the active views from the set_analysis_view command are loaded. Timing libraries or constraint files for non-active views are not loaded unless those views are made active with set_analysis_view later in the flow.
  • read_physical is used to load LEF or OA technology data and physical library data. This command is required by Innovus and can be optionally loaded in Tempus and Genus to support physical design flows.
  • read_netlist is used to load a Verilog gate-level netlist, or an OA netlist. Genus also allows the usage of read_hdl/elaborate instead of read_netlist to synthesize an RTL netlist (see the Genus documentation for details).
  • read_power_intent can optionally be used to load a power intent file (IEEE 1801, or CPF). The power data is incomplete until the binding done with the timing data during init_design. A power intent description in either CPF or IEEE 1801 format is generally required for MSV designs.
  • init_design loads any deferred timing data from read_mmmc above, and binds the timing data to the netlist, and binds the analysis views to any power domains, if needed. Various consistency checks are done, and after this step the design is ready for use.
  • read_def can optionally be used to load an initial DEF file after init_design. Innovus also allows read_floorplan to read in a previously saved floorplan file instead of read_def. After read_def is done, it is important to run commit_power_intent -keep_rows -power_domain to make sure any DEF GROUPS statements (or floorplan file Groups section) has not changed the power_domain group definitions, but keep the rows from the DEF or .fp file.

To load a design in DMMMC mode, refer to the “Distributed Multi-Mode Multi-Corner Timing Analysis” chapter of the Tempus User Guide.

Simple Timing Initialization

A single timing mode and delay corner (SMSC) analysis can use read_libs and read_sdc commands instead of loading a MMMC file using read_mmmc. The physical data is optional, and power intent is not supported. This is intended for simple synthesis flows or timing signoff analysis that only deals with one timing mode and delay corner at a time.

A typical initialization script is shown below:

read_libs all.lib           #required
read_netlist top.v          #required
read_sdc top.sdc            #required
init_design                 #required

The above flow is described below:

  • read_libs will save the file names, but defer reading them until the netlist is read. To configure the physical aware ECO flow of Tempus, use read_physical to add physical library data after read_libs.
  • read_netlist will load the timing libraries and a Verilog netlist, or an OA netlist. read_sdc will read in the SDC timing constraints into the analysis.
  • init_design does various consistency checks, finishes setting some default initialization values, and after this step the design is ready for use. To configure the physical aware ECO flow of Tempus, use read_def (after this step), to load a DEF file.

When the data is imported using non-MMMC commands, Tempus internally stores it in the MMMC configuration as the following MMMC objects:

default_emulate_view
default_emulate_delay_corner
default_emulate_rc_corner
default_emulate_libset_max
default_emulate_libset_min
default_emulate_constraint_mode
