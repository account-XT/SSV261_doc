check_design

 check_design 
[-id violation_id]
[-out_file fileName]
{[-type {library netlist power_intent timing hierarchical pin_assign budget assign_statements place opt cts route signoff all} [-format {table detail}] |-type_3d {tech_lib netlist power_intent timing place floorplan route report_only all}}][-no_check ]} 

Checks that all prerequisites to run all or part of the hierarchical or block implementation flow are met. The check_design command checks the preconditions for the major flow steps before they are run. You can run these checks standalone using the check_design command. If there are errors in the check_design run, the current script will stop.

Parameters

-help

Prints a brief description that includes the type and default information for each check_design parameter.

For a detailed description of the command and all of its parameters, use the man command:
man check_design
-format {table detail}

Specifies the format for reporting violations.

  • table: Prints the results in the table format.
  • detail: Prints details of violations.
-id violation_id

Specifies the violation IDs.
-type

Specifies the category of the flow to be checked:

  • power_intent: Performs checks related to MSV setup including power domain/fence checks.
  • timing: Performs checks related to timing setup integrity.            
  • hierarchical: Performs check if the partition has a fence and if the fence is inside the core boundary.
  • pin_assign: Performs checks related to pin assignment for partitioning flows.
  • budget: Performs checks related to time budgeting for partitioning flows.
  • assign_statements: Performs checks for the netlist for assign statements.
  • place: Performs checks related to placement such as PG rail alignment and pin access issues.
  • opt: Performs checks related to optimization such as checks for available cells.
  • cts: Performs checks related to clock tree definition such as constraint targets and route types.
  • route: Performs checks related to routing such as congestion, placement, and pin access issues.
  • signoff: Checks related to the signoff activities including extraction and ECOs.
  • all: Runs all categories.
-type_3d {tech_lib netlist power_intent timing place floorplan route report_only all}}

Specifies the 3DIC design categories to check. You can specify  single or multiple categories

  • tech_lib
    • Checks the library integrity and corrects binding 
    • Checks all timing lib wh
  • netlist
    • Checks the library integrity and corrects binding
  • power_intent
    • Checks related to MSV setup including power domain/fence checks.
    • Checks related power domain bind to correct design
  • timing
    • Performs checks related to timing setup integrity.
  • place
    • Checks related to placement such as pin alignment
  • floorplan
    • Checks related to floorplanning
  • route
    • Checks related to routing
  • all
    • Checks all categories
-no_check

Just echo out all the messages that would be checked, don't do any checks

Do not run the checks but echo the checks that would run per the categories provided by the user

-out_file fileName

Specifies the output report file. Contents dumped to this file in the Tcl format.
