report_constraint

report_constraint
[-help]
[-all_violators]
[-verbose]
[-late]
[-early]
[-em_type {peak | rms | avg | all}]
[-check_type { pulse_width | clock_period | recovery | removal | clock_gating_setup | clock_gating_hold | skew | pulse_clock_max_width | pulse_clock_min_width | electromigration | rail_swing}]
[-clock]
[-connection_class]
[-data]
[-drv_abs_margin float]
[-drv_fields {field_list}]
[-drv_output_format {txt|csv}]
[-drv_ratio_margin float]
[-drv_violation_type { max_capacitance | max_transition | max_fanout | min_capacitance | min_transition | min_fanout | pulse_clock_max_transition | pulse_clock_min_transition}]
[-max_pins_per_drv <integer>]
[-retime {aocv | path_slew_propagation | aocv_path_slew_propagation}]
[-retime_mode {path | exhaustive}]
[-view viewName ]
[-worst_drv_per_net]
[ pin_port_list ]
[{> | >>} filename[.gz]]

Reports constraint information of the current design. The constraints information includes information such as whether or not a constraint is violated, by how much, and the worst violator object.

The following timing checks are reported when you use the report_constraint command:

  • All setup and hold checks
  • DRV
  • Clock and asynchronous checks including pulse_width, min_period, recovery, removal, clock_gating_setup, clock_gating_hold, skew

You can specify the design rule constraints on pins, ports, cells, or a design using the commands: set_min_fanout, set_max_fanout, set_min_transition, set_max_transition, set_min_capacitance, and set_max_capacitance.

The report_constraint command checks against the worst design rule constraint between the library constraint limit and the user-specified constraint value when both are applied to the violating pin or port.

The report_constraint command supports multi-threaded reporting. You can make the following settings to enable multi-threaded reporting:
set_multi_cpu_usage -localCpu number_of_CPU
set_table_style -no_frame_fix_width [-nosplit]

By default, the report_constraint command reports only the mean slews in transition DRV checks. You can enable DRV checking to use mean as well as the n-sigma slew values (in SOCV mode), with the following setting:
set timing_report_max_transition_check_using_nsigma_slew true

The report_constraint command allows merging of reports. The following check type report outputs from various MMMC analysis views can be merged into a single report using the merge_timing_reports command:

  • min/max delay reports
  • recovery/removal reports
  • DRV reports
  • pulse width reports
  • skew/period checks

The input reports must be created with the reporting table format conforming to the set_table_style -no_frame_fix_width -nosplit format, which can be any of the following:

  • group or non-group
  • verbose or non-verbose
  • compressed or uncompressed

The merged report will have endpoints from various views sorted in order of slack. For a pin reported from multiple analysis views, slack from all the views is available.

You can use a one-step method for generating merged MMMC view reports from the DMMMC master shell. After running the  distribute_views command, you can issue the report_constraint command, which generates reports collectively from all active distributed views (that is, views available for interactive DMMMC analysis). The merged output report is arranged according to slack/criticality order across active views.
All the options of the report_constraint command are supported in this mode.

Configurable DRV Reports

Tempus allows you to perform design rule violation (DRV) checks to ensure that the netlist meets the design rule constraints specified in the design library. To enable configurable DRV reporting, you can use the timing_report_constraint_format global variable. For example,

set timing_report_constraint_format {list of DRV fields}
report_constraint –drv_violation_type {list of DRV checks} \
        –all_violators | pin_or_port_list

You can also use the following command to specify DRV fields:

report_constraint -drv_violation_type {list of DRV checks} -drv_fields field_list

The field list specified with the -drv_fields parameter has higher precedence and will override the field list specified with the timing_report_constraint_format global variable. If DRV fields are not specified with this global variable (or with the report_constraint -drv_fields command), then the default set of DRV fields will be displayed. For a complete list of DRV fields, refer to the DRV Fields table.

For more information, refer to the Design Rule Violation (DRV) Reporting section in the Tempus User Guide.

Parameters 

-help Prints out the command usage.

{> | >>} filename

When specified with >, writes the report to the specified file name. If the file already exists, the software overwrites it.

When specified with >>, writes the report to the specified file name. If the file already exists, the software concatenates the report to the end of the file.

The filename parameter must be the last argument in the list.

Note: To write a compressed report, add the .gz extension to the file name.

Default: Report is displayed on standard output without being saved.

-all_violators

Reports the worst negative slack per violating pin against all the timing and design rule constraint checks. For timing checks, the violations are reported at timing endpoints. The DRV is checked and reported on leaf pins and ports.

The supported check types are:

  • setup
  • hold
  • clock_gating_setup
  • clock_gating_hold
  • recovery
  • removal
  • clock_period
  • pulse_width
  • max_capacitance
  • max_transition
  • max_fanout
  • min_capacitance
  • min_transition
  • min_fanout
  • skew
  • pulse_clock_max_width
  • pulse_clock_min_width
  • pulse_clock_max_transition
  • pulse_clock_min_transition

You can use the -all_violators parameter for reporting specific check types to generate a report for that particular check type only. For example, you can use -all_violators with -late to report setup checks and path delays from set_max_delay.

-check_type

Reports setup or hold checks. The supported check types are:

  • clock_gating_setup: Reports only the paths that end at the clock_gating_setup timing check.
  • clock_gating_hold: Reports only the paths that end at the clock_gating_hold timing check.
  • electromigration: Reports signal EM analysis related violations. When high-density current passes through a thin metal wire, the high-energy electrons exert forces on atoms, causing them to migrate. Electromigration (EM) can drastically reduce the lifetime of a chip by increasing the resistivity of a metal wire or creating a short circuit between adjacent lines. When this option is specified, the software reports standard cell-level electromigration violations.
  • recovery: Reports paths that end at the recovery timing check.
  • removal: Reports paths that end at the removal timing check.
  • pulse_width: Reports only the paths that end at the pulse_width timing check.
    If you do not specify the -all_violators parameter, then the pulse_width option reports only one entry of the most critical pulse_width check. The DRV checks also report only the most critical entry.

    To report all the violated pulse_width checks, you need to specify the report_constraint -check_type pulse_width -all_violators command (which is consistent with other check types of the report_constraint command).
    To report both violating and met entries, you can use the report_min_pulse_width command.
  • clock_period: Reports only the paths that end at the clock_period timing check.
  • skew: Reports skew checks.
    The report_constraint command performs skew checks by default.
    Skew checks are implemented as setup checks that are reported in the late analysis or simultaneous mode. These checks are not reported in the early mode. Skew checks are performed assuming the signal and reference clocks have the same frequency. If the frequencies of the signal and reference clocks differ, a warning message is displayed.
  • pulse_clock_max_width: Reports the maximum pulse clock width checks set using the set_pulse_clock_max_width command.
  • pulse_clock_min_width: Reports the minimum pulse clock width checks.
  • rail_swing: Reports details related to the rail swing checks. For rail swing check settings, you can use the following global variables:
    • timing_rail_swing_checks_low_voltage_threshold
    • timing_rail_swing_checks_high_voltage_threshold
-clock Specifies that the DRV checks will be restricted to the clock network. If any pin is part of both the clock and data network, it will be reported as a clock.
-connection_class Reports violations if the connection class attributes of the driving and receiving pins of a net are different.
-data Specifies that the DRV check will be restricted to the data network. If any pin is part of both the clock and data network, it will be reported as a clock network pin.
By default, the DRV checks are applied to both clock and data networks.
-drv_abs_margin float Specifies the absolute DRV margin value applied to obtain the threshold transition.
-drv_fields {field_list}

Allows only the specified fields to be included in the DRV report - in the same order as defined.

For a complete list of DRV fields, refer to the DRV Fields table.
-drv_output_format {txt | csv}

Specifies the DRV output format – txt or CSV. The default value is “txt”.
-drv_ratio_margin float

Specifies the ratio of the DRV margin value applied to obtain the threshold transition.

-drv_violation_type

Reports DRV violations. The supported DRV check types are:

  • max_capacitance: Reports pins having the worst max_capacitance constraint. If you specify the -all_violators parameter, you can see all the pins whose actual capacitance is greater than the max_capacitance value specified in the library and timing constraints file.
  • min_capacitance: Reports pins having the worst min_capacitance constraint. If you specify the -all_violators parameter, you can see all the pins whose actual capacitance is less than the min_capacitance value specified in the library and timing constraints file.
  • max_transition: Reports pins having the worst max_transition constraint. If you specify the -all_violators parameter, you can see all the pins whose actual transition is greater than the max_transition value specified in the library and timing constraint file.

    Note: These checks are not reported in hold analysis mode. The set_si_mode -enable_drv_with_delta_slew true setting is required for max_transition DRV violations with SI slew.

  • min_transition: Reports pins having the worst min_transition constraint. If you specify the -all_violators parameter, you can see all the pins whose actual transition is less than the min_transition value specified in the library and timing constraints file.
  • max_fanout: Reports pins having the worst max_fanout constraint. If you specify the -all_violators parameter, you can see all the pins whose actual fanout is greater than the max_fanout value specified in the library and timing constraints file.
  • min_fanout: Reports pins having the worst min_fanout constraint. If you specify the -all_violators parameter, you can see all the pins whose actual fanout is less than the min_fanout value specified in the library and timing constraints file.
  • pulse_clock_max_transition: Reports maximum pulse clock transition checks.
  • pulse_clock_min_transition: Reports minimum pulse clock transition checks.

-early

Reports all of the hold checks, including regular, clock_gating_hold, and data-to-data hold checks. Also reports path delays from set_min_delay.

Note: This parameter does not report removal checks.

-em_type {peak | rms | avg | all} 

Reports DRV violations as per the specified EM type table lookup.

When this parameter is specified, the software reads the em_max_toggle_rate table in the Liberty library for the specified EM current type (RMS, peak, or average).

-late

Reports all of the setup checks, including regular, clock_gating_setup, and data-to-data setup checks. Also reports path delays from set_max_delay.

Note: This parameter does not report recovery checks.

-max_pins_per_drv

Reports the specified number of top worst violations per DRV category, such as max_transition, max_capacitance. If this parameter is not specified, 1000 entries per DRV category will be reported by default.

pin_port_list

Controls the output of DRV constraints. When specified, all DRV violations are reported only for the specified pins or ports.
-retime {aocv | path_slew_propagation | aocv_path_slew_propagation}

Reanalyzes the specified set of paths using the specified method.

Note: The parameter supports only setup/hold check types.

aocv: Re-evaluates the given set of graph-based analysis (GBA) paths by reverting back graph-based AOCV derate factors and applying path-based AOCV derates instead of less pessimistic derates. In this case, the slew (and respective delays) values are worst that are propagated during graph-based analysis.

aocv_path_slew_propagation: Re-evaluates the given set of graph-based analysis (GBA) paths by using path-based AOCV derates and delays using actual path- based propagated slew.

path_slew_propagation: Re-evaluates the given set of graph-based analysis (GBA) paths by recalculating the delay values based upon actual propagated slew across the path. In this case, the AOCV derates are the ones that are reported during graph-based analysis.
-retime_mode {path | exhaustive}

Allows the report_constraint command to be run in exhaustive path-based analysis (PBA) mode.

In this mode, the software will exhaustively examine nworst paths of the selected endpoints and then select the true worst path to be reported - based on retimed slacks of all the examined paths.

To enable exhaustive mode, the use model is given below:

report_constraint -all_violators -retime path_slew_propagation -retime_mode exhaustive

When you use this parameter, reporting can be run time intensive as the software needs to do an exhaustive search for the true worst paths. Therefore, it is recommended to use this option in the later phases of the sign-off stage when there are very few violations left for analysis.

Default: path

-verbose

Generates a report that displays the full data path, along with the accompanying required time and slack calculations. This report is equivalent to the default report_timing report.

When you specify the -verbose parameter, you can set the timing_report_constraint_use_report_timing_for mat global variable to honor the report_timing_format settings.

The DRV reports, with or without the -verbose parameter, are the same.

-view viewName

Generates a report containing endpoint and other constraint information for the specified analysis view.

You can only specify this parameter when the software is in multi-mode multi-corner analysis mode.

Default: Generates a report containing the worst endpoint and constraint information based on all of the analysis views.
-worst_drv_per_net Reports only the worst DRV violation per net.

Actual Transition

Specifies the actual minimum/maximum transition at a pin or port. This may be a base transition or a base plus crosstalk-induced transition, depending on the timing_max_transition_use_si_transition setting to false (default) or true, respectively.

SI Transition

Specifies only the delta SI transition time at a pin or port.

The total transition time comprises the base transition time (transition value without SI crosstalk analysis) as well as the delta SI transition time. 

transition_sigma

Transition N-Sigma

Specifies the N-Sigma multiplier defined for transition with the set_socv_reporting_nsigma_multiplier -transition <nsigma> command.

This field will be reported for SOCV STA, under timing_report_max_transition_check_using_nsigma_slew, to the true setting.

This is sensitive to views and -data and -clock specifications.

Note: This field will impact transition_actual and transition_slack computation for max_transition, min_transition, pulse_clock_max_transition, and pulse_clock_min_transition checks.

transition_slack

Transition Slack

Specifies the max_transition/min_transition slack at a pin/port pin/port.

user_constraint

User Constraint

Specifies user defined tran/cap/fanout limit value set by constraints as a command or through SDC on the violating pin. If not defined, reports as "NA".

Name of the pertaining analysis view.
