set_pba_mode

set_pba_mode
[-help]
[-reset]
[-epba_bounded_mode {true | false}]
[-ipba_endpoints_max_limit {100000}]

Enables IPBA infinite depth path-based analysis (IPBA).

This feature runs faster analysis (vs full depth exhaustive PBA (EPBA)) and attains PBA design coverage with no depth limit per endpoint. 

Parameters

-help Prints out the command usage.

-epba_bounded_mode {true | false}

Enables IPBA mode with exhaustive PBA analysis (run using the report_timing -retime_mode exhaustive command).

In this mode, the software ensures that all the paths to the violating endpoints are covered for PBA, and the slack is the worst PBA slack reported across all the paths to the endpoint. For any endpoint that is considered for IPBA analysis, the complete fanin cone (all timing paths ending at that endpoint) is evaluated for any possible PBA violation.

Default: false

-ipba_endpoints_max_limit {100000}

Specifies the maximum number of worst critical GBA endpoints, which will be picked for IPBA analysis. The rest of the GBA endpoints will report GBA slack. 

This parameter should be set to a number higher than the total number of GBA violating endpoints, in order to cover all the violating endpoints for IPBA.

To ensure that all the GBA violations are considered for IPBA analysis, the report_timing -max_paths parameter should be set equal to or greater than the total number of GBA violating endpoints.

Default : 100000

Min: 1

Max: 1000000
-reset  Resets the specified or all the options to their default value.
