Generates the SPICE trace for a path.

While generating a Spice Deck, the create_spice_deck command looks for library cells required to run Spice and adds all cells as ".include" in the generated Spice netlist.

The output Spice deck includes:

  • Active and passive devices such as field-effect transistors (FETs), capacitors, and resistors.
  • Initial conditions and voltage sources
  • Actual names of the gates, nets, and cell instances, which help the simulator interpret this information effectively. For example, consider the following excerpt, which shows an entry for a gate named U0 in the Spice deck:
    *Gate U0
    *----------------------------------
    *Cell ports in order : x a VSS VDD
    *----------------------------------
    XU0 U0/x U0/a 0 U0/VDD inv_ahvt_64
    *----------------------------------

Note: In order to output a Spice deck that generates the same report output as the report_timing command, you must run the create_spice_deck command with the -report_timing, -segment_start, and -segment_end parameters.

Parameters

-help Prints out the command usage.
-add_driver_for_constraint_check {true | false}

Enables constraint check deck generation with pre-driver.
-aging_correlation_type {full | timingonly} Creates the aging-aware Spice deck. You can use one of the following options:
  • timingonly: Writes out the Spice deck for timing-only correlation mode. The Spice deck contains device degradation parameters computed by Tempus.
  • full: Writes out the Spice decks for full correlation. This involves two Spice simulations. The first Spice simulation computes device degradation using stress simulation. The second Spice simulation uses this data for transient simulation, where delays and slew are measured for timing correlation.
-aging_stress_num_cycles <integer greater than 0>

Specifies the number of cycles in stress simulation in full Spice correlation mode.

When this parameter is specified, the periodic stress waveform propagates through the entire path on which correlation is required.

It is recommended to use the value 6, which is based on the path depth.
-aging_stress_use_timing_slew {false | true} Uses the slew from STA in the stress Spice deck for full Spice correlation, instead of using the default slew of 1ps.
-aginglevel_only <string>

Indicates the type of aging, BTI, HCI, or both. This parameter is required only for URI models.

Note: The exact aging level value is foundry-specific.

Specifies the list of cells to be considered as black boxes in SPICE simulations.
-add_side_load_measurement {true | false}

Adds the side-load measurement to the clock mesh Spice deck.

By default, Tempus measures the latency, delays, and slews of arcs that are part of the clock mesh specified using the -from/-to parameters.

When set to true, the software additionally measures the latency and slews of the side receivers at each stage.

Default: false
-add_voltage_for_missing_sensitization Adds the voltage for missing sensitization.
-bbox_cells string

Specifies the list of cells to be considered as black boxes in SPICE simulations.

This parameter allows you to continue simulations even if a subckt is missing for one or more cells. All instantiations of these cells will be replaced by pin caps to replace the input pins' connectivity of black boxes, and Tempus-computed PWL waveforms will be applied at the output pins of black boxes.

The SPICE delays/slews reported for these black boxes will be the Tempus computed values.
-constraint_check {true | false}

Enables constraint check deck generation.
-depth integer

Creates a clock-mesh Spice deck for the specified stage depth.

Tempus only traces the clock mesh up to the user-specified depth, starting from the specified -from pin.

If both the -depth and -to parameters are specified, then Tempus generates the deck till the depth, which is the minimum of the -to pin depth and the user-specified depth.
-enable_arrival_measurements {true | false}

Allows adding arrival measurements.
-enable_fast_simulation {true | false}

When set to true, the software enables the fast simulation mode. In this mode, additional clock cycles are not required to initialize sequential cells in the Spice deck, which speeds up Spice simulations. All the sequential cells are initialized using the initial conditions, and only a single clock edge is applied as input.

By default, this parameter is set to false. In this mode, two clock cycles are applied as inputs to the clock network, where the first triggering edge is used to initialize sequential cells, and the second edge is used for delay measurement.

Note:  For better performance with sequential cell simulations, you can set the -enable_fast_simulation parameter to true during constraint check generation.
-enable_spectre_x {true | false} Enables the spectreX license checkout when launching Spectre.
-enable_mis {tied_input | independent_input | none}

Enables advanced multi-input switching (AMIS) during Spice deck creation. You can specify one of the following options:

  • tied_input: Multiple inputs of an instance will be tied together in a netlist. You can set the set_analysis_mode -multi_input_switching_mode parameter to 1 to enable this behavior.  
  • independent_input: Allows the Spice deck to write out input stimulus for side inputs for multi-input gates. The switching times of each input depend on the timing windows. This option can be used when the set_analysis_mode -multi_input_switching_mode parameter is set to 2.
  • none: Disables AMIS during the Spice deck creation.

Default: none 
-exclude_side_load_cells string

Specifies a list of cells for which the pin capacitance will be used for side loads instead of instantiating them.
-exclude_side_load_cells_for_missing_subckt {true | false} When set to true, the software will add side load pin capacitance for a missing Spice subckt cell instead of instantiating it.
-file_prefix string

Adds the specified prefix to the generated Spice deck files.

If this parameter is not used, one of the following default names of the generated Spice decks will be used:

  • path_<index>_setup.sp: for setup paths
  • path_<index>_hold.sp: for hold paths
  • path_<index>_vl_glitch.sp: for VL glitch
  • path_<index>_vh_glitch.sp: for VH glitch

The <index> in the above file names is controlled based on the number of decks that are generated using the create_spice_deck command.

A user-specified string (specified using this parameter) is used as a prefix to the above mentioned file names.
-force_delete_output_dir Completely removes the directory specified by the user using the -outdir parameter.
-format string

Allows you to modify the internal reporting format for the run path simulation.

The format columns should be compatible with the report_timing_format settings.
-from string

Creates the Spice deck with a mesh net starting from the specified pin.
-from_fall string Creates the Spice deck with a mesh net starting from the falling transition of the specified from pin.
-from_rise string Creates the Spice deck with a mesh net starting from the rising transition of the specified from pin.
-generate_output_only {true | false}

Generates the report output only, without triggering any simulations.

Default: false
-glitch_simulation_mode {input_output | output}

Specifies the glitch simulation mode.

When set to input_output, the software uses both the RIP and ROP for Spice calculations. When output is specified, the Spice ROP will be computed using the RIP.
-ground string Specifies a list of ground nodes.
-include_cell_variation {true | false}

Writes out the Spice deck required to run simulations.

When set to true, the software runs Monte Carlo simulations within Tempus.

Default: false
-lsf_job_string string

Specifies a handle to the farm job used to launch the simulation.
-mc_simulation_init_args string

Passes the necessary Monte Carlo parameters that are required to run MC simulations. The Monte Carlo analysis refers to “statistics blocks”, where statistical distributions and correlations of netlist parameters are specified. This parameter initializes these parameters under the statistics block.

Note: This parameter can be used when -include_cell_variation is set to true. 
-mc_simulation_tran_args string Initializes the full simulation transient time and the transient time step. 
-measure_point {all | path | stage}

Specifies whether to add all, path, or stage measurements.

Default: all
-merge_spice_deck {true | false} Allows you to enable the merged Spice deck. 

-model_file string

Specifies the path to SPICE model files that contain SPICE model information. This information is necessary to get accurate Spice information.

If sub-circuit and model files are not provided and cdBs are available, Spice information is dumped using cdB.
-no_hard_stop_at_to_pins {true | false}

When set to false (default mode), the Spice deck is generated only for traced paths that start from the -from pin and end at the -to pin. It does not traverse fanout branches that do not lead to the -to specified pin.

When set to true, traversal occurs through the whole fanout cone of the -from pin till it hits a clock pin of a flop, or any stop point specified with the -to parameter, or passes through a depth specified with the -depth parameter.
-omipath <string> Specifies the OMI (Open Model Interface) directory - required only for OMI.

-outdir string

Specifies the name of the output directory that will contain the generated delay and/or glitch spice decks.

If simulation is also performed using the -run_simulation parameter, the Spice simulation output will also be saved in this directory.

Default: tempus_pathsim

-power string

Specifies the list of global names for the power nets.

If the -power and –ground parameters are not specified, the software obtains this information from the power/ground supplies set via other ways in the design, such as libraries/cdb, and so on.

If the information is not available, the software uses the default list of power node names (VDD and VCC) and ground node names (GND and VSS).
-reliability_commands string

Allows you to specify the analysis type.

Spice deck creation while using OMI models requires you to provide the following strings using the -reliability_commands parameter, to direct the Spice simulator for the appropriate analysis.

The following 3 Spice parameters need to be defined as per the required analysis type:

Analysis                             bti_on             hci_on          btirec
BTI-Only                                1                     0                     0
BTI-Only with Recovery         1                     0                     1
HCI-Only                               0                     1                     0
BTI+HCI without Recovery    1                     1                     0
BTI+HCI with Recovery          1                     1                     1

A few examples are given below:

BTI-only without recovery:

-reliability_commands ".param hci_on=0 bti_on=1 she_on=0 btirec_on=0"

HCI-only:

-reliability_commands ".param hci_on=1 bti_on=0 she_on=0 btirec_on=0"

BTI+HCI without recovery:

-reliability_commands ".param hci_on=1 bti_on=1 she_on=0 btirec_on=0"

BTI-only with recovery:

-reliability_commands ".param hci_on=0 bti_on=1 she_on=0 btirec_on=1"

BTI+HCI with recovery:

-reliability_commands ".param hci_on=1 bti_on=1 she_on=0 btirec_on=1"

Note: HCI support for OMI is not available.
-reliability_model_type {URI | OMI | TMI} Specifies the aging-aware deck type: URI, OMI. or TMI.
-receiver_pin string

Specifies the list of receiver pins for which glitch Spice decks need to be generated.

When used with the -run_simulation parameter, the software writes out a comparison report comparing various glitch parameters between Tempus and Spice, such as RIP, input glitch area, and ROP (only if the ROP node name is available in the noise models) for the given receiver pins.
-report_noise string

Specifies the report_noise command parameters as a list of arguments within brackets.

When specified, the Spice deck will be generated for all receiver pins reported by the report_noise command for the specified options.

When specified with the -run_simulation parameter, the software writes out a comparison report comparing various glitch parameters between Tempus and Spice, such as RIP, input glitch area, and ROP (only if the ROP node name is available in the noise models).

-report_timing string

Specifies the report_timing command options as a list of arguments within curly brackets.

You can use this option to define the paths for which to generate a Spice trace. To select the paths for generating the Spice trace, specify the report_timing command options, as shown:

create_spice_deck -report_timing {-clock_from CLK -clock_to CPU_CLK -nworst 2}

When the -report_timing option is not used, the software generates a Spice trace for the worst path identified by the report_timing command.

If the -path_type {full_clock} is used, then the clock path will also be processed.

See the report_timing command for a complete list of options that can be used as arguments with the -report_timing option.

Note: The end and summary values of the -path_type option of report_timing are not supported.

-run_simulation

Enables path simulation in addition to generating the Spice Deck.

-scale_mode string

Allows you to specify the UMC_URI scale mode option.

Default: effective 
-segment {data_path | launch_path launch_clock_path | capture_path all}

Creates the Spice deck of a segment out of the path spice deck.

The following command/global variable settings have the following impact on the -segment parameter options:

  • -path_type full_clock is defined under the create_spice_deck-report_timing parameter, then the -segment default value is launch_path.
  • -path_type full_clock is not specified, then the default value is data_path.
  • timing_disable_retime_clock_path_slew_propagation global variable is set to false, the default value is launch_path (irrespective of -path_type settings).
  • timing_disable_retime_clock_path_slew_propagation global variable is set to true (default), then launch_clock_path and capture_path options are supported only when the -path_type full_clock option of the create_spice_deck -report_timing parameter is used.

-segment_end string

Specifies the name of the segment end term.
-segment_start string Specifies the name of the segment start term.

-side_path_level integer

Specifies the number of levels of side path stages to be included in the Spice trace. The maximum number of levels that can be specified is 4.

Default: 1

-spectre string

Specifies the location of the Spectre version that should be used for simulation. If the path is not specified with this option, the software will check if you have the Spectre location defined in your path.
-spectre_analysis_options <string> Adds Spectre analysis options to the run. When specified, the software provides instructions to Spectre, for example, run a session with extra accuracy.
-spectre_cmd_options string Specifies the command-line options for Spectre.
-spectre_lang_escape_chars string Specifies a list of escape characters in Spectre.

-spice_include string

Specifies the user-defined lines that should be written to the Spice deck.

For example,

create_spice_deck -spice_include {.include extra_cmds.sp}

where extra_cmds.sp includes additional SPICE commands required for the run and not included in the SPICE model file loaded with the -models parameter.
-stimuli_file string

Allows you to specify the file path containing stimuli to be used for the specified library cells. The cells' sensitization from the user-specified stimuli file takes precedence over Tempus-inferred sensitization.

Syntax for delay Spice decks is given below:
lib_cell string <from | from_rise | from_fall> string <to | to_rise | to_fall> string input_vector string num_clk_pulse integer

Syntax for glitch Spice decks is given below:
lib_cell string glitch_type <VL | VH> output_pin string input_vector string num_clk_pulse integer # For victim driver sensitization
lib_cell cell_name glitch_type <VL | VH> input_pin string input_vector string num_clk_pulse integer # For victim receiver sensitization

The num_clock_pulse integer is significant for sequential arcs and specifies where to align the data pin transition with respect to the clock transition.

For example, a value of ‘1’ (default setting) specifies that the data pin transition must be aligned with the last clock transition, where the delay measurement is intended. This value can be used for regular flip-flops.
The value ‘2’ specifies that the data pin transition needs to be aligned with respect to the second-last triggering clock edge. This value can be used for cascaded 2-bit flip flops.

Additionally, for sequential arcs, the first pin in the user-specified input vector must be the data pin, whose signal will be latched in the sequential cell.

Here are some examples of stimuli file:

  • The following example shows the stimuli file containing sensitizations for CP(rise)->Q(fall) and CP(rise)->Q(rise) timing arcs of library cell FF1:
    lib_cell FF1 from_rise CP to_fall Q input_vector !D&CDN&!SE&!SI num_clk_pulse 2
    lib_cell FF1 from_rise CP to_rise Q input_vector D&CDN&!SE&!SI num_clk_pulse 2
  • The following example shows the stimuli file containing sensitizations for the victim driver cell AOI for both VL and VH glitches:
    lib_cell AOI glitch_type VL output_pin Z input_vector !A&!B&!C
    lib_cell AOI glitch_type VH output_pin Z input_vector A&!B&C

-subckt_file string

Specifies the path of the Spice sub-circuit file,, which contains the Spice information. This information is necessary to get accurate Spice information.

If sub-circuit and model files are not provided and cdBs are available, then Spice information is dumped using cdB.
-supply_voltage_file string

Specifies the file containing user-specified power/ground voltages to be used for SPICE simulations. By default, the design operating voltages will be used.

The format of the supply voltage file is as follows:

GLOBAL POWER #Specifies the global supply for all power pins

GLOBAL GROUND #Specifies the global supply for all ground pins

GLOBAL #Specifies the voltage to be used for the given pg pin for all instances

POWER #Specifies the VDD to be used for the specified I/O port PWLs

GROUND #Specifies the VSS to be used for specified I/O port PWLs

POWER / #Specifies the VDD used for the specified instanceAC/AEURAtms signal pin PWL or sensitization

GROUND / #Specifies the VSS used for the specified instanceAC/AEURAtms signal pin PWL or sensitization

/ #Specifies the voltage used for the specified instanceAC/AEURAtms pg pin
-supply_voltage_file_stress <file> Specifies an optional extra file containing the stress voltages for supply or ground pins that are in the cell sub-circuit definition.
-sweep_range float Specifies the range to sweep the victim.
-sweep_steps integer Specifies the number of steps by which the victim is swept.
-sweep_victim {true | false} Enables victim sweep.
-temperature float

Specifies a user-defined temperature to be used in SPICE simulations.

Unit: Celsius
-through string

Creates the Spice deck with mesh net going by -through points.
-to string

Creates the Spice deck with a mesh net ending at the specified to pins.
-uri_lib_file <string>

Specifies the URI model file (required only for URI).

Default: none
-uri_mode <string>

Specifies the URI appendage option.

Default: appendage
-use_control_param {true | false}

Allows you to control the power/ground voltage levels in the created Spice deck through user-specified parameters.

When set to true, an additional file with the same name as the deck and the .control extension is created, containing the parameterized design voltage levels for the PG pins of all cells instantiated in the deck. You can modify the *.control file as needed without altering the original deck.

-use_distributed_load_for_side_receivers {true | false}

Allows you to control whether to use the receiver output load as a distributed or lumped load.

Default: false

-user_defined_measure_statements {append | overwrite}

Specifies whether to overwrite the default measurement statements in the Spice deck by user-defined measurements specified using the -user_defined_measure_statements_file parameter, or append it with default measure statements.

Default: append
-user_defined_measure_statements_file string

Allows you to add the delay/slew measurement statements for any given segment of the path for which the Spice deck is generated.

The format of the file is given below:
<MEASURE_TAG_NAME TRIGGER_PIN_NAME TARGET_PIN_NAME>

Multiple such lines with unique tags can be specified in the file.

The measure statement is written in the Spice deck for delay measurement between TRIGGER_PIN and TARGET_PIN, and slew measurement at TARGET_PIN.
-use_ndw_for_constraint_check  {true | false}

Enables constraint check deck generation with NDW waveforms.
-use_noise_model_when_cond {true | false}

Allows the use of the when condition from a pin noise model.
-view string

Specifies the view name - if a glitch Spice deck is created for a view other than the default view.
-waveform_aware_pulse_width_checks {true | false} Generates the Spice deck for waveform-aware pulse width checks.

-xtalk {delay | vl_glitch | vh_glitch | vlu_glitch | vho_glitch}

Generates the SI Spice deck for the stage specified using the report_timing parameter.

  • A stage can start with the victim driver input to the victim receiver input.
  • A stage can start with the victim driver input to the victim receiver output.

The stage will be specified in the report_timing command using the –point_to_point parameter.

You can specify one of the following options:

  • delay: Allows dumping the SI delay Spice deck.
  • vl_glitch | vh_glitch: Specifies the type of glitch (VL or VH) the Spice deck will be used for. This option must be used for glitch Spice deck generation.
  • vlu_glitch | vho_glitch: Supports simulation of vlu/vho glitches

> <filename>

Redirects -run_path_simulation/-run_simulation output to file.

>> <filename>

Appends -run_path_simulation/-run_simulation to output file.

Examples

  • The following set of commands generates a Spice deck for a path and outputs it in the path1_spice directory:
    tempus > set rpt_tim_opt [ list -clock_from CLK -clock_to CPU_CLK -nworst 2 ]
    tempus > create_spice_deck -outdir path1_spice -report_timing $rpt_tim_opt
    -subckt_file  /path/subckt.sp  -model_file /path/models.sp
  • The following command creates a Spice deck and simulates it using the Spectre simulator: 
    tempus > create_spice_deck -run_simulation -spectre /tools/spectre
    -subckt_file  /path/subckt.sp  -model_file /path/models.sp
  • The following command creates a Spice deck in mydir and keeps the instances up to three levels for each side path attached to the main path: 
    tempus > create_spice_deck -side_path_level 3 -outdir mydir
    -subckt_file  /path/subckt.sp  -model_file /path/models.sp
  • The following command creates a Spice deck for the best path: 
    tempus > create_spice_deck -report_timing { -early }
    -subckt_file  /path/subckt.sp  -model_file /path/models.sp
  • The following command creates a Crosstalk Spice Deck for the specified Stage:
    tempus > create_spice_deck –xtalk delay –model_file /path/models.sp –subckt_file /path/subckt.sp –report_timing {-point_to_point –from <victim_driver_input> –to <victim_receiver_driver_output>} –output spice_output

  • The following command dumps the VL spice deck report_timing command options so that the transition at the receiver pin is failing:
    tempus > create_spice_deck –xtalk vl_glitch –report_timing < -from driver/input -to_fall receiver/input –point_to_point > –outdir <output dir> –model_file <model file> -subckt_file <subckt file>

  • The following command dumps the VH Spice deck report_timing command options so that the transition at the receiver pin is rising:
    tempus > create_spice_deck –xtalk vh_glitch –report_timing < -from driver/input -to_rise receiver/input –point_to_point > –outdir <output dir> –model_file <model file> -subckt_file <subckt file>

  • The following command run simulations and then generates a report:
    create_spice_deck -report_timing “-net -from clk -to ca53/as_12/ff/D -path_type full_clock” -run_simulation -include_cell_variation true > spice.socv.rpt

  • The following command generates a report (if simulations have already been run):
    create_spice_deck -generate_output_only true -report_timing “-net -from clk -to ca53/as_12/ff/D -path_type full_clock” -run_simulation -include_cell_variation_true -format {arrival spice_arrival spice_arrival_detail arrival_error_detail hpin} > spice.socv.rpt

  • The following section in Spice deck specifies global supplies and the transient analysis window time.
    *--------------------
    *Command and Options
    *--------------------
    .GLOBAL vdd vbbnw
    V0Xvdd  vdd 0 1.0
    V0Xvbbnw vbbnw 0 1.0
    .GLOBAL vss vbbpw
    V0Xvss vss 0 0
    V0Xvbbpw vbbpw 0 0
    .TEMP -40.0000
    .TRAN 1p 10256p
    *--------------------

  • The following section shows an example of a net and its instance connections.
    *------------------------
    *Net Instances
    *------------------------
    *Net module1/inst_1/net
    *------------------------
    Xmodule1/inst_1/net module1/inst_1/q
    + module1/inst_2/a wc:module1/inst_1/q
    *------------------------
  • The following section shows an example of a gate instance and its port connections.
    *----------------------------------------
    *Gate Instances
    *----------------------------------------
    *Gate module1/inst_2
    *----------------------------------------
    *Cell ports in order : a y vss vdd vbbpw vbbnw
