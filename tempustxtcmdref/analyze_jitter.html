analyze_jitter

analyze_jitter 
[-help]
[-cycle_interval integer]
[-eiv_end_time float]
[-eiv_file string]
[-eiv_start_time float]
[-eiv_vdd_vss string]
[-enable_spectre_x {true | false}]
[-force_delete_output_dir]
[-from string] 
[-from_fall string]
[-from_rise string]
[-levels_combine integer]
[-lsf_job_string string]
[-mode {period | cycle_to_cycle | time_interval_error | backward_compatible}]
[-model_file string]
[-no_hard_stop_at_to_pins {true | false}]
[-num_cycle integer]
[-outdir string]
[-run_simulation]
[-skip_stage_fanout string] 
[-spectre string]
[-spectre_cmd_options string]
[-subckt_file string]
[-start_cycle integer]
[-through string]
[-to string]
[[ > | >> ]]

Allows the software to perform Spice jitter analysis on a clock network using a user-specified EIV database. The EIV database stores the effective instance voltages (EIV) for each cycle across different instances in the design.

The software reads the EIV files and identifies the worst two consecutive cycles for each instance where the voltage variation is maximum. The voltage levels from these identified cycles are used as the corresponding supplies for different instances in the generated Spice deck, which is simulated using the Spectre simulator to compute cycle-to-cycle IR-induced jitter.

Parameters

-help

Prints out the command usage.
-cycle_interval

Specifies the cycle interval to use when selecting the EIV values for each instance in jitter computation. The default value is 1, where all the EIV values are considered for jitter computation.

When ‘N’ is specified, the analyze_jitter command considers only the EIV entries in step size of ‘N’, starting from the value specified by the -start_cycle parameter.

-eiv_end_time float

Specifies the end time for EIV reading. The voltages specified in the EIV database for timestamps beyond this value are ignored.

Default: The last timestamp from the EIV file is considered as the end time. 

-eiv_file string

Specifies the effective instance voltage files for accounting for IR Drop in jitter computation.

-eiv_vdd_vss string

Specifies the power and ground net names for each EIV file specified using the -eiv_file parameter.

For example, "vdd1 vss1 vdd2 vss2", vdd1 and vss1 are for the first, and vdd2 and vss2 for the second EIV file defined using the -eiv_file parameter.

-eiv_start_time float

Specifies the start time for EIV reading. The voltages specified in the EIV database for time stamps before this value are ignored.

Default: The first timestamp in the EIV file is considered the start time.
-enable_spectre_x Enables SpectreX license checkout when launching Spectre.
-force_delete_output_dir Completely removes the directory specified by the user using the -outdir parameter.

-from string

Creates a Spice deck of the clock network starting from the specified pin.

-from_fall string

Creates a Spice deck of the clock network starting from the falling transition of the specified pin.

-from_rise string

Creates a Spice deck of the clock network starting from the rising transition of the specified pin.

-levels_combine integer

Specifies the number of levels, going up from the leaf nodes, at which the sub-trees can be combined.

By default, the whole clock network is simulated as a single Spice netlist for jitter analysis. But for large networks, running a single simulation can significantly increase run time.

When you use this parameter, the software partitions the clock network into multiple subtrees and runs Spice simulations in parallel. For the following values, the behavior is as follows:

  • 0: Divides the network such that the path traversed from a clock source to each leaf node is part of a separate sub-tree.
  • 1: Each sub-tree contains the path traversed from a clock source to one level up of a leaf node. And all the leaf nodes in the fanout of the identified level are part of this sub-tree, and so on.

Note: The -max_spectre_lic parameter must be set to a value greater than 1 to enable this parallelization.

-lsf_job_string string

Specifies the handle to the farm job used to launch the simulation.

-max_spectre_lic integer

Specifies the number of available Spectre licenses for simulation parallelization.

Default: 1 license is assumed to be available, thereby disabling parallelization.
-mode {period | cycle_to_cycle | time_interval_error | backward_compatible}

Runs the analyze_jitter command natively - with the specified mode.

Default: period

-model_file string

Specifies the path of Spice model files that contain the Spice model information.

-no_hard_stop_at_to_pins {true | false}

When set to false, the Spice deck is generated only for the traced paths starting from the -from pin and ending at the -to pin. It does not traverse through the fanout branches that do not lead to the -to specified pin.

When set to true, traversal occurs through the whole fanout cone of the -from pin till it hits a clock pin of a flop, or any stop point specified with the -to parameter

Default: false
-num_cycle Specifies the number of cycles for which jitter computation needs to be performed. By default, all the available EIV cycles in the input EIV file are considered for jitter computation.

-outdir string

Specifies the output directory for the created Spice decks and the simulation output files.

Default: tempus_pathsim

-run_simulation

Enables jitter simulation and generates the Spice deck.

-skip_stage_fanout string

Accepts two positive integers in the format "N1 N2", and scans up to N1 stages in the fan-in cone of each endpoint. The software skips the segments where a stage is found to have a fanout greater than N2.

For example, a jitter path Clk_root1 -> … -> B3 -> B2 -> B1 -> Reg2, B2 and B1 are the last 2 levels.

1） Assume B1’s fanout is 100 and B2’s fanout is 80, then

  • When N1 = 1, N2 = 80, B1 will be skipped.
  • When N1 = 2, N2 = 100, B1 will be skipped
  • When N1 = 2, N2 = 80, B2 & B1 will be skipped

Note: B2 will always cause B1 to be skipped even when B1’s fanout is less than 80. So the reduction continues to increase when the level changes from 1 to 2.

2） Assume B1’s fanout is 80, and B2 fanout is 100, then,

  • When N1 = 2, N2 = 90, both B2 and B1 will be skipped.

-spectre string

Specifies the location of the Spectre path.

-spectre_cmd_options string

Specifies the command-line options for Spectre.
-start_cycle <integer> Specifies the EIV cycle to be used as the starting point for jitter computation. All EIV cycles before this point will be ignored. The default value is 1.

-subckt_file string

Specifies the file(s) containing subckt definitions of all the instances for which the Spice simulation needs to be performed.

-through string

Creates the Spice deck of a clock network that starts from the -to pin and traverses through the specified pin(s).

-to string

Creates the Spice deck of a clock network terminating at the specified pin(s).

> filename

Redirects the -run_simulation output to a file.

>> filename

Appends the -run_simulation output to a file.

Examples

  • The following command generates the Spice deck for jitter analysis of the entire clock network starting from the CLK pin in the JITTER_SPICE directory, and runs the simulations:
    tempus> analyze_jitter -from CLK -no_hard_stop_at_to_pins true -outdir JITTER_SPICE -eiv_file ./eiv.txt -eiv_vdd_vss {vdd vss} -run_simulation

    When the Spice simulations are completed, a summary of the jitter analysis will be saved in the output directory that contains the jitter values of all the endpoints, as shown below:
    -----------------------------------------------------------------------------------------------------
    Start-point-> [through-point-> through-point] -> End-point Rise/Fall Cycle-to-Cycle Jitter Value (ps)
    -----------------------------------------------------------------------------------------------------
    CLK -> DFF_2/DFF/D (F) 10.782
    CLK -> DFF_2/DFF/D (R) 11.072
    CLK -> DFF_2/DFF/CP (R) 9.054
    CLK -> DFF_2/DFF/CP (F) 9.438
  • The following command runs jitter analysis for the clock network that originates from the CLK node, and traverses through an intermediate node INV/ZN:
    tempus> analyze_jitter -from CLK -though INV/ZN -no_hard_stop_at_to_pins true -outdir JITTER_SPICE -eiv_file ./eiv.txt -eiv_vdd_vss {vdd vss} -run_simulation -levels_combine 1 -max_spectre_lic 8

    The specified clock network is not simulated as a single netlist, but is broken down into multiple sub-trees. All the leaf nodes driven by a single driver are part of one sub-tree. The simulations on these smaller netlists are scheduled in such a way that a maximum of 8 simulations are run in parallel at any given time.
