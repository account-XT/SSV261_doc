set_clock_transition

set_clock_transition 
[help]
[-rise]
[-fall] 
[-min]
[-max] 
slew_time
clock_list

Specifies the transition time of sequential endpoints of the ideal clock network.

This command only affects ideal clock networks, so typically it is used before the clock network is implemented. If no clock transition is explicitly specified for an ideal clock, the system’s default transition time (often close to 0.0) is used. For propagated clocks, the calculated transition times are used, so you can set propagated clocks only after the final clock tree is constructed.

This command only affects sequential clock endpoints, typically the clock pin of registers in the combinational fanout of the clock. Any data endpoints that are also in the combinational fanout of the clock will not be affected. The software will always use the propagated transition times. You can consider turning off clock-source data paths until the clock tree is built or, you can use the set_ideal_network command for additional control.

Parameters

-help Prints out the command usage.

clock_list

Specifies a list of clocks only with ideal mode in the design, which affects the slew times on all register clock pins in the transitive fanout of the specified clocks. Specified set_clock_transition values on register clock pins in the fanout of a clock with propagated latency are ignored.

-rise/-fall

Specifies the rising or falling edge of the register clock pins on which the slew time is asserted.

-min/-max

Specifies the clock slew time for minimum or maximum process corner slew time.

slew_time

Specifies the slew time (transition time) of the clock pins.

Examples

  • The following commands specify a 2.0 rise slew time and a 1.0 fall slew time for register clock pins clocked by CLKA:
    tempus > set_clock_transition -rise 2.0 [get_clocks CLKA]
    tempus > set_clock_transition -fall 1.0 [get_clocks CLKA]
