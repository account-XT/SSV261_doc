create_glitch_boundary_model

create_glitch_boundary_model 
[-help]
[-add_bound_lib_report]
[-bound_lib_report <string>]
-dir string
[-max_stages integer]
[-overwrite]
[-skip_constant_ports]
[-skip_constants]
[-skip_ports string]

Creates a boundary model for the current design for performing glitch analysis.

Parameters

-help                    

Prints out the command usage.

-add_bound_lib_report

Allows writing a report into the model directory as bound_libs.rpt.gz.

-bound_lib_report <string>

Specifies the name of a file to which a report will be written if the bound library/libraries for every instance are included in the model. When this parameter is not specified, a report will not be written.

-dir string         

Specifies the directory where the model will be saved. If a directory does not exist, it will be created. If it already exists, and the -overwrite parameter is specified, then the existing directory will be deleted first; otherwise, an error will be displayed.

-max_stages integer    

Specifies the maximum number of levels of interface logic to keep from the boundary ports. All attackers on any net along the interface logic path will be kept with the attacker’s driver and receiver. When this parameter is specified, the glitch at the interface input paths to the output pins will be retained and fed into the block's internal nets.

Default: 2

-overwrite               

Allows the software to replace the contents of any existing directory with the generated boundary model.
-skip_constant_ports Ignores the timing endpoints driven exclusively by constant ports.

-skip_constants          

Allows the software to skip any logic that is constant across all views during forward tracing from input ports to find timing endpoints. In addition, the fanin logic is not traced for output ports that are constant in all the views.

-skip_ports string    

Specifies primary ports of a block that should be skipped when tracing the interface paths to be included in the model. The ports can be specified as a port name or a list of port names.

The forward tracing to find endpoints will not be performed from skipped input ports, and fanin tracing will not be performed from skipped output ports. Note that timing endpoints reachable from both a skipped and a non-skipped input port will be included in the model. In such a case, the skipped input port will be included in the model since it is a part of the fanin logic of the endpoint.

Note: This parameter does not support collections.

Examples

  • The following command creates a boundary model in the specified directory and overwrites any existing directory contents:
    create_glitch_boundary_model -dir model_dir -overwrite
  • The following command creates a boundary model that keeps up to 6 stages of logic from the input ports and to the output ports of the design:
    create_glitch_boundary_model -dir model_dir -max_stages 6
  • The following command creates a boundary model that does not include any logic constrained as constant:
    create_glitch_boundary_model -dir model_dir -skip_constants
  • The following command creates a boundary model that does not include the fanout logic from input port “scan_in” or fanin logic to the output port “scan_out”:
    create_glitch_boundary_model -dir model_dir -skip_ports {scan_in scan_out}
