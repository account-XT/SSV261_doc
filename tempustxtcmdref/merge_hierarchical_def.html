merge_hierarchical_def

merge_hierarchical_def

[-skip_pg]

[-topcell_placement {x y}]
[-transform_file string]
[-skip_routing {[pg|signal] [regular|special] [high_layer_routing]}... [-to_layer routing_layer_name]]

[-modules <vCell>+ | -hInsts <hInst>+]

Merges DEF data from various blocks to a single chip database.

The merge_hierarchical_def command provides the following features:

  • Takes the TOP DEF file and a set of block DEF files and merges them into a single chip database.
  • The Verilog files for each of the blocks and TOP need to be loaded first through read_verilog.
  • The block and TOP Verilog files (or their DEF files) can be specified in any order. However, if there are empty Verilog module stubs for blocks in some parent Verilog files, ensure that the parent Verilog files are specified before the child Verilog files.
  • There is no need to specify the LEF files for the blocks.
  • During the course of this command, TOP rows will be cut around the block boundary, and all block rows will be brought back as is.
  • Partition definitions are created for each of the assembled blocks as per the DIE AREA statement in the block DEF.
  • The wire at the block boundaries will be stitched with the electrically connected net’s wires at the TOP.
  • All orientations of blocks are supported for assembly. Repeated blocks are also supported. Non-R0 master is also supported.

Note: The save_design command does not write out physical data added by the merge_hierarchical_def command unless you include the Innovus license. You can add one of the possible Innovus licenses by using the tempus -lic_startup_extra option when Tempus is started.

Note: To prevent ECO timing optimization on hierarchical modules for which the DEF file was not loaded, you can use the following command:
set_dont_touch [get_cells <hier_module_name>] true

Parameters 

-help

Outputs a brief description that includes the type and default information for each merge_hierarchical_def parameter.

For a detailed description of the command and its parameters, use the man command:
man merge_hierarchical_def
-add_blockage Specifies that the missing instances from the netlist should be converted into placement blockages.
defFiles <...> Specifies DEF files for TOP and blocks to be provided one by one in any order.
-delete_blockages_over_partition_macro Deletes the top design placement and routing (both rectangular and rectilinear) blockages overlapping partition modules. 
-hInsts <hInst>+

Specifies the list of hierarchical instances for which physical data needs to be loaded. The tool then reads data from def file(s) associated with the specified hInstance(s).
-ignore_drcfill Ignores the special routing with the DRCFILL shape attribute.
-incremental_ilm_def Incrementally flatten the ILM def.

-modules <vCell>+

Specifies the list of modules for which physical data needs to be loaded. The tool then reads data only from def file(s) associated with the specified module(s). 
-preserve_shape Preserves shapes and geometries when DEF data from various blocks is merged into a single chip database.

-rdl_def string

Specifies RDL def file.
-rdl_orientation orientation Specifies orientation for RDL def.
-rdl_placement {x y} Specifies the offset of the RDL def.
-secondary {{suffix def_file_list}...} Specifies the secondary DEF file(s) to load.
-skip_filler Skip merging filler and decap cells.
-skip_pg Skips merging routing on pg nets.
-skipNets Skips merging signal nets section.
-skip_routing {[pg|signal] [regular|special] [high_layer_routing]}...

Skips merging routing based on the settings specified. This setting can be any combination of the three optional keywords from the following set:

  • [pg|signal]: Specifies the type of the net on which the routing is to be skipped. pg – pg net, signal – signal net, both if not specified.
  • [regular|special]: Specifies the type of routing to be skipped. regular – regular routing, special – special routing, both if not specified.
  • [high_layer_routing]: Specifies that only the routing on high layers is to be skipped, where the layers are calculated automatically. If not specified, the routing on all layers is skipped. The layers can be specified with the -to_layer parameter. In that case, the routing on the layers from the top to the specified layer is skipped.
    Note: You need to specify the -to_layer parameter explicitly if high_layer_routing is specified in -skip_routing; otherwise, high_layer_routing is not applicable.

For example, you can specify multiple sets of arguments to this parameter, as shown below:

-skip_routing {{pg regular} {signal special high_layer_routing}}
-to_layer routing_layer_name Skips the routing of layers from the top to the specified layer (inclusive) when the high_layer_routing option is specified in the -skip_routing parameter.
-top_scope Merges routing on top scope nets only.
-topcell_orientation orientation Specifies orientation for topcell.
-topcell_placement {x y} Specifies placement for topcell.
-transform_file string Reports the final x and y offsets and orientation in the top-level of each LEF block that got replaced by DEF.
-use_top_def_die_area Enables the use of TOP DEF DIE AREA.

Examples

The following command sequence merges DEF data of a top (DTMF_CHIP) and a block (tdsp_core) into a single chip database:

# load timing libraries first

tempus> read_lib {./LIBS/tlf/pllclk_slow_4.3.tlf ./LIBS/tlf/ram_128x16A_slow_4.3.tlf ./LIBS/tlf/ram_256x16A_slow_4.3.tlf ./LIBS/tlf/rom_512x16A_slow_4.3.tlf ./LIBS/tlf/slow_4.3.tlf ./LIBS/tlf/tpz973gwc-lite_slow_4.3.tlf ./LIBS/tlf/fast_4.3.tlf ./LIBS/tlf/pllclk_fast_4.3.tlf ./LIBS/tlf/ram_128x16A_fast_4.3.tlf ./LIBS/tlf/ram_256x16A_fast_4.3.tlf ./LIBS/tlf/rom_512x16A_fast_4.3.tlf ./LIBS/tlf/tpz973gbc-lite_fast_4.3.tlf }

# load LEF files of std cells. No need to load the LEF file of the block to be assembled (tdsp_core)

tempus> read_lib -lef {./LIBS/lef/all.lef.save ./DESIGN/row/DTMF_CHIP/arb.partition.lef}

# load verilog files of top (DTMF_CHIP) and block (tdsp_core), in any order.

tempus> read_verilog PTN/DTMF_CHIP/DTMF_CHIP.v.gz
tempus> read_verilog PTN/tdsp_core/tdsp_core.v.gz

# specify the top verilog module now

tempus> set_top_module DTMF_CHIP

# Assemble top and block DEF files into a single Tempus database

tempus> merge_hierarchical_def {PTN/DTMF_CHIP/DTMF_CHIP.def.gz PTN/tdsp_core/tdsp_core.def.gz}
