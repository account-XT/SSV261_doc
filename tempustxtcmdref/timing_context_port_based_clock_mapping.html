timing_context_port_based_clock_mapping

timing_context_port_based_clock_mapping {true | false}

Default: false

Data_type: Boolean

Enables clock mapping based on block ports.

When set to true, clock mapping is done depending solely on clock property of the top and block clock for each clock and data port separately. For enabling N-to-1 or 1-to-N clock mapping, this global variable should be set true.

When set to false, only 1-to-1 clock mapping is done. In such cases, the following rules are used to determine clock mapping:

  • Rule1: Clocks with matching property (period/duty cycle)
  • Rule2: Clocks with matching name
  • Rule3: Clocks present on maximum number common ports
  • Rule4: Any one of the matching clocks

For example,

  • Consider the following illustration:


    When set to true, the following mapping will be seen:

    Block Port

    Block Clock

    Mapped top clock

    P1

    CLK

    CLK, TCLK


    When set to false, CLK will be mapped to CLK according to Rule 2.

Notes:

  • The context_data property of block port can be accessed only when this global variable is set true.
  • When set to true, the software may increase the pessimism as the worst latency/arrival will be picked for block context analysis.
  • If there are multiple block clocks that can be mapped to same top clock on the same block port, then Tempus does not perform auto mapping (when set to true). Whereas for the false setting, clock mapping is done depending on the above mentioned rules.

To set this global variable, use the set command.
