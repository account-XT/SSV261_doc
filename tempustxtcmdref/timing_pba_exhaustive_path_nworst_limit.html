timing_pba_exhaustive_path_nworst_limit

timing_pba_exhaustive_path_nworst_limit value

Default: 10000

Data_type: Integer

Specifies the maximum number of paths per endpoint (nworst) that will be re-timed in exhaustive path-based analysis (PBA). 

In exhaustive PBA mode, the value specified with the report_timing -nworst parameter is used only during the final reporting. The value specified with the timing_pba_exhaustive_path_nworst_limit global variable (and not the report_timing  -nworst value) is used to specify the maximum number of paths to be re-timed per endpoint.

If the limit specified by timing_pba_exhaustive_path_nworst_limit is reached and the timing_path_based_enable_exhaustive_depth_bounded_by_gba global variable is set to:

  • true: The worst of the current PBA slack is used and N+1th GBA path is reported.
  • false: The current PBA slack is reported - which may be optimistic.

To set this global variable, use the set command.
