load_timing_debug_report


load_timing_debug_report
[-help]
{{<file> [-name <string>]}|{ -proto  [-additional_slack_past_wns <float>] [-num_path <integer>]}} 

Loads the violation report in Tempus for debugging timing results.

The violation report that you specify using the load_timing_debug_report command has a special output binary format, which you can generate through the binary value of the report_timing -output_format command parameter.

Note: The violation report that you specify in this command has a special machine readable format. Use the report_timing -machine_readable command to generate the machine readable violation report.

For more information on timing debug categories,  see the 'Appendix - Timing Debug GUI' chapter in the Tempus User Guide.

Parameter 

-help

Outputs a brief description that includes type and default information for each load_timing_debug_report parameter.

For a detailed description of the command and all of its parameters, use the man command:
man load_timing_debug_report
-additional_slack_past_wns Specifies the the additional specified slack.

filename

Specifies the name of the timing debug file.

-name

Specifies the report name to load the machine readable timing report files incrementally.
-num_path Specifies the number of paths to be reported in path violations.
-proto Specifies the FlexModel prototyping.

Examples:

  • The following command loads the machine readable timing report top.btarpt:
    tempus> load_timing_debug_report top.btarpt
  • The following commands load two machine readable timing reports top1.btarpt and top2.btarpt together:
    tempus> load_timing_debug_report -name default_report top1.btarpt
    tempus> load_timing_debug_report -name default_report top2.btarpt
    GTD will first load the report top1.btarpt, then append top2.btarpt incrementally to the current report.

    Note: The name can be specified by user with any string, it is not the file name.
