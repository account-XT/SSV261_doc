report_voltage_scaling

report_voltage_scaling 
[-help]
[objectListOrCollection]
[-analysis_type {early | late}]
[-view string] 
[-output_file string]

Reports instances whose timing data is interpolated due to voltage mismatch. When a cell is operating at a voltage different from those at which it is characterized in the timing libraries, delay calculation (DC) interpolates/derives the timing data for the operating voltage. 

Parameters

-help Prints out the command usage.

-analysis_type {early | late}

Specifies whether early or late views have to be checked for voltage scaling. If unspecified, only ‘late’ views are checked.

-output_file string

Specifies the name of the output file to which the report will be written. When the specified file name includes a directory path, the directory hierarchy is automatically created if it does not already exist. If this option is not specified, the report is written to standard output (screen).
objectListOrCollection Specifies the name(s) or a collection of leaf-level instances for which voltage scaling needs to be checked and reported. If not specified, all instances of the design are checked.

-view string

Specify the name(s) of view(s) to be checked for voltage scaling. If unspecified, all active analysis views are checked.

Examples

The following example shows a sample report_voltage_scaling report:

tempus 2 > report_voltage_scaling i_6 -analysis_type late -view func_worst_cmax 

VIEW: func_worst_cmax -- ANALYSIS TYPE: late
<pin-name> : <cell-name> : <actual-voltage> : <low-lib-name> : <high-lib-name>
i_6/Y      : BUFX5MTH    : 0.820            : elc_08v        : elc_09v

The report is generated with the func_worst_cmax view. You can use the -view parameter to report for other views. You can run the report_analysis_views command to list views.
