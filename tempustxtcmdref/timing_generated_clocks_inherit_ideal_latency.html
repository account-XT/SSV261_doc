timing_generated_clocks_inherit_ideal_latency

timing_generated_clocks_inherit_ideal_latency 
{false | true | actual_partial_latency_path | ideal_partial_latency_path}

Default: false

Data_type: Enum

When the set_clock_latency command is used to define network latency for ideal clock mode at intermediate pins of a clock network, Tempus considers the latency. The timing_generated_clocks_inherit_ideal_latency global variable allows including the closest applied network latency for ideal inheritance also. You can use the following options:

  • false: Uses only the source latency of generated clocks, if it exists.
  • true: Allows the generated clocks to inherit the ideal network latency of the parent clock.
  • actual_partial_latency_path: Uses the network latency of the master clock asserted closest to the target pin and propagated delays for the path from this point to the assertion point of the generated clock.
  • ideal_partial_latency_path: Uses the network latency of the master clock asserted closest to the target pin and ideal delays for the path from this point to the assertion point of the generated clock.

Note: If the set_clock_latency -source parameter is used to specify latency of a generated clock, the software will completely override any inheritance.  

To set this global variable, use the set command.
