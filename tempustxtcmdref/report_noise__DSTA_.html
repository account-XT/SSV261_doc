report_noise (DSTA)

report_noise

[-help]
[-bumpy_waveform]
[-cell_type {bbox | clock | data | latch}]
[-clock]
[-delay {min | max}] 
[-expand_virtual_attacker_bus] 
[-failure]
[-format string]
[-gui_victim_nets_file]
[-histogram]
[-level {vl | vh | vlu | vho}]
[-nets string]
[-output_format {single_line | multiple_line}]]
[-overshoot_undershoot]
[-pins string]
[-quiet_nets]
[-report_virtual_attacker_constituents] 
[-slack float]
[-sort_by {noise | receiver_peak | slack | cell_type}]]
[-stdout]
[-style {default | extended}
[-threshold float]
[-txtfile string]
[-view string] 
[ [ > | >> ] ]

Generates text-based noise reports.

Note: You need to ensure that the set_si_mode -enable_glitch_report (to generate glitch report) or set_si_mode -enable_delay_report (to generate detailed delay report) commands are set to true before the report_timing, update_timing, or update_glitch commands are run.

For details about generating and interpreting report files, see "Signal Integrity Delay and Glitch Analysis" in the Tempus User Guide.

Parameters

-help Prints out the command usage.
-bumpy_waveform

Flags nets with bumpy waveforms at the receiver.

Note: This parameter will always show the maximum delay bumpy report (even if the -delay min option is specified).
-cell_type {bbox | clock | data | latch}

Generates a glitch report for the user-specified cell type. You can specify one of the following options:

  • bbox: Generates a report for only the black-box receivers
  • clock: Generates a report for only the clock pin receivers
  • data: Generates a report for only the data pin receivers
  • latch: Generates a report for only the latch pin receivers
-clock Prints the signal integrity report for the clock network.

-delay {min | max}

Reports delay uncertainty instead of noise values. The only legal values are min or max for minimum or maximum path delay analysis.

The report_noise -clock -delay min | max command outputs the minimum/maximum delay report for clock nets.
-expand_virtual_attacker_bus 

Reports virtual attacker components and expands bus bits in the noise reports.

This parameter works only when the bus virtual attacker feature is enabled using the set_si_mode -enable_virtual_attacker_constituent_report true setting.
-failure

Reports receiver peak failures and DC tolerance failure nets. You can use this option only for glitch noise failure reports.

The report_noise, without the -failure option, uses 10% of vdd as the default.

When you specify the -failure option, you need to use -threshold with the lowest noise level saved; if not specified, it defaults to 5% of Vdd.

Option: Directory Name:
-sort_by noise glitch 
-sort_by rcvr_peak glitch 
-format string

Specifies the fields for the output glitch report format. The valid fields are:

arc, attacker_edge, attacker_net, attacker_offset, attacker_peak, attacker_slew, attacker_source, attacker_status, attacker_vdd, attacker_xcap, cell_type, delay, glitch_slack, incr_delay, level, peak, receiver_cell, receiver_input_failure_threshold, receiver_input_pin, receiver_output_failure_threshold, receiver_output_peak, slack, slack_status, stage_info, thresh_source, victim_edge, victim_library, victim_net, victim_slew, victim_total_area, victim_total_cap, victim_total_cross_cap, victim_vdd, victim_width

Each field corresponds to the following columns of the glitch report:

  • arc: Arc
  • attacker_edge: Edge
  • attacker_net: Net
  • attacker_offset: Offset (ps)
  • attacker_peak: Peak (mV)
  • attacker_slew: Slew (ps)
  • attacker_source: Constituents: Source
  • attacker_status: Statue
  • attacker_vdd Vdd (V)
  • attacker_xcap: Xcap (fF)
  • glitch_slack: Slack
  • level: Level
  • peak: Peak (mV)
  • receiver_cell: Receiver cell
  • receiver_input_failure_threshold: Receiver Input Threshold
  • receiver_input_pin: ReceiverNet
  • receiver_output_failure_threshold: Failure threshold
  • receiver_output_peak: Receiver output peak Value
  • slack_status: Status
  • stage_info
  • thresh_source: ReceiverThresholdType (Global | User | Library)
  • victim_library: Library
  • victim_net: VictimNet
  • victim_total_area: TotalArea
  • victim_total_cap: TotalCap (fF)
  • victim_vdd: Vdd (V)
  • victim_width: Width (ps)

The following options are not available with the single-line format:

    • delay
    • incr_delay
    • slack
    • thresh_source
    • victim_edge
    • victim_slew
    • victim_total_cross_cap

To choose whether the report format should be on a single line or multiple lines, you can use the -output_format parameter.
-gui_victim_nets_file Generates the GUI format glitch reports (aae or aae_<viewname> files under the reporting directory) and incremental delay reports (aae_<max/min>_incDelay or aae_<viewname>_<max/min>_incDelay  files under the reporting directory) to be used in the Display Noise Net form.
-histogram Generates the noise histogram.
-level {vl | vh | vlu | vho} Specifies the level for which a report should be generated when a single-level report is desired. You can specify one of these options -  vl, vh, vlu, and vho.
-nets string

Reports the specified nets in the noise report.
-pins string Reports on the specified list of pin names.
-output_format {single_line | multiple_line}]

Specifies whether the output format should be single-line or multiple lines. You can specify one of the following options:

  • single_line
  • multiple_line

If the single_line option is specified and the attacker info field is selected, all the attacker-related format options will be printed together.

The -output_format parameter only works with the -format option and does not affect the default reporting output format.

Default: multiple_line
-overshoot_undershoot

Reports the overshoot (VHO) and undershoot (VLU) glitches.

The set_si_mode -enable_overshoot_undershoot_glitch must be set to true before the analysis is performed to generate the overshoot-undershoot glitch report.

Default: If this option is not used during glitch reporting, then VL and VH types of glitches will be reported.
-quiet_nets

Generates a report of all the quiet attackers.
-report_virtual_attacker_constituents Generates reports for virtual attacker constituents.
-slack float Specifies the maximum slack value for a bumpy net.

-sort_by {noise |
receiver_peak | slack | cell_type}

Requests the sorting of entries. You can sort by:

  • noise
  • receiver_peak
  • slack
  • cell_type

Tempus determines the default HTML output directories based on your chosen options.

Depending on the sorting option you select, Tempus sorts the report fields in the following order:

-sort_by Option Level 1 Level 2 Level 3 Level 4
rcvr_peak receiver peak noise netname level 
noise noise - netname level

For example, if you use the -sort_by noise option, the first level of sorting will be based on noise, followed by receiver peak, netname, and level.

Note: The report displays the vl noise level before the vh noise level.

Default: receiver_peak
-style {default | extended}

Generates reports in one of two styles - extended or default.

  • extended: Generates extended reports with victim and aggressor timing windows, dropped aggressor slews, and reasons for dropped aggressors. Additionally, the report also shows driver pins and driver library pins.
  • default: Generates the default report, which is similar to the text report generated using the -text parameter.

-threshold float

Specifies the minimum peak noise, absolute delay uncertainty, relative delay uncertainty, and receiver peak thresholds to report on.

Default:

  • 10% of vdd for nets - when the glitch report is generated using the report_noise -sort_by noise option.
  • 10 (ps) for nets - when a detailed delay report is generated using the report_noise -delay parameter.

Note:

  • The -threshold parameter accepts percentage values.
  • All -sort_by values that represent voltages will be in mV.

-txtfile string

Specifies the name of the text report file. If the specified file name ends in .gz extension, the file is gzipped.

If you do not specify the -txtfile option:

  • Tempus automatically names the text report as ‘glitch’ for noise glitch reports and ‘delay’ for noise delay reports.
  • Tempus dumps the generated report to the console window for better usability.

If the -txtfile parameter is not used, then Tempus will output the SI report to the screen. When the -txtfile parameter is specified, then Tempus uses the user-specified name. In case of MMMC, Tempus uses the <txtfile Name>_<view Name> naming convention.
-view string Specifies the view name.
[> | >>]

Stores the generated report in the specified file.

You can add the .gz extension to the file name to generate a compressed report.

Note: The file name must be the last parameter specified.

  • To generate a glitch report, you can use the following command:
    tempus > report_noise –txtfile glitch.txt
  • To generate a glitch report sorted by input noise, you can use the following command:
    tempus > report_noise –txtfile sort_by_glitch_input.txt –sort_by noise
  • To generate a glitch failure report, you can use the following command:
    tempus > report_noise –txtfile glitch_failure.txt –failure

  • To generate a glitch report for VL noises sorted by input noise, you can use the following command: 
    tempus > report_noise –sort_by noise -level vl

  • To generate a glitch report for only latch receiver pin cell types, you can use the following command: 
    tempus > report_noise -txtfile latch_glitch.txt –cell_type latch

For more information on glitch reporting, refer to "SI Glitch Reporting" in the Tempus User Guide.  

Note: DSTA supports only AAE specific reports so some of the options will be different from STA options. For more details on STA options, refer to report_noise.
