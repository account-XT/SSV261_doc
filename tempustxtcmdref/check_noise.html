check_noise

check_noise 
[-help]
[-all]
[-check_only {receiver_no_propagation_model | receiver_no_dc_tolerence |
driver_no_current_source_model | driver_no_model}]
[-instance_list string]
[-instance_only {true | false}]
[-pin_list string]
[-type {receiver_model | driver_model}]
[-unique {true | false}]
[-verbose]
[-view string]
[ [ > | >> ] filename] 

Performs several consistency and completeness checks on noise models specified for a design. These checks help ensure that the correct set of models is available for the SI analysis engine to perform crosstalk noise analysis.

Note: You need to set set_delay_cal_mode -siAware to true before running the check_noise command.

The settings from both the set_glitch_threshold and set_annotated_glitch commands are taken into account when the check_noise command is issued. 

Parameters

-help Prints out the command usage.
-all Displays all the debug information.
-check_only {receiver_no_propagation_model | receiver_no_dc_tolerence |
driver_no_current_source_model | driver_no_model}

Checks the warning name. The following warnings are checked:

  • receiver_no_propagation_model: Shows how many design pins are missing the receiver model for propagation.
  • receiver_no_dc_tolerence: Shows how many pins have no DC VH/VL tolerance specified.
  • driver_no_current_source_model: Shows how many design pins are missing the current source model.
  • driver_no_model: Specifies how many design pins are missing the driver model.
-instance_list string

Specifies a list of instance names.
-instance_only {true | false} Prints each instance only once.
-pin_list string Specifies the instance pin names.
-type {receiver_model | driver_model}

Checks the presence of a valid model type - receiver_model or driver_model. If the specified model is missing, a warning will be issued.

The valid receiver models are those with vivo tables, such as CDB, CCSN, and ECSMN. The valid driver models are CDB, CCS, ECSM, NLDM, and UDN.
-unique {true | false} Reports unique cells or pins for each power domain.
-verbose Generates verbose details.
-view string Specifies the view name.
filename Redirects output to a file.
>> filename Appends to an output file.

Examples

Here are some examples.

  • The following command generates the output as shown below:
    tempus> check_noise -type receiver_model
