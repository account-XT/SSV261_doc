Sets the global parameters for ECO. Parameters that you specify with set_eco_opt_mode are then used automatically when you run ECO optimization by running the eco_opt_design command.

Parameters

-help

Outputs a brief description that includes type and default information for each set_eco_opt_mode parameter.

For a detailed description of the command and all of its parameters, use the man command: man set_eco_opt_mode.

-reset

Resets all or the specified parameters to their default value.

-add_inst {true|false}

Specifies whether the timing optimizer is allowed to add buffer/delay cell instances. This parameter applies to setup, hold, and DRV optimization.

Default: true

Note: If set, this parameter must be applied before eco_opt_design.
-add_load {true|false}

Specifies whether the Hold optimizer can add dummy cell instances.

Default: false 

Note: If set, this parameter must be applied before eco_opt_design.

-allow_multiple_incremental {true|false}

Allows running multiple types of optimization in incremental mode. Note that there should not be any report_* commands between successive eco_opt_design commands. The recommended order to fix violations is DRV, Hold, and Setup. Hold and Setup can be interchanged, but DRV optimization must be performed first. You must specify a unique ECO file prefix before each optimization step. You can then source all the ECO files in the same order as they were generated to run the What-If analysis later.

Default: false

Note:

If set, this parameter must be applied before eco_opt_design.
-allow_skewing {true|false}

Allows clock skew to be applied during Setup timing optimization to improve Setup slack further.

Default: false

Note:

  • If set, this parameter must be applied before eco_opt_design.
  • When HC-ECO (High Capacity ECO) is enabled, the -set_eco_opt_mode -allow_skewing true setting must be set before the design is loaded (that is, before the distribute_read_design command).
-along_route_buffering {true|false}

When set to true, it uses the nodes' location provided through the parasitic data to insert buffers along the routing topology, not only at the start or end of the net. This helps to better balance the slew or the load for long nets, which is typically needed for Setup timing optimization or DRV fixing.

Default: true.

Note:

  • The prerequisite of this parameter is that parasitic with the node location is provided to eco_opt_design. Further, the node location parasitic should be read using the -starN parameter (For example: read_spef –starN).
  • If set, this parameter must be applied before eco_opt_design.

-buffer_cell_list cell_list

Specifies a list of buffer/delay cells that can be used for the timing optimizer, regardless of whether those cells have a dont_use attribute. In the Setup fixing mode, this parameter is ignored to give the tool greater flexibility to insert any usable buffer cells. When the list is empty, the tool will automatically identify the list of usable buffer/delay cells.

Note: If set, this parameter must be applied before eco_opt_design.

-check_type {early | late | both}

Specifies the type of ECO Timing DB to be generated in PBA mode. early specifies hold ECO Timing DB, and late specifies setup ECO Timing DB. When set to “both”, the ECO Timing DB generation will be done in PBA for both Setup and Hold timing.

Default: both

Note:

  • This parameter is only active when the –retime option is being set.
  • If set, this parameter must be applied before write_eco_opt_db.
-clock_cell_list {}

Restricts the list of buffers/inverters/gating or any other cells that are allowed to be used by ECO on the clock tree.

Default: empty

Note: If set, this parameter must be applied before eco_opt_design.
-clock_max_level <INT>

Specifies the maximum levels in clock skewing, thus limiting the number of clock tree levels and avoiding the creation of an unbalanced clock tree. This parameter sets an upper boundary when adding a buffer or pair of inverters to the clock nets. The software counts the number of levels in the clock tree branch being modified to ensure that the maximum level will be equal to or below the value set by this parameter.

Default: 0

Note: If set, this parameter must be applied before eco_opt_design. 
-create_smart_mmmc_db {true|false} Enables saving the additional compact timing information in the ECO DB directory during the STA session. When set to true, the parameter must be applied before the write_eco_opt_db command and does not affect the eco_opt_design command.
-delete_inst {true | false}

Enables buffer deletion when doing timing, power, or area reduction. This option is not honored by the -leakage parameter of eco_opt_design, since it only performs swapping.

Default: true

Note: If set, this parameter must be applied before eco_opt_design. 
-dont_touch_partition_list <string>

Selects a list of partition module names not to be touched during optimization(s). For paths that traverse across the specified hierarchies, optimization would only be applied to a portion of the paths that lie on the non-dont_touch side.

Notes:

  • This parameter is exclusive to touch_partition_list.
  • This parameter must be applied before eco_opt_design and can be changed between each call of eco_opt_design. 
-disable_geometry_checks {true|false}

Performs Vth swapping without checking the pins and geometry of a design. You can relax/stop/avoid the geometry checks during Vth swapping so that Tempus only checks the cell size while performing Vth swapping. This will lead to more Vth swaps. The counterpart to this is that ecoRouting will be needed once the ECOs are applied, since pin geometries might always match between old and new cells.

Default: false

Note: If set, this parameter must be applied before eco_opt_design. 

-drv_margin <FLOAT>

Specifies the ratio by which the DRV check would be relaxed or tightened. It scales the maximum capacitance and maximum transition constraints based on the specified margin decimal value.

For example, specifying a value of 0.2 for this parameter tightens the margin (makes it more pessimistic) by 20 percent during optimization, and specifying a value of -0.2 relaxes the margin (makes it more optimistic) by 20 percent.

This margin is honored for DRV optimization.

Default: 0

Note: If set, this parameter must be applied before eco_opt_design. 

-eco_file_prefix name

Specifies a prefix name for the ECO files generated.

Note: If set, this parameter must be applied before eco_opt_design. 
-em_type {avg | peak | rms | all}

Fixes the electromigration (EM) type during DRV optimization in standalone Tempus ECO. You can specify any one of the following options:

  • avg: Specifies the average current limit violations.
  • peak: Specifies the peak current limit violations.
  • rms: Specifies the Root-Mean-Square (RMS) current limit violations.
  • all: Specifies the worst of the avg/peak/rms violations.

Default: all

-enable_high_capacity_eco {true | false}

Enables database size reduction on the manager session for high-capacity ECO timing/power closure, based on timing violations, a list of partition names, or user-defined path_group. You must apply this parameter before the write_eco_opt_db command, whereas it is not required during the ECO fixing session. Note that in the Tempus Paradime flow or Certus, this parameter is replaced by set_distribute_mmmc_mode -enable_high_capacity_eco, and is set before distribute_read_design.

Default: false
-fix_cell_em {true|false}

Fixes cell-level signal electromigration violations during DRV by resizing and applying additional transformational techniques.

Default: false

Note: 

  • If set, this parameter must be applied before eco_opt_design -drv.
  • If set during DRV fixing, the tool will fix only the cell EM violations. This implies that fixing of max_transition/max_capacitance/SI glitch/SI Xtalk/IR drop will be disabled.
-fix_clock_drv {true | false}

Fixes max_cap/max_tran violations on the clock networks. This is performed only when the eco_opt_design -drv command is run.

Default: false

Note:

  • For clock networks DRV fixing, only the cells listed in the clock cell list (specified using the set_eco_opt_mode -clock_cell_list parameter) will be used. The DRV fixing is not performed if a cell list is not provided.
  • If set, this parameter must be applied before eco_opt_design. 
-fix_data_drv {true | false}

Fixes max_cap/max_tran violations on the data networks. This is performed only when the eco_opt_design -drv command is run.

Default: true
-fix_glitch {true|false}

Performs SI glitch fixing during DRV fixing using resizing and buffering techniques.

Default: false

Note:

  • If set, this parameter must be applied before write_eco_opt_db.
  • The glitch fixing is done before max_tran/max_cap fixing. 
-fix_hold_allow_setup_degrade {none|low|medium}

Guides the Hold fixing engine in determining the effort required to resolve timing violations, and the flexibility it has to affect the Setup timing.

Default: none

  • When set to low, the Hold optimization engine will buffer sink pins that have large Setup positive slack, even though the net Setup slack is barely meeting timing.
  • When set to medium, the Hold optimization engine will behave the same as in the low mode but will also allow Setup TNS to degrade, if required.

Note:

  • This parameter is honored by the Hold optimization engine.
  • If set, this parameter must be applied before eco_opt_design.
  • When -fix_hold_allow_setup_degrade is set to low or medium, the -fix_hold_allow_setup_tns_degrade parameter is ignored.
-fix_hold_allow_setup_optimization {true|false}

When set to true, it performs incremental Setup fixing during Hold fixing to create more Setup margins for Hold violated nodes that could not be fixed earlier due to Setup timing conflicts.

Default: false

Note: If set, this parameter must be applied before eco_opt_design.

-fix_hold_allow_setup_tns_degrade {true|false}

When active, the setup's total negative slack can be degraded during hold time violation fixing while still maintaining the setup's worst negative slack in every setup active view.

Default: false

Note: If set, this parameter must be applied before eco_opt_design.
-fix_hold_variation_aware {true|false}

When set to true, more sizing and Vth swapping are performed during Hold fixing to reduce the cost of buffer insertion. This is particularly effective when the Hold timing paths have incremental delay due to SI or large SOCV-impacted instances.

Default: false

Note:

  • This parameter is only honored by eco_opt_design -hold.
  • If set, this parameter must be applied before eco_opt_design.

-fix_hold_with_margin <FLOAT>

Specifies a slack margin value in nanoseconds for hold-time violation fixing. The purpose is to overfix any hold violations by the amount of the margin value. This margin is not applied to nets that are already meeting the hold target slack.

Default:0

Note: If set, this parameter must be applied before eco_opt_design.
-fix_ir_drop {true|false}

Fixes the IR drop voltages for all instances in the design.

Default: false

Note: If set, this parameter must be applied before eco_opt_design.
-fix_max_cap {true|false}

Fixes max_cap violations only when fixing DRVs.

Note: If set, this parameter must be applied before eco_opt_design.
-fix_max_tran {true|false}

Fixes max_tran violations only when fixing DRVs.

Note: If set, this parameter must be applied before eco_opt_design.
-fix_osus_glitch {true|false}

Fix nets due to overshoot and undershoot glitches during DRV optimization. 

Default: false

-fix_si_slew {true|false}

Reports SI slews violations and fixes during DRV optimization. This is run as the first step of optimization before proceeding with any other incremental optimization.

Default: false

Note: If set, this parameter must be applied before write_eco_opt_db and eco_opt_design.
-fix_slack_in_range_lower_limit <FLOAT>

Sets the lower slack limit for a violated path to be considered during timing closure.

Default: -1e+30
-fix_slack_in_range_upper_limit <FLOAT>

Sets the upper slack limit for a violated path to be considered during timing closure.

Default: 1e+30
-fix_xtalk {true|false}

Reduces crosstalk on the net that violates the thresholds set by you.

Default: false

Note: If set, this parameter must be applied before write_eco_opt_db and eco_opt_design.
-fix_xtalk_preserve_hold {true false}

When this parameter is set to true, the Xtalk fixing engine is not allowed to degrade Hold timing.

Default: false

Note:

  • This parameter is only honored by eco_opt_design -drv when Xtalk fixing is enabled.
  • If set, this parameter must be applied before eco_opt_design.
-fix_xtalk_preserve_setup {true false}

When this parameter is set to true, the Xtalk fixing engine is not allowed to degrade Setup timing.

Default: false

Note:

  • This parameter is only honored by eco_opt_design -drv when Xtalk fixing is enabled.
  • If set, this parameter must be applied before eco_opt_design.
-high_effort_cell_list <list of cells>

Enables the controlled utilization of high-leakage or high-power cells during signoff optimization. These cells are typically classified as dont_use or dont_touch due to their power characteristics; however, they may be beneficial in specific scenarios. When this parameter is specified, ensure that the don’t_use constraint is set to false for cells included in -high_effort_cell_list.

    • In setup timing optimization, the cells are considered only if they are essential to meet timing requirements without causing a significant increase in power consumption. 
    • In power optimization, the cells may be inserted if their usage leads to an overall decrease in power usage, such as enhancements in fanin/fanout cone.

This parameter permits considering the specified cells as high-effort resources, using them only when necessary to enhance timing or power efficiency, while maintaining the broader design objective of reducing power impact.

Default: empty

-hold_target_slack number

Specifies a target slack value in nanoseconds for hold timing.

Default:0

Note: If set, this parameter must be applied before eco_opt_design.
-hold_target_slack_per_view {viewName 1 slack1 viewName2 slack2 … }

When enabled, this parameter allows for the force of a specific hold target slack per view. If a given Hold active view is not listed in this parameter, the software will use the global Hold target slack set by the -hold_target_slack parameter for that view.

Default: "" (empty string)

Note:

  • This parameter is honored by Setup, Hold, Area, Power, and Leakage optimization engines.
  • If set, this parameter must be applied before eco_opt_design.
-hold_xtalk_delta_threshold <DOUBLE>

Fixes the nets with the crosstalk delta delay value equal to or greater than a specified threshold value for hold views.

Default: 0.3 ns

Note: If set, this parameter must be applied before eco_opt_design.
-hold_xtalk_slack_threshold <DOUBLE>

Fixes the nets with the slack threshold value equal to or less than a specified threshold value for hold views.

Default: 1000 ns

Note: If set, this parameter must be applied before eco_opt_design.
-ignore_drv_checks {true|false}

Ignores DRV checks for the max_tran and max_cap degradation during the start of an optimization session and for any subsequent optimizations when running in incremental mode.

Note: If set, this parameter must be applied before eco_opt_design.

-include_hold_path_groups <string>

 Allows you to select which path group to consider for Hold timing during eco_opt_design. It is set before write_eco_opt_db, and also specified before eco_opt_design in case of a different session.

-include_setup_path_groups <string>

Allows you to select which path group to have the interface for Setup timing during eco_opt_design. It is set before write_eco_opt_db, and also specified before eco_opt_design in case of a different session.

-inter_partition <string>

Selects a list of partition module names to be optimized for the interface logic of the specified partition. During the High Capacity ECO flow, it will reduce the database to have the interface logic of the listed partitions only. Each listed partition is treated separately, thus all from/to paths for each partition are included. This parameter must be applied before write_eco_opt_db and eco_opt_design. In case of the Tempus Paradime flow or Certus, it must be applied before distribute_read_design.

Note:

It is mandatory to list the partition name inside the file specified with the -partition_list_file parameter.

  • For High Capacity ECO flow, the -partition_list_file parameter should be specified before distribute_read_design.
  • For non-High Capacity ECO flow, the -partition_list_file parameter should be specified before the first optimization.

However, any partition name, which is a part of -inter_partition and missing in -partition_list_file will result in an error, as shown below:

**ERROR: (IMPESO-616): Partition 'tdsp_core' is missing in -partition_list_file file. Partition specified for inter/intra partition fixing should be present in -partition_list_file list as well.

In case of Certus, since -partition_list_file is not required, the software will use -distributed_opt_block_restore_file to identify the partition names.

-inter_partition_exclusive {{blockA blockB} {blockC blockD}}

Selects a list of partition module pair names to be optimized for the interface logic between the specified partitions. During the High Capacity ECO flow, the tool will reduce the database to have the interface logic of the listed partition pairs only. Each listed partition pair is treated separately, and all from/to paths between partition pairs are included.

Notes:

  • This parameter must be applied before write_eco_opt_db and eco_opt_design. However, in the case of the Tempus Paradime flow or Certus, it must be applied before distribute_read_design.
  • It is mandatory to list the partition name(s) inside the file specified using the -partition_list_file parameter:
    • For High Capacity ECO flow, the -partition_list_file parameter must be specified before distribute_read_design.
    • For non-High Capacity ECO flow, the -partition_list_file parameter must be specified before the first optimization.

However, an error is issued when any partition name, which is a part of -inter_partition_exclusive is missing in -partition_list_file, as shown below:

**ERROR: (IMPESO-616): Partition 'tdsp_core' is missing in -partition_list_file file. Partition specified for inter/intra/inter_partition_exclusive partition fixing should be present in -partition_list_file list as well.

In case of Certus, since -partition_list_file is not required, the software will use -distributed_opt_block_restore_file to identify the partition names.

-intra_partition <string>

Selects a list of partition module names to be optimized for the core logic of the specified partition. During the High Capacity ECO flow, it will reduce the database having the core logic of the listed partitions only. This parameter must be applied before write_eco_opt_db and eco_opt_design. In case of the Tempus Paradime flow or Certus, it must be applied before distribute_read_design.

Note:

It is mandatory to list the partition name inside the file specified with the -partition_list_file parameter.

  • For High Capacity ECO flow, the -partition_list_file parameter should be specified before distribute_read_design.
  • For non- High Capacity ECO flow, the -partition_list_file parameter should be specified before first optimization.

However, any partition name, which is a part of -intra_partition and missing in -partition_list_file will result in an error :

**ERROR: (IMPESO-616): Partition 'tdsp_core' is missing in -partition_list_file file. Partition specified for inter/intra partition fixing should be present in -partition_list_file list as well.

In case of Certus, since -partition_list_file is not required, the software will use -distributed_opt_block_restore_file to identify the partition names.
-keep_temp_files {true|false}

Keeps all the temporary files generated by DMMMC and Tempus clients for debugging purposes.

Default: false

Note: If set, this parameter must be applied before eco_opt_design.
-legal_only {true|false}]

Enables the tool to use the physical data to search for legal location while doing any buffer insertion or instance movement. This ensures that there is no instance overlap at the end of the ECO fixing stage, and after sourcing the ECO file in the implementation tool, you can directly run ECO routing.

When this parameter is set to false, eco_opt_design will not check for legal location, although physical data is provided. In this mode, eco_opt_design behaves in a logical mode flow, which means that physical data will be ignored, and this might create an instance overlap, and it will not check local density while inserting buffers. Also, the routing congestion checks are skipped when this parameter is set to false. So it is recommended that you first run ECO fixing in the legal-only mode (which is the default mode) and then, depending on the requirement, you may perform an incremental run by setting -legal_only to false.

Default: true

Note:

  • The -legal_only parameter is also honored by the Setup/Hold/DRV fixing engines.
  • If set, this parameter must be applied before eco_opt_design.
-load_cell_list <cell_list>  

Specifies the list of load cells to be inserted during Hold fixing, regardless of whether those cells have a dontUse attribute.

Note: If set, this parameter must be applied before eco_opt_design.

-load_eco_opt_db name

Specifies the path of the directory where previously generated ECO Timing DB files are kept. If not specified, the ECO Timing DB files will be generated.

Default=""

Note: If set, this parameter must be applied before eco_opt_design.
-load_irdrop_db name

Specifies the path of the directory where the command, debug_irdrop, generated IR drop DB files are kept.

Note: If set, this parameter must be applied before eco_opt_design.
-load_smart_mmmc_db <dirName> Points Tempus ECO to the ECO DB directory containing the additional compact timing information during the ECO fixing session. This parameter must be set before the design is loaded and must point to an ECO DB directory, which was previously generated through write_eco_opt_db using the setting, set_eco_opt_mode -create_smart_mmmc_db true.

Note: Before eco_opt_design, you still need to point to the ECO DB directory using the setting, set_eco_opt_mode -load_eco_opt_db <dirName>.
-max_cap_margin <float>  

Specifies the ratio by which the max_capacitance constraints would be relaxed or tightened. The parameter takes values between the range of -10 and 0.99

Default:0

Note: If set, this parameter must be applied before eco_opt_design.
-max_local_density <float>

Applies a local placement density threshold that Tempus will honor during timing optimization. When the local density for a given area has overpassed the threshold value, the software stops adding or moving more instances in that local area. 

The default value of this parameter is -1, which means that the software will not perform any local placement density checks because by default it is running with -legal_only true.

This parameter accepts values greater than 0. For example, to allow a maximum local placement density of 98%, set the value to 0.98.

Default: -1

Note:

  • This parameter is honored by DRV, Setup, and Hold optimization engines.
  • If set, this parameter must be applied before eco_opt_design.
  • The max_local_density (greater than 1) and -legal_only false settings can cause some placement in later stages while doing eco_route.
-max_opt_run_time <minutes>

Specifies the timeout period for the timing or power optimization phase of the set_eco_opt_mode command. When the value of this parameter is set to a positive value, the software restricts the optimization runtime by that value, specified in minutes. 

Default:0

This means that there is no limit for the timeout period. When the timeout period is reached, the software will exit the optimization phase, and displays the Tempus prompt with a stable DB.

Note: If set, this parameter must be applied before eco_opt_design.

-max_slack <FLOAT>

Specifies the maximum slack value to be used during ECO Timing DB generation when using PBA. Setting a positive -max_slack value forces the tool to retime positive GBA slack paths so that ECO optimization engine can benefit from an extra PBA Setup slack credit when doing Hold fixing or Power recovery. A positive -max_slack value implies larger runtime during ECO Timing DB generation, but tool will retime only as many paths as what is specified through the -max_paths parameter.

Default: 0

Note:

  • This parameter is only active when the -retime parameter is being set.
  • If set, this parameter must be applied before write_eco_opt_db.

-max_paths <paths>

Specifies the worst path found for each endpoint up to the number specified by the -max_paths parameter during ECO Timing DB generation. By default, the tool will automatically set a value for -max_paths that would lead to good PBA coverage of the design within reasonable run time. You can overwrite this by setting a specific -max_paths value, but it is recommended to keep it larger than 1 million. In any case, you must ensure that -max_paths value is superior or equal than the -nworst value multiplied by the number of GBA violated endpoints.

Default : 5000000

Note:

  • This parameter is only active when the -retime parameter is set.
  • If set, this parameter must be applied before write_eco_opt_db.
-max_run_time <minutes>

Specifies the time out period (in minutes) after which eco_opt_design will exit the session.

Note: If set, this parameter must be applied before eco_opt_design.
–max_tran_margin <float>

Specifies the ratio by which the max_transition constraints would be relaxed or tightened. The parameter takes values between the range of -10 and 0.99.

Default: 0.

Note: If set, this parameter must be applied before eco_opt_design.

-nworst <INT>

Specifies the number of paths to be enumerated for each endpoint. By default, the tool will automatically set a value for -nworst that would lead to a good PBA coverage of the design within reasonable run time. You can overwrite this by setting a specific -nworst value, but it is recommended to keep it larger than 50.

Default : 50

Note:

  • This parameter is only active when the -retime parameter is set.
  • If set, this parameter must be applied before write_eco_opt_db.
-optimize_core_only {true|false}

When set to true, enables the tool to automatically skip the timing optimization on the IO paths in order to focus only on the internal register to register paths. However, when set to true for leakage and area optimization, the tool doesn't touch any instances, which would be part of an IO path in order to avoid creating any new timing violations on the IO paths.

Default: false 

Note:

  • This parameter is not applicable for DRV optimization.
  • If set, this parameter must be applied before eco_opt_design.
-optimize_replicated_modules {true|false}

By enabling the –optimize_replicated_modules parameter, the tool will be able to optimize timing in the replicated modules. Any netlist change will be checked against each clone’s timing and physical context to ensure that no violations are created.

In this mode, only one ECO file is generated per group of clones. It is mandatory to list the cell name of the clones inside the file specified with the –partition_list_file parameter.

Default: false

Note:

  • The design must be assembled in Tempus through the merge_hierarchical_def command. You can also load an assembled DB from Innovus. This parameter works only in the physical mode optimization.
  • If set, this parameter must be applied before eco_opt_design.

-optimize_sequential_cells {true|false}

Enables the timing optimizer to optimize the sequential cells. In addition, it performs VT swapping and resizing of sequential cells.

Default : true 

Note: If set, this parameter must be applied before eco_opt_design.

-partition_list_file <string>

Enables the software to select the hierarchical instances that should be treated as partitions. The file specified with this parameter must contain a list of module names of those hierarchical instances. The eco_opt_design command will generate an ECO file for the top module and the partitions (with relative placement locations for cells). The default ECO files are generated as mentioned below:

top_eco_tempus.tcl and top_eco_innovus.tcl; blockA_eco_tempus.tcl and blockA_eco_innovus.tcl and so on.

where the top ECO file contains all ECOs, which is a union of top and partition ECOs.

Default: empty

-pba_effort {medium|high}

Creates a high or medium effort PBA mode honored by all optimization engines. When set to high, all optimization engines perform more aggressive timing closure or area/power recovery with respect to PBA timing and the expectation is to get better quality of results.

In some cases, when large amount of ECOs are done in this mode, the final timing signoff might show some setup timing degradation, which can be recovered by running a second ECO loop doing only setup timing recovery with the set_eco_opt_mode -setup_recovery parameter set to true.

Default: high

-post_mask {true|false}

Enables the timing closure engine to perform the following netlist changes without touching the base layer mask:

  • Inserts the Gate Array buffers or an inverter pair in place of existing Gate Array filler cells.
  • Resizes regular cells to Gate Array cells. It also resize Gate Array cells to Gate Array cells.
  • Deletes a regular cell.

The software automatically identifies the Gate Array cells by checking which library instances have the same SITE name as the Gate Array filler cells specified by the user. Here, empty spaces will be filled up by the Gate Array filler cells to ensure 100% placement density.

Note:

  • This is supported by DRV, Setup, and Hold fixing.
  • When setTieHiLoMode -cell {{<tieLo_name> <tieHi_name>}} setting is used, the Metal ECO flow will insert the TieLo cells to connect dangling input pins, in case the existing TieLo cells in the floorplan are extremely far or too overloaded.

-power_aware {true|false}

Specifies power awareness in all optimizers and transforms.

Tempus ECO provides the ability to take power as part of the overall cost function when doing timing closure.

When this parameter is enabled before the start of an optimization session, the current optimization and any subsequent optimizations (if running in incremental mode) checks for power changes for all optimizers and transforms during any changes in the design.

In any of the above cases, the first priority remains getting best final timing but enabling this option will get there with possibly slighter ECO although resulting in lesser final power.

For example, while fixing a Setup timing path violation, by default, the tool chooses to size one instance to a high leakage cell, while with the -power_aware mode, the tool tries to get to same timing by doing multiple sizing to non-high leakage cells.

Note :

  • This feature requires power activity to be annotated on the netlist with the report_power command, either through external activity file (recommended) or using propagated activity based on some default toggling rate.
  • This feature honors the -power_opt_focus parameter, which means that you can decide to force the tool in reducing more the total or leakage, or dynamic power increase.

Default: false
-power_opt_focus {total|leakage|dynamic|leakageOnly|dynamicOnly}

Specifies whether a given netlist should be optimized only for leakage or dynamic power reduction, or more for leakage or dynamic power while still reducing the overall total power during total power optimization.

The options are described below:

  • total: The power optimization engine focuses on getting the optimal total power in the design.

  • leakage: The power optimization engine optimizes total power but focuses more on leakage power reduction than on dynamic power reduction.

  • dynamic: The power optimization engine optimizes total power but focuses more on dynamic power reduction than on leakage power reduction.

  • leakageOnly: The power optimization engine focuses only on leakage power reduction.
  • dynamicOnly: The power optimization engine focuses only on dynamic power reduction.

Default: total

Note:

  • This parameter is honored by eco_opt_design -power and also by eco_opt_design -drv/-setup/-hold when the -power_aware parameter is set to true.
  • If set, this parameter must be applied before eco_opt_design.

-smart_mmmc_effort {low|medium|high}

Controls the trade-off between memory or runtime and timing QoR for timing or power ECO closure flow. This means that the higher the effort, the less memory or runtime, but the lesser timing QoR while running the eco_opt_design command.

  • low: Is the recommended (default) setting and ensures there is no timing QoR loss.
  • medium: Reduces memory and runtime significantly with minimal timing QoR loss.
  • high: Reduces memory and runtime further when compared to the medium mode, but with additional timing QoR loss.

In the low effort mode, which is the default and recommended setting, there is no compromise on timing QoR.

The medium and high effort modes can be used for initial rounds of ECO timing/power ECO closure flow.

Note: This parameter must be set before the design is loaded.

Default: low

Examples

  • The following command resets all set_eco_opt_mode parameters to their default values:

    tempus> set_eco_opt_mode -reset


  • The following example shows how to run eco_opt_design to fix hold-timing violations up to +150ps while ensuring no setup timing degradation below +100ps :

    tempus> set_eco_opt_mode -setup_target_slack 0.1 -hold_target_slack 0.15

    tempus> eco_opt_design -hold

     

  • The following example shows how to run eco_opt_design to fix maximum capacitance and maximum transition violations that are 10 percent above their respective maximum constraints:

    tempus> set_eco_opt_mode -drv_margin -0.1

    tempus> eco_opt_design -drv

     

  • The following example shows how to run eco_opt_design to optimize leakage power without allowing any setup timing degradation:

    tempus> set_eco_opt_mode -setup_target_slack 0

    tempus> eco_opt_design -leakage

     

  • The following example shows how to perform hold fixing and treat every cell listed in the partition.txt file as a partition.

    tempus> set_eco_opt_mode –partition_list_file partition.txt

    tempus> eco_opt_design -hold

     

  • The following commands will perform Hold fixing, and the replicated modules of the cell listed in the partition list file will be treated as clones:

    tempus> set_eco_opt_mode –optimize_replicated_modules true

    tempus> set_eco_opt_mode –partition_list_file partitions.txt

    tempus> eco_opt_design -hold

     

  • The following example shows an incremental optimization flow:

    tempus> set_eco_opt_mode -load_eco_opt_db <>

    tempus> set_eco_opt_mode -allow_multiple_incremental true

    tempus> set_eco_opt_mode -eco_file_prefix FULL_DRV

    tempus> eco_opt_design -drv

    tempus> set_eco_opt_mode -eco_file_prefix FULL_HOLD

    tempus> eco_opt_design -hold

    tempus> set_eco_opt_mode –eco_file_prefix FULL_SETUP

    tempus> eco_opt_design -setup

     

  • The following command is used to perform Hold fixing in routing congestion-aware mode.

    tempus> set_eco_opt_mode -routing_congestion_aware true

    tempus> eco_opt_design -hold

     

  • The following command performs Hold fixing via regular buffering/resizing/swapping along with inserting a dummy load cell, namely, dummyX1 cell.

    tempus> set_eco_opt_mode -add_load true -load_cell_list {dummyX1}

    tempus> eco_opt_design -hold

     

  • The following command fixes IR Drop violations in a C-MMMC session: 

    tempus> analyze_rail -results_directory ./dynamic_rail -type domain all

    tempus> debug_irdrop -domain all -output_directory my_ir_db -state_directory dynamic_rail/all_25C_dynamic_1 -eco_report -nworst_instances 1000000

    tempus> set_eco_opt_mode -save_eco_opt_db ECODB

    tempus> write_eco_opt_db

    tempus> set_eco_opt_mode -load_eco_opt_db ECODB

    tempus> set_eco_opt_mode -fix_ir_drop true

    tempus> set_eco_opt_mode -load_irdrop_db my_ir_db

    tempus> set_eco_opt_mode –fix_max_tran false –fix_max_cap false

    tempus> eco_opt_design -drv


  • The following command enables Hold fixing in the metal ECO mode by allowing the listed Gate Array filler cells to be deleted or inserted during the ECO process.

    tempus> set_eco_opt_mode –post_mask true 

    tempus> set_eco_opt_mode –use_ga_filler_list {GFILL1BWP GFILL2BWP GFILL4BWP GFILL10BWP}

    tempus> eco_opt_design -hold

     

  • The following command saves the regular timing and additional compact timing information in the ECO DB directory named EcoTimingDB in the STA SMSC session.
    tempus> set_eco_opt_mode -save_eco_opt_db EcoTimingDB                    
    tempus> set_eco_opt_mode -create_smart_mmmc_db true 
    tempus> write_eco_opt_db

 
  • The following command loads the design with a minimized set of data to reduce the memory or runtime during an ECO fixing stage when many timing views are enabled, and performs Setup timing closure in the ECO MMMC session.
    tempus > set_eco_opt_mode -load_smart_mmmc_db EcoTimingDB
    tempus> <load_design>
    tempus> set_eco_opt_mode -load_eco_opt_db EcoTimingDB
    tempus> eco_opt_design -setup

  • The following commands allow Hold timing closure in the post-mask mode using programmable filler cells.

    tempus> set_eco_opt_mode -post_mask true
    tempus>     set_eco_opt_mode -use_pfc_filler_list {ln10_ecofiller40x … ln10_ecofiller4x}
    tempus>     set_eco_opt_mode -use_pfc_decap_list {ln10_ecofillsgcap40x … ln10_ecofillsgcap4x}
    tempus>     set_eco_opt_mode -use_pfc_regular_list {ln10_ecodlybt01 ln10_ecobuft04 … ln10_ecoand02 … ln10_ecoinv04 …}
    tempus>     eco_opt_design -hold

  • The following commands perform clock skewing during setup fixing. Only CKBUFX1 and CKBUFX4 can be added to the clock tree.

    tempus> set_eco_opt_mode -clock_cell_list {CKBUFX1 CKBUFX4}
    tempus> set_eco_opt_mode -allow_skewing true
    tempus> eco_opt_design -setup

  • The following commands enable cell EM fixing for all types of EM violations.

    tempus> set_eco_opt_mode -fix_cell_em true
    tempus> set_eco_opt_mode -em_type all
    tempus> eco_opt_design -drv

  • The following command specifies the number of views for setup timing, hold timing, and drv:
    tempus> set_eco_opt_mode -smart_mmmc_max_view_count {{setup 3} {hold 2} {drv 1}}
  • The following command considers the specified cells (BUF8_L3_P48_ELVT and BUF6_L3_P48_ELVT) as high-effort resources to enhance timing or power efficiency during signoff optimization:
    tempus> set_eco_opt_mode -high_effort_cell_list {BUF8_L3_P48_ELVT BUF6_L3_P48_ELVT}
    tempus> eco_opt_design -setup
