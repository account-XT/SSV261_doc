CONST_COMP_TIM2

NAME

CONST_COMP_TIM2 (CONSTRAINT_COMPARISON)

MESSAGE

Inconsistent set_annotated_delay at the top-level vs. block

DEFAULT SEVERITY

Warning

DESCRIPTION

Indicates that an inconsistency in  set_annotated_delay command is found between top level and block level constraints. The following are the possible causes for this violation:

  •  set_annotated_delay command specified at either top level or block level
  •  set_annotated_delay commands specified at both top level and block level but with different values

This rule is checked by compare_constraints command and the results can be reported by report_rule_check command.


This rule has specific rule occurrence attributes for the details about the violation.

In addition, common rule occurrence attribute type provides the possible causes for the violation.

AttributeValueDescription
type BLOCK_NO_CONSTRAINT

Missing constraint at block level

TOP_NO_CONSTRAINT Missing constraint at top level

DIFFERENT_CONSTRAINTS Inconsistent constraints between top level and block level

EXAMPLE

  • For the figure below, the block level constraints file has this following constraint. The Litmus issues a warning if the top level constraints file does not have a set_annotated_delay specified for the net timing arc from i_blk/g4/Z.

    Block level constraint (instance scope: i_blk)

    set_annotated_delay 1 -net -from [get_pins g4/Z]
  • For the above figure, the top and the block level constraints files have the following constraints, respectively, where the net timing arc from i_blk/g4/Z gets annotated delay value of 2 at top level. The Litmus issues a warning because the net timing arc gets annotated delay value of 1 at block level.

    Top level constraint

    set_annotated_delay 2 -net -from [get_pins i_blk/g4/Z]

    Block level constraint (instance scope: i_blk)

    set_annotated_delay 1 -net -from [get_pins g4/Z]
