CONST_HIER_GRP1

NAME

CONST_HIER_GRP1 (CONSTRAINT_HIER_SIGNOFF)

MESSAGE

Inconsistent clock relations between block-level clocks and top-level clocks

DEFAULT SEVERITY

Warning

DESCRIPTION

This rule reports that the relationship between the block-level clock and its corresponding top-level clock is inconsistent. The relationships being checked are: synchronous/asynchronous and mutually exclusive. The report_hierarchical_clock_mapping command can be used to understand how the clocks are mapped between the top level clocks and block level clocks to determine if this rule violation is due to incomplete clock mapping. This rule is checked by check_target_constraints command and results can be reported by report_rule_check command.

If multiple relationships are implied between the same clock pair, the following precedence is applied:

  • Physically exclusive (highest)
  • Asynchronous
  • Logically exclusive (lowest)

RULE ATTRIBUTES

This hierarchical signoff rule check is customizable; its properties are specified through the attributes listed below. To view all the attributes for this rule check from the tool, the following command should be used:

report_rule_source "CONST_HIER_GRP1" -verbose
AttributeDescription
check_type

Specifies the types of clock relationships to be checked

Possible Value: <all | asynchronous | logically_exclusive | physically_exclusive>

Where:

all: Check the consistency of all types of clock relationships in block versus top. This is the default.

asynchronous: Checks the consistency of only the synchronous/asynchronous clock relationship in block versus top.

logically_exclusive: Checks the consistency of logically mutually exclusive clocks in block versus top.

physically_exclusive: Checks the consistency of physically mutually exclusive clocks in block versus top.
check_connected

Specifies whether to check the clock connectivity before reporting an occurrence of this rule. This attribute will affect only the asynchronous check type.

Possible Value: <yes | no>

Where:

yes: Clock connectivity is checked. This is the default.

no: Clock connectivity is not checked.

EXAMPLE

  • For the figure below, the following top level constraints file defines Top_clk1 and Top_clk2 as physically exclusive, whereas the corresponding mapped clocks to block level, Blk_clk1 and Blk_clk2, respectively are synchronous to each other. This rule reports that the relationship between the top-level clocks (physically exclusive) is inconsistent to their corresponding block-level clocks (synchronous).

    Top level constraints

    create_clock -name Top_clk1 -period 8  [get_ports Top_clk1]
create_clock -name Top_clk2 -period 8  [get_ports Top_clk2]
set_clock_groups -name grp1 -group {Top_clk1} -group {Top_clk2} -physically_exclusive

    Block level constraints (instance scope: i_blk)

    create_clock -name Blk_clk1 -period 8  [get_ports Blk_clk1]
create_clock -name Blk_clk2 -period 8  [get_ports Blk_clk2]

    Hierarchical clock mapping

    Top_clk1 is mapped to Blk_clk1
Top_clk2 is mapped to Blk_clk2
