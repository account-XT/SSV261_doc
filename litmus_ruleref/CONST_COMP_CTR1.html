CONST_COMP_CTR1

NAME

CONST_COMP_CTR1 (CONSTRAINT_COMPARISON)

MESSAGE

Inconsistent set_clock_transition at the reference-level vs. target

DEFAULT SEVERITY

Warning

DESCRIPTION

Indicates that an inconsistency in set_clock_transition command is found between reference and target level constraints. The following are the possible causes for this violation:

  • set_clock_transition command specified at either reference or target level
  • set_clock_transition commands specified at both reference and target level but with different values

This rule is checked by compare_constraints command and the results can be reported by report_rule_check command.


This rule has specific rule occurrence attributes for the details about the violation.

Attribute

Type

Description

occurrence_id unsigned Occurrence id
target_view_name string Target View Name
reference_view_name string Reference View Name

target_clock object Target clock
reference_clock object Reference clock

In addition, common rule occurrence attribute type provides the possible causes for the violation.

Attribute

Value

Description

type BLOCK_NO_CONSTRAINT

Missing constraint at target level

TOP_NO_CONSTRAINT Missing constraint at reference

DIFFERENT_CONSTRAINTS Inconsistent constraints between reference and target level

EXAMPLE

  • For the figure below, the following constraints contain set_clock_transition commands specified in both reference and target level constraints. This rule is reported for the set_clock_transition commands, because they are specified with different values.

    Top level constraints

    create_clock -name Top_clk -period 2 [get_ports Top_clk]
set_clock_transition 0.5 [get_clocks Top_clk]

    Block level constraints (instance scope: i_blk)

    create_clock -name Blk_clk -period 2 [get_ports Blk_clk]
set_clock_transition 1.0 [get_clocks Blk_clk]

    Hierarchical clock mapping

    Top_clk is mapped to Blk_clk
