CONST_HIER_IO3

NAME

CONST_HIER_IO3 (CONSTRAINT_HIER_SIGNOFF)

MESSAGE

Block output port with delay vs. a clock is not in a timing path within the same clock group at the top level

DEFAULT SEVERITY

Warning

DESCRIPTION

For every block output port OUT with output delay versus clock CLK, Litmus finds the top level clock group of CLK's top level equivalent clock, and checks that there is a path between timing points in that clock group that traverses OUT. This rule is checked by check_target_constraints command and results can be reported by report_rule_check command.


This rule has specific rule occurrence attributes for the details about the violation.

AttributeTypeDescription
occurrence_id unsigned Occurrence id
block_view_name string Block View Name
top_view_name string Top View Name
scope object Block Instance
block_port object Output port of the block
block_clock object Block-level clock
relative_top_clocks object_list Top clock
type object_list type
block_file_line object_list Block file number
block_file_name object_list Block file name


In addition, common rule occurrence attribute type provides the possible causes for the violation.

AttributeValueDescription
type TOP_NO_LAUNCH_CLOCK Launch clock is absent at top-level

TOP_NO_CAPTURE_CLOCK Capture clock is absent at top-level

TOP_UNCONSTRAINED top-level unconstrained

TOP_ASYNC Top-level is asynchronous

TOP_EXCLUSIVE Top-level is mutually exclusive

DIFFERENT_CLOCK_MAPPING Inconsistent clock mapping

EXAMPLE

  • The design in the figure below (where OUT1A has a delay versus CLK1A) would cause a rule check violation if none of the following were present in the combinational fanout of OUT1A. This rule would also be flagged if no DFF/port in the same clock group can be found in the fanin of OUT1A.
    • A DFF that is clocked by the top level clock CLK1
    • A pin or primary output OUT1 that has an output delay versus CLK1

  • For the figure above, if a top level clock CLK2 is connected to the block level clock CLK1A and the the top level DFF is clocked by another top level clock CLK1 from a different clock group other than CLK2 (asynchronous, defined like the following top level constraints), then this rule check violation will happen for the following block level constraints. Here, the block output port Block_A/OUT1A has set_output_delay relative to block clock CLK1A which is getting top level equivalent clock CLK2. But at top level, the timing path is not in the same clock group of the top level equivalent clock.

    Top level constraints

    create_clock -name CLK1 -period 8 [get_ports CLK1] -waveform {0 4}
create_clock -name CLK2 -period 8 [get_ports CLK2] -waveform {0 4}
set_clock_groups -name group1 -group {CLK1} -group {CLK2} -asynchronous

    Block level constraints (instance scope: Block_A)

    create_clock -name CLK1A -period 8 [get_ports CLK1A] -waveform {0 4}
set_output_delay 1 -clock CLK1A [get_ports OUT1A]
