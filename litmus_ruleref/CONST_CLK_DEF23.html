CONST_CLK_DEF23

NAME

CONST_CLK_DEF23 (CONSTRAINT_SIGNOFF)

MESSAGE

Clock redefined: used create_clock on an object that is in the transitive fanout of another clock

DEFAULT SEVERITY

Warning

DESCRIPTION

Indicates that there is a redefined clock. This happens when create_clock is used on an object that is in another clock's transitive fanout. When checking if a clock is defined in the fanout of another one, Litmus takes into account constant propagation. Also, a clock's fanout propagation is interrupted where other clocks are defined. If a clock GCLK is defined in the fanout of MCLK, then the logic in the fanout of GCLK is not considered to be in the fanout of MCLK unless it can be reached from MCLK without traversing the definition point of GCLK. This rule is checked by verify_timing_intent command and results can be reported by report_rule_check command.


This rule has specific rule occurrence attributes for the details about the violation.

Attribute

Type

Description

occurrence_id unsigned Occurrence id

EXAMPLE

  • The following case reports this rule because clock GCLK is defined on the output pin g1/X of the g1 cell, since one of the inputs of the g1 cell is in the transitive fanout of another clock MCLK:

    create_clock -name MCLK -period 10 -waveform {0 5} [get_ports {clk1}]
create_clock -name GCLK -period 20 -waveform {0 5} [get_pins {g1/X}]
