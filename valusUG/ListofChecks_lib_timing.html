LIB_TIMING

The LIB_TIMING checks are performed during the validation of timing attributes/groups of a library. These checks consist of a number of specific checks for NLDM data, ECSM timing data, and CCS timing data.

LIB_TIMING
Message Prefix ID Message Severity Description

VALUS

14

The %s capacitances %s table group %s%s%s for %s transition in pin '%s' of cell '%s' is not in the range of min cap value.

Error

For correct calculation of delay value the capacitances value should be more than or equal to min cap value.

VALUS

1008

Identified trigger arcs with timing sense 'non_unate' and having only 'rise' or 'fall' table. These trigger arcs can have only half unateness.

Error

The trigger arcs with only rise or fall table cannot have unateness non_unate. These trigger arcs can have only half unateness i.e positive_unate/negative_unate. This can cause incorrect timing analysis. The generated library should be further looked for correctness.

VALUS

1011

Identified more than 2 parallel arcs with timing type '%s' between '%s'->'%s' pins of cell '%s'. The number of parallel arcs cannot be more than 2, between pins pair.

Error

Between a pin pair there can be 2 parallel arc possible. One for early and another for late. When more than 2 parallel arcs are present, the generated library should be further checked for correctness.

VALUS

1026

The function specified on the pin '%s' is '%s', but a timing arc is missing between pins '%s' and '%s' of cell '%s'. This missing timing arc can cause issues in timing analysis.

Error

The timing arc needs to be present from all the input pins specified in the function to the output pin. Absence of timing arc can cause inaccuracy during timing analysis.

VALUS

1029

Identified missing tables '%s' and '%s' for the combinational arc in pin '%s' of cell '%s'. This can cause issue during timing analysis.

Error

For a combinational arc al the four tables - (cell_rise and rise_transition) and (cell_fall and fall_transition) should be defined. For combinational_rise, cell_rise and rise_transition should be present and for combinational_fall, cell_fall and fall_transition should be present.

VALUS

36

The timing arc(s) with related pin '%s' timing_type '%s' is closed for the when condition but not for the Input Pin (s) '%s' in pin '%s' for cell '%s'.

Warning

The when condition in a timing arc(s) should be closed for a specific related pin and timing type. Otherwise this can cause problems during timing analysis.

VALUS

VALUS

1467

The 'dynamic_current' waveform specified in cell '%s' has very long tail with long tail ratio '%f' and time value reaching '%f'. This may impact the accuracy of transient power analysis.

Warning

This message is issued when there are points in CCS power waveform resulting in very long tail with long tail ratio exceeding the specified threshold. The long tail ratio is calculated as (T3-T2)/(T2-T1), where T1 is start time, T2 is peak time and T3 is end time. The threshold can be controlled using global 'set timing_library_ccsp_long_tail_threshold' in tempus and using command set_valus_mode -ccsp_long_tail_threshold in Valus. These long tails in waveform if used as such may cause issues in accuracy of power analysis. To fix the issue, review the characterization and modify it with appropriate values.

1468

The '%s' group on cell '%s'%s, has when condition '%s' which is not mutually exclusive with when condition '%s'.

Warning

This message is issued when the leakage_power or internal_power groups, present on a cell or pin respectively, have when conditions which are not mutually exclusive. For example, if two equivalent internal_power groups have when conditions 'D & !SE' and 'D & SE', they will be mutually exclusive. But if they have when conditions 'D' and 'D & SE', then they will not be mutually exclusive. To fix this issue, you should modify the specified when conditions such that they are mutually exclusive.
