set_eco_opt_mode

set_eco_opt_mode
[-help] 
[-custom_distribution_file file]
[-distributed_opt_block_restore_file file]
[-distributed_opt_max_clients_per_host value]   
[-distributed_opt_out_dir directoryname]   
[-distributed_opt_pre_eco_route_tcl  file]      
[-distributed_opt_post_eco_route_tcl file]    
[-distributed_opt_pre_extraction_tcl  file]   
[-distributed_opt_post_extraction_tcl  file]
[-distributed_opt_post_restore_design_tcl file]
[-distributed_opt_pre_restore_design_tcl file]  

Sets the global parameters for ECO. The parameters that you specify with the set_eco_opt_mode command are then used automatically when you run ECO optimization by running the eco_opt_design command.                

Parameters

-help

Outputs a brief description that includes type and default information for each set_eco_opt_mode parameter.

-custom_distribution_file file

Specifies a file that provides differentiated resource distribution information for CPU and memory configurations of Certus and Tempus clients. This parameter supports various resource requirements, helping ensure optimal performance.

Note:

This parameter must be specified before distribute_read_design.

Default: ""

For details, see the Recommended Guidelines for Certus chapter in the Certus User Guide
-distributed_opt_block_restore_file file

Provides a list of pointers to the Innovus database that can be loaded on Certus clients when calling the start_distributed_eco_clients command. If some partitions in the Certus client manager netlist are not included in the block restore file, those partitions will be considered don’t touch during ECO closure.

If the Certus client manager has a reduced database when running in High Capacity ECO mode, partitions not present in the Certus client manager will not be loaded by any Certus client.

Example:

blockName1 INVS_DB_PATH_for_block1

blockName2 INVS_DB_PATH_for_block2

and so on

Any partition that is listed as part of -dont_touch_partition_list or -touch_partition_list or -intra_partition or -inter_partition or -inter_partition_exclusive must be specified in the block restore file; however, for a few partitions that are excluded from ECO, only the partition name needs to be specified.

Example:

blockName3 is a nested partition inside blockName2. If Signoff ECO optimization is not allowed inside blockName3, and -intra_partition partition fixing is applied to blockName2 only, then you must specify the partition name, blockName3, in the block restore file, and skip specifying its Innovus database:

blockName1 INVS_DB_PATH_for_block1

blockName2 INVS_DB_PATH_for_block2

blockName3
-distributed_opt_max_clients_per_host <value>

When a value greater than 0 is provided, the Certus client manager is instructed to reuse the Tempus client's machines when starting Certus clients using the start_distributed_eco_clients command. This allows sharing CPUs between Tempus and Certus clients. 

Note that memory usage on those machines is equal to the sum of one of the Tempus client process memory and N Certus client process memory, where N is the value set by this parameter.

Default: 0
-distributed_opt_out_dir directoryname 

Specifies the directory name where the Certus clients' log files will be generated. By default, the tool uses DistOpt/ in the current directory.
-distributed_opt_pre_eco_route_tcl file

Provides a TCL script that each Certus client will source before performing ECO routing during the implement_distributed_eco command.
-distributed_opt_post_eco_route_tcl file

Provides a TCL script that each Certus client will source after performing ECO routing during the implement_distributed_eco command.
-distributed_opt_pre_extraction_tcl file

Provides a TCL script that each Certus client will source before performing parasitic extraction during the implement_distributed_eco command.
-distributed_opt_post_extraction_tcl file

Provides a TCL script that each Certus client will source after performing parasitic extraction during the implement_distributed_eco command.
-distributed_opt_post_restore_design_tcl file

Provides a TCL script that each Certus client will source after loading the Innovus DB.

Default: ""
-distributed_opt_pre_restore_design_tcl file  

Provides a TCL script that each Certus client will source before loading the Innovus DB.

Default: ""

Note: The above set_eco_opt_mode parameters are specific to Certus only. For details related to other parameters of the set_eco_opt_mode command, refer to the Tempus Text Command Reference document.

Examples 

  • The following command refers to a file (blocks.txt) pointing to all Innovus DBs that are opened for ECO:

set_eco_opt_mode -distributed_opt_block_restore_file blocks.txt

Below is a template for the blocks.txt file:

blockName1 <dirName>/blockName1.enc.dat

blockName2 <dirName>/blockName2.enc.dat

Refer to the Template Scripts section of the Certus User Guide.

  • The following command refers to a file (distribution.tcl) referring to each client requesting a separate machine:
    set_eco_opt_mode -custom_distribution_file distribution.tcl

where (distribution.tcl) file includes:

module=topChip nCpu=16 {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 8 -R 'select\[OSREL==EE80\] rusage\[mem=250000,tmp=50000\] span\[hosts=1\]'} 
module=small_cpu nCpu=8 {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 8 -R 'select\[OSREL==EE80\] rusage\[mem=150000,tmp=50000\] span\[hosts=1\]'} 
module=big_GPU nCpu=16 {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 16 -R 'select\[OSREL==EE80\] rusage\[mem=250000,tmp=50000\] span\[hosts=1\]'}
view=setup_view1 nCpu=16 {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 16 -R 'select\[OSREL==EE80\] rusage\[mem=200000,tmp=100000\] span\[hosts=1\]'}
view=setup_view2 nCpu=16  {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 16 -R 'select\[OSREL==EE80\] rusage\[mem=200000,tmp=100000\] span\[hosts=1\]'} 
view=setup_hold1 nCpu=8  {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 8 -R 'select\[OSREL==EE80\] rusage\[mem=200000,tmp=100000\] span\[hosts=1\]'} 
view=setup_power  nCpu=8  {bsub -q batch -W 100:00 -P SSV:26.1:Certus -o /dev/null -n 8 -R 'select\[OSREL==EE80\] rusage\[mem=200000,tmp=100000\] span\[hosts=1\]'}
