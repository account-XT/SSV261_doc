Certus Text Command Reference

generate_summary

generate_summary
[-help]
[-logvFileName <string>]
[-outputFile <string>]

Displays the Certus log summary report in a text file. The log summary report includes the following details:

  • Runtime details of the full flow.
  • Tool versions for Certus Manager, Certus Clients, and Tempus Clients.
  • Active views for each Tempus Client.
  • Partition Name, Netlist Size, the Number of Replications, and Log Pointer for each Certus Client.
  • Number of CPUs enabled for Certus Manager, Certus Clients, and Tempus Clients.
  • Size of the netlist on the Certus Manager, Certus Clients, and Tempus Clients. 
  • RC annotation summary for each partition loaded as a Certus client.
  • QoR/TAT/Memory summary from time_design_signoff, ECO optimization, and implement_distributed_eco steps.

  • Mean displacement, Max displacement, Instances moved, and Errors in refinePlace for each partition.

  • Final Routing DRC after each implement_distributed_eco call for each partition.

  • Initial density (from the first optimization step) and the final density (from the last optimization step) for each partition.
  • List of error codes and DIAGs for Certus Manager, Tempus Clients, and Certus Clients.

Parameters 

-help

Outputs a brief description that includes type and default information for each generate_summary parameter.

For a detailed description of the command and all of its parameters, use the man command:

man generate_summary.

-logvFileName <string>

Specifies the name of the log file. By default, the log file name is certus.logv.

Note: This parameter is optional.

-outputFile <string>

Specifies the name of the output file, which includes the log summary details for the specified log file.

For the log file, certus.logv, the default log summary file name is certus.logv.summary.txt.

Note: This parameter is optional.

Examples

  • The following command generates the summary report, certus.logv.summary.txt, for the Certus log file, certus.logv:
    certus> generate_summary

  • The sample script below performs distributed hold optimization in full-flat mode and ends with the ECO implementation step. This step performs ECO routing and parasitic extraction for each Certus client, followed by a timing update with updated parasitics for the timing clients.

    set eco_setup_view_list "V1 V2"
    set eco_hold_view_list "V1 V2"
    set eco_dynamic_view V1
    set eco_leakage_view V2
    set_multi_cpu_usage -localCpu 12 -remoteHost 2 -cpuPerRemoteHost 8
    set_eco_opt_mode -distributed_opt_block_restore_file blkRestore.txt
    distribute_read_design -restore_design {save_db_dmmmc_V1 save_db_dmmmc_V2} -outdir paradime_Output
    set_multi_cpu_usage -localCpu 12 -remoteHost 3 -cpuPerRemoteHost 8
    start_distributed_eco_clients
    set_eco_opt_mode -verbose true
    time_design_signoff -outDir INITIAL_TDS -report_power
    set_eco_opt_mode -eco_file_prefix ECO/drv
    eco_opt_design -drv
    set_eco_opt_mode -eco_file_prefix ECO/setup
    eco_opt_design -setup
    set_eco_opt_mode -eco_file_prefix ECO/hold
    eco_opt_design -hold
    implement_distributed_eco
    time_design_signoff -outDir FINAL_TDS -report_power
    generate_summary
