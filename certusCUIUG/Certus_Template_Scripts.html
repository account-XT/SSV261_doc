Certus Template Scripts

Use the template scripts below to run Certus in different modes:

Script 1 - Certus Distributed Hierarchical Timing Closure - Full Flat Mode

The script below performs distributed hold optimization in full-flat mode and ends with the ECO implementation step. This step performs ECO routing and parasitic extraction for each Certus client, followed by a timing update with the updated parasitics on the timing clients.

set_multi_cpu_usage –local_cpu 24 –remote_host 8 –cpu_per_remote_host 4
set_distributed_hosts <your LSF args> -time_out 10000
set_distributed_mmmc_mode -eco true
set_distributed_mmmc_mode –eco_merge_mmmc
set_db eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set_db eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set_db eco_dynamic_view {setup_3v} ; set_db eco_leakage_view {setup_3v}

File Pointing to all Innovus DBs Opened for ECO

set_db opt_signoff_distributed_optimization_block_restore_file blocks.txt 

Required before Design Loading

set_db opt_signoff_optimize_replicated_modules true

Loads the STA Sessions on Tempus Clients

distribute_read_db -read_db {…} -out_dir reports_Paradime

Sets the Distributed Options for Certus Clients

set_multi_cpu_usage –remote_host <equal_to_partition_count> \
-cpu_per_remote_host <value>
set_distributed_hosts <your LSF args> -time_out 10000

Starts the Certus Clients

start_distributed_eco_clients

Runs Hold Fixing in PBA Mode

opt_signoff –hold

Performs ecoRoute/extraction and Parasitic Back-annotation

implement_distributed_eco

Collects Final Signoff Timing from Tempus Clients and Saves the Final Innovus DB

time_design_signoff
export_distributed_eco -out_dir Final -export_only innovus_dbs

Script 2 - Certus Distributed Hierarchical Timing Closure - Inter-partition High Capacity ECO Mode

The script below performs Hold timing closure by enabling existing High capacity ECO for large sub-systems and top level designs. It optimizes the logical inter-partition, which means that each timing path crosses the boundary of exactly one of the listed partitions. The script ends with the ECO implementation step, which performs ECO routing and parasitic extraction on each Certus client, followed by a timing update with updated parasitics on the timing clients.

set_multi_cpu_usage –local_cpu 24 –remote_host 8 –cpu_per_remote_host 4
set_distributed_hosts <your LSF args> -time_out 10000
set_distributed_mmmc_mode -eco true
set_distributed_mmmc_mode –eco_merge_mmmc
set_db eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set_db eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set_db eco_dynamic_view {setup_3v} ; set_db eco_leakage_view {setup_3v}

File pointing to all the Innovus DB that are opened for ECO

set_db opt_signoff_distributed_optimization_block_restore_file blocks.txt

Required before Design loading

set_db opt_signoff_optimize_replicated_modules true

Reduces the DB around partition-to-partition and between top-and-partition

set_distributed_mmmc_mode -enable_high_capacity_eco
set_db opt_signoff_inter_partition {blockA blockB}

Loads the STA sessions on Tempus Clients

distribute_read_db -read_db {…} -out_dir reports_Paradime

Sets the distributed options for Certus clients

set_multi_cpu_usage –remote_host <equal_to_partition_count> \ 
-cpu_per_remote_host <value>
set_distributed_hosts <your LSF args> -time_out 10000

Starts the Certus clients

start_distributed_eco_clients

Runs Hold Fixing in PBA Mode

opt_signoff –hold

Performs ecoRoute/extraction and Parasitic Back-annotation

implement_distributed_eco

Collects Final Signoff Timing from Tempus Clients and Saves the Final Innovus DB

time_design_signoff
export_distributed_eco -out_dir Final -export_only innovus_dbs

Script 3- Distributed Hierarchical Power Reduction - With ECO implementation and parasitic back-annotation loop

The script below performs Power recovery by enabling existing High capacity ECO for large subsystems and top-level designs. It optimizes the logical inter-partition, meaning that each timing path crosses the boundary of exactly one of the listed partitions. The script performs the ECO implementation step, which runs ECO routing and parasitic extraction on each Certus client, followed by a timing update with updated parasitics on the timing clients. Next, a Setup timing recovery using Vth swapping only is performed to address any timing violations that would have resulted from extensive ECO during power optimization.

set_multi_cpu_usage –local_cpu 24 –remote_host 8 –cpu_per_remote_host 4
set_distributed_hosts <your LSF args> -time_out 10000
set_distributed_mmmc_mode -eco true
set_distributed_mmmc_mode –eco_merge_mmmc
set_db eco_setup_view_list {setup_1v setup_2v setup_3v setup_4v}
set_db eco_hold_view_list {hold_1v hold_2v hold_3v hold_4v}
set_db eco_dynamic_view {setup_3v} ; set_db eco_leakage_view {setup_3v}
set_db opt_signoff_distributed_optimization true
set_db opt_signoff_distributed_optimization_block_restore_file blocks.txt
set_db opt_signoff_optimize_replicated_modules true
set_distributed_mmmc_mode -enable_high_capacity_eco
set_db opt_signoff_inter_partition {blockA blockB}
distribute_read_db -read_db {…} -out_dir reports_Paradime
set_multi_cpu_usage –remote_host <equal_to_partition_count> \
-cpu_per_remote_host <value>
set_distributed_hosts <your LSF args> -time_out 10000
start_distributed_eco_clients
set_db opt_signoff_retime path_slew_propagation
set_db opt_signoff_pba_effort high; set_db opt_signoff_nworst 50 ;    
set_db opt_signoff_max_paths 5000000; set_db opt_signoff_max_slack 0
set_db opt_signoff_along_route_buffering true; set_db opt_signoff_verbose false
set_db opt_signoff_allow_multiple_incremental true
opt_signoff –power
implement_distributed_eco

Performs Setup Timing Recovery to Fix any Timing Gaps Post ECO Implementation

set_db opt_signoff_setup_recovery true; set_db opt_signoff_max_slack 0
opt_signoff –setup
